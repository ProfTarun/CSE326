Responsive Content Structuring

More than half of the Web is read on phones. A responsive page is one whose content adapts to any screen, from a 360-pixel handset to a wide monitor, without a separate mobile site. Most of the adapting is done by CSS in Unit 3, but it only works if the HTML is structured for it. This chapter covers the HTML half: the viewport tag, mobile-first thinking, source order, flexible media and the mistakes that make a page impossible to fit on a small screen.

21.1 What "responsive" means

A responsive page has one HTML document that responds to the device it is shown on: text reflows, columns stack, images shrink, menus collapse. The alternative, a fixed 980-pixel desktop layout, forces phone users to pinch and scroll sideways, and search engines rank it lower (Chapter 11). Responsiveness is achieved by three things working together: HTML that provides a clean, logical structure; CSS media queries that rearrange it for each screen width; and media that can scale.

21.2 The viewport meta tag

Mobile browsers were built when the Web was made of desktop pages, so by default they pretend to be a wide desktop screen (about 980 pixels), lay the page out at that width and then shrink the whole thing to fit the phone. The result is a miniature desktop page with unreadable text. The viewport meta tag tells the browser to stop pretending:

<meta name="viewport" content="width=device-width, initial-scale=1.0">
  • width=device-width: lay the page out at the device's real screen width.
  • initial-scale=1.0: start at 100% zoom, not zoomed out.

It belongs in the <head> of every page and is essential for a mobile-responsive page; without it, media queries measure the wrong width and nothing else in this chapter works. Do not add user-scalable=no: preventing zoom is an accessibility failure.

21.3 Mobile-first and logical source order

Mobile-first means designing for the smallest screen first, then enhancing for larger ones. Start with a single column that works on a phone; when there is room, CSS adds a second column, then a third. Working the other way, shrinking a desktop design down, produces cramped, compromised phone pages. Mobile-first is also honest about priorities: on a small screen only the important content fits, so you decide what matters first.

Because the single-column view is simply the HTML in the order it was written, logical source order is the foundation: header, navigation, main content, related content, footer. Chapter 14 showed why this also serves screen readers and search engines. If the source order is right, the page is already responsive on a phone before a line of CSS exists.

21.4 Flexible, scalable media

A 1200-pixel image with width="1200" hard-coded in the HTML will overflow a 360-pixel phone and force horizontal scrolling. Responsive content requires that images and videos scale with their container: they should be allowed to shrink, never given fixed pixel widths that exceed small screens. The standard CSS rule is:

img, video { max-width: 100%; height: auto; }

With that in place you can still set width and height attributes on the <img> (Chapter 8) to prevent layout shifts: they describe the image's natural proportions, and the CSS caps the displayed width at the container. Do not replace images with text on phones, and do not load them only on desktop; scale them.

<style> img { max-width: 100%; height: auto; border: 3px solid #E07B1E; } </style>
<p>This image is 800px wide by nature, but it never overflows its container:</p>
<img src="https://picsum.photos/id/1018/800/300" alt="A mountain lake" width="800" height="300">

Serving the right image

Scaling a huge image down still downloads the huge file. The responsive-image tools from Chapter 8 fix that: srcset lists candidate files with their widths, sizes tells the browser how wide the image will be displayed, and the browser picks the smallest file that is sharp enough. <picture> goes further and lets you supply a differently cropped image for phones.

<img src="hero-800.jpg"
     srcset="hero-480.jpg 480w, hero-800.jpg 800w, hero-1600.jpg 1600w"
     sizes="(max-width: 600px) 100vw, 800px"
     alt="Campus at dawn" width="800" height="400">

<picture>
  <source media="(max-width: 600px)" srcset="hero-portrait.jpg">
  <img src="hero-wide.jpg" alt="Campus at dawn">
</picture>

21.5 A first look at media queries

The CSS side belongs to Unit 3, but one example makes the whole idea concrete. A media query applies CSS only when a condition about the screen is true. Here, two sections sit side by side when the viewport is at least 600px wide and stack otherwise. Run it and drag the preview's edge, or view it on a phone.

<style>
  .row { display: flex; flex-direction: column; gap: 10px; }
  .row > section { background: #E9F7E7; padding: 12px; border-radius: 8px; }
  @media (min-width: 600px) {          /* only when there is room */
    .row { flex-direction: row; }
    .row > section { flex: 1; }
  }
</style>
<div class="row">
  <section><h2>About</h2><p>Stacked on a phone, side by side on a desktop.</p></section>
  <section><h2>Courses</h2><p>Same HTML, different arrangement.</p></section>
</div>

Notice what the HTML did not have to change: nothing. That is the payoff of structuring content first.

Missing viewport tagThe shrunken-desktop layoutAdd it to every page

Wide tables

A data table with eight columns cannot become one column without losing its meaning. The standard answer is to let the table scroll sideways inside its own container while the page does not: wrap it in a <div style="overflow-x: auto">. The table stays a table; only its box scrolls.

21.7 Testing on real screens

Chrome DevTools (F12, then the device toolbar icon or Ctrl+Shift+M) emulates phone and tablet sizes and shows the viewport width as you drag. Use it constantly, and then test on an actual phone, because emulators do not reproduce touch, real keyboards or slow networks. A page passes when: no horizontal scrollbar appears at any width, text is readable without zooming, images fit, every control can be tapped, and nothing important is hidden.

A checklist for responsive content structure

  • Viewport meta tag in the head.
  • Semantic regions in logical source order; no layout tables; no br stacks.
  • No fixed pixel widths or heights on containers.
  • Images and videos scale (max-width: 100%); large images use srcset/sizes or picture; lazy-load below the fold.
  • Wide tables in a scrolling wrapper.
  • Correct input types for phone keyboards; big enough tap targets.
  • Tested in DevTools device mode and on a real phone.

Exam-style checks

Which meta tag is essential for a mobile-responsive page?L2
  • A. <meta charset="UTF-8">
  • B. <meta name="author" content="...">
  • C. <meta name="description" content="...">
  • D. <meta name="viewport" content="width=device-width, initial-scale=1.0">

Answer: D.

A page has no viewport meta tag. What happens on a mobile browser?L3
  • A. It renders a shrunk-down desktop layout with tiny, unreadable text
  • B. The page refuses to load
  • C. The browser applies a default mobile stylesheet
  • D. All images on the page are hidden

Answer: A.

"Mobile-first" content structuring means designing primarily for:L2
  • A. The largest screen first, then shrinking it down
  • B. Desktop browsers only
  • C. The smallest screen first, then enhancing for larger ones
  • D. Print layouts

Answer: C.

For responsive content, images and videos should be:L2
  • A. Given fixed pixel widths in the HTML
  • B. Allowed to scale with their container
  • C. Replaced with text on small screens
  • D. Loaded only on desktop devices

Answer: B.

Which habit best prepares HTML for a responsive layout before any CSS is written?L3
  • A. Hardcoding width="800" on every container
  • B. Nesting layout tables three levels deep
  • C. Using a logical source order and flexible, scalable media
  • D. Setting fixed pixel heights on all sections

Answer: C.

On a responsive <img>, what does the sizes attribute tell the browser, and what does srcset provide?L3

Answer: sizes states how wide the image will be displayed so the browser can pick a file from srcset; srcset lists several image files (with widths) so the browser can choose one suited to the display.

Which statement about the <picture> element is correct?L2

Answer: it offers several image sources for different conditions, with an <img> inside as the required fallback. It does not replace img, is not limited to one source, and is not for captions.

Why should tables not be used to lay out an entire web page today?L3

Answer: it breaks accessibility and responsiveness; a table cannot reflow into one column, and tables are for tabular data.

Quick revision

Key takeaways

  1. Responsive = one document that adapts: HTML structure + CSS media queries + scalable media.
  2. The viewport meta tag (width=device-width, initial-scale=1.0) is essential; without it phones show a shrunken desktop layout.
  3. Mobile-first: smallest screen first, enhance upward. Logical source order gives a correct single-column view for free.
  4. Media scale with their container (max-width: 100%); srcset/sizes and picture serve the right file; no fixed pixel widths or heights; no layout tables; wide tables scroll in a wrapper.
  5. Test in DevTools device mode and on a real phone: no sideways scroll, readable text, tappable controls.
