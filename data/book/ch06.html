Text Formatting

Most of any page is text, and HTML gives you about thirty elements for it. The trick is that they come in two families: logical (semantic) elements that say what a piece of text means, and physical (presentational) elements that only say how it should look. This chapter covers headings, paragraphs, breaks, emphasis, quotations, code, scientific notation and contact details, and teaches you to pick the element by meaning.

6.1 Headings: the outline of the document

HTML provides six levels of heading, <h1> to <h6>. <h1> is the highest level, the title of the whole page's content; <h2> marks the major sections; <h3> subsections within them, and so on down. Browsers render h1 largest and h6 smallest, but the sizes are a side effect. What headings really do is build the document outline: the table of contents that screen readers let their users jump through and that search engines use to understand what the page is about.

Three rules follow from "headings are an outline":

  1. Exactly one h1 per page, describing the page's main topic. Not one per paragraph, not as many as styling needs, and not none.
  2. Do not skip levels. A page that goes from h1 straight to h4 breaks the logical outline: a screen-reader user hears a gap and a search engine sees a malformed structure. Browsers still render it; that is not the point.
  3. Never choose a heading level for its size. If you want a subheading smaller than an h2, use h3 (the correct next level) and set the size in CSS. Reaching for h5 because it "looks right", or faking a heading with <p><b> or <div class="h2">, throws away the outline entirely.
<h1>School of Computing and AI</h1>
<h2>Departments</h2>
<h3>Computer Science</h3>
<h3>Artificial Intelligence</h3>
<h2>Courses</h2>
<h3>CSE326 Internet Programming</h3>

6.2 Paragraphs, line breaks, thematic breaks and preformatted text

<p>: the paragraph

<p> defines a paragraph of text: a block of sentences about one idea. Browsers add vertical space before and after it automatically. Separate ideas go in separate paragraphs; that is how you create space between them, not with line breaks.

<br>: a line break inside a block

<br> forces a line break inside a paragraph without starting a new one. It is a void element. Its correct use is a break within one piece of text: the lines of a postal address, the lines of a poem or song lyrics.

<p>
  Department of Computer Science<br>
  Lovely Professional University<br>
  Phagwara, Punjab
</p>
Never <br><br> for spacing. Two breaks between two ideas is poor practice for three reasons: a screen reader announces one run-on paragraph instead of two; the spacing cannot be adjusted without editing the HTML; and spacing is CSS's job. Separate ideas need separate <p> elements.

<hr>: a thematic break

<hr> represents a thematic break: the point where the subject changes, such as between two sections of an article or two scenes in a story. Browsers draw it as a horizontal rule, but the line is the side effect; the meaning is "the topic changes here". It is void, and it is not a page break, not an image and not a table row.

<pre>: preformatted text

Normal HTML collapses whitespace: ten spaces become one, and newlines vanish. <pre> is the one element that preserves spaces and line breaks exactly as typed, rendered in a monospace font. Use it for ASCII tables, code listings and anything where alignment matters.

<pre>
Name     Marks   Grade
Rahul    90      A+
Priya    95      O
</pre>
<p>
Name     Marks   Grade
Rahul    90      A+
</p>

6.3 Logical versus physical formatting

Here is the idea that organises the whole chapter. Some elements describe meaning: <strong> says "this is important", <em> says "stress this word". Others describe only appearance: <b> says "bold", <i> says "italic". Both kinds still exist in HTML5, but they mean different things, and the exam asks you to know which is which.

Logical (semantic)MeaningPhysical (presentational)Meaning
<strong>Strong importance, seriousness, urgency<b>Draw attention; bold with no extra importance
<em>Stressed emphasis that changes the sentence's meaning<i>Alternate voice or kind of text: a term, a species name, a foreign phrase
<del>Removed content<strike>Obsolete: use del or CSS
<mark>, <small>, <ins>Relevance, fine print, inserted content<u>An unarticulated annotation, shown underlined (avoid: looks like a link)

strong versus b

Both look bold by default. <strong> conveys importance; <b> only applies bold styling. A screen reader can speak <strong> with a change of tone; <b> is read in a normal voice. So a genuine safety warning, an exam-time alert or a critical instruction is <strong>; a keyword you merely want to catch the eye is <b>. <strong> was not removed in HTML5, and the two are not "the same thing".

em versus i

<em> indicates stressed emphasis within a sentence: it changes how the sentence would be spoken and therefore what it means. "Please submit the form today" stresses the day. <i> marks text of a different kind without stress: a technical term, a ship's name, a species name (Homo sapiens), a phrase in another language. <i> is not deprecated and is the right choice for those cases; using <em> just because you want italics is the mistake.

6.4 The rest of the inline formatting set

<mark>: highlighted, relevant here
Highlights text because it is relevant in the current context, like a marker pen on a page: a search match, the key term in a passage. Renders with a yellow background by default. <p>The exam starts at <mark>10:00 AM</mark>.</p>
<small>: fine print
Side comments, disclaimers, copyright lines, legal notes: text of lesser prominence. It renders one size smaller, but it expresses relative importance, not an exact font size. Common inside <footer>. <small>Terms and conditions apply.</small>
<del> and <ins>: removed and inserted
<del> marks text that has been deleted from the document, shown struck through; <ins> marks text that has been inserted, shown underlined. Together they show a revision: Fee: <del>₹1500</del> <ins>₹1200</ins>. E-commerce price cuts are the everyday example.
<sub> and <sup>: subscript and superscript
<sub> lowers text (the 2 in H2O: H<sub>2</sub>O); <sup> raises it (the 2 in x2: x<sup>2</sup>, and ordinals like 18th). Memory aid from the lecture: sub = down like a submarine, sup = up like Superman.
<abbr>: abbreviation
Marks an abbreviation or acronym; its title attribute holds the expansion, shown as a tooltip and available to screen readers: <abbr title="HyperText Markup Language">HTML</abbr>.
<u>: underline (rarely)
An unarticulated, non-textual annotation such as a misspelling mark, rendered underlined. Avoid it for ordinary emphasis: underlined text looks like a link, and links are already <a>.

6.5 Quotations and citations

Three elements, three different jobs, and they are examined together constantly.

<q>: a short inline quotation
Placed inside a sentence. The browser adds the quotation marks automatically, so do not type them yourself, or you get two sets. <p>Teacher said, <q>Practice every day.</q></p>
<blockquote>: a long quotation as its own block
A block-level element for an extended quotation from another source, rendered indented. It may carry a cite attribute holding the URL of the source. <blockquote cite="https://example.com">The journey of a thousand miles begins with a single step.</blockquote>
<cite>: the title of a creative work
Marks the title of a book, paper, film, song or other work, rendered in italics: Read <cite>Clean Code</cite> by Robert Martin. It is not the author's name, not a URL and not a quotation.
cite element versus cite attribute. The <cite> element wraps a work's title. The cite attribute on <q> or <blockquote> holds the URL the quotation came from. Questions exploit this difference.
<p>He said, <q>HTML is easy to learn.</q></p>
<blockquote cite="https://example.com/speech">
  The journey of a thousand miles begins with a single step.
</blockquote>
<p>Recommended reading: <cite>Clean Code</cite> by Robert Martin.</p>

6.6 Code, keyboard, output and variables

Technical writing has its own set of elements. All four render in a monospace font by default; the difference is meaning.

6.7 Contact information: address

<address> represents contact information for its nearest article or for the document as a whole: the author's or organisation's email, phone, postal address or social handle. It typically sits in a <footer>. It is not for any random postal address that happens to appear in the text (a shop's location in an article is just text), and it is not a generic "contact" or "info" element; those do not exist.

<footer>
  <address>
    Department of Computer Science<br>
    Lovely Professional University<br>
    <a href="mailto:cse326@example.edu">cse326@example.edu</a>
  </address>
</footer>

6.8 Obsolete formatting tags

Older pages are full of tags that HTML5 has made obsolete because they describe appearance, which is CSS's job. Know them so you can read legacy code; never write them.

ObsoleteUse instead
<strike><del> for removed content, or CSS text-decoration: line-through
<font>CSS font-family, font-size, color
<center>CSS text-align: center
<big>CSS font-size: larger
<tt><code> or <kbd>
<marquee>CSS @keyframes animation (and usually: do not animate text at all)

6.9 Worked example: a well-marked-up notice

Read this page and name the reason for each element. Every choice is by meaning.

<h1>CSE326 Lab Notice</h1>
<p><strong>Important:</strong> the lab test is on <mark>Friday at 9 AM</mark>.
   Please arrive <em>before</em> the doors close.</p>
<h2>What to bring</h2>
<p>Your ID card and the <abbr title="Continuous Assessment">CA</abbr> slip.
   Fee for a replacement slip: <del>&#8377;50</del> <ins>&#8377;20</ins>.</p>
<h2>During the test</h2>
<p>Save often with <kbd>Ctrl</kbd>+<kbd>S</kbd>. If you see
   <samp>Permission denied</samp>, call an invigilator.
   Name your file <code>index.html</code>.</p>
<blockquote cite="https://example.edu/rules">Work submitted after the deadline
   will not be evaluated.</blockquote>
<hr>
<p><small>Water is H<sub>2</sub>O. Area of a square is s<sup>2</sup>.
   Questions? See <cite>The CSE326 Handbook</cite>.</small></p>
<address>Lab in-charge: <a href="mailto:lab@example.edu">lab@example.edu</a></address>

Exam-style checks

Which element defines the highest-level heading on a page?L1
  • A. <h6>
  • B. <h1>
  • C. <head>
  • D. <header>

Answer: B. h1 is the top of the outline; h6 the lowest. head is metadata and header is a page region.

How many heading levels does HTML provide, and how many h1 elements should a page normally contain?L1

Answer: six levels (h1–h6), and exactly one h1 describing the page's main topic.

A page uses <h1> and then jumps straight to <h4>. Why is this poor practice?L3
  • A. Browsers refuse to render an <h4>
  • B. It breaks the logical content outline used by screen readers and search engines
  • C. <h4> is deprecated in HTML5
  • D. Headings must all sit inside one <section>

Answer: B. Levels are an outline; skipping them leaves gaps in the structure.

You want a subheading smaller than h2. What is correct?L2
  • A. Skip to h5 because it renders smaller
  • B. Use h3 and set the size in CSS
  • C. Use <p><b>text</b></p>
  • D. Use <small>

Answer: B. Level describes position in the outline; appearance is CSS's job.

Which element defines a paragraph of text?L1
  • A. <text>
  • B. <para>
  • C. <p>
  • D. <pg>

Answer: C. Only p exists.

Which tag forces a line break inside a paragraph?L1
  • A. <p>
  • B. <hr>
  • C. <lb>
  • D. <br>

Answer: D. br breaks the line within one block of text; hr is a thematic break; lb does not exist.

What is the correct use of <br>, and why is <br><br> between two ideas poor practice?L2

Answer: br is for a line break within a single block of text (an address, a verse). Two breaks between ideas make a screen reader announce one run-on paragraph and make the spacing unadjustable without editing HTML. Use separate p elements; spacing is CSS's job.

Which tag inserts a horizontal thematic break between sections of content?L1
  • A. <div>
  • B. <br>
  • C. <line>
  • D. <hr>

Answer: D. Semantically hr means the subject changes; drawing a line is the side effect.

Which element displays preformatted text, preserving spaces and line breaks exactly as typed?L1
  • A. <samp>
  • B. <code>
  • C. <pre>
  • D. <blockquote>

Answer: C. pre is the only element that does not collapse whitespace.

Which pair correctly contrasts <strong> with <b>?L2
  • A. <strong> was removed in HTML5
  • B. <b> conveys importance; <strong> only applies bold styling
  • C. Both are purely presentational and mean the same thing
  • D. <strong> conveys importance; <b> only applies bold styling

Answer: D. For a genuine safety warning use strong; b merely looks bold.

Which element indicates stressed emphasis within a sentence, and when is <i> the correct choice over <em>?L2

Answer: <em> marks stressed emphasis that changes the meaning. <i> is correct for a different kind of text with no stress: a species name, a technical term, a foreign phrase. i is not deprecated; it is simply not for emphasis.

Which pair is SEMANTIC rather than purely presentational?L2
  • A. <b> and <i>
  • B. <strong> and <em>
  • C. <u> and <strike>
  • D. <big> and <small>

Answer: B. strong means importance and em means emphasis; the others describe appearance.

Which tag highlights text like a marker pen?L1

Answer: <mark>. It renders with a highlight background by default; high, hl and yellow do not exist.

Which element marks text that has been inserted into a document, usually shown underlined, and which shows text struck through as removed?L1

Answer: <ins> for inserted (underlined) and <del> for deleted (struck through). Not u, not strike (obsolete), not mark.

Which element renders text as subscript, such as the 2 in H2O? And as superscript, such as the 2 in x²?L1

Answer: <sub> for subscript (H<sub>2</sub>O) and <sup> for superscript (x<sup>2</sup>). small, low and high are wrong.

Which element marks an abbreviation whose expansion is given in its title attribute?L1
  • A. <cite>
  • B. <abbr>
  • C. <dfn>
  • D. <span>

Answer: B. <abbr title="HyperText Markup Language">HTML</abbr>; the title shows as a tooltip.

Which element marks a short quotation placed inline within a sentence, and which marks a long block-level quotation?L1

Answer: <q> inline (browser adds the quote marks) and <blockquote> for the block. cite is for a work's title; abbr for abbreviations; pre for preformatted text.

What is wrong with <q>"a decisive shift"</q>?L2

Answer: the quote marks are typed manually. The browser adds quotation marks around q automatically, so this shows two sets.

What does the <cite> ELEMENT mark up?L2
  • A. The author's name
  • B. The title of a creative work
  • C. The URL of a source
  • D. A short quotation

Answer: B. The cite element holds a work's title; the cite attribute on q or blockquote holds a URL.

Which element marks a fragment of computer code shown inline in a sentence, and which marks keyboard input by the user?L1

Answer: <code> for inline code, <kbd> for keyboard input. samp is program output; var is a variable; pre is a preformatted block.

Which element represents contact information for its nearest article or for the document as a whole?L1
  • A. <contact>
  • B. <address>
  • C. <footer>
  • D. <cite>

Answer: B. address is for contact details, usually inside a footer; contact and info do not exist.

Quick revision

Key takeaways

  1. Headings h1–h6 build an outline: one h1, no skipped levels, sizes in CSS.
  2. p for a paragraph; br for a line break within one block (addresses, poems), never br br for spacing; hr for a thematic break; pre preserves whitespace.
  3. Logical vs physical: strong (importance) vs b (bold); em (stress) vs i (other voice); del/ins for revisions; mark for relevance; small for fine print; sub/sup for H2O and x2.
  4. q is inline and auto-quoted; blockquote is a block; cite element = title of a work; cite attribute = source URL.
  5. code inline, pre for blocks, kbd for keyboard input, samp for output, var for variables, abbr with title for abbreviations, address for contact details.
  6. strike, font, center, big, tt and marquee are obsolete: use del or CSS.
