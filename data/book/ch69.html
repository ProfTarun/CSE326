Unit 6 · Chapter 69 · Browser Developer Tools

Browser Developer Tools

Your files say what you meant to build. The browser knows what it actually built — which styles won, which picture failed to arrive, what a variable held at the moment things went wrong. Developer tools let you look inside the browser and see all of that for yourself. Once you can use them, you stop guessing at bugs and start looking at them.

About 36 minutes · Course outcome CO6

Before you start — one-line reminders

  • Debugging means reproduce, read the error, isolate, guess, test, fix and retest; console.log with a label and the debugger statement are your first tools (Chapter 68).
  • localStorage keeps text keys and values for a site until they are removed; sessionStorage forgets when the tab closes (Chapter 64).
  • document.querySelector("#id") returns the first matching element, or null when nothing matches (Chapter 48).

By the end of this chapter you can

  • Open DevTools three ways on Windows and on a Mac, and pick the right panel for a problem.
  • Use the Elements panel to inspect the live page, edit HTML and CSS temporarily, read computed styles and the box model, and force a :hover state.
  • Use the Console to read errors with their file and line, run expressions, use $0, and clear and filter messages.
  • Pause code with a breakpoint, step over, into and out of lines, and read the Scope, Watch and Call Stack panes.
  • Read the Network panel's status codes, sizes and timings, disable the cache, throttle the connection and find a failed request.
  • View, edit and clear localStorage, sessionStorage and cookies in the Application panel; test a page at phone width; run a first Lighthouse report.

69.1 What developer tools are

Chrome, Edge, Firefox and Safari each carry a free, built-in set of inspection and debugging tools called the developer tools or DevTools. Their whole job fits in one sentence: they show you what the page really is — not what you think you wrote.

Between your files and the screen, a lot happens. The browser downloads the files, repairs small mistakes in your HTML, builds the DOM, decides which CSS rule wins for each element, runs your JavaScript (which may add or remove elements) and stores data. When the page looks wrong, the cause is somewhere in that chain. Rereading your source file shows only the start of the chain; DevTools shows every link.

Picture this. A patient tells the doctor, "I feel unwell." A good doctor does not guess. She takes the temperature, listens with a stethoscope and, if needed, orders an X-ray. Each instrument answers one question, and together they turn "unwell" into a diagnosis. DevTools is your instrument tray: Elements is the X-ray of the page's structure, the Console is the patient's own account of what hurts, Network is the record of everything that went in. The skill is knowing which instrument to pick up first.

This chapter uses Chrome, as the lecture slides do. Edge is built on the same engine and its DevTools are practically identical; Firefox and Safari have the same panels under slightly different names. Everything here works on your own Live Server localhost site as well as on any public website.

69.2 Opening DevTools

There are three ways in, and you will use all three.

  1. Right-click → Inspect. Right-click any element and choose Inspect. DevTools opens on the Elements panel with that very element selected — the most useful way, because it takes you straight to the thing you are worried about.
  2. The browser menu. In Chrome: the ⋮ menu → More tools → Developer tools. Edge and Firefox have the same item under More tools.
  3. A keyboard shortcut — the fastest once your fingers know it.

69.3 The Elements panel: the live page

On the left of the Elements panel is the DOM tree: the page's elements, nested like folders, with triangles to open and close them. On the right are panes about the selected element — Styles, Computed, Layout and others. Hover over a line in the tree and that element lights up on the page.

The DOM is not your file

The tree is the live DOM. It includes every element your JavaScript added, leaves out what it removed, and shows the browser's repairs: forget to close a <p> and the tree shows it closed; write table rows without a <tbody> and the tree shows one anyway. What the server actually sent is View page source (Ctrl+U). Next to the selected element you will see == $0: in the Console, $0 now means that element (section 69.4).

Editing the page live

Double-click a tag name, attribute or text to edit it; press Delete to remove the selected element, or drag it elsewhere. Right-click for Edit as HTML, Add attribute and more; Ctrl+Z undoes.

The Styles pane lists every CSS rule matching the selected element, strongest at the top, each with its file and line. Click a value to change it, click at the end of a rule to add a declaration, untick a checkbox to switch one off. A struck-through declaration is not being used. Usually it lost: a rule with a stronger selector, or equal strength written later, set that property. If a warning triangle sits beside it too, the browser could not understand it — a misspelling such as colour: red.

DevTools edits are temporary. They change the page in the browser's memory, never your files; reload and every change is gone. So experiment freely, and copy a value that looks right into your styles.css by hand.
In plain words: the Elements panel shows the page as the browser built it, lets you try changes instantly, and forgets them all on reload. Experiment there, then type what worked into your real file.

Computed styles and the box model

Styles shows the argument; the Computed tab shows the verdict: each property once, with the final value after every rule, inherited value and default was weighed. Expand a property to see which rule supplied it.

At the top of Computed (and at the bottom of Styles) sits the box model diagram: nested rectangles for margin, border, padding and content, labelled in pixels. Hover over a layer and the page shades it — the one-glance answer to "where is this extra space coming from?"

Forcing hover and focus

A :hover style vanishes the moment you move the mouse to DevTools. The :hov button at the top of the Styles pane offers checkboxes for :hover, :active, :focus, :visited and more; tick one and the selected element stays in that state until you untick it. The .cls button beside it adds or removes classes.

Run the example, right-click the teal heading and choose Inspect. Find the crossed-out color: navy, open Computed, and hover over the second list item — it is in the tree, though nowhere in the HTML.

Quick check: you change a colour in the Styles pane and it looks perfect. You press F5. What happens, and why?

The old colour comes back. DevTools changed only the copy of the page in the browser's memory; reloading builds the page again from your unchanged files. Copy the value into your CSS file to keep it.

69.4 The Console panel: messages and experiments

The Console is a noticeboard where the browser and your code post messages, and a scratchpad where you type JavaScript and see the answer straight away.

Reading messages

Messages come at different levels, coloured so you can tell them apart:

  • console.log(...) and console.info(...) — plain messages.
  • console.warn(...) — yellow, with a warning sign: something looks odd but the program carried on.
  • console.error(...) — red: something failed. The browser's own uncaught errors also appear in red as Uncaught, the error type and its message, such as Uncaught TypeError: Cannot read properties of null (reading 'addEventListener').
  • console.table(...) — an array of objects drawn as a table.

On the right of every message is a link such as app.js:3: the file and line that produced it. Click it and DevTools jumps to that line in the Sources panel. The triangle beside a red error opens its call stack — the chain of function calls that led there — and any logged object or array has a triangle that opens it to show every property.

Running JavaScript at the prompt

At the bottom of the Console is a › prompt. Type any expression, press Enter, and the Console shows its value on a line starting with ←. It runs inside the current page, so it sees the page's global variables and elements: document.title gives the page's title, and tasks.length says how many items a global array tasks holds right now. Chrome often previews the answer in grey before you press Enter.

The up arrow brings back earlier commands, and Shift+Enter starts a new line without running. Typing console.log("hi") prints hi and then ← undefined; that undefined is not an error, just the value console.log itself returns.

A few shortcuts exist only at the Console prompt, not in your scripts. $0 is the element selected in Elements ($1 the one before it). $("css selector") is a quick document.querySelector (unless the page defines its own $), and $$("css selector") gives an array of every match. Select a heading in Elements, switch to Console and type $0.textContent or $0.style.color = "red".

Keeping the noise down

  • Clear the Console with the ⊘ button at the top, with Ctrl+L, or by running console.clear().
  • Filter with the text box: type total and only messages containing "total" stay visible.
  • Choose levels with the Default levels drop-down: tick only Errors to hide everything else. console.debug messages count as "Verbose", hidden by default.
  • Preserve log (Console settings, the gear icon) keeps messages across a reload or navigation.
<p id="out">Open the Console panel below.</p>
<script>
  console.log("Application started");
  console.warn("Check the form input");
  console.error("Unable to load data");

  const students = [
    { name: "Asha", marks: 91 },
    { name: "Rahul", marks: 78 },
    { name: "Meera", marks: 85 }
  ];
  console.table(students);

  // Testing an assumption about types, the way you would at the prompt
  console.log('"5" * 2 gives', "5" * 2, typeof ("5" * 2));
  console.log('"5" + 2 gives', "5" + 2, typeof ("5" + 2));
</script>

You get three lines at three levels, a three-row table with the columns (index), name and marks, then "5" * 2 gives 10 number and "5" + 2 gives 52 string. Multiplication turns the text "5" into a number; + with a string joins text instead — the reason to write Number(input.value) before doing sums with a form value. In the real Chrome Console, typing "5" + 2 at the prompt shows ← '52'; the quotes mark a string.

In plain words: the Console is where problems announce themselves, with a clickable file and line. It is also a calculator inside your page, so you can check a hunch in two seconds.

69.5 The Sources panel: pausing your code

console.log shows a value at one moment, and only the values you thought to print. The Sources panel can freeze your program mid-run, show every variable, and then move forward one line at a time — the most powerful debugging skill there is.

The place where the program freezes is a breakpoint. Using one takes seven small steps:

  1. Open Sources and find your file (say app.js) in the file tree under the Page tab; Ctrl+P opens a file by name.
  2. Set a breakpoint by clicking a line number, say 5. A blue marker appears; click again to remove it.
  3. Trigger the code: reload the page, or click the button that runs it.
  4. Paused. The page freezes and line 5 is highlighted ("Paused on breakpoint"). That line has not run yet.
  5. Inspect. Hover over a variable to see its value, or read the Scope pane.
  6. Step forward one line at a time with the buttons described below.
  7. Resume (F8) to run freely until the next breakpoint.

Reading the panes while paused

  • Scope lists every variable the paused line can see, with its current value. Local holds the function's parameters and variables; let and const variables made inside a loop or other { } block get their own Block section; Global holds window and everything on it. Double-click a value to edit it and try a "what if".
  • Watch holds expressions you choose. Click + and type, say, total > 200; it is re-evaluated every time the program pauses.
  • Call Stack shows how you got here: the current function on top, its caller below, and so on down to the script. Click a lower line to see the caller's variables.
  • Breakpoints lists your breakpoints with checkboxes, so you can switch them off without losing them.

Stepping: over, into, out

The stepping buttons sit above the panes. Each runs some code and pauses again:

  • Step over (F10) runs the highlighted line completely — including any function it calls — and pauses on the next statement to run.
  • Step into (F11) goes inside the function called on this line and pauses on its first line.
  • Step out (Shift+F11) finishes the current function and pauses back in the function that called it.

Conditional breakpoints and the debugger statement

A breakpoint inside a loop pauses on every pass, which is tiresome with 500 students. Right-click the line number, choose Add conditional breakpoint and type a condition such as i === 1 or item.price > 1000; the program pauses there only when it is true. The same menu offers Add logpoint, which prints a message each time the line is reached without pausing — a console.log you never have to delete from your file.

The other way to pause you met in Chapter 68: write debugger; in your code. With DevTools open, the program pauses there as if a breakpoint were set; with DevTools closed, the statement does nothing. It suits this book's example frames, whose code is hard to find in the file tree. Delete it before you publish.

<p id="out"></p>
<script>
  function lineTotal(item) {
    return item.price * item.qty;
  }

  function calculateTotal(items) {
    let total = 0;
    for (let i = 0; i < items.length; i++) {
      const item = items[i];
      debugger;                     // pauses here only while DevTools is open
      total += lineTotal(item);
    }
    return total;
  }

  const cart = [
    { price: 100, qty: 2 },
    { price: 50, qty: 1 }
  ];
  const result = calculateTotal(cart);
  console.log("Total:", result);
  document.querySelector("#out").textContent = `Total: ₹${result}`;
</script>

With DevTools closed, the example simply prints Total: 250. With DevTools open, Run pauses on the debugger line. Scope shows total: 0 and, under Block, i: 0 and item: {price: 100, qty: 2}. Press F8 and it pauses again with i: 1, item: {price: 50, qty: 1} and total: 200 — this pass's += has not run yet. Press F10 twice (past debugger, then over the total line) and it becomes 250; on another run, press F10 once and then F11 to land inside lineTotal.

In plain words: a breakpoint is a pause button you place on a line. While paused you can read every variable, then move forward one line at a time and watch the values change, until one of them goes wrong.
Quick check: paused on total += lineTotal(item);, you want to see the multiplication inside lineTotal happen. Which button?

Step into (F11). Step over would run lineTotal completely without stopping inside it.

69.6 The Network panel: everything the page downloaded

A web page is never one file. The HTML asks for CSS, JavaScript, images and fonts, and the JavaScript may ask a server for data. Each is a separate request, and the Network panel lists every one with its result. It records only while DevTools is open, so open it first, then reload the page.

Note hero.jpg too: almost 2 MB and most of a second, on a fast connection.

Status codes

The status is a three-digit HTTP status code, and the first digit tells you the story:

CodeMeaningExample
2xxSuccess200 OK
3xxLook elsewhere, or use your saved copy301 moved permanently; 304 Not Modified — your cached copy is still good
4xxThe request was wrong (client error)404 Not Found; 403 Forbidden
5xxThe server failed (server error)500 Internal Server Error

A 404 usually means a wrong path in your own HTML or CSS. A 500 is the server's fault, but your page must still cope: as Chapter 70 explains, fetch does not reject on a 404 or 500, so your code must check response.ok and show a friendly message.

Looking inside one request

Click any row for tabs: Headers (URL, method such as GET, status, headers both ways), Preview (images shown, JSON as a tree), Response (the raw text), Initiator (which file and line asked for it, perhaps index.html:12) and Timing (waiting for the server versus downloading).

Capital letters matter on servers. Your HTML asks for logo.png; the file is called Logo.png. Windows ignores the difference, so Live Server may show the logo happily. GitHub Pages and most real web servers run Linux, where names must match exactly, and the logo becomes a 404 the moment you deploy. Keep file names lower-case, and read the Name and Initiator of every red row.

Disable cache and throttling

Browsers keep copies of downloaded files in the cache, so the next visit is faster — which can show you yesterday's CSS after today's edit. Tick Disable cache at the top of the Network panel and every reload fetches fresh files. It applies only while DevTools is open.

Next to it is the throttling drop-down, normally No throttling. Choose Slow 4G or 3G to feel how your page loads on a weak hostel signal, or Offline to test the no-connection case your error handling must survive. Preset names vary a little between Chrome versions. Remember to set it back.

69.7 The Application panel: what the site saved

Websites keep small pieces of data in your browser: a chosen theme, a half-filled form, a login session. The Application panel shows all of it, grouped by origin — the site's address without the path, such as http://localhost:5500. The Storage list on the left holds:

  • Local storage and Session storage — open one and click the site's origin for a table of keys and values. Double-click a value to edit it, select a row and press Delete to remove it, or use the clear button to empty them all. If the table lags behind your code, click its refresh icon.
  • IndexedDB — a larger in-browser database, for bigger apps.
  • Cookies — small values the browser sends back to the server with every request to that site, listed with name, value, domain, expiry and flags. A cookie marked HttpOnly cannot be read by JavaScript at all, which is why servers set login cookies that way.
StorageLastsSent to the server?Typical use
localStorageUntil code or the user clears itNoTheme, saved drafts
sessionStorageUntil the tab is closedNoProgress through a multi-step form
CookiesUntil their expiry date (or the browser closes, if none is set)Yes, with every request to that siteLogin sessions, set by the server

Editing storage by hand tests your code. Delete the theme key and reload: does the page behave for a first-time visitor? Type banana into a key that should hold JSON: does your try...catch cope? The top Storage item's Clear site data button wipes the site's storage, cookies and cache together, so you see the site as a brand-new visitor does.

Never store passwords, tokens or personal data in localStorage. Any script running on the page can read it, including a bad script that sneaked in. If you can see it in the Application panel, so can an attacker's code.

One honest warning: this book's frames have no address of their own, so they use a temporary in-memory stand-in for localStorage that Run again wipes and the Application panel cannot see. Open a copy with Live Server, and a theme row appears under http://127.0.0.1:5500, survives a reload, and vanishes on Clear site data.

Quick check: which of the three stores is sent to the server with every request?

Cookies. localStorage and sessionStorage stay in the browser; the server never sees them unless your JavaScript sends them.

69.8 Phones, speed and scores

The device toolbar

Most of your users are on phones. Press Ctrl+Shift+M (or click the phone-and-tablet icon at the top-left of DevTools) and the page is redrawn in a resizable frame; choose Responsive and type a width, or pick a phone. The toolbar sets the page's viewport width, imitates a touch screen and the phone's screen sharpness, and can throttle the network too.

Test at least three widths: about 375 px (phone), 768 px (tablet) and 1280 px (laptop). The classic clue is a horizontal scroll bar at phone width: something is wider than the screen. Hover down the tree in Elements; the element sticking out past the edge is the culprit. The toolbar is a good imitation, not a real phone, so check the finished site on an actual handset too.

The Performance panel

When a page feels slow to respond — you click Search and nothing happens for half a second — the Performance panel shows why. Press record, do the slow action, press Stop, and you get a timeline of everything the browser did. The Main track shows the work of the single thread that runs your JavaScript and also draws the page, as coloured blocks stacked by which function called which.

Any piece of work longer than 50 milliseconds is a long task, marked with a red corner and red stripes; during it the page cannot respond to clicks or typing. Click it, and the Bottom-Up tab names the functions that took the most time — say, a renderList that calls appendChild 500 times. Fix that function, record again, and compare. Chapter 74 goes deeper into measuring speed.

Lighthouse: a first report card

The Lighthouse panel (behind » if hidden) audits a page. Choose Mobile or Desktop and the categories — Performance, Accessibility, Best Practices and SEO — and click Analyze page load. You get a score from 0 to 100 for each (90 and above green, 50–89 orange, below 50 red) and a list of specific problems such as "Buttons do not have an accessible name", each linked to its fix. Run it in an Incognito window, because extensions can drag scores down. Lighthouse is a guide, not a verdict, but its failing audits make a good to-do list before you deploy.

69.9 Case study: fix a broken webpage

Here is the lecture's hands-on exercise. The TechFest 2026 ticket page has four problems, each found fastest with a different panel. Try to find all four before reading the solution, writing down for each: symptom → panel → cause → fix.

Why the stylesheet says flex: 0 0 400px. With only width: 400px (as on the slide), the cards would not overflow: flex items may shrink by default, so the browser squeezes all three to fit. The bug needs something that stops the shrinking — flex-shrink: 0, a min-width, or flex: 0 0 400px. The Elements panel settles such claims.

Quick check: which of the four bugs could never be found from the Console alone, and why?

The ₹450 total. It throws no error; the code simply takes the wrong branch. You need the value of qty and of qty > 3 at that moment, which a breakpoint in Sources gives you.

69.10 Common misunderstandings

✗ "I fixed it in DevTools, so it's fixed."
DevTools edits live in the browser's memory. Reload and the bug is back.
✓ "I found the fix in DevTools; now I copy it into my file."
DevTools is the test bench; your files are the product.
✗ "The Elements panel shows my HTML file."
It shows the live DOM: after the browser's repairs and after your JavaScript ran.
✓ "Elements shows what the page is now; View source shows what the server sent."
When they differ, that difference is often the clue.
✗ "When paused on a breakpoint, that line has already run."
Execution freezes just before the highlighted line.
✓ "Step over once, then read the values the line produced."
That is why total still showed 200 in the example.
✗ "No red in the Console means no bugs."
Logical errors, like the ₹450 total, never print anything.
✓ "A clean Console rules out crashes, not wrong answers."
For wrong answers, pause the code and check the values.

Exam-style checks

Which key combination opens Chrome DevTools on Windows?L1
  • A. Ctrl+Shift+M
  • B. Ctrl+U
  • C. Ctrl+Shift+I
  • D. Cmd+Option+I

Answer: C. Ctrl+Shift+I (or F12) opens DevTools on Windows. Cmd+Option+I is the Mac shortcut, Ctrl+Shift+M the device toolbar, Ctrl+U View page source.

In the Styles pane, the declaration color: navy; appears struck through, with no warning icon beside it. What does that mean?L2
  • A. The browser could not understand the value
  • B. Another matching rule set color and won, so this declaration is not used
  • C. The declaration was deleted from the CSS file
  • D. The element is hidden

Answer: B. navy is a valid colour, so the declaration lost to a stronger or later rule for the same property. A declaration the browser cannot understand is also struck through, but carries a warning triangle as well — so A does not fit here. Nothing in DevTools touches your file (C).

A developer changes padding to 16px in the Styles pane, likes the result, and reloads the page. What happens?L2
  • A. The padding goes back to its old value
  • B. The new padding stays, because DevTools saved it to styles.css
  • C. The page shows an error
  • D. The new padding stays until the browser is closed

Answer: A. DevTools changes only the in-memory page; reloading rebuilds it from the unchanged files. Copy the value into the CSS file by hand.

A <p> has width: 200px; padding: 8px; border: 2px solid; margin: 10px; and the normal box-sizing. How wide is it on screen, border included?L3
  • A. 200 px
  • B. 216 px
  • C. 240 px
  • D. 220 px

Answer: D. 2 + 8 + 200 + 8 + 2 = 220. With the default box-sizing: content-box, width sets only the content; padding and border are added on top. Margin lies outside the border; adding it gives the tempting 240.

Execution is paused on a breakpoint at line 5. Which statement is true?L2
  • A. Line 5 has run; its result is in Scope
  • B. Line 5 has not run yet
  • C. Lines 5 onwards have been skipped
  • D. The whole program has finished

Answer: B. A breakpoint freezes the program just before the marked line. Step over runs it; Resume carries on to the next breakpoint.

Paused on total += lineTotal(item);, you press Step over (F10). What happens?L3
  • A. DevTools pauses on the first line inside lineTotal
  • B. The program resumes and runs to the end
  • C. lineTotal runs completely, total is updated, and DevTools pauses on the next statement to run
  • D. The line is skipped without running

Answer: C. Step over runs the whole line, including the function it calls, and pauses at the next step (in a loop, the i++). Pausing inside lineTotal is what Step into (F11) does.

In the Network panel, logo.png shows status 404 but the logo appeared fine on your Windows laptop. What is the most likely cause?L3
  • A. The server crashed
  • B. The image is too large
  • C. The cache is disabled
  • D. The file name differs in capital letters, such as Logo.png, and the live server is case-sensitive

Answer: D. 404 means no file at that path. Windows ignores capital letters, so it worked locally; Linux servers such as GitHub Pages do not. A server crash would be a 5xx code.

Where in DevTools can you see and delete the value a site saved with localStorage.setItem("theme", "dark")?L1
  • A. Application → Local storage → the site's origin
  • B. Network → Headers
  • C. Elements → Styles
  • D. Sources → Watch

Answer: A. The Application panel lists localStorage, sessionStorage, IndexedDB and cookies by origin, and can edit or delete each key. Network shows downloads, not saved data.

Predict the output. At the Console prompt you type "5" * 2, press Enter, then type "5" + 2.L3

10, then '52'. * converts the text "5" to the number 5, giving 10. + with a string joins text, giving the string "52" (the quotes mark a string).

Predict the output. In the broken TechFest code, PRICE is 150, the box holds 3, and the test is if (qty > 3) { total = total * 0.9; }. What does the page show after the button bug is fixed? Then give the corrected line.L3

Total: ₹450. 3 × 150 = 450, and 3 > 3 is false, so no discount. "3 or more" needs if (qty >= 3), giving 450 × 0.9 = Total: ₹405.

Short answer: you set a conditional breakpoint with the condition i === 2 inside a loop that runs 5 times (i = 0 to 4). How many times does the program pause there, and when?L2

Once — on the third pass, when i is 2. On the other four passes the condition is false and the line runs without stopping.

Quick revision

Key takeaways

  1. DevTools show what the browser actually built, downloaded and stored: F12 or Ctrl+Shift+I (Cmd+Option+I on a Mac), or right-click → Inspect.
  2. Elements shows the live DOM; edits are lost on reload. Struck-through = not used (invalid if a warning triangle shows); Computed = the final value; :hov forces :hover.
  3. Console shows errors with a clickable file:line and runs any expression you type; $0 is the selected element.
  4. Sources: a breakpoint pauses before its line. Step over (F10), into (F11), out (Shift+F11), resume (F8); read Scope, Watch and Call Stack.
  5. Network: 2xx success, 3xx redirect or cached, 4xx client error (404), 5xx server error. Open it before reloading; use Disable cache and throttling.
  6. Application shows localStorage, sessionStorage and cookies by origin; Clear site data gives a first-visit view.
  7. Device toolbar for phone widths; Performance for long tasks (over 50 ms); Lighthouse for 0–100 scores in four categories.
