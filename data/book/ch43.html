Unit 4 · Chapter 43 · Data Types

Data Types

To you, 25 and "25" are the same thing. To JavaScript they are two different kinds of value: one is a number you can do sums with, the other is a piece of text that happens to contain a 2 and a 5. Every value has a kind like this, called its data type, and the type decides what the value can do. This chapter introduces the eight types, shows you how to ask any value what type it is, and explains what happens when JavaScript quietly turns one type into another.

  • let makes a variable you can change; const makes one you cannot reassign (Chapter 42).
  • A variable declared without a value holds undefined, and a const object can still change inside (Chapter 42).

43.1 Every value has a type

Work these out in your head. 25 + 5 is 30. "25" + 5 is "255". The digits are the same; the answers are not. The difference is the quotes. 25 is a number, "25" is text, and JavaScript treats them differently because they are different data types.

A data type is the kind of a value. The kind decides what you can do with the value (you can multiply marks, but not names), how JavaScript stores it, and what an operator such as + does when it meets it. Every value in a program, from 3.14 to a whole student record, has exactly one type.

A type is the answer to "what kind of thing is this?" Marks are numbers. A name is text. "Has she paid the fee?" is a yes-or-no. JavaScript keeps track of the kind of every value, and the kind decides what happens to it.

JavaScript has eight types. Seven are primitive types: each value is one simple thing. The eighth, object, is for values that are collections of other values, such as a student record or a list of marks. Arrays and functions are kinds of object.

Asking a value its type: typeof

You never have to guess. Write typeof in front of any value and JavaScript answers with a string naming its type: typeof 25 is "number" and typeof "25" is "string". The lecture writes it with brackets, typeof(exampleVar), which also works; typeof is an operator, so the brackets are optional (Chapter 44). Here are the lecture's example values, each with its type:

43.2 Text, numbers and true/false

string: text

A string is text: a name, a message, a single letter, or even no letters at all. You write it inside quotes. Single and double quotes do exactly the same job, as long as both ends match. Backticks are a third way to write a string, the template literal, which Chapter 45 teaches.

let name = "John";        // the slide example: double quotes
let city = 'Phagwara';    // single quotes: the same type
let roll = "12302457";    // digits inside quotes are still text
let empty = "";           // the empty string: a string with nothing in it

The quotes are not part of the text; they only mark where it starts and ends. Anything between them is text, even if it looks like a number. Roll numbers and phone numbers are best kept as strings: you never add two phone numbers, and stored as a number, 09876 would become plain 9876 and lose its leading zero.

number: every kind of number

A number is any numeric value: whole numbers like 25 and -7, and decimals like 3.14 (the slides call these floating-point numbers). Many languages keep whole numbers and decimals as separate types. JavaScript has one: typeof 25 and typeof 3.14 are both "number". Write numbers without quotes and without commas: one lakh is 100000, not 1,00,000.

The number type also holds three special values. Infinity and -Infinity come, for example, from dividing a non-zero number by zero (1 / 0 is Infinity), and NaN is the answer to a sum that has no numeric answer, such as "abc" * 2. All three are of type "number". Chapter 46 explains them.

boolean: true or false

A boolean has exactly two possible values, true and false, written without quotes. It answers a yes-or-no question: is she a student? has the fee been paid? Comparisons produce booleans (Chapter 44), and the decisions of Chapter 47 run on them.

let isStudent = true;      // the slide example
let feePaid = false;
let passed = 72 >= 40;     // true: a comparison gives a boolean
Quotes change the type. true is a boolean; "true" is a four-letter string. 25 is a number; "25" is a string. If you see quotes, you are looking at text.
Quick check: what are the types of 3.0, "3", false and "false"?

Number, string, boolean, string. 3.0 is just the number 3 written with a decimal point. The two with quotes are text, whatever letters or digits are inside.

43.3 Nothing, two ways: undefined and null

Sometimes there is no real value yet. JavaScript has two different values for "nothing", and each is the only value of its own type.

undefined means no value has been given. JavaScript puts it there itself. You met it in Chapter 42: a variable declared but never assigned holds undefined. You also get it when you ask an object for a property it does not have, and from a function that finishes without handing back an answer.

let undefinedVar;                // the slide example: declared, never assigned
console.log(undefinedVar);       // undefined

let person = { name: "Alice" };
console.log(person.email);       // undefined: there is no email property

null means empty on purpose. A programmer writes it to say "I know about this, and there is deliberately nothing here". A few built-in tools also return it to mean "nothing found": prompt() gives null when the user presses Cancel.

let nullVar = null;     // the slide example
let winner = null;      // no winner yet: the match has not been played
winner = "Asha";        // later, a real value

Think of a printed admission form. A box nobody has filled in yet is undefined. A box where the student has written "None", as in "Previous college: None", is null: someone read the question and recorded, on purpose, that the answer is nothing.

They are two different values, so null === undefined is false. The rule for your own code: leave undefined to JavaScript, and write null when you mean "nothing, on purpose".

Quick check: after let seat; what does seat hold? And when the student leaves, what should you store in it?

It holds undefined, because no value was given. When the student leaves, write seat = null; to record that the seat is empty on purpose.

43.4 The two rare primitives: bigint and symbol

The last two primitives were added to the language later: symbol in 2015 and bigint in 2020. You will hardly need them in this course, but you must be able to name them.

bigint: whole numbers of any size

The number type stores whole numbers exactly only up to 9,007,199,254,740,991, about nine thousand trillion (JavaScript calls this Number.MAX_SAFE_INTEGER). Beyond that it starts rounding. A bigint stores a whole number of any size exactly. You make one by putting n after the digits.

console.log(9007199254740993);    // 9007199254740992   - rounded!
console.log(9007199254740993n);   // 9007199254740993n  - exact
console.log(typeof 25n);          // bigint
console.log(10n + 20n);           // 30n
console.log(7n / 2n);             // 3n   whole numbers only: the .5 is dropped
console.log(10n + 1);             // TypeError: Cannot mix BigInt and other types

Bigints only do arithmetic with other bigints. Mixing one with an ordinary number in a sum throws a TypeError, so you convert one side first with BigInt() or Number(). They are used for very large ID numbers and for cryptography.

symbol: a label that is guaranteed unique

A symbol is a value whose only job is to be unique. You make one with Symbol(), optionally passing a description that helps when debugging. Every call to Symbol() makes a new symbol, never equal to any other, even one with the same description:

const id1 = Symbol("id");
const id2 = Symbol("id");
console.log(typeof id1);     // symbol
console.log(id1 === id2);    // false: every symbol is one of a kind

Symbols serve as special property names inside objects, so that code written by different people can never overwrite each other's properties by accident. Libraries use them; beginners rarely need to.

43.5 The object type: objects, arrays and functions

Every value that is not one of the seven primitives is an object. A primitive is one value; an object is a container that groups many values. The slides show the three kinds you will use most.

An object is a collection of key-value pairs inside curly braces. Each key is a name, and each value can be of any type, even another object. You read a property with a dot.

let person = {
  name: "Alice",      // key: name,      value: a string
  age: 30,            // key: age,       value: a number
  isStudent: false    // key: isStudent, value: a boolean
};
console.log(person.name);   // Alice

An array is an ordered list inside square brackets. Each item has a position number, its index, counted from 0, so the first item is fruits[0]. The slide's array mixes a number with two strings, which JavaScript allows.

let fruits = [1, "banana", "orange"];
console.log(fruits[0]);     // 1        the first item is at index 0
console.log(fruits[1]);     // banana

A function is a named, reusable block of code. You give it inputs, it runs, and it can hand back a result. A function is a value too: you can store it in a variable, and its type is object, though typeof gives it a special answer.

function add(a, b) {
  return a + b;
}
let sum = add(2, 3);    // the slide writes var a = add(2, 3)
console.log(sum);       // 5

Chapters 48, 50 and 51 give functions, arrays and objects a chapter each. For now one fact matters: all three are objects, and objects behave differently from primitives when you copy them (43.8).

typeof always answers with one of eight strings. This table is examined often:

Quirk 1: typeof null is "object". The first version of JavaScript, written in ten days in 1995, stored every value with a small type tag, and the tag for objects was 0. null was stored as zero, so typeof read it as an object. By the time anyone noticed, thousands of websites depended on that answer. A later proposal to fix it was turned down because it would have broken them, a choice made for backward compatibility. null really is a primitive; typeof is simply wrong about it. To test for it, compare directly: value === null.

Quirk 2: arrays say "object". That is true, since arrays are objects, but it means typeof cannot tell a list from a plain object. Use Array.isArray(value), which is true only for arrays.

Quirk 3: functions say "function". Functions are objects too, but typeof gives them their own answer. That is handy: it tells you whether a value can be called.

typeof is right about every primitive except null, and it lumps every object together except functions. So: for null, test value === null; for arrays, use Array.isArray(value).

Exam tip. The two favourite typeof questions are typeof null (answer "object", not "null") and typeof [] (answer "object", not "array"). typeof never answers "null" or "array".

43.7 Dynamic typing: values have types, variables do not

A variable is a name for a box (Chapter 42). In JavaScript the box itself has no type; only the value inside it does. So the same variable can hold a number now and a string a moment later. The slide example:

let dynamicVar = 10;        // dynamicVar holds a number
dynamicVar = "Hello";       // now it holds a string
dynamicVar = true;          // and now a boolean
console.log(typeof dynamicVar);   // boolean

This is called dynamic typing: the type is worked out at run time, from whatever value is in the box at that moment. Languages such as C and Java are statically typed: you state the type when you declare the variable, as in int marks = 10;, and putting text in marks later is an error caught before the program even runs. (A const cannot be reassigned at all, so it keeps the type of its first value.)

Dynamic typing makes JavaScript quick to write. The price is that a type mistake shows up only when the code runs, and often not as an error at all, just a wrong answer such as "255". Careful programmers therefore keep each variable to one type. TypeScript, a popular add-on to JavaScript, adds static types for exactly this reason.

In JavaScript the label on a box does not say what may go inside. You can keep marks in it today and a name tomorrow. JavaScript looks at the kind of thing only when it uses it.

43.8 Copied or shared: primitives and objects

What happens when you copy one variable into another? The answer depends on the type, and it surprises almost everyone the first time. This section is a preview; Chapters 50 and 51 return to it.

With a primitive, the value itself is copied:

let a = 10;
let b = a;      // b gets its own copy of 10
b = 20;
console.log(a, b);   // 10 20

The two boxes are independent, so changing b leaves a alone.

With an object, the variable never holds the object itself. The object lives somewhere in the computer's memory, and the variable holds a reference to it: directions to where it lives. Copying the variable copies the directions, not the object:

const asha = { name: "Asha", maths: 80 };
const copy = asha;      // copies the reference: still ONE object
copy.maths = 95;
console.log(asha.maths);   // 95

There was only ever one object. asha and copy are two names for it, so a change made through either name is seen through both.

Picture this. Asha photocopies her marksheet and gives the copy to Rahul. Rahul scribbles all over it, and Asha's original is untouched: that is a primitive. Now suppose Asha instead gives Rahul a duplicate key to her hostel room. Rahul goes in and moves the desk, and when Asha comes back the desk has moved, because there was only ever one room. A variable holding an object is the key, not the room.

Two consequences follow. First, === on objects asks "is this the same object?", not "do they look alike?". asha === copy is true, but two separately written { maths: 80 } objects are not equal. Second, this is why a const object can still change inside, as Chapter 42 showed: const fixes which object the name leads to, not what is inside it.

<p>The answers are in the Console panel below.</p>
<script>
  // a primitive: the VALUE is copied
  let a = 10;
  let b = a;
  b = 20;
  console.log("a:", a, "b:", b);                 // a: 10 b: 20

  // an object: the REFERENCE is copied, so both names share ONE object
  const asha = { name: "Asha", maths: 80 };
  const copy = asha;
  copy.maths = 95;
  console.log("asha.maths:", asha.maths);        // asha.maths: 95
  console.log("same object?", asha === copy);    // same object? true

  // two objects that look identical are still two objects
  const one = { maths: 80 };
  const two = { maths: 80 };
  console.log("one === two?", one === two);      // one === two? false

  // arrays are objects, so they are shared too
  const bag = ["pen"];
  const sameBag = bag;
  sameBag[1] = "pencil";
  console.log(bag);                              // ['pen', 'pencil']
</script>
Quick check: const list = ["tea"]; const other = list; other[0] = "coffee"; What is list[0] now?

"coffee". An array is an object, so other = list copied only the reference. There is one array with two names, and the change made through other shows up through list.

43.9 Automatic conversion: type coercion

What should "5" + 1 be? Text plus a number makes no obvious sense, but JavaScript tries to be helpful: instead of stopping with an error, it quietly converts one of the values to another type and carries on. This automatic conversion is called type coercion. The slide's example is 5 + "5", which gives the string "55".

For the strings, numbers, booleans, null and undefined of this chapter, two rules explain nearly everything:

  1. + with a string on either side joins. The other value is turned into text and the two are joined end to end: "5" + 1 is "51", and 5 + "5" is "55".
  2. Every other arithmetic operator works only with numbers. -, *, /, % and ** turn both sides into numbers first: "5" - 1 is 4 and "5" * "2" is 10. If a value cannot be read as a number, the answer is NaN: "abc" - 1 is NaN.

When neither side of + is a string, it adds, turning booleans, null and undefined into numbers on the way: true becomes 1, false and null become 0, and undefined becomes NaN.

true + 1         // 2
false + 1        // 1
null + 1         // 1
undefined + 1    // NaN
true + "1"       // "true1"   a string is involved, so it joins

+ has two jobs, adding and joining, and a string on either side switches it to joining. The other operators only know maths, so they turn everything into numbers, and answer NaN when they cannot.

Coercion happens in two more places. Comparisons with a number convert: "10" > 9 is true, because "10" becomes 10. (Two strings are compared as text, letter by letter, so "10" > "9" is false.) And the loose equality operator == converts, which is why 5 == "5" is true. The strict operator === never converts, so 5 === "5" is false: different types, different values. That is the main reason to always compare with ===; Chapter 44 lists the stranger results == produces. Finally, wherever JavaScript needs a yes or a no, as in an if (Chapter 47), it converts the value to a boolean by the Boolean() rules of 43.10.

<p>The answers are in the Console panel below.</p>
<script>
  // + with a string: JOIN
  console.log("'5' + 1 =", "5" + 1);             // '5' + 1 = 51
  console.log("5 + '5' =", 5 + "5");             // 5 + '5' = 55    (the slide example)
  console.log(typeof ("5" + 1));                 // string

  // - * / with a string: turn it into a number first
  console.log("'5' - 1 =", "5" - 1);             // '5' - 1 = 4
  console.log("'5' * '2' =", "5" * "2");         // '5' * '2' = 10
  console.log("'abc' - 1 =", "abc" - 1);         // 'abc' - 1 = NaN

  // booleans, null and undefined become numbers
  console.log("true + 1 =", true + 1);           // true + 1 = 2
  console.log("null + 1 =", null + 1);           // null + 1 = 1
  console.log("undefined + 1 =", undefined + 1); // undefined + 1 = NaN

  // comparisons convert too, and == converts, but === never does
  console.log("'10' > 9:", "10" > 9);           // '10' > 9: true
  console.log("5 == '5':", 5 == "5");            // 5 == '5': true
  console.log("5 === '5':", 5 === "5");          // 5 === '5': false

  // the classic bug: marks that came from a form are text
  let maths = "40";
  let bonus = 5;
  console.log("Total:", maths + bonus);          // Total: 405   (joined, not added!)
</script>
Quick check: what do "8" - 3 and "8" + 3 give, and of what type?

"8" - 3 is the number 5, because - only does maths. "8" + 3 is the string "83", because + joins when a string is involved.

43.10 Converting on purpose: String(), Number(), Boolean()

Coercion is JavaScript guessing what you meant. Explicit conversion is you saying it. Three built-in functions, named after the types they produce, turn a value into a string, a number or a boolean.

String(value) gives the text form of anything: String(42) is "42", String(true) is "true" and String(null) is "null". It works for a value of every type in this chapter.

Number(value) reads a value as a number. A string converts only if it is a clean number; anything else gives NaN.

CodeResultWhy

Number("42px")NaNNot a clean number (Chapter 46's parseInt() can read it)
Number("abc")NaNNot a number at all
Number(true), Number(false)1, 0
Number(null)0
Number(undefined)NaN

Boolean(value) answers "is there something here?". Six common values give false: false, 0, "" (the empty string), null, undefined and NaN. Apart from two rare relatives of 0 (-0 and the bigint 0n), everything else gives true, including "0", "false", " " (a single space) and every object and array, even an empty one. The two groups are called falsy and truthy, and Chapter 46 gives the complete list.

Everything typed is a string. The value in a form box, and whatever the user types into prompt(), is always text, even when it is digits (Cancel on a prompt() gives null). "1500" + 250 is "1500250". Convert first: Number("1500") + 250 is 1750. And call the three without new: new Number("42") makes a wrapper object (typeof says "object"), which is almost never what you want.

Explicit conversion also means you never need ==. Instead of typed == 40, write Number(typed) === 40, which says exactly what you mean.

Empty the box and press: Number("") is 0, so the total is a misleading Rs 250.

43.11 Common misunderstandings

✗ "A variable has a type, fixed when it is declared."
That is true in C and Java, not in JavaScript.
✓ "Values have types; a variable can hold any type over time."
let x = 10; x = "ten"; is legal, and typeof x is then "string".
✗ "typeof null is "null", and typeof [] is "array"."
typeof never gives either answer.
✓ "Both give "object"."
Test with value === null and Array.isArray(value).
✗ "null and undefined mean the same thing."
They are different values of different types, and null === undefined is false.
✓ "undefined: no value given yet. null: empty on purpose."
JavaScript supplies undefined; you write null.
✗ "const copy = asha; makes a copy of the object."
It copies only the reference.
✓ "Both names now lead to one object."
A change through copy is seen through asha. Primitives, by contrast, really are copied.
✗ "Boolean("0") and Boolean("false") are false."
They are non-empty strings.
✓ "The only string that converts to false is ""."
Any text at all, even one space, is true.

Answer: A. A bug from the first version of JavaScript, kept so that old websites keep working. null is really a primitive; typeof never answers "null". To test for it, write value === null.

  • C. typeof marks === "object"
  • D. marks === []

Answer: B. A is never true, because typeof never says "array". C is also true for plain objects and for null. D compares references, so it is false even when marks is an empty array: [] creates a brand-new array.

What does console.log("5" - 1, "5" + 1, true + 1); print?L3
  • A. 4 51 2
  • B. 4 6 2
  • C. 51 51 true1
  • D. NaN 51 2

Answer: A. - only does maths, so "5" becomes 5 and the answer is 4. + with a string joins, giving "51". With no string involved, + adds, and true becomes 1, giving 2. Option B forgets that + joins strings.

What does this print, and why? let a = { score: 50 }; let b = a; b.score = 90; console.log(a.score);L3

Answer: 90. An object is not copied when you assign it. b = a copies the reference, so a and b are two names for one object, and the change made through b is seen through a. With a primitive (let a = 50; let b = a; b = 90;) a would still be 50.

What are Number(""), Number("42px") and Number(null)?L2
  • A. NaN, NaN, NaN
  • B. 0, 42, 0
  • C. 0, NaN, 0
  • D. undefined, NaN, null

Answer: C. An empty string counts as 0, "42px" is not a clean number so it gives NaN, and null converts to 0. Option B is what parseInt("42px") would give for the middle value, but Number() is stricter.

Which of these gives true?L2
  • A. Boolean(0)
  • B. Boolean("")
  • C. Boolean(null)
  • D. Boolean("0")

Answer: D. "0" is a non-empty string, and every non-empty string converts to true. The number 0, the empty string and null are all on the short list of values that convert to false.

What happens when this line runs? console.log(10n + 1);L3
  • A. It prints 11
  • B. It throws a TypeError
  • C. It prints 11n
  • D. It prints 10n1

Answer: B. A bigint cannot be mixed with an ordinary number in a sum: "Cannot mix BigInt and other types". Convert one side first: 10n + 1n is 11n, and Number(10n) + 1 is 11.

A form field holds the fee "1500". The code fee + 250 shows 1500250. Explain why, and fix it.L3

Answer: everything read from a form is a string, so fee is the text "1500". With a string on one side, + joins instead of adding: "1500" + 250 is "1500250". Convert on purpose first: Number(fee) + 250 is 1750.

Quick revision

Key takeaways

  1. Every value has a type. JavaScript has eight: seven primitives (string, number, bigint, boolean, undefined, null, symbol) and object. Arrays and functions are objects.
  2. typeof answers with a string. Its quirks: typeof null is "object", typeof [] is "object" (use Array.isArray), and a function gives "function".
  3. undefined means no value has been given yet (JavaScript's default); null means empty on purpose (you write it).
  4. JavaScript is dynamically typed: values have types, variables do not, so one let can hold any type over time.
  5. Primitives are copied when assigned; objects are shared through a reference. === on objects asks "the same object?".
  6. Coercion: + with a string joins; - * / % ** convert to numbers; true is 1, null is 0, undefined is NaN.
  7. Convert on purpose with String(), Number() and Boolean(), and compare with === so nothing is converted behind your back.
