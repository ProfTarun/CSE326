Tables and Data Representation

Marks sheets, timetables, price lists, results: whenever data has rows and columns whose intersection means something, it belongs in a table. This chapter covers the complete anatomy of an HTML table, the two attributes that merge cells, the attributes that make a table readable by screen readers, and the one thing tables must never be used for.

About 17 minutes · Course outcome CO2

By the end of this chapter you can

  • Build a table with caption, thead, tbody, tfoot, tr, th and td in the correct order.
  • Merge cells with colspan and rowspan and count the cells each row needs.
  • Make headers explicit with scope and headers.
  • Use colgroup and col for column-wide properties.
  • Explain why tables are not for layout and what role="presentation" means.

19.1 When a table is the right element

A table is for tabular data: information that is naturally organised in rows and columns where each cell's meaning comes from its row header and its column header. A marks sheet (student × subject), a timetable (day × period), a comparison of products (product × feature). If you can put a header on every column and every row and the intersections make sense, it is a table. If the "table" is just a way of putting things side by side, it is layout, and layout is CSS's job (see 19.6).

19.2 The anatomy of a table

<table>
The container for the whole grid.
<caption>
An announced, visible title for the whole table. It must be the first child of <table>, before thead; anywhere else is invalid and may not render. It is not a column width, a footer row or a per-cell tooltip. (Not to be confused with <figcaption>, which captions a figure.)
<thead>, <tbody>, <tfoot>
Group the header rows, the body rows and the footer rows (totals, summaries) separately. They do not merge cells, add borders or replace tr. Grouping lets CSS style the sections differently, lets a long table's header repeat when printed, and lets screen readers understand which rows are headings.
<tr>
A single row. Every cell must be inside a row: <table><td>A</td></table> is invalid because the cell is not in a tr.
<th>
A header cell: it describes what its column or row contains. Bold and centred is only the default look; the meaning is the point. Screen readers use th to announce the context of each data cell ("Marks: 85").
<td>
A standard data cell holding a value.
<style> table { border-collapse: collapse } th, td { border: 1px solid #999; padding: 6px 12px } caption { font-weight: bold; padding: 6px } </style>
<table>
  <caption>CSE326 Internal Assessment</caption>
  <thead>
    <tr><th scope="col">Name</th><th scope="col">CA1</th><th scope="col">CA2</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Rahul</th><td>28</td><td>25</td></tr>
    <tr><th scope="row">Priya</th><td>30</td><td>29</td></tr>
  </tbody>
  <tfoot>
    <tr><th scope="row">Average</th><td>29</td><td>27</td></tr>
  </tfoot>
</table>

Browsers draw no borders by default; the CSS at the top adds them. Old HTML used a border attribute; today borders belong in CSS.

19.3 Merging cells: colspan and rowspan

Two attributes on td or th make a cell occupy more than one grid position. colspan="2" makes a cell stretch across two columns (sideways). rowspan="2" makes a cell span two rows (downwards). The values count grid cells, not pixels.

Counting cells: the rule

Each row must add up to the table's column count, counting spans. Two consequences that are tested:

  • In a 4-column table, a row containing a cell with colspan="3" needs only one more cell: two cell tags in total (3 + 1 = 4).
  • When a cell has rowspan="2", the next row must omit one cell in that column, because the spanning cell already occupies it. Repeating the cell, adding an empty one or switching to colspan all break the grid.
<style> table { border-collapse: collapse } th, td { border: 1px solid #999; padding: 6px 12px; text-align: center } </style>
<table>
  <caption>Weekly lab schedule</caption>
  <thead><tr><th scope="col">Time</th><th scope="col">Mon</th><th scope="col">Tue</th><th scope="col">Wed</th></tr></thead>
  <tbody>
    <tr><th scope="row" rowspan="2">9-11</th><td colspan="2">CSE326 double lab</td><td>CSE201</td></tr>
    <tr><td>CSE201</td><td>Free</td><td>CSE326</td></tr>
  </tbody>
  <tfoot><tr><td colspan="4">All labs in Block 34.</td></tr></tfoot>
</table>

Count the second body row: three cells, because the rowspan="2" header from the row above still fills the Time column. The footer row has one cell with colspan="4", covering all four columns. A category label shared by two consecutive data rows is exactly the rowspan case.

19.4 Making tables readable by screen readers

A sighted user reads a table by glancing up to the column header and left to the row header. A screen-reader user cannot glance; the table must say which headers apply. Three tools:

scope on th
scope="col" tells assistive technology that the header applies to the entire column below it; scope="row" that it describes its row. (There are also colgroup and rowgroup values.) With th and scope, a screen reader announces "Monday, 9 AM, CSE326" rather than just "CSE326".
headers on td
For a complex table with several levels of headers, the headers attribute explicitly associates a data cell with its header cells by listing their ids: <td headers="mon t9">. scope handles simple tables; headers handles the rest.
caption
Announced when the user reaches the table, so they know what it is before hearing forty cells.

So the fix for "an exam-results table reads confusingly with a screen reader" is: use th for header cells, add scope, and add a caption. Replacing the table with divs, changing fonts and colours, or adding colspan everywhere does nothing for it.

<table>
  <caption>Lab timetable</caption>
  <tr><td></td><th id="mon" scope="col">Mon</th><th id="tue" scope="col">Tue</th></tr>
  <tr><th id="t9" scope="row">9 AM</th><td headers="mon t9">CSE326</td><td headers="tue t9">CSE201</td></tr>
</table>

19.5 colgroup and col

<colgroup> and <col> let properties be applied to whole columns without repeating them on every cell: a background for the first column, a width for the third. They go right after caption and before thead. <col span="2"> covers two columns. They do not merge cells, define headers or position the caption.

<style> table { border-collapse: collapse } th, td { border: 1px solid #999; padding: 6px 12px } </style>
<table>
  <caption>Fees by course</caption>
  <colgroup>
    <col style="background: #FFF1E0">
    <col span="2" style="background: #E9F7E7">
  </colgroup>
  <thead><tr><th>Course</th><th>Year 1</th><th>Year 2</th></tr></thead>
  <tbody><tr><td>CSE</td><td>1,20,000</td><td>1,25,000</td></tr></tbody>
</table>

The full order of children inside <table> is therefore: caption, then colgroup, then thead, then tbody, then tfoot. Putting tbody before thead, caption after thead, or caption outside the table is wrong.

19.6 Tables are not for layout

Before CSS, whole pages were built inside tables: one row for the banner, cells for columns. Do not do this. It breaks accessibility and responsiveness; tables are for tabular data. A screen reader announces a data table and reads meaningless row and column positions; the fixed grid cannot reflow on a phone; and the markup says the page is data when it is not. Chapter 14 covers the modern way: semantic regions plus CSS Flexbox and Grid.

Occasionally you inherit a layout table you cannot rewrite (old HTML emails are the classic case). Then <table role="presentation"> tells assistive technology to ignore the table's data semantics because it is only a layout grid. It does not mark the table as primary content, does not hide borders and does not make it sortable; it only switches off the "this is data" announcement.

19.7 Worked example: a marks sheet from scratch

<style> table { border-collapse: collapse } th, td { border: 1px solid #999; padding: 6px 12px } thead th { background: #FFF1E0 } tfoot { font-weight: bold } </style>
<table>
  <caption>Semester 1 marks: Rahul Sharma (Reg 12345678)</caption>
  <thead>
    <tr><th scope="col">Subject</th><th scope="col">CA (30)</th><th scope="col">ETE (70)</th><th scope="col">Total</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">CSE326</th><td>27</td><td>61</td><td>88</td></tr>
    <tr><th scope="row">CSE305</th><td>25</td><td>58</td><td>83</td></tr>
  </tbody>
  <tfoot>
    <tr><th scope="row" colspan="3">Grand total (out of 200)</th><td>171</td></tr>
  </tfoot>
</table>

Check it against the rules: caption first; thead with column headers; row headers as th scope="row"; a tfoot whose merged cell (colspan="3") plus one data cell equals the four columns; borders and colours in CSS, not attributes.

Exam-style checks

Which tag must be used for a table's header cells so screen readers announce context correctly?L1
  • A. <th>
  • B. <td>
  • C. <tr>
  • D. <caption>

Answer: A.

What is the difference between <th> and <td>?L2

Answer: th is a header cell that describes what its row or column means; td is a data cell. Bold and centred is only th's default styling, and th is not restricted to thead (row headers live in tbody).

Which tag defines a single row inside a table, and which defines a standard data cell?L1

Answer: <tr> and <td>. (tc does not exist.)

Which is INVALID?L2
  • A. <table><tr><td>A</td></tr></table>
  • B. <table><td>A</td></table>
  • C. <table><thead><tr><th>A</th></tr></thead></table>
  • D. <table><caption>X</caption></table>

Answer: B. A cell must sit inside a tr.

What does <caption> provide for a table, and where must it be placed?L2

Answer: an announced, visible title for the whole table; it must be the first child of table, immediately inside it before thead.

What do <thead> and <tbody> do in a table, and which element groups the summary or total rows?L2

Answer: they group header rows separately from body rows; totals go in <tfoot>. They do not merge cells, add borders or remove the need for tr.

Which is the correct order of child elements inside a <table>?L2
  • A. <tbody>, then <thead>, then <caption>
  • B. <thead>, then <caption>, then <tbody>
  • C. <caption>, then <thead>, then <tbody>, then <tfoot>
  • D. <caption> must be placed after </table>

Answer: C. (colgroup, if present, goes between caption and thead.)

The attribute colspan="2" makes a cell stretch across two:L1
  • A. Rows
  • B. Tables
  • C. Columns
  • D. Pages

Answer: C. rowspan stretches across rows.

A category label must be shared by two consecutive data rows. Which attribute achieves this?L3
  • A. rowspan="2"
  • B. colspan="2"
  • C. span="2"
  • D. scope="rowgroup"

Answer: A.

A 4-column table has a row containing a cell with colspan="3". How many cell tags does that row need in total?L3

Answer: 2. The spanning cell covers three columns; one more cell completes the four.

A cell has rowspan="2". What must the NEXT row do?L3
  • A. Repeat the cell
  • B. Omit one cell in that column
  • C. Add an empty cell
  • D. Use colspan instead

Answer: B.

On a <th>, scope="col" tells assistive technology that the header applies to:L2
  • A. The entire column
  • B. The entire row
  • C. Only the cell immediately below
  • D. The whole table

Answer: A. scope="row" describes the row.

In a complex table, which attribute explicitly associates a data cell with its header cells?L2
  • A. headers
  • B. scope
  • C. for
  • D. colspan

Answer: A. <td headers="id1 id2">. scope is for simple tables.

An exam-results table reads confusingly with a screen reader. Which set of changes fixes it?L3
  • A. Replace the table with nested <div> elements
  • B. Increase the font size and add background colours
  • C. Use <th> for header cells, add scope, and add a <caption>
  • D. Add colspan to every cell in the table

Answer: C.

What is the purpose of the <colgroup> and <col> elements in a table?L2
  • A. They merge cells across several rows
  • B. They let properties be applied to whole columns without repeating them on every cell
  • C. They define the table's header row
  • D. They set the caption position

Answer: B.

Why would a developer write <table role="presentation">?L3
  • A. To mark the table as the page's primary content
  • B. To make the table's borders invisible
  • C. To tell assistive technology to ignore the table's data semantics because it is only a layout grid
  • D. To allow the table to be sorted by the user

Answer: C.

Why should tables not be used to lay out an entire web page today?L3

Answer: it breaks accessibility and responsiveness; tables are for tabular data. Layout is done with semantic elements and CSS.

Quick revision

Key takeaways

  1. Tables are for tabular data only. Order inside table: caption, colgroup, thead, tbody, tfoot. Every cell (th or td) lives in a tr.
  2. th = header cell (column or row); td = data cell; caption = the table's title, first child; thead/tbody/tfoot group rows.
  3. colspan stretches across columns; rowspan across rows. Rows must add up: colspan="3" in a 4-column row leaves one more cell; the row under a rowspan cell omits that cell.
  4. scope="col" / "row" on th, headers="ids" on td for complex tables, plus a caption: that is how screen readers read tables.
  5. colgroup/col style whole columns. Never lay out a page with a table; role="presentation" only for an unavoidable layout table.
