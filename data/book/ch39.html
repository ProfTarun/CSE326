CSS Animations

A transition needs something to happen: a hover, a click, a class being added. An animation runs on its own, can have as many steps as you like, and can repeat for ever. This is how a loading spinner spins and a notification badge pulses — and it is the last chapter of Unit 3.

39.1 Two halves: define, then apply

An animation always comes in two pieces, and they are written separately.

/* 1. define the steps, and give them a name */
@keyframes grow {
  from { transform: scale(1); }
  to   { transform: scale(1.3); }
}

/* 2. apply that name to an element */
.badge {
  animation: grow 1.5s ease-in-out infinite alternate;
}

The name (grow) is yours to choose. It is the only link between the two halves, so a typo in either place means nothing happens — silently, as ever.

39.2 Writing @keyframes

Inside the braces you list the stages of the animation. Two ways to write them:

/* two steps: from and to */
@keyframes fade {
  from { opacity: 0; }
  to   { opacity: 1; }
}

/* any number of steps, as percentages of the total time */
@keyframes pulse {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.14); }
  100% { transform: scale(1); }
}

from is simply 0% and to is 100%. Percentages are of the duration, not of any distance: in a two-second animation, 50% happens one second in.

The browser fills in every frame between the stages you wrote. You describe the milestones; it does the work.

You can group stages that share a value, which keeps things short:

@keyframes blink {
  0%, 100% { opacity: 1; }
  50%      { opacity: 0.2; }
}

39.3 The animation properties

PropertyValuesMeans
animation-nameThe @keyframes nameWhich recipe to run
animation-duration1.5s, 800msHow long one run takes. Required — the default is 0.
animation-timing-functionease, linear, ease-in-outThe speed curve, as in Chapter 38
animation-delay0.3sWait before the first run
animation-iteration-count1, 3, infiniteHow many times. Default is 1.
animation-directionnormal, reverse, alternatealternate plays forwards, then backwards, so it returns smoothly
animation-fill-modenone, forwards, backwards, bothforwards keeps the final frame instead of snapping back
animation-play-staterunning, pausedPause it — often on :hover

The shorthand takes them in a readable order, and you can leave out anything you do not need:

animation: pulse 1.6s ease-in-out infinite alternate;
/*         |     |    |           |        |
           |     |    |           |        direction
           |     |    |           iteration-count
           |     |    timing-function
           |     duration
           name                                        */
Two gotchas. (1) With no animation-duration nothing runs, however correct your keyframes. (2) Without animation-fill-mode: forwards, an animation that runs once snaps back to the original styles the instant it finishes — which looks like a bug and is the commonest surprise with one-shot animations.

A loading spinner

A circle with one coloured edge, rotated for ever. It is four declarations and no image file.

<style>
  body { display: grid; place-items: center; height: 140px; }
  .spinner {
    width: 44px; height: 44px;
    border: 5px solid #E3E9F0;
    border-top-color: #E07B1E;     /* one edge coloured, so you see it turn */
    border-radius: 50%;
    animation: spin 0.9s linear infinite;
  }
  @keyframes spin { to { transform: rotate(360deg); } }
</style>
<div class="spinner"></div>

Note two choices. linear, because a spinner that speeds up and slows down looks broken. And only a to stage — when you leave out from, the browser uses the element's current style as the starting point.

A pulse, to draw the eye

<style>
  body { font-family: system-ui, sans-serif; padding: 24px; }
  .badge {
    display: inline-block; background: #C42B2B; color: #fff;
    padding: 6px 14px; border-radius: 999px; font-weight: 700;
    animation: pulse 1.6s ease-in-out infinite;
  }
  @keyframes pulse {
    0%, 100% { transform: scale(1); }
    50%      { transform: scale(1.15); }
  }
</style>
<span class="badge">3 new messages</span>

A fade-in for content arriving

<style>
  body { font-family: system-ui, sans-serif; background: #F1F5F9; padding: 18px; }
  .card {
    background: #fff; border-radius: 10px; padding: 14px 16px;
    margin-bottom: 10px; box-shadow: 0 2px 6px rgba(16,32,64,.08);
    opacity: 0;                                   /* start invisible   */
    animation: fadeUp .5s ease-out forwards;      /* forwards: STAY visible */
  }
  .card:nth-child(2) { animation-delay: .15s; }
  .card:nth-child(3) { animation-delay: .30s; }

  @keyframes fadeUp {
    from { opacity: 0; transform: translateY(14px); }
    to   { opacity: 1; transform: translateY(0); }
  }
</style>
<div class="card">CSE326 Internet Programming</div>
<div class="card">CSE305 Database Systems</div>
<div class="card">CSE201 Data Structures</div>

Three things worth noticing there. forwards keeps the final frame, so the cards stay visible. Different animation-delay values on each card produce the staggered arrival. And :nth-child from Chapter 32 applies the delays without extra classes.

Typing dots

Three dots, the same animation on each, staggered by a delay — the pattern is identical to the fade above.

39.5 Animation or transition?

TransitionAnimation
StartsOnly when something changes (hover, focus, a class)By itself, as soon as the element exists
StepsTwo: the from and the toAs many as you like
RepeatsNoYes — any number, or infinite
Written asOne property@keyframes plus the animation property
Best forHovers, buttons, panels openingSpinners, pulses, entrances, anything with several stages

If the movement is a reaction to the user, use a transition. If it should happen on its own, or has more than two steps, or repeats, use an animation. When either would work, the transition is simpler — choose it.

39.6 Using motion responsibly

Animation is the easiest thing in CSS to overdo, and the fastest way to make a page feel amateur. Four rules:

  1. Give it a job. Motion should show a relationship, draw attention to something that changed, or say "wait". Motion for its own sake is noise.
  2. Never animate body text. Text that moves cannot be read, and for a dyslexic reader it can be impossible.
  3. Beware infinite loops. Anything repeating for ever competes for attention permanently. A spinner earns it, because it means "still working". A bouncing arrow does not.
  4. Honour prefers-reduced-motion. WCAG 2.2 also requires that any animation running for more than five seconds can be paused.
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}

Put that at the end of every stylesheet. It is five lines and it is the difference between a site someone can use and one that makes them feel ill.

And a reminder from Chapter 38: animate transform and opacity wherever you can. Animating width, height, top or margin forces the browser to re-calculate the layout on every single frame, and on a modest phone that stutters visibly.

Exam-style checks

Which pair defines an animation?L2
  • A. @media and animate
  • B. @keyframes and animation
  • C. @motion and move
  • D. transition and transform

Answer: B. @keyframes defines the steps; the animation property applies them to an element. Neither does anything alone.

What do from and to mean inside @keyframes?L2

from is 0% and to is 100% of the animation's duration. Percentages let you add as many intermediate stages as you like.

Which value makes an animation repeat for ever?L1

animation-iteration-count: infinite;, or infinite inside the animation shorthand. The default is 1.

An animation runs once and then snaps back to the original style. What is missing?L3

animation-fill-mode: forwards; — it keeps the final keyframe after the animation ends. Without it, the element reverts the moment the last frame is drawn.

What does animation-direction: alternate do?L2

Plays the animation forwards, then backwards, then forwards again. It is what makes a pulse or a slide return smoothly instead of jumping back to the start.

Which timing function suits a loading spinner, and why?L3

linear — a constant speed. With ease the spinner would speed up and slow down on every turn, which reads as broken rather than busy.

When should you use a transition rather than an animation?L3

When the movement is a reaction to the user — a hover, a focus, a class being toggled — and there are only two states. Use an animation when it must run on its own, has more than two steps, or repeats.

Why animate transform rather than top or width?L3

Because transform and opacity can be handled by the graphics card and do not affect the layout. Animating top, width, height or margin forces the browser to re-calculate positions every frame, which stutters on a modest phone.

Your keyframes look right but nothing moves. Name two likely causes.L3

(1) No animation-duration — it defaults to 0, so the animation finishes instantly. (2) The name does not match between the @keyframes rule and the animation property. Both fail silently.

Give two rules for using animation responsibly.L2

Any two of: give every animation a job; never animate body text; be sparing with infinite loops; honour prefers-reduced-motion; allow anything running over five seconds to be paused (WCAG 2.2).

Quick revision

Key takeaways

  1. Two halves: @keyframes name { ... } defines the steps, animation: name duration ... applies them. The name links them.
  2. Steps are from/to or percentages of the duration; group stages with commas.
  3. animation: name duration timing-function iteration-count direction;. Duration is required; infinite repeats; alternate plays back and forth; forwards keeps the last frame.
  4. Transition = a reaction with two states. Animation = self-starting, multi-step or repeating.
  5. Animate transform and opacity. Stagger several elements with animation-delay and :nth-child.
  6. Always add the prefers-reduced-motion block.
