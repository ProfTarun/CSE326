Forms and Form Controls

Forms are how the Web listens: logins, registrations, searches, feedback, checkouts. This chapter explains the form element and how it sends data, every kind of control you can put inside it, how to label and group controls so they are usable, and the rules that decide exactly what reaches the server when the user presses Submit.

About 19 minutes · Course outcome CO2 · Chapter 17 covers the input types in detail

By the end of this chapter you can

  • Write a form with the right action, method and enctype.
  • Explain name versus id versus value, and predict what is submitted.
  • Use label, textarea, select/option/optgroup, button, fieldset/legend, datalist, output, progress and meter.
  • Choose between GET and POST.
  • Build a complete, accessible registration form.

16.1 The form element and how submission works

A <form> groups the controls that collect user input and submits their values to a server. When the user presses the submit button, the browser gathers every control that has a name, pairs each name with its current value, and sends the pairs to the URL in the form's action using the HTTP method in method.

<form action="/register" method="post">
  ... controls ...
</form>
action
The URL the form data is sent to. Not a validation pattern, not the HTTP method, not the name of the button. Leave it out and the form submits to the current page's URL.
method="get"
The field values are appended to the URL as a query string: /search?q=html&page=2. Because the data is in the URL it appears in the address bar, in browser history and in server logs, and it can be bookmarked and shared. Good for searches and filters; unsuitable for passwords, and files cannot be uploaded this way. GET is the default if method is omitted.
method="post"
The field values are sent in the body of the HTTP request instead of the URL. Use it for anything that changes data on the server (registrations, orders), for sensitive fields, and for file uploads. POST does not encrypt anything (that is HTTPS's job), does not restrict you to text fields, and does not skip validation.
enctype="multipart/form-data"
How the data is encoded. The default, application/x-www-form-urlencoded, is fine for text. A form that carries uploaded files must use method="post" with enctype="multipart/form-data". It is not encryption, not AJAX, and not a validation setting.

16.2 name, id and value: three attributes, three jobs

Beginners confuse these constantly, and questions target the confusion.

AttributeWho uses itJob
nameThe serverThe key under which the control's value is submitted. A control without a name is not submitted at all: the commonest reason a field "goes missing" at the server.
idThe browserUnique identifier on the page; what <label for>, fragment links and scripts point at. Never sent to the server.
valueBothThe control's data: the pre-filled text of an input, the value submitted for a chosen radio/checkbox/option, the text on a button.

So <input type="text" id="email" name="email" value="you@lpu.in"> has an id for the label, a name for the server, and a value that pre-fills the field. Two different controls may share a name (radio buttons in a group must); no two elements may share an id.

What actually gets submitted

  • Every control with a name that is not disabled: its name and current value.
  • A disabled control: nothing. It is greyed out and left out of the submission.
  • A readonly control: submitted normally; the user just cannot edit it.
  • A checkbox that is unchecked: nothing at all is sent for that control: not "false", not an empty string, not "0". A checked checkbox sends its value (or "on" if it has none).
  • A radio group: only the checked button's value, under the shared name.
  • A <select>: the selected option's value (or its text if it has no value); with multiple, every selected value.
  • The submit button that was pressed, if it has a name.

16.3 Labelling every control

<label> provides the human-readable name of a control. Connect it with for matching the control's id, or wrap the control inside the label. A connected label is announced by screen readers together with the field, and clicking the label focuses the field: a bigger target for everyone. Every visible control should have one; a placeholder is only a hint (Chapter 15).

<label for="uname">Username</label>
<input id="uname" name="username" type="text">
<br><br>
<label><input type="checkbox" name="news" value="yes"> Send me updates</label>

16.4 The controls

input

<input> is a void element whose type attribute selects the kind of control: a text box, a password box, a checkbox, a date picker, a file chooser, a submit button and more. It is the subject of the whole of Chapter 17. For now: <input type="text" name="city">.

textarea: multi-line text

For a feedback message, a bio or an address that spans lines, use <textarea>. It is not a void element: it has a closing tag, and any default text goes between the tags, not in a value attribute. rows sets the visible number of text lines and cols the visible width in characters (CSS usually overrides both). There is no <input type="textarea"> or type="multiline".

<label for="fb">Feedback</label><br>
<textarea id="fb" name="feedback" rows="4" cols="40" placeholder="Tell us what you think..."></textarea>

select, option and optgroup: a dropdown list

<select> creates a dropdown list of choices; each <option> is one choice, and its value is what gets submitted (the text between the tags is what the user sees). selected on an option pre-chooses it when the page loads. <optgroup label="..."> groups related options under a shared heading inside the list. The multiple attribute on the select lets the user choose more than one option (with Ctrl or Shift), which is the right control for "pick several subjects from a list".

<label for="course">Course</label>
<select id="course" name="course">
  <optgroup label="Engineering">
    <option value="cse">Computer Science</option>
    <option value="ece" selected>Electronics</option>
  </optgroup>
  <optgroup label="Management">
    <option value="mba">MBA</option>
  </optgroup>
</select>
<br><br>
<label for="subs">Subjects (choose several)</label>
<select id="subs" name="subjects" multiple size="3">
  <option>HTML</option><option>CSS</option><option>JavaScript</option>
</select>

button: submit, reset or nothing

A <button> has three types. type="submit" submits the form it belongs to, and it is the default if you write no type, so a bare <button> inside a form submits it. type="reset" clears every control back to its initial value. type="button" has no built-in behaviour at all: it does nothing until JavaScript gives it a job. The same three exist as <input type="submit">, <input type="reset"> and <input type="button" value="...">; a form whose only button is <input type="button" value="Submit"> does nothing when clicked, however it is labelled, because type="button" has no default submit behaviour. A link (<a href="#">Send</a>) does not submit either.

<form onsubmit="event.preventDefault(); alert('Submitted!')">
  <input type="text" name="q" value="type here">
  <button type="submit">Submit</button>
  <button type="reset">Reset</button>
  <button type="button" onclick="alert('I only do what a script tells me')">Plain button</button>
</form>

fieldset and legend: grouping related controls

<fieldset> groups a set of related controls inside a form, drawn with a border, and <legend> supplies its visible caption. This is essential for radio and checkbox groups: with a fieldset, a screen reader announces "Spice level: Mild" instead of a bare "Mild", because the legend is read with each control. Not <div>, not <section>, not <group>; and the caption is legend, not caption (tables), label or summary.

<fieldset>
  <legend>Spice level</legend>
  <label><input type="radio" name="spice" value="mild" checked> Mild</label>
  <label><input type="radio" name="spice" value="medium"> Medium</label>
  <label><input type="radio" name="spice" value="hot"> Hot</label>
</fieldset>

datalist: suggestions, not restrictions

A <datalist> attached to a text input through the input's list attribute offers suggestions while still letting the user type any value. That is the difference from select, which restricts the user to the options given.

<label for="city">City</label>
<input id="city" name="city" list="cities" placeholder="Start typing...">
<datalist id="cities">
  <option value="Jalandhar"><option value="Ludhiana"><option value="Chandigarh">
</datalist>

output, progress and meter

<output> displays the result of a calculation made from the form's controls. <progress value="70" max="100"> shows progress toward completing a task (an upload, a quiz). <meter min="0" max="100" value="80"> shows a measurement within a known range (disk space, battery, a score). Progress is "how far along"; meter is "how much".

16.5 Choosing the control

16.6 Worked example: a complete registration form

<form action="/register" method="post" enctype="multipart/form-data"
      onsubmit="event.preventDefault(); alert('Form is valid and would now be sent by POST');">
  <fieldset>
    <legend>Student Registration</legend>

    <p><label for="name">Full name</label><br>
       <input type="text" id="name" name="name" required></p>

    <p><label for="email">Email</label><br>
       <input type="email" id="email" name="email" required></p>

    <p><label for="course">Course</label><br>
       <select id="course" name="course">
         <option value="">-- choose --</option>
         <option value="cse">Computer Science</option>
         <option value="ece">Electronics</option>
       </select></p>

    <fieldset>
      <legend>Year of study</legend>
      <label><input type="radio" name="year" value="1" checked> First</label>
      <label><input type="radio" name="year" value="2"> Second</label>
    </fieldset>

    <p><label><input type="checkbox" name="hostel" value="yes"> I need hostel accommodation</label></p>

    <p><label for="photo">Photo</label><br>
       <input type="file" id="photo" name="photo" accept="image/*"></p>

    <p><label for="about">About you</label><br>
       <textarea id="about" name="about" rows="3" cols="40"></textarea></p>

    <input type="hidden" name="source" value="web">
    <button type="submit">Register</button>
    <button type="reset">Clear</button>
  </fieldset>
</form>

Trace what would be submitted if the user fills the name and email, leaves the course on "-- choose --", keeps First year, ticks the hostel box and chooses no photo: name, email, course= (empty), year=1, hostel=yes, photo (empty), about (empty) and the hidden source=web. Had the hostel box been left unticked, hostel would not appear at all. Had any control lacked a name, it would not appear either.

Exam-style checks

In <form action="/submit" method="post">, the action attribute specifies:L2
  • A. The validation pattern for all fields
  • B. The HTTP method used for the request
  • C. The name of the submit button
  • D. The URL the form data is sent to

Answer: D.

Which statement is true of a form submitted with method="get"?L2
  • A. The values are hidden from the browser history
  • B. The field values are encrypted before sending
  • C. Files can be uploaded reliably
  • D. The field values appear in the URL as a query string

Answer: D.

Compared with method="get", a form using method="post":L2
  • A. Can only transmit plain text fields
  • B. Encrypts the submitted data automatically
  • C. Sends the data in the request body instead of appending it to the URL
  • D. Skips all client-side validation

Answer: C. Encryption is HTTPS's job, not POST's.

What does enctype="multipart/form-data" on a <form> enable?L2
  • A. The form data is encrypted in transit
  • B. The form can carry uploaded files
  • C. The form submits without reloading the page
  • D. The form validates on the server only

Answer: B.

What does the name attribute on a form control determine?L2
  • A. The key under which the control's value is submitted
  • B. The text shown beside the control
  • C. The control's position in the tab order
  • D. The CSS rule applied to the control

Answer: A.

What is the difference between id and name on an input, and what is the likeliest cause of a field missing at the server?L3

Answer: id links the label and is for the browser; name is the key the value is submitted under and is for the server. A field missing at the server almost always has no name attribute (or is disabled).

A field is filled in but marked disabled. On submit it is:L2

Answer: not submitted at all. disabled excludes the field; use readonly if the value must still be sent.

A checkbox is left unchecked when the form is submitted. What is sent for that control?L3
  • A. The text "false" is sent
  • B. Nothing at all is sent for that control
  • C. An empty string is sent
  • D. The value "0" is sent

Answer: B.

Which attribute on <label> ties it to a field?L1

Answer: for, which must match the input's id exactly.

Which element accepts multi-line free text such as a feedback message, and which of these is written correctly: <textarea />, <textarea></textarea>, <textarea value="x">, <input type="textarea">?L2

Answer: <textarea>, written as <textarea></textarea>: it is not void, and its value goes between the tags. Which attribute sets its visible lines? rows.

Which element creates a dropdown list of choices, which attribute marks one option as pre-chosen, and which element groups related options under a shared label?L2

Answer: <select> (with <option> children); selected on the option (checked is for radio/checkbox); <optgroup label="...">.

Which control lets a user pick several subjects from a single list, and which attribute on <select> allows more than one option?L2

Answer: <select multiple>; the attribute is multiple. (Checkboxes are the alternative for a few options.)

Which button triggers submission of the form it belongs to?L2
  • A. <button type="button">Send</button>
  • B. <a href="#">Send</a>
  • C. <button type="reset">Send</button>
  • D. <button type="submit">Send</button>

Answer: D. type="button" does nothing by itself; reset clears; a link navigates.

A form's only button is <input type="button" value="Submit">. Why does clicking it do nothing?L2
  • A. An <input> can never submit a form
  • B. type="button" has no default submit behaviour
  • C. The value attribute overrides the type
  • D. The button must be placed outside the <form>

Answer: B. Use type="submit".

Which element groups a set of related controls inside a form, and which supplies its visible caption?L1

Answer: <fieldset> and <legend>. Essential for radio groups: the screen reader announces the legend with each option.

Which markup offers a text input a list of suggestions while still allowing the user to type any value?L3
  • A. <input list="cities"> together with a <datalist id="cities">
  • B. <select> with an extra empty <option>
  • C. <input type="text" options="cities">
  • D. <textarea list="cities">

Answer: A.

Which attribute pre-fills a default entry into a text input?L1
  • A. placeholder
  • B. value
  • C. default
  • D. text

Answer: B. placeholder is only a hint that disappears.

Quick revision

Key takeaways

  1. form action = where; method get = in the URL (searches), post = in the body (changes, secrets, files); enctype multipart/form-data for uploads.
  2. name = the submission key (no name, no data); id = for labels and scripts; value = the data.
  3. Submitted: named, enabled controls. Not submitted: disabled controls, unchecked checkboxes. readonly is submitted.
  4. label for/id (or wrap); textarea between tags with rows/cols; select + option (value, selected) + optgroup, multiple; button submit (default) / reset / button (does nothing); fieldset + legend for groups; datalist + list for suggestions; output, progress, meter.
  5. Radio for one of few; checkboxes or select multiple for several; input/textarea for free text.
