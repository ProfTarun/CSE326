Pseudo-classes

So far every rule has styled an element because of what it is. A pseudo-class styles it because of what is happening to it, or where it sits among its brothers and sisters: the button the mouse is over, the field the keyboard is in, the first row of a table, every second list item. One extra colon unlocks all of it.

About 23 minutes · Course outcome CO3

Before you start — one-line reminders

  • A selector points at elements; a pseudo-class is added to one (Chapter 23).
  • Siblings are elements with the same parent (Chapter 3).
  • Keyboard users move through a page with Tab and must be able to see where they are (Chapter 15).

By the end of this chapter you can

  • Style the four link states in the right order.
  • Give every interactive element a visible focus style, and say why that is not optional.
  • Stripe a table or list with :nth-child, and read a formula like 2n+1.
  • Style form fields by their state: checked, disabled, required, invalid.
  • Use :not() and :root.

32.1 A state is not an element

A pseudo-class is written with one colon after a selector:

a:hover { color: orange; }
/* |  |
   |  the pseudo-class: "while the mouse is over it"
   the element: every link                            */

Read it as a sentence: "a link, while hovered, is orange." The word "pseudo" means "false" — there is no hover class written anywhere in your HTML. The browser adds and removes it invisibly as things happen.

Picture this. A door is still the same door whether it is open, closed or locked. A pseudo-class styles the door in a particular state, without you having to write three different doors in the HTML.

Pseudo-classes fall into three families, and it helps to know which one you are reaching for:

FamilyDepends onExamples
InteractionWhat the user is doing right now:hover, :focus, :active, :visited
PositionWhere the element sits among its siblings:first-child, :last-child, :nth-child()
Form stateThe condition of a form control:checked, :disabled, :required, :invalid

32.2 Link and interaction states

Pseudo-classApplies when
:linkThe link has not been visited yet
:visitedThe user has already opened that page
:hoverThe mouse pointer is over the element
:activeThe moment it is being pressed
:focusIt has keyboard focus — the user tabbed to it or clicked into it

:hover works on every element, not only on links. A card can lift on hover, a table row can highlight, an image can brighten.

Hover me dark → orange on hover → red while pressed

Write them in the right order

The four link states have to be written in a fixed order, because they have the same specificity and a later rule beats an earlier one (Chapter 23). Write :hover before :link and hover will never show.

a:link    { color: #1D4ED8; }
a:visited { color: #6D28D9; }
a:hover   { color: #E07B1E; }
a:active  { color: #C42B2B; }

The memory aid is LoVe HAte: Link, Visited, Hover, Active.

Hover does not exist on a phone. There is no mouse pointer, so a touch user may never see your hover effect, and a "hover to reveal" menu can be impossible to open. Treat hover as a bonus, never as the only way to reach something.

32.3 :focus — the one you must not remove

When a keyboard user presses Tab, focus moves from one interactive element to the next. The browser draws a ring round whatever has focus so the user can see where they are. That ring is the :focus style.

Many beginners find the ring ugly and write this:

/* NEVER do this on its own */
:focus { outline: none; }

The page now looks tidier and has become unusable for anyone who does not use a mouse. They press Tab and nothing visible changes; they are navigating blind. Keyboard users cannot otherwise see where they are. It is a genuine accessibility failure, and your syllabus explicitly names focus styles.

If the default ring does not suit your design, replace it:

input:focus {
  outline: 3px solid #FF9933;   /* your own, clearly visible ring */
  outline-offset: 2px;
  border-color: #E07B1E;
}

Live — click in the first box, then press Tab to move to the second

Tab between those two fields. The first tells you exactly where you are; on the second you are lost. That is the whole argument.

Modern CSS adds :focus-visible, which applies the ring only when the browser judges it useful — for keyboard users, but not for a mouse click. It gives you the tidy look without abandoning anybody:

button:focus-visible { outline: 3px solid #FF9933; outline-offset: 2px; }

Remember from Chapter 28 that outline takes no space, so a focus ring never shifts your layout.

32.4 Position: :first-child, :last-child and :nth-child()

These pick elements by their position among their siblings — no extra classes in the HTML needed.

SelectorSelects
li:first-childThe list item that is the first child of its parent
li:last-childThe last one
li:nth-child(3)The third one
li:nth-child(odd)The 1st, 3rd, 5th …
li:nth-child(even)The 2nd, 4th, 6th …
li:nth-child(2n)Every second one — the same as even
li:nth-child(2n+1)Every second one starting at the first — the same as odd
li:nth-child(3n)Every third one
li:only-childOnly when it is the sole child

Reading an nth-child formula

In an + b, the browser tries n = 0, 1, 2, 3 and so on, and keeps whichever positions come out:

  • 2n → 0, 2, 4, 6… (position 0 does not exist, so: 2nd, 4th, 6th)
  • 2n+1 → 1, 3, 5, 7…
  • 3n+2 → 2, 5, 8, 11…

:first-child versus :first-of-type. p:first-child means "a paragraph that is the first child of its parent" — if a heading comes first, it matches nothing. p:first-of-type means "the first paragraph among its siblings", whatever came before it. When a :first-child rule mysteriously fails, this is usually why.

32.5 Form states

Forms have their own states, and styling them gives instant feedback for free — no JavaScript involved.

Pseudo-classApplies when
:checkedA checkbox or radio is ticked
:disabled / :enabledThe control is greyed out / usable
:required / :optionalThe field carries the required attribute or not
:valid / :invalidThe value satisfies the field's rules or not (Chapter 18)
:placeholder-shownThe field is still empty, so its placeholder is visible
 
<style>
  body { font-family: system-ui, sans-serif; }
  label { display: block; margin: 10px 0 4px; font-weight: 700; font-size: 14px; }
  input { padding: 8px 10px; border: 2px solid #CBD5E1; border-radius: 8px;
          font-size: 14px; width: 240px; }
  input:focus   { outline: 3px solid #FF9933; outline-offset: 2px; }
  input:required { border-left: 5px solid #E07B1E; }
  input:valid    { border-color: #138808; }
  input:invalid:not(:placeholder-shown) { border-color: #C42B2B;
                                          background: #FDF0F0; }
</style>
<label for="e">Email (required)</label>
<input id="e" type="email" required placeholder="you@example.edu">
<p style="font-size:14px;color:#6B7A90">Type a few letters, then finish the address properly.</p>

Read that :invalid:not(:placeholder-shown) rule: "invalid, but not while it is still empty". Without the :not() part, an untouched required field is red before the user has typed a single character, which feels like being told off for nothing.

32.6 :not() and :root

:not(...) excludes things. It takes a selector and matches everything that does not match it:

button:not(.ghost)      { background: #0B2545; }   /* every button except .ghost */
li:not(:last-child)     { border-bottom: 1px solid #eee; }  /* a divider between, not after */

That second line is a lovely little trick: it draws a separator under every item except the last, so there is no stray line at the bottom of the list.

:root matches the root element — the <html> element. It behaves almost like writing html, but has slightly higher specificity, and it is the conventional home for CSS variables (Chapter 36).

:root {
  --brand: #E07B1E;
}

32.7 Specificity note

From Chapter 23: a pseudo-class counts in the class column. So a:hover scores (0, 1, 1) — one pseudo-class, one element.

That explains the most common hover bug. If nav a { color: white; } (0, 0, 2) is beaten by #menu a { color: navy; } (1, 0, 1), then your nav a:hover (0, 1, 2) still loses to the id rule, and nothing happens on hover. The fix is to raise your hover rule's specificity, not to reach for !important.

Exam-style checks

How many colons does a pseudo-CLASS use?L2

One, as in :hover and :focus. Two colons mark a pseudo-element such as ::before (Chapter 33). States get one colon; parts get two.

Which pseudo-class selects an element when the mouse is over it, and can it be used on elements other than links?L1

:hover, and yes — it works on any element, so cards, rows and images can all react.

Why must you keep a visible :focus style?L3
  • A. It looks better
  • B. Keyboard users cannot otherwise see where they are
  • C. It is required by CSS
  • D. It improves SEO

Answer: B. Removing outlines with nothing to replace them is a real accessibility failure — and your syllabus names focus styles explicitly. If the default ring is ugly, replace it with your own.

Which selects every second list item?L2
  • A. li:second
  • B. li:nth-child(2n)
  • C. li:even
  • D. li[2]

Answer: B. nth-child accepts odd, even or a formula such as 2n+1. There is no :even or :second.

In which order must the four link states be written?L2

:link, :visited, :hover, :active — remember LoVe HAte. They have equal specificity, so a later rule beats an earlier one; write :hover too early and it never shows.

p:first-child is not matching the first paragraph. Why might that be?L3

Because something else is the first child — a heading, for instance. p:first-child means "a p that is the first child of its parent". What you probably want is p:first-of-type, which means "the first p among its siblings".

Which pseudo-class styles a checkbox that is ticked?L1

:checked. Its relatives are :disabled, :required, :valid and :invalid.

Why write input:invalid:not(:placeholder-shown) instead of just input:invalid?L3

So the field is not marked as wrong before the user has typed anything. An empty required field is technically invalid from the moment the page loads; the :not(:placeholder-shown) part waits until there is something in it.

What does li:not(:last-child) select?L2

Every list item except the final one. It is the neat way to put a divider between items with no stray line under the last one.

Your nav a:hover rule does nothing. What should you check first?L3

Specificity. A pseudo-class counts as a class, so nav a:hover scores (0,1,2) and still loses to an id rule such as #menu a (1,0,1). Count the winning rule in DevTools and match it — do not reach for !important (Chapter 23).

Which pseudo-class matches the <html> element and is the usual home for CSS variables?L2

:root. Declaring custom properties there makes them available to every rule on the page (Chapter 36).

Quick revision

Key takeaways

  1. A pseudo-class uses one colon and styles an element in a state or a position: a:hover.
  2. Link states in order — LoVe HAte: :link, :visited, :hover, :active. :hover works on any element, and does not exist on touch screens.
  3. Never remove :focus without replacing it. Keyboard users need to see where they are. :focus-visible gives the tidy version.
  4. :first-child, :last-child, :nth-child(odd/even/2n+1) select by position. :first-of-type counts only elements of that type.
  5. Form states: :checked, :disabled, :required, :valid, :invalid, :placeholder-shown.
  6. :not() excludes; :root is the html element and holds variables. A pseudo-class counts as a class for specificity.

input:focusThe field with keyboard focus

tr:nth-child(even)Every second row — zebra striping

li:not(:last-child)Everything but the last
