CSS Transitions

Every state change you have written so far happens instantly: the button is dark, then in the same frame it is orange. A transition tells the browser to take the journey slowly instead. One property, one duration, and a page stops feeling like a slide show.

About 21 minutes · Course outcome CO3

Before you start — one-line reminders

  • :hover and :focus style an element in a state (Chapter 32).
  • Both a normal rule and a :hover rule can set the same property (Chapter 23).
  • box-shadow and border-radius are box properties (Chapter 28).

38.1 Instant, and smooth

Hover the two buttons below. They have identical colours; only the second has a transition.

Live — hover each one

No transition
With a transition

The first snaps. The second glides. The difference is one declaration:

.btn        { background: #0B2545; transition: background-color 0.35s ease; }
.btn:hover  { background: #E07B1E; }

A transition tells the browser: "when this property changes, do not jump to the new value — travel there over this much time." You still write only the start state and the end state. The browser invents every frame in between.

Picture this. A light switch is instant: dark, then bright. A dimmer takes a second to get there. Same two states, completely different feeling. transition is the dimmer.

38.2 The four parts

transition: background-color 0.35s ease 0s;
/*          |                |     |    |
            |                |     |    delay: wait this long first (optional)
            |                |     timing function: the speed curve
            |                duration: how long it takes  (REQUIRED)
            property: which one to animate                             */
PartValuesNotes
transition-propertybackground-color, transform, opacity, allName the property. all is tempting and usually a mistake.
transition-duration0.3s, 200msRequired. With no duration nothing happens, because the default is 0.
transition-timing-functionease, linear, ease-in, ease-out, ease-in-outThe speed curve. Default is ease.
transition-delay0s, 0.2sWait before starting. Rarely needed.

You can transition several properties by separating them with commas:

transition: transform 0.25s ease, box-shadow 0.25s ease;
Why not transition: all? It animates every property that changes, including ones you did not intend, and the browser has to watch them all. It is a common cause of sluggish pages and of odd little movements nobody asked for. Name the properties you mean.

  • linear — the same speed all the way. Machine-like; right for a loading bar, wrong for a button.
  • ease — starts briskly, slows at the end. The default, and a good default.
  • ease-in — starts slowly. Good for something leaving.
  • ease-out — ends slowly. Good for something arriving; the most natural feel for hovers.
  • ease-in-out — gentle at both ends. Good for longer movements.

How long?

DurationFeels
Under 100msInstant — you have wasted the effect
150–300msRight for hovers, buttons and small moves
300–500msRight for panels and larger movements
Over 600msThe interface starts to feel slow and unresponsive

38.3 Which rule does the transition go in?

This is the exam question, and it has one right answer: put transition on the normal state rule, not on the :hover rule.

Here is why. The transition property is read from whichever rule currently applies.

  • On the normal rule: it applies while the mouse arrives and while it leaves. The effect eases in and eases out. Correct.
  • On the :hover rule only: it exists while hovering, so the effect eases in — but the moment the mouse leaves, the hover rule no longer applies, the transition vanishes with it, and the element snaps back. Half-broken, and a very recognisable glitch.
<style>
  body { font-family: system-ui, sans-serif; display: flex; gap: 16px; padding: 18px; }
  div { background: #0B2545; color: #fff; padding: 14px 20px;
        border-radius: 10px; font-weight: 700; }

  /* correct: on the normal rule */
  .good { transition: background-color .4s ease; }
  .good:hover { background: #138808; }

  /* wrong: only while hovered */
  .bad:hover { transition: background-color .4s ease; background: #C42B2B; }
</style>

38.4 transform: move, scale and rotate

transform changes an element's shape or position without disturbing the layout around it. Nothing else moves to make room, which is exactly what you want for a hover effect.

FunctionDoesExample
translateY(-6px)Moves it up 6 pixelsA card lifting on hover
translateX(10px)Moves it rightAn arrow nudging forward
scale(1.1)Makes it 10% bigger, from the centreA button or image growing
rotate(8deg)Turns it clockwiseA badge, an icon
translateY(-6px) scale(1.02)Several at once, space-separatedLift and grow together

scale(1.12)

Why transform and not margin-top or width? Two reasons. First, changing a margin or a width makes the browser re-calculate the position of everything else on the page, so neighbours jump about. Second, transform and opacity are the two properties browsers can animate on the graphics card, so they stay smooth even on a cheap phone. Animating width, height, top or margin is visibly jerkier.

For anything that moves, reach for transform. For anything that fades, reach for opacity. Those two cover most effects and are the two that stay smooth.

<style>
  body { font-family: system-ui, sans-serif; background: #F1F5F9; padding: 20px; }
  .card {
    background: #fff; border-radius: 12px; padding: 18px;
    box-shadow: 0 2px 6px rgba(16,32,64,.10);
    transition: transform .25s ease, box-shadow .25s ease;   /* normal rule */
  }
  .card:hover {
    transform: translateY(-6px);
    box-shadow: 0 14px 28px rgba(16,32,64,.18);
  }
  .card h3 { margin: 0 0 4px; color: #0B2545; }
  .card p  { margin: 0; color: #6B7A90; font-size: 14px; }
</style>

38.5 What cannot be transitioned

A property can only be transitioned if the browser can calculate the values in between. Colours, lengths, opacity and transforms all work.

display does not. There is no halfway between none and block, so a fade-in written with display simply pops. The usual pattern is to animate opacity and transform instead, and keep the element in the layout:

.panel        { opacity: 0; transform: translateY(-8px);
                transition: opacity .25s ease, transform .25s ease; }
.panel.is-open{ opacity: 1; transform: translateY(0); }

Other things that cannot be transitioned: font-family, position, and any value that is a keyword with nothing in between.

38.6 Motion and the reader

Movement on screen makes some people genuinely unwell — vestibular disorders, migraine, motion sensitivity. Those readers can ask their operating system to reduce motion, and CSS can hear that request:

@media (prefers-reduced-motion: reduce) {
  * {
    transition-duration: 0.01ms !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
  }
}

Paste that at the end of your stylesheet. For almost every reader nothing changes; for the ones who asked, the motion stops and your interface still works, because a transition is decoration on top of a state change that happens anyway.

Three rules for tasteful motion. Keep it short (150–300ms). Keep it small (a few pixels, a few per cent). Make it respond to the user — a hover, a click, a panel opening. Motion that happens on its own, repeatedly, is a distraction, and Chapter 39 has more to say about that.

38.7 Build it: the project's interactive polish

<style>
  * { box-sizing: border-box; }
  :root { --brand: #E07B1E; --ink: #0B2545; }
  body { font-family: system-ui, sans-serif; background: #F1F5F9;
         padding: 20px; color: #3C4A60; }

  .card {
    background: #fff; border-radius: 12px; padding: 16px 18px;
    margin-bottom: 14px; border-left: 5px solid #E3E9F0;
    box-shadow: 0 2px 6px rgba(16,32,64,.08);
    transition: transform .22s ease, box-shadow .22s ease,
                border-left-color .22s ease;
  }
  .card:hover {
    transform: translateY(-4px);
    box-shadow: 0 12px 24px rgba(16,32,64,.16);
    border-left-color: var(--brand);
  }

  .btn {
    display: inline-block; text-decoration: none; font-weight: 700;
    background: var(--ink); color: #fff; padding: 11px 22px;
    border-radius: 999px;
    transition: background-color .2s ease, transform .12s ease;
  }
  .btn:hover  { background: var(--brand); }
  .btn:active { transform: scale(0.96); }        /* presses in */
  .btn:focus-visible { outline: 3px solid #FF9933; outline-offset: 3px; }

  a.arrow { color: #1D4ED8; text-decoration: none; }
  a.arrow::after { content: " \2192"; display: inline-block;
                   transition: transform .2s ease; }
  a.arrow:hover::after { transform: translateX(5px); }

  @media (prefers-reduced-motion: reduce) {
    * { transition-duration: 0.01ms !important; }
  }
</style>

Four transitions, none longer than a quarter of a second, every one triggered by the user. Hover the arrow links: the arrow slides because the transition is on the ::after pseudo-element, which can be styled and animated exactly like any other box.

Exam-style checks

Where should the transition property be written?L3
  • A. On the :hover rule
  • B. On the normal state rule
  • C. On both
  • D. Inside @keyframes

Answer: B. On :hover only, the effect eases in and snaps back out, because the transition disappears with the hover rule.

Which part of a transition is compulsory?L2

The duration. It defaults to 0s, so a transition with no duration does nothing at all. The property, timing function and delay all have usable defaults.

What does transition: transform 0.25s ease; mean, word by word?L2

"When transform changes, take 0.25 seconds to get there, starting briskly and slowing at the end." Property, duration, timing function.

Why prefer transform: translateY(-6px) over margin-top: -6px for a hover lift?L3

Because transform does not affect the layout, so neighbouring elements do not shift; and because browsers can animate transform and opacity on the graphics card, so the movement stays smooth on a cheap phone. Animating margins, widths or top forces a re-layout every frame.

Which two properties are the smoothest to animate?L3

transform and opacity. Anything that moves should use transform; anything that fades should use opacity.

Why does a fade-in written with display not work?L3

Because there is no value halfway between none and block, so display cannot be transitioned. Animate opacity (and usually transform) instead, and toggle a class.

What is a sensible duration for a button hover?L2

About 150–300 milliseconds. Under 100ms is imperceptible; over 600ms makes the interface feel slow to respond.

Why avoid transition: all?L3

It animates every property that happens to change, including ones you never meant, and the browser has to watch them all. It causes both surprise movements and sluggishness. Name the properties, separated by commas.

Which media query respects a reader who has asked for less motion?L3

@media (prefers-reduced-motion: reduce). Inside it, cut transition and animation durations to almost nothing. Motion can cause real nausea and migraine for some readers.

Which timing function keeps a constant speed throughout?L2

linear. It suits a progress bar or a continuously spinning loader, but feels mechanical on a button, where ease or ease-out is more natural.

Quick revision

Key takeaways

  1. transition: property duration timing-function delay; — the duration is the only compulsory part.
  2. Write it on the normal state rule, so the effect eases both in and out.
  3. transform moves, scales and rotates without disturbing the layout. With opacity it is one of the two smoothest properties to animate.
  4. 150–300ms for hovers; ease or ease-out feels natural; avoid transition: all.
  5. display cannot be transitioned — fade with opacity instead.
  6. Honour prefers-reduced-motion. Motion should be short, small and a response to the user.
