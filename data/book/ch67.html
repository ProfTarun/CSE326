Drag and Drop API

Trello boards, “drop your file here” boxes, playlists you can re-order and matching games all let you pick something up with the mouse and put it down somewhere else. The browser has this built in. Seven events, one small bag of data and one line that says “yes, you may drop here” are all it takes. This chapter builds each piece in order, then closes Unit 5 by putting all four browser APIs side by side.

67.1 Grab it, move it, drop it

You have used drag and drop all your life: a file into the Recycle Bin, a photo into a WhatsApp Web chat, a card across a Trello board. On a web page the gesture is handled by the HTML Drag and Drop API: attributes, events and one helper object that every browser provides ready-made, so no library is needed. It lets a user pick up an element with the mouse, carry some data with it, and drop it onto a place that accepts it: task boards, “drag your assignment PDF here” boxes, re-orderable playlists and learning games.

Three roles in every drag

  • The source element — the thing being dragged. It must be draggable.
  • The dragged data — a short piece of text that travels with the drag inside event.dataTransfer. Usually it is the element's id.
  • The drop target — an element that agrees to accept the drop. Until it agrees, nothing can land on it.
Picture this. A railway parcel office. You never carry the heavy trunk from counter to counter; you carry a small slip with its number on it (setData). Every counter is closed unless the clerk holds up an “OPEN” board, and keeps holding it up for as long as you stand there (dragover, cancelled every time). You hand your slip to an open counter (drop); the clerk reads the number (getData) and has the real trunk wheeled onto their shelf (appendChild). Finally you tidy up your own things (dragend), whether or not any counter took your slip.

draggable="true"

Most elements cannot be picked up. Press on a paragraph and drag, and you select text instead. To make an element draggable, give it one attribute:

<!-- any element can be made draggable -->
<div id="box" draggable="true">Drag me</div>

<!-- links and images drag by default; you can switch that off -->
<img src="logo.png" alt="Logo" draggable="false">

Three kinds of thing are draggable without being asked: images (<img>), links (<a> with an href) and text you have selected. Everything else needs draggable="true". From JavaScript the same switch is a property: box.draggable = true;

Write the word true. draggable is not an on/off attribute like required or checked. It takes the words "true" or "false". A bare <div draggable> is read as “auto”, the browser's own default, and for a div that means not draggable. Always write draggable="true" in full.
Quick check: does an <img> need draggable="true" before you can drag it?

No. Images, links and selected text are draggable by default. You only write draggable="false" if you want to stop an image or link being dragged.

67.2 Seven events on two sides

Making something draggable only lets the user pick it up. Everything useful happens in events, and the browser fires seven of them during one drag. The way to remember them is to split them by where they fire: three on the item being dragged and four on the drop zone.

EventFires onWhen it happensTypical use
dragstartDragged elementThe user starts draggingsetData(), add a “dragging” style
dragDragged elementAgain and again while draggingRarely needed
dragenterDrop targetThe dragged item enters the targetHighlight the drop zone
dragoverDrop targetAgain and again while over the targetpreventDefault() to allow dropping
dragleaveDrop targetThe dragged item leaves the targetRemove the highlight
dropDrop targetThe item is released on a target that accepts itgetData(), move the element
dragendDragged elementThe drag finishes (dropped or cancelled)Clean up styles

Three things happen to the thing you carry: you pick it up (dragstart), you are carrying it (drag), you put it down or give up (dragend).

Four things happen to the place: something arrives (dragenter), it hovers (dragover), it goes away (dragleave), or it lands (drop).

A drag ends in one of two ways: the zone receives drop, or (if the user lets go somewhere that refuses, or presses Esc) it receives dragleave. Either way dragend comes last, on the source, which makes it the right place to tidy up the dragged item.

Do not take the order on trust. The example below only listens; it moves nothing. It prints each event, and just counts the repeating drag and dragover, which would otherwise flood the Console.

<style>
  body { font-family: system-ui, sans-serif; padding: 14px; color: #1E293B; }
  #card { width: 160px; padding: 12px; background: #FFF1E0; border: 2px solid #E07B1E;
          border-radius: 8px; cursor: grab; font-weight: 700; }
  #zone { margin-top: 18px; height: 110px; border: 3px dashed #94A3B8; border-radius: 10px;
          display: flex; align-items: center; justify-content: center; color: #64748B; }
</style>
<div id="card" draggable="true">Drag me slowly</div>
<div id="zone">Drop zone</div>
<script>
  const card = document.getElementById("card");
  const zone = document.getElementById("zone");
  let drags = 0;          // how many times "drag" fired
  let overs = 0;          // how many times "dragover" fired
  let dropped = false;

  // ---- three events on the DRAGGED card ----
  card.addEventListener("dragstart", (event) => {
    drags = 0;
    overs = 0;
    dropped = false;
    event.dataTransfer.setData("text/plain", card.id);
    console.log("1. dragstart on the card");
  });
  card.addEventListener("drag", () => {
    drags++;              // far too many to print one by one
  });
  card.addEventListener("dragend", () => {
    console.log("4. dragend on the card. Dropped?", dropped);
    console.log("drag fired", drags, "times, dragover fired", overs, "times");
  });

  // ---- four events on the DROP ZONE ----
  zone.addEventListener("dragenter", () => {
    console.log("2. dragenter on the zone");
  });
  zone.addEventListener("dragover", (event) => {
    event.preventDefault();   // "yes, you may drop here" (section 67.3)
    overs++;
  });
  zone.addEventListener("dragleave", () => {
    console.log("dragleave on the zone (you left without dropping)");
  });
  zone.addEventListener("drop", (event) => {
    event.preventDefault();
    dropped = true;
    console.log("3. drop on the zone. The bag holds:", event.dataTransfer.getData("text/plain"));
  });
</script>

A straight drag into the zone prints something like this (your two counts will differ; they depend on how long you hold and how much you move):

1. dragstart on the card
2. dragenter on the zone
3. drop on the zone. The bag holds: card
4. dragend on the card. Dropped? true
drag fired 52 times, dragover fired 23 times

Now try the other endings: drag in, back out, and let go outside; or drag in and press Esc. Both give dragleave and Dropped? false. And notice that a successful drop prints no dragleave; that matters in section 67.5.

Quick check: which of the seven events fire on the element being dragged?

dragstart, drag and dragend. The other four (dragenter, dragover, dragleave, drop) fire on the drop target.

67.3 The one line that allows a drop

Here is the rule that catches almost everyone the first time: by default, no element accepts a drop. Every event has a default action, and the default action of dragover is to answer “you cannot drop here”. The cursor usually shows a “not allowed” sign, and when the user lets go, drop never fires; the zone gets dragleave instead.

Calling event.preventDefault() inside dragover cancels that refusal. It is how an element says “drops are welcome here”:

zone.addEventListener("dragover", (event) => {
  event.preventDefault();      // "yes, you may drop here"
});

preventDefault() always means “stop the browser doing its usual thing”. On a link it stops the page changing; on a form it stops the submit (Chapter 57). In dragover, the usual thing is refusing the drop, so preventing it means accepting. You are cancelling the “no”.

Why in dragover, and not once at the start? Because dragover fires again and again while the item hovers, and the browser asks afresh each time; any event left uncancelled is a refusal at that moment. So the safe habit is: make event.preventDefault() the first line of the dragover handler. That is the clerk keeping the “OPEN” board up.

Two more preventDefault() calls you will see

  • In drop. Some browsers have their own default for a drop: Firefox, for example, may treat dropped text or a link as an address and navigate away from your page. Cancelling it keeps the user where they are.
  • In dragenter. The HTML standard's own example cancels this one too. The major browsers accept a drop with dragover alone, which is why the deck's code (and MDN's introductory example) cancels only dragover; adding dragenter does no harm.
Exam tip. “Why call event.preventDefault() in dragover?” has one answer: to allow the drop. The matching bug, “my drop handler never runs”, almost always means a dragover handler with no preventDefault(), or none at all.
Quick check: you forgot preventDefault() in the zone's dragover. The user lets go over the zone. Which event fires on the zone, and which never does?

The zone gets dragleave; drop never fires, so nothing moves. dragend still fires on the dragged item, because it fires however the drag ends.

67.4 dataTransfer: the bag that carries the id

When the drop finally happens, the zone has a question: what was dropped on me? The answer travels with the drag in event.dataTransfer, an object that every drag event carries. Think of it as a small bag. You put something in at dragstart, and you take it out at drop.

// at dragstart, on the item: put its id in the bag
item.addEventListener("dragstart", (event) => {
  event.dataTransfer.setData("text/plain", item.id);
});

// at drop, on the zone: take the id out and find the element
zone.addEventListener("drop", (event) => {
  event.preventDefault();
  const id = event.dataTransfer.getData("text/plain");   // for example "t2"
  const card = document.getElementById(id);
  zone.appendChild(card);
});

setData(format, value) takes two strings. The first, "text/plain", is the format: a label saying what kind of data is in the bag. getData(format) must use the same label to get it back. The value is always a string, which is why we carry the id and not the element itself.

You cannot put the box itself in the bag — only a short text, like a name tag. The drop handler reads the tag and goes and fetches the real box by its id.

Then appendChild(card) does the moving. Recall from Chapter 56 that appendChild with an element already on the page does not copy it: it takes it out of its old parent and puts it into the new one, because an element can only be in one place at a time. That is why a drag-and-drop “move” needs no deleting code at all. (One more reason always to call setData() in dragstart: older versions of Firefox will not start the drag without it.)

The bag is sealed until the drop

During dragenter, dragover and dragleave the bag is sealed: by the standard, and in Chrome and Edge, getData() there returns an empty string. The drag might have come from another website or program, and a page should not peek at it just because the pointer passed over. You may read the labels (event.dataTransfer.types, such as ["text/plain"]) but not the values.

So when you need to decide whether a drop is acceptable, either decide inside drop, where getData() works, or remember the dragged element in an ordinary variable at dragstart:

let dragged = null;                          // the card being carried
card.addEventListener("dragstart", () => { dragged = card; });

zone.addEventListener("dragover", (event) => {
  if (dragged && dragged.dataset.category === zone.dataset.accept) {
    event.preventDefault();                  // accept only the right kind
  }
});

The bag can carry files too

Drag a file from your desktop onto a page and the four drop-zone events fire as before (dragstart, drag and dragend do not, because the drag did not start on your page); this time dataTransfer.files holds the files, in a FileList. That is how every “drop your file here” box works. Nothing below is uploaded: the page only reads each file's name, size and type (sending it to a server would be a job for fetch(), Chapter 65).

<style>
  body { font-family: system-ui, sans-serif; padding: 14px; }
  #drop { border: 3px dashed #7c3aed; border-radius: 12px; padding: 34px 12px;
          text-align: center; color: #5b21b6; }
  #drop.over { background: #ede9fe; }
</style>
<div id="drop">Drag a file from your computer and drop it here</div>
<ul id="list"></ul>
<script>
  const drop = document.getElementById("drop");
  const list = document.getElementById("list");

  // a file that misses the box must not be opened by the browser
  window.addEventListener("dragover", (event) => event.preventDefault());
  window.addEventListener("drop", (event) => event.preventDefault());

  drop.addEventListener("dragover", (event) => {
    event.preventDefault();
    drop.classList.add("over");
  });
  drop.addEventListener("dragleave", () => drop.classList.remove("over"));
  drop.addEventListener("drop", (event) => {
    event.preventDefault();
    drop.classList.remove("over");
    const files = event.dataTransfer.files;          // a FileList
    console.log("Files dropped:", files.length);
    for (const file of files) {
      const kb = (file.size / 1024).toFixed(1);
      const li = document.createElement("li");
      li.textContent = `${file.name}: ${kb} KB, type "${file.type || "unknown"}"`;
      list.appendChild(li);
      console.log(file.name, kb, "KB");
    }
  });
</script>

The two lines on window are new. A browser normally opens a file dropped on a page that does not handle it, replacing the page; cancelling dragover and drop on the whole window stops a near-miss from doing that. (Some browsers will not hand files to a practice frame like this one; if nothing appears, Copy the code into a .html file and open that.)

67.5 Build it: drag a box

Now the deck's first complete example. The CSS prepares two looks in advance: .dragging fades the box while it is carried, and .over tints the zone while something hovers above it. The JavaScript only adds and removes those classes: CSS decides how it looks, JavaScript decides when.

<style>
  body { font-family: system-ui, sans-serif; padding: 14px; }
  #box { width: 100px; height: 100px; cursor: grab; background: #f97316; color: white;
         display: flex; align-items: center; justify-content: center; border-radius: 8px; }
  #box.dragging { opacity: 0.4; }
  #dropZone { width: 220px; height: 160px; margin-top: 20px; padding: 8px;
              border: 3px dashed #7c3aed; border-radius: 10px; box-sizing: border-box; }
  #dropZone.over { background: #ede9fe; }
</style>
<div id="box" draggable="true">Drag me</div>
<div id="dropZone">Drop here</div>
<p id="message"></p>
<script>
  const box = document.getElementById("box");
  const dropZone = document.getElementById("dropZone");

  box.addEventListener("dragstart", (event) => {
    event.dataTransfer.setData("text/plain", box.id);    // 1. put the id in the bag
    box.classList.add("dragging");                        //    and fade the box
  });

  box.addEventListener("dragend", () => {
    box.classList.remove("dragging");                     // 5. full colour again
  });

  dropZone.addEventListener("dragover", (event) => {
    event.preventDefault();                               // 2. allow the drop
    dropZone.classList.add("over");                       //    and highlight the zone
  });

  dropZone.addEventListener("dragleave", () => {
    dropZone.classList.remove("over");                    // 3. remove the highlight
  });

  dropZone.addEventListener("drop", (event) => {
    event.preventDefault();
    const id = event.dataTransfer.getData("text/plain");  // 4. take the id out,
    dropZone.appendChild(document.getElementById(id));    //    move the real box
    dropZone.classList.remove("over");
    document.getElementById("message").textContent = "Done!";
    console.log("Dropped:", id);
  });
</script>
StepEventWhat the code does
1dragstart on the boxSaves the box's id in the bag; fades the box (.dragging)
2dragover on the zonepreventDefault() allows dropping; highlights the zone
3dragleave on the zoneRemoves the highlight
4drop on the zoneReads the id, appendChild moves the box, shows “Done!”
5dragend on the boxRestores full opacity

Try it.

  1. Delete event.preventDefault(); in the dragover handler and Run again. Can you still drop? (No. The zone still lights up, because the class is added in the same handler, but letting go does nothing and “Done!” never appears.) Put the line back.
  2. Double-click the word here in the zone to select it, then drag the selected word into the zone. A red TypeError appears in the Console: the bag held "here", getElementById("here") returned null, and appendChild(null) failed. Section 67.6 adds the guard.

Why the highlight is added in dragover, and removed twice

The natural pair for a highlight is dragenter to add it and dragleave to remove it. The deck adds it in dragover instead, for a good reason: child elements. When the pointer moves from the zone onto something inside it (a heading, a card), the browser fires dragenter on the child and dragleave on the zone, so the highlight is removed although you never left. Because dragover keeps firing, adding the class there puts it straight back.

And the class is removed in two places because a successful drop does not fire dragleave (you saw this in the logger). Forget the line in drop and the zone stays purple after every drop.

Add the highlight in the event that keeps repeating (dragover), so it heals itself. Remove it both when the item leaves (dragleave) and when it lands (drop), because landing is not leaving. And tidy the dragged item in dragend, which comes last whatever happened.

67.6 The task board

A real board has many cards and several columns, but you do not write separate listeners for each one. querySelectorAll finds them all and forEach attaches the same listeners to every one (Chapter 56). Each card puts its own id in the bag; each column accepts drops. Here is the deck's board, as one page:

<style>
  body { font-family: system-ui, sans-serif; padding: 12px; }
  .board { display: flex; gap: 12px; }
  .column { flex: 1; min-height: 220px; padding: 8px; background: #f1f5f9; border-radius: 8px; }
  .column h3 { margin: 4px 0 8px; font-size: 15px; }
  .column.over { background: #ede9fe; }
  .task { background: white; padding: 8px; margin: 6px 0; border-radius: 6px; cursor: grab;
          box-shadow: 0 1px 3px rgba(0, 0, 0, .12); }
</style>
<div class="board">
  <div class="column" id="todo"><h3>To Do</h3>
    <div class="task" id="t1" draggable="true">Learn localStorage</div>
    <div class="task" id="t2" draggable="true">Practice fetch()</div>
  </div>
  <div class="column" id="progress"><h3>In Progress</h3>
    <div class="task" id="t3" draggable="true">Geolocation demo</div>
  </div>
  <div class="column" id="done"><h3>Completed</h3></div>
</div>
<script>
  const tasks = document.querySelectorAll(".task");
  const columns = document.querySelectorAll(".column");

  // every task puts its OWN id in the bag
  tasks.forEach((task) => {
    task.addEventListener("dragstart", (event) => {
      event.dataTransfer.setData("text/plain", task.id);
    });
  });

  // every column accepts drops
  columns.forEach((column) => {
    column.addEventListener("dragover", (event) => {
      event.preventDefault();
      column.classList.add("over");
    });
    column.addEventListener("dragleave", () => {
      column.classList.remove("over");
    });
    column.addEventListener("drop", (event) => {
      event.preventDefault();
      column.classList.remove("over");
      const id = event.dataTransfer.getData("text/plain");
      const card = document.getElementById(id);
      if (!card || !card.classList.contains("task")) return;   // not one of our cards
      column.appendChild(card);
      console.log(`Moved "${card.textContent}" to ${column.querySelector("h3").textContent}`);
    });
  });
</script>

Drag “Practice fetch()” into In Progress and the Console prints Moved "Practice fetch()" to In Progress. Three details in this code are worth slowing down for.

1. Each listener remembers its own card. Inside forEach, the arrow function for card t2 is created while task is t2, and it keeps that value. A function that remembers the variables around it like this is a closure. That is also why every card needs draggable="true" and a unique id: if two cards shared an id, getElementById would always find the first, and you would drag one card and watch the other move.

2. It says column, not event.target. Drop on top of another card and event.target is that card, the innermost element under the pointer (Chapter 57). event.target.appendChild(card) would put the dropped card inside the other card, and dropping a card on its own old position would throw an error, because an element cannot contain itself. column (or event.currentTarget, which the deck's syntax slide uses) is always the column whose listener is running.

3. The guard line. Someone may drag selected text, a link or an image onto the board. Then getElementById finds nothing (null), or something that is not a card (drag in the selected word todo and it finds the To Do column). The if (...) return; line leaves quietly: the deck's “check the data in drop”.

Key idea. Because the listeners are attached by querySelectorAll, adding a fourth column called “Review” means adding one div class="column" to the HTML. It works at once, with no new JavaScript.

67.7 Checking the drop: a sorting game

The deck's practice task: columns for Programming Languages and Web Browsers, and four items, JavaScript, Python, Chrome and Firefox. A right drop shows a green “Correct!” and the item moves in; a wrong drop shows a red “Try again” and the item stays put. The answers live in the HTML as data-* attributes (Chapter 56): each item says what it is (data-category="language"), each zone what it accepts (data-accept="language"), and the drop handler compares the two through dataset.

<style>
  body { font-family: system-ui, sans-serif; padding: 12px; }
  #tray { display: flex; gap: 8px; flex-wrap: wrap; min-height: 44px; padding: 8px;

  .item { background: #fff; border: 2px solid #94a3b8; border-radius: 6px;

<div id="tray">
  <div class="item" id="i1" draggable="true" data-category="language">JavaScript</div>
  <div class="item" id="i2" draggable="true" data-category="browser">Chrome</div>
  <div class="item" id="i3" draggable="true" data-category="language">Python</div>
  <div class="item" id="i4" draggable="true" data-category="browser">Firefox</div>
</div>
<div class="zones">
  <div class="zone" data-accept="language"><h3>Programming Languages</h3></div>
  <div class="zone" data-accept="browser"><h3>Web Browsers</h3></div>

<script>
  const msg = document.getElementById("msg");
  const label = { language: "a programming language", browser: "a web browser" };
  let placed = 0;
  let wrong = 0;

  document.querySelectorAll(".item").forEach((item) => {
    item.addEventListener("dragstart", (event) => {
      event.dataTransfer.setData("text/plain", item.id);
    });
  });

  document.querySelectorAll(".zone").forEach((zone) => {
    zone.addEventListener("dragover", (event) => {
      event.preventDefault();               // accept every drop, judge it in "drop"
      zone.classList.add("over");
    });
    zone.addEventListener("dragleave", () => zone.classList.remove("over"));
    zone.addEventListener("drop", (event) => {
      event.preventDefault();
      zone.classList.remove("over");
      const item = document.getElementById(event.dataTransfer.getData("text/plain"));
      if (!item || !item.classList.contains("item")) return;
      if (item.classList.contains("correct")) return;        // already sorted

      const name = item.textContent;
      const kind = label[item.dataset.category];
      if (item.dataset.category === zone.dataset.accept) {
        zone.appendChild(item);
        item.classList.add("correct");
        item.draggable = false;                              // sorted: lock it
        placed++;
        msg.className = "good";
        msg.textContent = `Correct! ${name} is ${kind}.`;
      } else {
        wrong++;
        msg.className = "bad";
        msg.textContent = `Try again: ${name} is ${kind}.`;  // the item stays put
      }
      console.log(name, "->", zone.dataset.accept, "| placed:", placed, "| wrong tries:", wrong);
      if (placed === 4) {
        msg.textContent += ` All four sorted, with ${wrong} wrong ${wrong === 1 ? "try" : "tries"}.`;
      }
    });
  });
</script>

Make your first move a wrong one: drop Chrome on Programming Languages and the Console prints Chrome -> language | placed: 0 | wrong tries: 1 while the message turns red; drop it on Web Browsers and it moves in, turns green and is locked with item.draggable = false. The message paragraph has role="status", so a screen reader announces each new message (Chapter 59).

Quick check: how could a keyboard-only student play this sorting game?

67.8 Limitations and accessibility

HTML drag and drop was designed for a mouse. That leaves three groups of people stranded:

  • Touch-screen users. On phones and tablets support is limited and behaves differently: some mobile browsers ignore draggable, others need a long press. Test on a real phone.
  • Keyboard-only users. No key starts an HTML drag, so someone who cannot use a mouse (a broken wrist, a motor disability) cannot drag at all.
  • Screen-reader users. A screen reader has no way to perform a drag gesture.
Key idea. The deck's rule: every drag action should also work by click or keyboard. Offer buttons or a menu that perform the same move.

The deck's two other points you have already practised: visual feedback (fade the item, highlight valid zones) and prevent invalid drops (check the data in drop).

One function, two doors

The clean way to keep the rule is to write the move once, as a function, and call it from two places: the drop handler for mouse users, and a button for everyone else.

  const columns = Array.from(document.querySelectorAll(".column"));

  // ONE function does the move, whoever asks for it
  function moveTask(card, column) {
    column.appendChild(card);

    const now = columns.indexOf(card.closest(".column"));
    const next = columns[now + direction];
    if (next) {
      moveTask(card, next);
    } else {
      live.textContent = "That card is already at the end of the board.";
    }

Click inside the preview, press Tab until a card's → button is outlined, and press Enter. The card moves, the line under the board says what happened, and the Console prints, for example, moveTask: Learn localStorage -> In Progress. Three details from Chapter 59 make this genuinely usable:

  • Real <button> elements, so Tab, Enter, Space and screen readers work for free. Each gets an aria-label such as “Move Practice fetch() right”, because an arrow alone means nothing read aloud.
  • Focus goes back. appendChild lifts the card out of the page for an instant, so the pressed button loses focus and the keyboard user is thrown back to the top. left.focus() puts focus back on the same button in the card's new home (the deck's task.focus() does the same job, but a plain div card accepts focus only if it has a tabindex attribute, such as tabindex="-1", Chapter 15; a button needs nothing extra).
  • The announcement. Screen readers read out the aria-live="polite" paragraph whenever its text changes: “Practice fetch() moved to In Progress.”

Drag and drop is a shortcut for mouse users, never the only way. Build the button way first; the drag is the extra. Because both doors call the same moveTask(), they can never disagree about what a move does.

67.10 Common misunderstandings

✗ "<div draggable> makes it draggable."
The attribute takes the words true or false; a bare draggable means “auto”, and a div stays put.
✓ "Write draggable="true" in full."
Images, links and selected text are the only things draggable without it.
✗ "preventDefault() in dragover stops the drag."
The drag carries on exactly as before.
✓ "preventDefault() in dragover allows the drop."
It cancels the browser's default refusal. Without it, drop never fires.
✗ "dataTransfer carries the element to the zone."
It can only carry strings (and, from the computer, files).
✓ "dataTransfer carries the id; the drop handler finds the element."
getElementById(getData("text/plain")), then appendChild.
✗ "event.target is the column I dropped on."
It is the innermost element under the pointer, often another card or the heading.
✓ "Use the column variable, or event.currentTarget."
That is always the element whose listener is running.
✗ "dragleave will clear my highlight after a drop."
A successful drop fires drop, not dragleave.
✓ "Remove the highlight in dragleave AND drop; tidy the item in dragend."
dragend fires last, whether the drop worked or not.
✗ "Everyone can drag, so the board needs no buttons."
Many phones, every keyboard-only user and every screen-reader user cannot.
✓ "Every drag action also works by click or keyboard."
One moveTask(), two doors: the drop event and a real button.

Quick revision

Key takeaways

  1. draggable="true" makes any element draggable; images, links and selected text drag by default.
  2. Seven events: dragstart, drag, dragend on the item; dragenter, dragover, dragleave, drop on the zone. dragend always comes last.
  3. No element accepts a drop by default. dragover must call event.preventDefault(), or drop never fires. Call it in drop too.
  4. dataTransfer carries strings: setData("text/plain", id) at dragstart, getData("text/plain") at drop. It is sealed in between.
  5. appendChild moves an element that is already on the page. Append to the column (or event.currentTarget), not event.target, and guard against null.
  6. Feedback with CSS classes: fade the item at dragstart and restore it at dragend; highlight the zone in dragover and remove it in dragleave and drop.
  7. Drag and drop is mouse-first. Every drag needs a button alternative calling the same function, with focus put back and the change announced.
  8. Storage REMEMBERS (sync), Fetch TALKS (Promise), Geolocation LOCATES (callbacks, permission, HTTPS), Drag and Drop MOVES (event-driven).

event.dataTransfer.getData("text/plain")In drop: read the id back

event.preventDefault() in dropStops the browser's own handling, such as opening a link
zone.appendChild(el)Moves the element into the zone
