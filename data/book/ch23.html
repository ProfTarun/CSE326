CSS Selectors and Specificity

A rule can only style what it can point at. This chapter teaches you every way of pointing — by tag, by class, by id, by group, by what is inside what — and then answers the question that follows every beginner around: two rules want to style the same thing, so which one wins?

About 34 minutes · Course outcome CO3 · Builds on Chapter 22

Before you start — one-line reminders

  • A CSS rule is selector { property: value; } (Chapter 22).
  • class is an attribute you can reuse on many elements; id is an attribute that must be unique on the page (Chapter 5).
  • Elements sit inside other elements, forming a tree: the outer one is the parent, the inner ones its children (Chapter 3).

By the end of this chapter you can

  • Write element, class, id, universal and grouping selectors without hesitating.
  • Say exactly what the space in article p means, and how > differs from it.
  • Explain the difference between .card .wide and .card.wide.
  • Score two selectors and say which one wins, and why.
  • Fix a rule that "is not working" without reaching for !important.

23.1 A selector is a way of pointing

Imagine a classroom. A teacher can call on people in several ways: "all the students", "everyone in the back row", "everyone wearing a badge", "Asha". Each of those is a different way of pointing at the same crowd, and each reaches a different number of people.

CSS selectors work exactly like that. Before the browser can apply your declarations it has to know who they are for, and the selector is how you say it.

Picture this. The tag name is "all the students". A class is "everyone wearing a badge" — many people can wear one. An id is "Asha" — one person, no one else. Keep that picture; the whole chapter hangs on it.

23.2 The five selectors you will use every day

Element selector — p

Selects all HTML elements of that tag. No symbol in front: just the tag name as it appears in the HTML, without angle brackets.

<style>
  p { color: #1D4ED8; }
</style>
<h1>This heading is untouched</h1>
<p>Every paragraph turns blue.</p>
<p>This one too, automatically.</p>

Class selector — .card

Selects every element whose class attribute contains that name. You write a full stop in the CSS; you do not write the full stop in the HTML.

<style>
  .card {
    background: #FFF7ED;
    border: 1px solid #F0C79A;
    border-radius: 10px;
    padding: 12px;
    margin-bottom: 10px;
  }
</style>
<div class="card">Student Profile</div>
<div class="card">Course: Web Development</div>
<p>No class, so no box.</p>
The number one beginner slip. class="card" in the HTML, .card in the CSS. Writing .card in the HTML, or card in the CSS, silently does nothing. The same trap applies to ids: id="login" in the HTML, #login in the CSS.

Id selector — #login

Selects the single unique element whose id matches. Because an id must appear only once on a page (Chapter 5), an id selector should match exactly one element.

<style>
  #login { color: white; background: #138808; padding: 8px 14px;
           border-radius: 6px; display: inline-block; }
</style>
<p id="login">Log in</p>
<p>This paragraph is unaffected.</p>

Ids are also used for links that jump inside a page and for joining a <label> to an input (Chapter 16), so a page usually has a few. For styling, prefer classes — section 23.6 explains why.

Universal selector — *

One star selects every single element on the page. Its honest, everyday use is a reset at the top of a stylesheet:

* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;   /* explained in Chapter 28 */
}

That wipes the browser's default spacing so you start from a clean sheet. Beyond resets, use it sparingly: a rule that touches everything is hard to reason about.

Grouping selector — h1, h2, h3

A comma means "and also". Groups several selectors so the same declarations apply to each of them. It saves repeating yourself.

<style>
  h1, h2, p {
    font-family: Georgia, serif;
    color: #0B2545;
  }
</style>
<h1>Hello World!</h1>
<h2>Smaller heading</h2>
<p>This is a paragraph.</p>
One bad comma spoils the group. If one selector in a comma list is invalid, some browsers throw away the whole rule, not just that one part. If a grouped rule mysteriously does nothing, check every name in the list.
Quick check: which selector targets class="card", and which targets id="header"?

.card for the class (a full stop) and #header for the id (a hash). Writing card selects a <card> tag that does not exist; *card and .header are not valid ways to reach them.

23.3 Selecting by position: inside, and directly inside

Often you want "the paragraphs inside the article, but not the ones in the footer". For that you combine two selectors, and the character between them decides the relationship.

The descendant combinator — a space

article p means any paragraph somewhere inside an article — a child, a grandchild, any depth at all. A single space is doing all that work, which is why it is so easy to miss.

The child combinator — >

article > p means only direct children: one level down, no deeper.

<style>
  article p   { color: #C42B2B; }            /* any p inside   */
  article > p { background: #FFF1E0; }       /* direct children only */
</style>
<article>
  <p>Direct child: red text AND a cream background.</p>
  <div>
    <p>Grandchild: red text, but no background.</p>
  </div>
</article>
<p>Outside the article: neither rule touches me.</p>

The space that changes everything

This next pair looks almost identical and means two completely different things. Read it twice.

SelectorMeansMatches
.card .wide
(with a space)		An element with class wide that is inside an element with class card<div class="card"><p class="wide">
.card.wide
(no space)		One element that has both classes at once<div class="card wide">
 
<style>
  .card .wide { color: #C42B2B; }    /* a .wide inside a .card  */
  .card.wide  { background: #E9F7E7; } /* one element, both classes */
</style>
<div class="card">
  <p class="wide">I am inside a card, so I am red.</p>
</div>
<div class="card wide">I have both classes, so I am green.</div>

Two more combinators exist and are worth recognising: h2 + p selects the paragraph immediately after an h2 (its next sibling), and h2 ~ p selects all following paragraph siblings. You will meet them occasionally; the space and the > are the two you need daily.

Quick check: what does nav ul li a select?

Every link (a) that is inside a list item, that is inside an unordered list, that is inside a nav. Each space means "somewhere inside". Long chains like this work, but two levels is usually enough — the longer the chain, the more fragile the rule.

23.4 The problem: two rules, one element

You write a stylesheet. Somewhere near the top you say paragraphs are grey. Further down you say paragraphs inside a card are navy. Now a paragraph inside a card is being told two different things. Only one colour can be painted.

The browser settles this with three tests, applied strictly in this order.

Strongest first: a rule shouting !important, then the more specific rule, and only if those tie does the rule you wrote later win.

23.5 Specificity, scored properly

"More specific" is not a feeling. It is a number — in fact three numbers, counted for every selector.

Count three things in the selector:

  1. Ids — how many #something parts.
  2. Classes — how many .something parts, plus attribute selectors like [type="text"] and pseudo-classes like :hover.
  3. Elements — how many plain tag names, plus pseudo-elements like ::before.

Now compare the two selectors column by column, left to right, and stop at the first difference. Higher wins. The universal selector * and the combinators (a space, >, +, ~) score nothing at all.

Why left to right, and not a total? Because the columns are not worth the same. Think of them as a leaderboard: gold medals first, then silver, then bronze. A country with one gold beats a country with nine silvers. In the same way #box p (1, 0, 1) beats .card .inner .text p (0, 3, 1), no matter how long the second selector looks.

Worked example

<style>
  p              { color: grey; }    /* 0,0,1 */
  article p      { color: teal; }    /* 0,0,2 */
  .note          { color: orange; }  /* 0,1,0  <-- beats both above */
  #special       { color: crimson; } /* 1,0,0  <-- beats everything here */
</style>
<article>
  <p>Plain paragraph inside an article.</p>
  <p class="note">One class beats any number of tags.</p>
  <p class="note" id="special">One id beats any number of classes.</p>
</article>

And the tie-breaker, for when two selectors score identically:

<style>
  .btn { background: #C42B2B; }   /* 0,1,0 */
  .btn { background: #138808; }   /* 0,1,0 - identical score, written later */
</style>
<p class="btn" style="color:#fff;padding:10px;display:inline-block;border-radius:6px">Which colour?</p>

This is why the order of rules in your stylesheet matters, and why a stylesheet is usually written general first, specific afterwards.

Quick check: score nav a:hover and #menu a. Which wins?

nav a:hover = 0 ids, 1 class-level thing (:hover), 2 elements → 0,1,2. #menu a = 1,0,1. Compare the first column: 1 beats 0, so #menu a wins — and your hover effect will appear not to work. The fix is to raise the hover rule's specificity (#menu a:hover), not to add !important.

23.6 Inheritance, and the !important trap

Inheritance fills the gaps

Some properties pass automatically from a parent to everything inside it. These are the ones about text: color, font-family, font-size, line-height, text-align. Setting them once high up saves dozens of rules.

Properties about boxes do not inherit: border, padding, margin, width, background. If they did, a border on body would draw a border round every element on the page.

<style>
  .outer {
    color: #6D28D9;           /* inherited by everything inside */
    border: 2px solid #6D28D9; /* NOT inherited */
    padding: 12px;
  }
</style>
<div class="outer">
  <p>Purple text, inherited. No border of my own.</p>
  <p>Same here.</p>
</div>

A rule that targets an element always beats an inherited value, however weak the rule looks. Inheritance is the fallback used when nobody said anything.

!important: the button you should not press

Adding !important to a declaration lifts it above the whole specificity contest:

p { color: red !important; }

It works, and it is a trap. The next time something needs to override that rule, the only way is another !important, and then a more specific !important, and within a month nobody can predict what any rule will do. It is an arms race that ends with an unmaintainable stylesheet.

When a rule "is not working", do this instead. Open DevTools (F12), click the element, and read the Styles panel: it lists every rule that matched, in winning order, with the losing declarations crossed out. Count the specificity of the rule that is beating yours, then match or exceed it — usually by adding one class. Reach for !important only when you cannot edit the CSS that is winning, such as a third-party library.

23.7 How to choose a selector in practice

  • Reach for a class first. Classes are reusable, easy to override and easy to read. Almost all professional CSS is class-based.
  • Use element selectors for the base look — body, h1, p, a — and then refine with classes.
  • Avoid styling by id. An id is unique, so the style can never be reused, and its specificity is so high that overriding it later is painful.
  • Keep chains short. .card .header .title span works, but it breaks the moment anyone moves the markup. .card-title does not.
  • Never add !important just to win an argument with yourself.

Build it: the profile card gets classes

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Asha Kumar | Student Profile</title>
  <style>
    * { box-sizing: border-box; }            /* universal: a reset */
    body { font-family: system-ui, sans-serif; color: #3C4A60;
           line-height: 1.7; padding: 22px; background: #FBFCFE; }

    h1, h2 { color: #0B2545; }               /* grouping */

    .card {                                   /* class: reused three times */
      background: #fff; border: 1px solid #E3E9F0;
      border-radius: 12px; padding: 14px 18px; margin-bottom: 12px;
    }
    .card h3 { margin: 0 0 4px; color: #B45309; }   /* descendant */
    .featured { border-color: #E07B1E; background: #FFF8F0; }
    #intro { font-size: 18px; }               /* id: the one intro line */
  </style>
</head>
<body>
  <h1>Asha Kumar</h1>
  <p id="intro">B.Tech Computer Science, first year.</p>

  <h2>Courses</h2>
  <div class="card featured">
    <h3>CSE326 Internet Programming</h3>
    <p>Featured course — in progress.</p>
  </div>
  <div class="card">
    <h3>CSE305 Database Systems</h3>
    <p>Completed.</p>
  </div>
</body>
</html>

Every selector type from this chapter appears there. Notice how .featured is written after .card: same specificity, later wins, so the featured card gets the orange border.

Exam-style checks

Which selector targets class="card"?L1
  • A. card
  • B. .card
  • C. #card
  • D. *card

Answer: B. A dot for a class, a hash for an id.

Which selector targets id="header"?L1
  • A. .header
  • B. #header
  • C. header
  • D. *header

Answer: B. Ids use #, and must be unique on the page. header with no symbol would select the <header> element instead.

Which selector selects every single element on the page?L1

Answer: the universal selector *, most often used for a reset such as * { box-sizing: border-box; }.

What does article p (with a space) select?L2
  • A. Articles and paragraphs
  • B. Any paragraph inside an article
  • C. Paragraphs that are direct children only
  • D. An element with both names

Answer: B. The space is the descendant combinator, meaning "somewhere inside", at any depth. A comma would mean "articles and paragraphs".

Which selects only DIRECT children?L2
  • A. article p
  • B. article > p
  • C. article + p
  • D. article ~ p

Answer: B. > is the child combinator, one level down only. + is the next sibling and ~ all following siblings.

What is the difference between .card .wide and .card.wide?L3
  • A. None
  • B. With a space: a .wide inside a .card. Without: one element with both classes
  • C. Without a space is invalid
  • D. With a space is invalid

Answer: B. That single space changes the meaning completely. Both forms are valid CSS, which is what makes the mistake hard to spot.

Which has the HIGHEST specificity: p, .intro, #intro, article p?L2

Answer: #intro (1,0,0). One id outranks any number of classes or elements, because the columns are compared left to right.

Which wins: #box p or .card .inner .text p?L3
  • A. #box p
  • B. .card .inner .text p
  • C. The one written last
  • D. They tie

Answer: A. #box p scores (1,0,1); the other scores (0,3,1). Compare left to right: one id beats any number of classes, however long the other selector looks.

When does source ORDER decide which rule wins?L2
  • A. Always
  • B. Only when specificity ties
  • C. Never
  • D. Only for classes

Answer: B. A more specific rule written earlier still beats a less specific rule written later.

Your CSS rule is being ignored. What should you do FIRST?L3
  • A. Add !important
  • B. Count the specificity of the rule beating it
  • C. Move it to the top
  • D. Use inline styles

Answer: B. !important starts an arms race that makes the stylesheet unmaintainable. Moving the rule to the top makes it lose more often, not less.

Which property is INHERITED by child elements?L2
  • A. border
  • B. padding
  • C. color
  • D. margin

Answer: C. color, font-family and line-height inherit; box properties do not.

What does the grouping selector h1, h2, p { ... } do?L1

Answer: it applies the same set of declarations to all three, saving you from writing them three times. A comma means "and also".

Quick revision

Key takeaways

  1. Selector symbols: nothing = tag, . = class, # = id, * = everything, , = "and also".
  2. A space means "somewhere inside"; > means "direct child only". .card .wide is a .wide inside a .card; .card.wide is one element with both classes.
  3. Conflicts are settled by !important, then specificity, then source order.
  4. Specificity = (ids, classes, elements), compared left to right. One id beats any number of classes.
  5. Text properties inherit; box properties do not. A direct rule always beats an inherited value.
  6. When a rule loses, count specificity in DevTools and add a class. Do not reach for !important.
