Regular Expressions

"Ten digits, starting with 6, 7, 8 or 9." "Six digits, never starting with 0." "Three capital letters, then three digits." You can say these rules in one breath, and with a regular expression you can hand the same rule to JavaScript in one short line. This chapter teaches the small set of symbols that make up those lines, how to read a pattern left to right like a sentence, and the four methods that use one to check, find and change text.

61.1 A pattern instead of exact text

Chapter 45 taught you to search for exact text: "CSE326".includes("326") is true. But a mobile number box must accept any ten digits, and you cannot list ten thousand million phone numbers. What you can do is describe their shape: "ten digits, nothing else".

A regular expression (regex for short; JavaScript calls the object RegExp) is exactly that: a pattern, written in a small language of symbols, that describes a kind of text. JavaScript can then tell you whether a string fits, find the parts that fit, or change them. The lecture's first example is the rule for a phone number:

const pattern = /^\d{10}$/;
console.log(pattern.test("9876543210"));   // true
console.log(pattern.test("98765"));        // false

The method test() belongs to the pattern. You give it a string and it answers with a Boolean: true if the string fits the pattern, false if it does not. That single yes-or-no answer is what a validation script needs, which is why Chapter 60 kept writing if (!pattern.test(value)).

Picture this. An India Post form has a row of six small boxes for the PIN code, one digit per box. The row of boxes is a pattern: it does not say which PIN you live at, only what any PIN must look like. The clerk checks the shape at a glance: a box left empty, a letter in a box, or a seventh digit squeezed in after the last box, and the form comes back. A regular expression is the same row of boxes written in symbols, and ^ and $ are the two hard edges at the ends of the row, so nothing can be written before the first box or after the last.

61.2 Writing a pattern: slashes, flags and new RegExp

There are two ways to make a regular expression. The usual one is a literal: the pattern written straight into your code between two forward slashes, like /^\d{10}$/. It is not a string, so it has no quotes. Just as [1, 2, 3] makes an array and { } makes an object, the slashes make a RegExp object (typeof /a/ is "object").

After the closing slash you may add one or more flags. Two matter in this course:

FlagStands forEffectExample
gglobalFind every match, not just the first (used with match, matchAll and replace)/\d+/g
iignore caseCapital and small letters count as the same/java/i finds Java, java and JAVA
gibothEvery match, any case/java/gi

The second way builds the pattern from a string, at the moment the code runs:

const a = /^\d{10}$/;                 // a literal: written between slashes
const b = new RegExp("^\\d{10}$");    // the same pattern, built from a string
console.log(a, b);                    // /^\d{10}$/ /^\d{10}$/
console.log(b.test("9876543210"));    // true

The longer form lets the pattern come from a variable, such as a search box; the flags go in a second string:

const word = "java";                        // imagine this came from a search box
const finder = new RegExp(word, "gi");
console.log("Java, java, JAVA".match(finder)); // ['Java', 'java', 'JAVA']

In b the string says "^\\d{10}$", with two backslashes. Inside any JavaScript string, a backslash is the string's own escape character (Chapter 45: \n is a new line, \" is a quote). The string eats one backslash before the RegExp ever sees it. Forget the doubling and the pattern quietly changes meaning:

const wrong = new RegExp("^\d{10}$");
console.log(wrong);                       // /^d{10}$/   the backslash has vanished
console.log(wrong.test("9876543210"));    // false
console.log(wrong.test("dddddddddd"));    // true  - ten letter d's!

Between slashes, write the pattern exactly as it is: /\d/. Inside quotes for new RegExp, every backslash must be written twice: new RegExp("\\d"). Use the slash form whenever you know the pattern while writing the code, which is almost always. Keep new RegExp for patterns built from a variable.

One more trap with user text: new RegExp("C++") throws SyntaxError: Invalid regular expression: /C++/: Nothing to repeat, because + is a pattern symbol (61.4). To find exact text, the plain string methods of Chapter 45 have no such trap.

Quick check: what pattern does new RegExp("\\w+", "i") make, written as a literal?

/\w+/i. The string "\\w+" holds one backslash, a w and a +, and the second argument becomes the flag after the closing slash.

61.3 One character at a time: classes, shorthands and the dot

A pattern is read from left to right, and each piece of it normally stands for one character of the text. The simplest piece is a literal character: a letter or digit with no special meaning stands for itself. /cat/ means "a c, then an a, then a t", so it finds cat inside concatenate. Patterns are case-sensitive unless you add the i flag, so /cat/ does not find Cat.

Character classes: one character from a set

Square brackets make a character class. However long the list inside, a class stands for exactly one character, which must be one of those listed. A dash between two characters means "everything from this one to that one".

ClassMatches one character that is…Example
[aeiou]a, e, i, o or u/[aeiou]/ finds a vowel in "sea", none in "sky"
[a-z]a small English letter, a to znot é, not a capital
[A-Z]a capital English letterfrom the slide
[0-9]a digit/[0-9]/ is true for "CSE326"
[A-Za-z]any English letter, either casetwo ranges in one class
[6-9]6, 7, 8 or 9the first digit of an Indian mobile number
[^0-9]not a digita ^ straight after [ turns the set inside out

Inside the brackets most symbols lose their special meaning: [.] matches only a real full stop. Three keep a job: the dash makes a range, a ^ placed first means "not", and the backslash still works, so [\s@] means "a whitespace character or an @". That ^ is unrelated to the "start of text" ^ of 61.5; same key, different job.

Shorthands: classes you will use every day

Some classes are so common that they have a two-character shorthand. Each is still one character of the text.

ShorthandSame asMeaningCapital letter = the opposite
\d[0-9]a digit\D anything that is not a digit
\w[A-Za-z0-9_]a "word" character: English letter, digit or underscore\W anything else, such as a space, @ or !
\s(space, tab, new line…)a whitespace character\S anything that is not whitespace
.any character at all, except a line break

Small letter "is one", capital letter "is anything but". Note that \w means English letters only: /^\w+$/.test("José") is false.

A class in square brackets is one box that accepts any character from a short list. \d, \w and \s are ready-made lists (digits; letters, digits and _; spaces). The capital versions accept everything except that list. The dot accepts any character at all.

The dot is the dangerous one, because in ordinary writing a dot is a full stop. In a pattern it is "any one character": /c.t/ matches cat, cut and c9t, but not ct. A real full stop is written \. (61.6).

61.4 How many: quantifiers

Writing \d\d\d\d\d\d\d\d\d\d for ten digits would work, but it is unreadable. A quantifier written straight after a piece says how many times that piece repeats.

QuantifierHow many of the piece before itExampleMatches
?0 or 1 (it is optional)/colou?r/color, colour
*0 or more/go*gle/ggle, gogle, google, gooogle…
+1 or more/go+gle/gogle, google… but not ggle
{n}exactly n/\d{6}/six digits in a row
{n,}n or more/[A-Za-z]{3,}/at least three letters (Chapter 18's example)
{n,m}from n to m/\d{1,3}/one, two or three digits

Three rules:

  1. A quantifier repeats only the one piece just before it. In /ha+/ the + repeats the a, not ha, so it matches haaa but not hahaha. To repeat several characters together, put them in a group: /(ha)+/ (61.6).
  2. No spaces inside the braces. {1,3} means one to three. {1, 3}, with a space, is not a quantifier at all; JavaScript reads it as the six ordinary characters {, 1, ,, space, 3, }. So /^\d{1, 3}$/.test("5") is false, and no error warns you.
  3. Quantifiers are greedy. +, * and {n,m} take as many characters as they can. "Room 2026".match(/\d+/) finds "2026", all four digits, not just the "2".

Most lines go as you would guess. /[^0-9]/ is false for "2026" because every character there is a digit; /c.t/ is false for "ct" because the dot needs one character to stand on; /go+gle/ rejects "ggle" while /go*gle/ accepts it, since * allows zero. Stop at the last line: /\d{3}/ on "Room 12345" prints true, though the text has five digits. The next section explains why.

Quick check: which of "ac", "abc", "abbbc" does /ab+c/ match? And /ab*c/?

/ab+c/ needs at least one b, so it matches "abc" and "abbbc" but not "ac". /ab*c/ allows zero b's, so it matches all three.

61.5 Anchors: why validation needs ^ and $

On its own, test() asks a loose question: is there a match anywhere inside this text? It slides the pattern along the string and says true the moment any stretch fits, so /\d{3}/ found "123" inside "Room 12345". For searching that is right. For a form it is a disaster: /\d{10}/ accepts "Call 9876543210 now" and "98765432101", because both contain ten digits in a row.

The cure is a pair of anchors. ^ means "the very start of the text" and $ means "the very end". They match a position, not a character; they use up nothing. Put ^ first and $ last, and the pattern must stretch from the first character to the last, with nothing left over on either side.

<style>
  body { font-family: system-ui, sans-serif; padding: 14px; color: #0B2545; }
  table { border-collapse: collapse; font-size: 14px; }
  th, td { border: 1px solid #CBD5E1; padding: 5px 9px; }
  th, td:first-child { font-family: ui-monospace, Consolas, monospace; }
  .t { color: #138808; font-weight: 700; }
  .f { color: #C42B2B; }
</style>
<table>
  <thead><tr><th>text</th><th>/\d{10}/</th><th>/^\d{10}/</th><th>/^\d{10}$/</th></tr></thead>
  <tbody id="rows"></tbody>

<script>
  const anywhere = /\d{10}/;      // ten digits somewhere inside
  const atStart = /^\d{10}/;      // ten digits right at the start
  const whole = /^\d{10}$/;       // ten digits, and nothing else

  const inputs = ["9876543210", "98765432101", "Call 9876543210", "9876543210 now", "98765"];
  const results = [];

  for (const text of inputs) {
    const row = {
      text: text,
      anywhere: anywhere.test(text),
      atStart: atStart.test(text),
      whole: whole.test(text),
    };
    results.push(row);

    // the same row, drawn on the page
    const tr = document.createElement("tr");
    for (const value of [row.text, row.anywhere, row.atStart, row.whole]) {
      const td = document.createElement("td");
      td.textContent = value;
      if (value === true) td.className = "t";
      if (value === false) td.className = "f";
      tr.append(td);
    }
    document.getElementById("rows").append(tr);
  }
  console.table(results);
</script>

Read the Console table column by column. anywhere says true for the first four texts. atStart rejects "Call 9876543210" (it starts with C) but still accepts "98765432101" and "9876543210 now", because nothing checks what follows. Only whole gives the answer a form needs: true for "9876543210" and false for everything else.

Key idea. Searching asks "is it in there somewhere?", so leave the anchors off. Validating asks "is the whole thing exactly this shape?", so begin with ^ and end with $. Forgetting them never throws an error; the form just lets bad values through.
Quick check: /^\d{6}$/ is the PIN rule. What does it say for "1444110", and why?

false. Six digits fit from the start, but then a seventh digit is left before the end, and $ demands the end right there. Without the $, /^\d{6}/ would wrongly say true.

61.6 Groups, either-or, and escaping

Groups ( ) and alternation |

Round brackets make a group: several pieces treated as one unit. A quantifier after a group repeats the whole group, and the bar | inside a group means "or". The bar is called alternation: try this alternative, or that one.

console.log(/^(ha)+$/.test("hahaha"));          // true:  the group "ha", repeated
console.log(/^ha+$/.test("hahaha"));            // false: + repeats only the a
console.log(/^(jpg|png|gif)$/.test("png"));     // true:  one of the three
console.log(/^(jpg|png|gif)$/.test("png.exe")); // false: ".exe" is left over
console.log(/^(\+91)?[6-9]\d{9}$/.test("+919876543210"));  // true: +91 is optional

The last line combines everything so far: a group holding \+91, made optional by ?, then the mobile number. Groups have a second job: they remember the text they matched, so you can pull it out later (61.7).

The bar splits the whole pattern. Without a group, | divides everything on its left from everything on its right. /^cat|dog$/ does not mean "exactly cat or exactly dog". It means "^cat or dog$": text that starts with cat, or text that ends with dog. So it says true for "catapult" and for "hotdog". Write /^(cat|dog)$/ to keep the anchors outside the choice.

Escaping: when you mean the symbol itself

These characters have jobs in the pattern language: . * + ? ^ $ ( ) [ ] { } | \ /. They are the metacharacters. When you want one of them to mean just itself, put a backslash in front: \. is a real full stop, \+ a real plus sign, \/ a real slash, \$ a real dollar sign, and \\ a real backslash.

console.log(/lpu.in/.test("lpu-in"));        // true:  the dot matched the "-"
console.log(/lpu\.in/.test("lpu-in"));       // false: \. is only a real dot
console.log(/lpu\.in/.test("lpu.in"));       // true
console.log(/^\d{2}\/\d{2}\/\d{4}$/.test("30/10/2026"));   // true: \/ is a real slash

Without the backslashes, the first / in the date would end the pattern early: a SyntaxError. The unescaped dot is quieter: no error, it just accepts too much.

Reading a pattern left to right

Any pattern can be read with one method. Split it into pieces, each being one thing (a character, a class, a shorthand or a group) plus its quantifier, if any, and say each piece aloud in order. Take a car number plate such as PB08AB1234:

PieceSay it asIn PB08AB1234
^from the start
[A-Z]{2}two capital lettersPB (the state)
\d{2}two digits08 (the district)
[A-Z]{1,2}one or two capital lettersAB (the series)
\d{4}four digits1234
$then the end

Put together, /^[A-Z]{2}\d{2}[A-Z]{1,2}\d{4}$/ accepts "PB08AB1234" and "PB08A1234" and rejects "PB08AB1234XYZ". To write a pattern, run the method backwards: say the rule in words, piece by piece, then turn each phrase into symbols.

Brackets ( ) glue pieces into one unit so a quantifier or a choice applies to all of them. The bar | means "or", and it splits everything around it unless it sits inside brackets. A backslash in front of a symbol, such as \., makes it mean just itself. To read a pattern, chop it into "one thing + how many" and say each chunk aloud.

61.7 Four methods: test, match, matchAll and replace

You already know test(). The other three are string methods that accept a pattern where Chapter 45 used plain text. Notice the sides: pattern.test(text), but text.match(pattern).

CallQuestion it answersGives back
pattern.test(text)Does it fit?true or false
text.match(/.../)What is the first match, and where?An array: [0] is the matched text, [1], [2]… the groups, plus .index. null if nothing fits
text.match(/.../g)What are all the matches?An array of every matched string, or null
text.matchAll(/.../g)All matches, each with its groupsA sequence you loop over with for...of. The g is compulsory
text.replace(/.../, "new")Change the first match (all of them with g)A new string. The original is untouched

Two details. When nothing matches, match gives null, not an empty array, so "Asha".match(/\d/g).length crashes with a TypeError; ("Asha".match(/\d/g) || []).length safely gives 0. And in replace, the new text may contain $1, $2…, meaning "what group 1, group 2… matched".

<style>
  body { font-family: system-ui, sans-serif; padding: 14px; color: #0B2545; }
</style>
<p>Everything this example finds and changes is printed in the Console.</p>

<script>
  const report = "Asha scored 85, Rahul 92 and Meera 78.";

  // match() WITHOUT g: the first match, and where it was found
  const first = report.match(/\d+/);
  console.log("First number:", first[0], "at position", first.index);

  // match() WITH g: every match, in an array of strings
  const all = report.match(/\d+/g);
  console.log("All numbers:", all);

  let total = 0;
  for (const mark of all) {
    total += Number(mark);              // each match is text, so convert it
  }
  console.log("Total:", total);

  // no match at all gives null, not an empty array
  console.log("Digits in 'Asha':", "Asha".match(/\d/g));

  // matchAll(): every match AND its groups (the g flag is compulsory)
  const data = "Asha:85, Rahul:92, Meera:78";
  for (const m of data.matchAll(/([A-Za-z]+):(\d+)/g)) {
    console.log(m[1], "scored", m[2]);
  }

  // replace(): without g only the first; with g every one; i ignores case
  const s = "I like java. Java is fun. JAVA!";
  console.log(s.replace(/java/, "JavaScript"));
  console.log(s.replace(/java/gi, "JavaScript"));

  // groups in the replacement: $1 is group 1, $2 is group 2 ...
  console.log("30-10-2026".replace(/(\d{2})-(\d{2})-(\d{4})/, "$3-$2-$1"));

  // two everyday clean-ups
  console.log("+91 98765-43210".replace(/\D/g, ""));       // keep only the digits
  console.log("  too   many    spaces ".trim().replace(/\s+/g, " "));

  // split at "one or more whitespace characters"
  console.log("Web  pages   are fun".split(/\s+/));
</script>

Trace the Console from the top.

  • First number: 85 at position 12. Without g, match stops at the first run of digits; .index counts from 0.
  • All numbers: ['85', '92', '78'], then Total: 255. The matches are strings, hence Number(); without it += would join text.
  • Digits in 'Asha': null. No match gives null.
  • Asha scored 85, Rahul scored 92, Meera scored 78. Each m from matchAll is like a match result: m[1] is the name group, m[2] the marks group.
  • I like JavaScript. Java is fun. JAVA! (only the first, small-letter "java"), then with gi: I like JavaScript. JavaScript is fun. JavaScript!
  • 2026-10-30. The groups caught day, month and year; "$3-$2-$1" reversed them.
  • 919876543210 and too many spaces: \D with g deletes every non-digit; \s+ squeezes each run of spaces to one.
  • ['Web', 'pages', 'are', 'fun']. Chapter 45 promised this: splitting at /\s+/ leaves no empty pieces between double spaces (trim first, or a leading space still leaves one).
Never put g on a pattern you use with test(). A g pattern remembers where its last match ended (in lastIndex) and starts the next search there. With const re = /a/g;, three calls of re.test("cat") give true, false, true, so a validation pattern with g can reject a correct value every other time. Keep g for match, matchAll and replace (matchAll without it throws a TypeError).
Quick check: what do "banana".replace(/a/, "o") and "banana".replace(/a/g, "o") give?

"bonana" and "bonono". Without g only the first a is replaced; with g every one is. "banana" itself is unchanged in both cases, because strings never change.

People type phone numbers in many styles, such as +91 98765-43210. Rather than a pattern that allows every style, clean first, then check:

const typed = "+91 98765-43210";
const cleaned = typed.replace(/[\s-]/g, "");             // "+919876543210"
console.log(/^(\+91)?[6-9]\d{9}$/.test(cleaned));        // true

The email trap

The email pattern is deliberately simple and lets some nonsense through. The official address rules allow strange forms almost nobody uses; a regex that follows them exactly is hundreds of characters long, unreadable, and still cannot tell you whether the mailbox exists. Real sites do a simple shape check to catch slips such as a missing @, then send a confirmation email. Only that proves the address is real.

    const note = result === expected ? "" : "   <-- SURPRISE";
    console.log(`"${text}" ${result ? "accepted" : "rejected"}${note}`);
    return result === expected;
  }

  let tried = 0;
  let surprises = 0;
  for (const rule of rules) {
    console.log(`--- ${rule.name}: ${rule.pattern}`);
    for (const text of rule.good) {
      tried++;
      if (!tryValue(rule, text, true)) surprises++;
    }
    for (const text of rule.bad) {
      tried++;
      if (!tryValue(rule, text, false)) surprises++;
    }
  }
  console.log("Surprises:", surprises);
  document.getElementById("sum").textContent =
    `${rules.length} patterns, ${tried} values tried, ${surprises} surprise(s) - see the Console.`;
</script>

Every mobile, PIN, registration and course-code line behaves as the table says. Then the last email line says "asha@lpu..in" accepted <-- SURPRISE, and the Console ends Surprises: 1. Why? The [^\s@]+ after the @ is greedy: it first takes all of lpu..in, then gives characters back until a \. can follow, and settles on lpu., dot included, since a dot is neither a space nor an @. Then \. takes the second dot and the last [^\s@]+ takes in. The rule, not the code, let it through.

That is what a list of bad values is for: it finds the holes in your rule before your users do. This hole is harmless (the confirmation email would bounce), so we keep the simple pattern.

Password strength: several small tests, not one monster

"At least 8 characters, with a small letter, a capital, a digit and a symbol" is really five questions. Each is a tiny pattern without anchors, because each asks "is there at least one of these anywhere?": /[a-z]/, /[A-Z]/, /\d/, and /[^A-Za-z0-9]/ for "not a letter or digit". Length needs no regex: pw.length >= 8.

Online you will find one-line versions such as /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^A-Za-z0-9]).{8,}$/. It works, but it is hard to read and cannot tell the user which rule failed. Separate tests can, and they turn straight into a checklist.

<script>
  // One rule, one small test. No pattern here has ^ or $, because each one
  // asks "is there at least ONE of these anywhere in the password?"
  const rules = [
    { id: "len",    passes: (pw) => pw.length >= 8 },
    { id: "lower",  passes: (pw) => /[a-z]/.test(pw) },
    { id: "upper",  passes: (pw) => /[A-Z]/.test(pw) },

  const words = ["", "very weak", "weak", "fair", "good", "strong"];

    for (const rule of rules) {
      if (rule.passes(pw)) count++;
    }
    return count;

On Run, the Console scores four passwords: asha: 1 of 5 - very weak, asha2026: 3 of 5 - fair (small letter, digit, exactly 8 characters), Asha2026: 4 of 5 - good and Asha@2026: 5 of 5 - strong. Now type in the box. Each key press fires input (Chapter 57) and the five tests run again: type A and only "A capital letter" turns green; at Asha2026 four are green; add the @ and all five are.

For a rule with several parts, write one small pattern per part and test them one by one: readable code, and a precise message for each part not yet met. Save the anchors for patterns that must describe the whole value.

61.9 Patterns in HTML, and testing a pattern step by step

The same patterns work without any JavaScript, in the HTML pattern attribute that Chapter 18 introduced. Three differences from the JavaScript form:

  1. No slashes and no flags. Write pattern="[6-9]\d{9}", not pattern="/[6-9]\d{9}/", or the slashes become characters the value must contain.
  2. It is anchored for you. The browser treats your pattern as ^(?:…)$: "start, your whole pattern as one group, end". So the whole value must match, and even pattern="cat|dog" means "exactly cat or exactly dog".
  3. An empty box is not checked. An empty value passes; add required if the box must be filled. A broken pattern, such as [6-9, is silently ignored, so every value passes. The browser also reads the pattern with the stricter v flag, under which a bare - or ( inside [ ] counts as broken: write [\s\-], not [\s-]. Test your patterns!
<label for="mobile">Mobile number</label>
<input id="mobile" name="mobile" required
       pattern="[6-9]\d{9}" title="10 digits, starting with 6, 7, 8 or 9">

From JavaScript, this box answers checkValidity() with true for 9876543210 and false for Call 9876543210 now, and its validity.patternMismatch flag (Chapter 60) is true in the second case.

Exam tip. In JavaScript, /[6-9]\d{9}/.test("Call 9876543210 now") is true, because there are no anchors. The same text in a box with pattern="[6-9]\d{9}" is invalid, because the attribute always demands a whole-value match. Questions love that difference.

Testing a pattern, one piece at a time

When a pattern misbehaves, do not stare at it. Build it up a piece at a time and test after every piece: \d (any digit?), then \d{10} (ten in a row?), then [6-9]\d{9} (first one 6–9?), then the anchors. Try the same pass and fail values at every step; when a result surprises you, the piece you just added is the culprit.

61.10 Common misunderstandings

✗ "/\d{10}/.test(value) checks that the value is ten digits."
It checks that the value contains ten digits somewhere, so "98765432101" and "Call 9876543210 now" pass.
✓ "Validation patterns start with ^ and end with $."
/^\d{10}$/ must fill the whole value. Only the HTML pattern attribute adds the anchors for you.
✗ "The dot means a full stop, so /lpu.in/ checks for lpu.in."
The dot means any character, so "lpu-in" and "lpuxin" pass too.
✓ "A real dot is \. (or [.])."
The same goes for every metacharacter: \+, \$, \(, \/…
✗ "new RegExp("^\d+$") is the same as /^\d+$/."
The string swallows the backslash, leaving /^d+$/, a pattern for the letter d.
✓ "Inside a string, write every backslash twice."
new RegExp("^\\d+$"). Better still, use the slash form whenever the pattern is fixed.
✗ "Adding g to a validation pattern does no harm."
With g, test() carries on from where the previous search stopped and can say false to a correct value on the next call.
✓ "No g with test(); g is for match, matchAll and replace."
✗ "A clever enough regex proves an email address (or a name) is real."
A pattern only checks shape. /^[A-Za-z ]+$/ even rejects a real name like D'Souza.
✓ "Patterns catch typing slips; real checks happen elsewhere."
A confirmation email proves the address. Keep name rules generous, and remember the server must check everything again (Chapter 60).

Exam-style checks

Answer each one before opening it. Most have four options and exactly one correct answer; three ask you to predict what the code prints.

What does the test() method of a regular expression return?L1
  • A. true or false
  • B. The matched text
  • C. The position of the match
  • D. An array of all matches

Answer: A. B and C describe match() without g; D is match() with g.

Which pattern accepts both "color" and "colour", and nothing else?L2
  • A. /^colou*r$/
  • B. /^colo?ur$/
  • C. /^colou?r$/
  • D. /^col(ou)r$/

Answer: C. u? makes the u optional. A also accepts "colouuur", because * allows any number. B makes the o optional instead and rejects "color". D accepts only "colour".

What does this print? console.log(/\d{10}/.test("My number is 98765432101"));L3

Answer: true. With no anchors, test() only asks whether ten digits in a row appear somewhere, and the eleven-digit run contains ten. /^\d{10}$/ would print false.

Why does a pattern used to validate a form field need ^ at the start and $ at the end?L2
  • A. Without them JavaScript throws a SyntaxError
  • B. They make the match ignore capital letters
  • C. They make the pattern find every match
  • D. Without them the pattern only has to match part of the value, so extra characters slip through

Answer: D. Anchors force the pattern to fill the whole value. A tempts, but a missing anchor never causes an error; it silently accepts bad input. B describes the i flag and C the g flag.

What does this print? console.log("a1b22c333".match(/\d+/g));L3

Answer: ['1', '22', '333']. With g, match returns every match, as strings; \d+ is greedy, so each run of digits comes out whole.

A product code must be PRD followed by exactly four digits, and nothing else. Which pattern is right?L2
  • A. /^[PRD]\d{4}$/
  • B. /^PRD\d4$/
  • C. /PRD\d{4}/
  • D. /^PRD\d{4}$/

Answer: D. A means one letter, P or R or D, then four digits. B means one digit followed by the character 4. C has no anchors, so "xPRD12345" passes.

A student writes const re = new RegExp("^\d{6}$"); for PIN codes, and re.test("144411") gives false. Why?L2
  • A. Inside the string, \d lost its backslash, so the pattern became /^d{6}$/: six letter d's
  • B. new RegExp cannot use anchors
  • C. test() works only with literal /.../ patterns
  • D. PIN codes need the g flag

Answer: A. The string swallowed the backslash. Write new RegExp("^\\d{6}$"), or simply /^\d{6}$/. D would add the lastIndex trap.

What is the value of "Red red RED".replace(/red/gi, "blue")?L3
  • A. "blue red RED"
  • B. "Red blue RED"
  • C. "blue blue blue"
  • D. "Red red RED"

Answer: C. i ignores case and g replaces every match. Without g (but with i) you would get A; with neither flag you would get B, the only small-letter "red".

A box has pattern="[6-9]\d{9}". The user types Call 9876543210 now. What happens on submit?L2
  • A. It is accepted, because the value contains a valid number
  • B. It is rejected, because the pattern attribute must match the whole value
  • C. Nothing is checked, because the pattern has no slashes
  • D. It is accepted, because there is no ^ or $

Answer: B. The browser anchors a pattern attribute automatically, so the whole value must be the number. A and D would be right for test() in JavaScript. C is backwards: the attribute is written without slashes.

What does this print, and why? console.log(/^cat|dog$/.test("catapult"));L3

Answer: true. The bar splits the whole pattern into ^cat or dog$, and "catapult" starts with cat. To mean "exactly cat or exactly dog", group the choice: /^(cat|dog)$/, which prints false here.

Which quantifier means "zero or one time", that is, optional?L1
  • A. *
  • B. +
  • C. {1}
  • D. ?

Answer: D. ? is 0 or 1. * (A) is 0 or more, + (B) is 1 or more, and {1} (C) is exactly one.

Quick revision

Key takeaways

  1. A regular expression is a pattern that describes a kind of text. Write it as /.../flags, or as new RegExp("...", "flags") with every backslash doubled.
  2. Each piece normally stands for one character: a literal, a class [a-z] / [^0-9], a shorthand \d \w \s (capitals mean "not"), or the dot (any character).
  3. Quantifiers repeat the piece just before them: ? 0–1, * 0+, + 1+, {n}, {n,}, {n,m} (no spaces). They are greedy.
  4. Without anchors a pattern matches anywhere. Validation needs ^ and $ so the pattern fills the whole value.
  5. ( ) groups pieces and remembers what they matched; | means "or" and splits the whole pattern unless grouped; \ makes a metacharacter literal, as in \..
  6. test says yes or no; match gives the first match (all with g) or null; matchAll needs g; replace with g changes every match and $1 reuses a group. No g with test.
  7. Patterns check shape, not truth: clean input first, use separate small tests for multi-part rules, keep email checks simple, and test with values that should fail.
  8. The HTML pattern attribute takes no slashes, is anchored automatically, skips empty boxes and silently ignores a broken pattern.
