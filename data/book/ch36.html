CSS Variables

Your brand colour appears in nineteen places in your stylesheet. The client asks for a different orange. You start hunting. CSS variables — properly called custom properties — let you name a value once and use it everywhere, so that change becomes a single edit. They are also how dark mode is built.

About 22 minutes · Course outcome CO3

Before you start — one-line reminders

  • :root is a pseudo-class that matches the <html> element (Chapter 32).
  • Some properties inherit from parent to child (Chapter 23).
  • A declaration is property: value; (Chapter 22).

By the end of this chapter you can

  • Declare a custom property and use it with var().
  • Say why they are nearly always declared on :root.
  • Give a fallback value, and redefine a variable for one component.
  • Build a small theme, and switch it in three lines.
  • Spot the four mistakes that make a variable silently do nothing.

36.1 The problem

Here is a stylesheet that has grown normally:

.header   { background: #E07B1E; }
.btn      { background: #E07B1E; }
.card     { border-left: 5px solid #E07B1E; }
.tag      { color: #E07B1E; }
h2        { color: #E07B1E; }
.link:hover { color: #E07B1E; }

Six copies of one colour, and this is a small file. Change the brand and you must find every one, including the ones you spell slightly differently and the one hiding inside a linear-gradient. Miss one and the page has a stray orange somewhere nobody notices until a marker does.

Picture this. Writing a phone number on nineteen sticky notes around your desk. When the number changes you have to find all nineteen. A variable is writing it once on the wall and pointing at it nineteen times.

36.2 Declaring and using

A custom property has a name that must begin with two dashes, and you use it with the var() function:

:root {
  --brand: #E07B1E;          /* declare: two dashes, then any name you like */
}

.btn {
  background: var(--brand);  /* use: var(--name) */
}

Three rules about the syntax, and each one is a mistake waiting to happen:

  • The name needs two dashes at the front. --brand, not brand, $brand or @brand. (Those last two belong to Sass and Less, which are different tools.)
  • Names are case-sensitive. --Brand and --brand are two different variables.
  • You must use var() to read it. Writing background: --brand; does nothing at all.
<style>
  :root {
    --brand: #E07B1E;
    --brand-light: #FFF8F0;
    --ink: #0B2545;
    --radius: 12px;
  }

36.3 Why :root?

  
A custom property behaves like an inherited property: it is available to the element it was declared on and to everything inside it.

  
:root is the <html> element — the outermost element on the page. Declare a variable there and every rule on the page can see it. That is why variables are declared on :root rather than on body or inside a particular rule.

  
Declare one inside .card instead and only .card and its children can use it. Everything else gets nothing, silently.

  
Redefining for one component

  
That scoping is a feature, not just a limitation. Declare a variable on :root for the normal case, then override it on one component:

  
<style>
  :root { --card-accent: #6B7A90; }

  .card {
    border-left: 6px solid var(--card-accent);
    background: #fff; padding: 12px 16px; margin-bottom: 10px;
    border-radius: 10px; font-family: system-ui, sans-serif;
  }
  .card b { color: var(--card-accent); }

  /* override the variable, not the rules */
  .card.done     { --card-accent: #138808; }
  .card.progress { --card-accent: #E07B1E; }
  .card.late     { --card-accent: #C42B2B; }
</style>
<div class="card done"><b>CSE305</b> Database Systems</div>
<div class="card progress"><b>CSE326</b> Internet Programming</div>
<div class="card late"><b>MTH101</b> Assignment overdue</div>
<div class="card"><b>PHY104</b> No status</div>

  
Read what happened: the .card rule was written once, with two uses of the variable. The three state classes change nothing except the value of --card-accent. Without variables you would repeat the border and the colour in every state class.






  
36.4 Fallback values

  
var() takes an optional second argument, used if the variable is missing:

  
color: var(--brand, #333);      /* if --brand is not defined, use #333 */

  
This matters for components you might reuse elsewhere, and for guarding against a typo. Without a fallback, a misspelled variable name makes the whole declaration invalid, and the property falls back to whatever it inherited — which is rarely what you wanted, and gives no error message.






  
36.5 Theming and dark mode

  
This is where variables stop being a convenience and become the only sane approach. Because every colour in your stylesheet points at a variable, changing the whole theme means changing the variables — not one rule.

  
<style>
  :root {
    --bg: #FBFCFE;
    --surface: #ffffff;
    --ink: #0B2545;
    --muted: #6B7A90;
    --brand: #E07B1E;
    --line: #E3E9F0;
  }
  .dark {
    --bg: #0E1B2E;
    --surface: #16263D;
    --ink: #E8EEF6;
    --muted: #9AB0C8;
    --brand: #FFB765;
    --line: #26405F;
  }

  /* not one rule below mentions a colour directly */
  .panel {
    background: var(--bg); padding: 16px; border-radius: 12px;
    font-family: system-ui, sans-serif; margin-bottom: 12px;
  }
  .card {
    background: var(--surface); border: 1px solid var(--line);
    border-left: 5px solid var(--brand); border-radius: 10px;
    padding: 12px 16px; color: var(--ink);
  }
  .card small { color: var(--muted); }
</style>
<div class="panel">
  <div class="card"><b>CSE326</b><br><small>Light theme</small></div>
</div>
<div class="panel dark">
  <div class="card"><b>CSE326</b><br><small>Dark theme — same CSS rules</small></div>
</div>

  
Adding a class to one element re-coloured everything inside it. In a real site a single line of JavaScript toggles class="dark" on <html>, and you can respect the reader's own system setting with a media query:

  
@media (prefers-color-scheme: dark) {
  :root { --bg: #0E1B2E; --ink: #E8EEF6; /* ... */ }
}






  
36.6 Naming, and the four silent failures

  
Good names describe the job, not the colour. --brand and --danger survive a redesign; --orange becomes a lie the day it turns blue. A small, ordinary set for a project:

  
:root {
  /* colour */
  --brand: #E07B1E;
  --ink: #0B2545;
  --muted: #6B7A90;
  --surface: #ffffff;
  --line: #E3E9F0;
  /* spacing and shape */
  --gap: 16px;
  --radius: 12px;
  /* type */
  --font: system-ui, sans-serif;
}

  

    
MistakeWhat happens

    
      
brand: #E07B1E; (no dashes)Not a custom property at all — an unknown property, ignored

      
background: --brand; (no var())Invalid value, ignored, no error

      
Declared inside .card, used in .footerOut of scope: the footer is not inside the card, so it sees nothing

      
var(--brnad) (a typo)The declaration is invalid; the property falls back to its inherited value. A fallback, var(--brand, #333), saves you.

    
  

  
These are not Sass variables. CSS custom properties are live in the browser: they inherit, they can be changed by a media query or by JavaScript at runtime, and DevTools shows their current value. Sass variables ($brand) are replaced before the browser ever sees the file. If you find $ or @ in a tutorial, it is a different tool.






  
36.7 Build it: the project's design tokens

  
<style>
  :root {
    --font: system-ui, "Segoe UI", sans-serif;
    --ink: #0B2545;
    --body: #3C4A60;
    --muted: #6B7A90;
    --surface: #ffffff;
    --bg: #F1F5F9;
    --line: #E3E9F0;
    --brand: #E07B1E;
    --brand-soft: #FFF8F0;
    --ok: #138808;
    --radius: 12px;
    --gap: 16px;
  }
  * { box-sizing: border-box; }
  body { font-family: var(--font); background: var(--bg); color: var(--body);
         padding: var(--gap); line-height: 1.7; }
  h1 { color: var(--ink); margin: 0 0 var(--gap); }

  .card {
    background: var(--surface);
    border: 1px solid var(--line);
    border-left: 5px solid var(--card-accent, var(--brand));
    border-radius: var(--radius);
    padding: 14px 18px;
    margin-bottom: var(--gap);
  }
  .card b { color: var(--card-accent, var(--brand)); }
  .card.done { --card-accent: var(--ok); background: #F6FCF7; }
  .card.featured { background: var(--brand-soft); }

  .btn {
    background: var(--brand); color: #fff; border: none;
    border-radius: var(--radius); padding: 10px 20px;
    font: inherit; font-weight: 700; cursor: pointer;
  }
</style>

Exam-style checks

  
Where must CSS variables be declared to be available everywhere?L2

    
  • A. In body
  • B. On :root
  • C. In a media query
  • D. In each rule

    
Answer: B. :root is the html element, so every rule on the page can see the variable.

  
How do you USE a custom property named --brand?L2

    
  • A. brand
  • B. $brand
  • C. var(--brand)
  • D. @brand

    
Answer: C. var(--brand), with a fallback such as var(--brand, #333) if you wish. $ and @ belong to Sass and Less.

  
How must a custom property's name begin?L1

    
With two dashes: --brand. Without them it is just an unknown property and is ignored.

  
What does var(--brand, #333) mean?L2

    
"Use --brand; if it is not defined, use #333 instead." The second argument is a fallback, which protects you against a typo or a missing declaration.

  
You declare --gap inside .card and use it in .footer. What happens?L3

    
Nothing — the footer cannot see it. Custom properties inherit downwards, so a variable declared on .card is visible only to .card and its descendants. Declare shared values on :root.

  
Why is it useful that variables can be redefined on a child element?L3

    
Because one set of rules can then produce many variants. Write .card once using var(--accent), then have .card.done and .card.late change only the variable. It is also exactly how dark mode works.

  
Why are CSS custom properties different from Sass variables?L3

    
CSS custom properties are live in the browser: they inherit, they can be changed at runtime by a media query, a class or JavaScript, and DevTools shows their current value. Sass variables are substituted before the browser ever sees the CSS, so they cannot respond to anything.

  
background: --brand; does nothing. Why?L2

    
The var() function is missing. It must be background: var(--brand);. The value --brand on its own is not valid for background, so the declaration is thrown away silently.

  
Which is the better variable name, --orange or --brand?L2

    
--brand — it names the job, not the current colour. When the brand turns blue, --orange: #1D4ED8 is a lie that future readers of the stylesheet have to decode.






  
Quick revision

  
Key takeaways
    
    
  1. Declare with two dashes: --brand: #E07B1E;. Read with var(--brand).
    2. 
    
  2. Declare on :root so the whole page can see it. Variables inherit, so a variable declared deeper is visible only inside that element.
    3. 
    
  3. var(--name, fallback) guards against a missing or misspelled name.
    4. 
    
  4. Redefining a variable on a component gives you variants and themes without duplicating rules — including dark mode.
    5. 
    
  5. Name by job (--brand, --danger), not by colour. They are live in the browser, unlike Sass variables.
    6.
