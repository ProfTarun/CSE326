Attribute Selectors

Sometimes the thing that makes an element special is not its tag or its class, but an attribute it already carries: this input is a type="email", this link goes to an external site, this file is a PDF. Square brackets let you select on exactly that — no extra classes, no extra markup.

About 15 minutes · Course outcome CO3

Before you start — one-line reminders

  • An attribute is written inside the opening tag as name="value" (Chapter 5).
  • input uses type to decide what kind of control it is (Chapter 17).
  • An attribute selector counts in the class column for specificity (Chapter 23).

By the end of this chapter you can

  • Select an element because an attribute exists, or because it has a particular value.
  • Use the three matching operators ^=, $= and *= correctly.
  • Style every input type differently without adding a single class.
  • Mark external links and file downloads automatically.

34.1 Square brackets

An attribute selector is written in square brackets after (or instead of) an element name:

[required]              { /* any element that HAS a required attribute */ }
input[type="email"]     { /* inputs whose type is exactly email         */ }

There are two basic forms:

FormMeansExample
[attr]The attribute is present, whatever its value[disabled] — every disabled control
[attr="value"]The attribute's value is exactly thatinput[type="checkbox"]

Quotes round the value are optional when it is a single simple word, but always writing them is safer and is what you will see in professional code.

Picture this. A class is a badge you pin on someone. An attribute is something they already carry — a passport, a ticket, a uniform. Attribute selectors let you say "everyone holding a ticket" without going round pinning badges first.
<style>
  body { font-family: system-ui, sans-serif; }
  label { display: block; margin: 10px 0 3px; font-weight: 700; font-size: 14px; }
  input { padding: 8px 10px; border: 2px solid #CBD5E1; border-radius: 8px;
          font-size: 14px; }

  input[type="email"]    { border-color: #1D4ED8; }
  input[type="password"] { border-color: #6D28D9; letter-spacing: 0.2em; }
  input[type="date"]     { border-color: #138808; }
  input[required]        { border-left-width: 6px; }
  input[disabled]        { background: #F1F5F9; color: #94A3B8; }
</style>

<label>Password (required)</label><input type="password" required>
<label>Date of birth</label><input type="date">
<label>Registration number (locked)</label><input value="12345678" disabled>

Look at the HTML: not one class. Every rule found its target through an attribute the element had to carry anyway.

34.2 The three matching operators

Often you do not want an exact match. Three operators handle "starts with", "ends with" and "contains". They are easiest to learn as a group.

SelectorMatches when the value…Example match
[href^="https"]starts with httpshttps://lpu.in
[href$=".pdf"]ends with .pdf/files/syllabus.pdf
[href*="lpu"]contains lpu anywherehttps://portal.lpu.in/x
[class~="card"]contains card as a whole word in a space-separated listclass="big card wide"
[lang|="en"]is en or begins en-lang="en-IN"
 
<style>
  body { font-family: system-ui, sans-serif; line-height: 2; }
  a { color: #1D4ED8; }

  /* an outward arrow on anything leaving this site */
  a[href^="https"]::after { content: " \2197"; color: #E07B1E; }

  /* a label on PDF downloads */
  a[href$=".pdf"]::after {
    content: " PDF"; background: #C42B2B; color: #fff;
    font-size: 11px; font-weight: 700; padding: 1px 6px;
    border-radius: 4px; margin-left: 4px;
  }

  /* email and phone links get their own icon */
  a[href^="mailto:"]::before { content: "\2709 "; }
  a[href^="tel:"]::before    { content: "\260E "; }
</style>
<p><a href="courses.html">An ordinary internal link</a></p>
<p><a href="https://example.com">An external link</a></p>
<p><a href="/files/syllabus.pdf">Download the syllabus</a></p>
<p><a href="mailto:asha@example.edu">Email me</a></p>
<p><a href="tel:+919876543210">Call the office</a></p>

Five kinds of link, styled correctly, and the HTML is just links. Add a new PDF tomorrow and it is labelled automatically.

34.3 Case sensitivity

Attribute values are matched case-sensitively by default, which bites with file extensions: [href$=".pdf"] does not match REPORT.PDF.

Add the i flag before the closing bracket to ignore case:

a[href$=".pdf" i] { /* matches .pdf, .PDF, .Pdf */ }

Attribute names in HTML are always case-insensitive, so [HREF] and [href] are the same. It is the values you have to watch.

34.4 Where attribute selectors earn their keep

  • Forms. Styling input[type="text"], input[type="checkbox"] and input[type="submit"] separately is the only sensible approach, because they are all the same tag (Chapter 35).
  • Links. External arrows, file-type badges, mail and phone icons, as above.
  • State written in HTML. [disabled], [required], [checked], [aria-expanded="true"] — styling from an attribute a script is already toggling saves you inventing a parallel set of classes.
  • Data attributes. [data-status="done"] lets your HTML carry the information and your CSS decide the colour.
<style>
  body { font-family: system-ui, sans-serif; }
  .row { padding: 10px 14px; border-radius: 8px; margin-bottom: 8px;
         border-left: 5px solid #CBD5E1; background: #F8FAFC; }
  [data-status="done"]     { border-left-color: #138808; background: #F2FBF4; }
  [data-status="progress"] { border-left-color: #E07B1E; background: #FFF8F0; }
  [data-status="late"]     { border-left-color: #C42B2B; background: #FDF0F0; }
  [data-status]::after     { content: " (" attr(data-status) ")";
                             font-size: 12px; color: #6B7A90; }
</style>
<div class="row" data-status="done">CSE305 Database Systems</div>
<div class="row" data-status="progress">CSE326 Internet Programming</div>
<div class="row" data-status="late">MTH101 Assignment 3</div>
<div class="row">PHY104 (no status attribute, so plain)</div>

Notice the last rule combines an attribute selector with attr() from Chapter 33: the label is read straight out of the HTML, so it can never drift out of step with the colour.

Do not over-use them. A plain class is easier to read and slightly faster for the browser to match. Reach for an attribute selector when the attribute is already there and meaningful — not as a way of avoiding classes on principle.

Exam-style checks

Which selector targets inputs of type email?L2
  • A. input.email
  • B. input#email
  • C. input[type="email"]
  • D. input:email

Answer: C. Square brackets make an attribute selector. .email would look for a class and :email is not a pseudo-class.

a[href^="https"] selects links whose href:L3
  • A. Contains https
  • B. STARTS WITH https
  • C. Ends with https
  • D. Equals https

Answer: B. ^= starts with, $= ends with, *= contains.

Which selector would put a PDF badge on download links?L2

a[href$=".pdf"] — "ends with .pdf". Add the i flag, a[href$=".pdf" i], so .PDF matches too.

What does the selector [required] on its own match?L1

Every element that carries a required attribute, whatever its value and whatever its tag. The value form [required="required"] is unnecessary for boolean attributes.

Why is [href$=".pdf"] not matching a link to Notes.PDF?L3

Attribute values are matched case-sensitively. Add the case-insensitive flag: [href$=".pdf" i].

What is the difference between [class="card"] and [class~="card"]?L3

= demands the whole attribute be exactly "card", so class="card wide" would not match. ~= looks for "card" as a whole word in the space-separated list, so it does. (In practice you would just write .card.)

How much specificity does an attribute selector have?L2

The same as a class — it counts in the middle column. So input[type="email"] scores (0, 1, 1): one attribute selector and one element (Chapter 23).

Which selector marks links that go anywhere containing "youtube"?L2

a[href*="youtube"] — *= matches the text anywhere inside the value.

Quick revision

Key takeaways

  1. [attr] matches when the attribute exists; [attr="value"] when it is exactly that value.
  2. ^= starts with, $= ends with, *= contains. ~= is a whole word in a list.
  3. Values are case-sensitive; add the i flag to ignore case.
  4. Best used for forms (styling by type), links (by href), HTML-carried state (disabled, required) and data-* attributes.
  5. They score the same as a class for specificity.
