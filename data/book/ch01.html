Introduction to Internet and Web Technologies

Before you write a single tag you should be able to explain, in plain words, what happens when someone opens a web page. This chapter gives you that story: what the Internet is, how the World Wide Web is different from it, what a browser and a server each do, and where HTML, CSS and JavaScript fit.

About 23 minutes · Course outcome CO1 · Read this before Chapter 2

By the end of this chapter you can

  • Explain the difference between the Internet and the World Wide Web in one sentence.
  • Name the roles of the browser, the server and the protocol between them.
  • Say what a URL is and what HTTP and HTTPS stand for.
  • Describe the jobs of HTML, CSS and JavaScript and why they are kept separate.
  • Say who writes the standards that every browser follows.

1.1 The Internet is the road system

Think about the last thing you did online: a WhatsApp message, a YouTube video, a bank transfer, a Google search. Every one of those travelled over the same thing, and that thing is the Internet: a worldwide network of networks that connects billions of devices. Your phone talks to your home router, the router talks to your Internet service provider, the provider talks to bigger networks, and somewhere on the far side a server answers. No single company owns it and no single computer is it.

The most useful picture is a road system. Roads do not care what vehicle uses them: a bus, a courier van and a car can all share the same highway. In the same way the Internet does not care what kind of data it carries. Messages, videos, emails and web pages are all chopped into small packets, each packet is labelled with the address it is going to, and the routers along the way (the junctions) pass it on until it arrives. The rules the devices use to address and deliver those packets are called protocols, and the pair that hold the Internet together are TCP/IP: IP gives every device an address and moves packets between addresses, and TCP makes sure they all arrive and are put back in order.

Key idea. Internet = infrastructure + protocols + connected devices. It is the plumbing, not the water. Google is a service that uses the Internet; it is not the Internet.

1.2 The Web is one service that runs on the Internet

Now the distinction that examiners love, because so many people get it wrong. The World Wide Web (the Web, WWW) is not the Internet. The Web is one of many services that run on top of the Internet. It consists of web pages and websites, written in HTML, connected by hyperlinks, and delivered by the HTTP protocol. Email (SMTP/IMAP), online games, video streaming, WhatsApp, cloud backups and voice calls all use the Internet too, but they are not part of the Web: they use their own protocols, not HTTP, and they are not made of web pages.

Because of this, the two sentences you must be able to produce on demand are:

  • The Internet is the underlying network infrastructure; the Web is one service that runs on it.
  • You can use the Internet without using the Web: sending an email, playing an online game or making a video call uses the Internet but not HTTP and not web pages.
Exam tip. A question that says email, online games and video streaming run over the Internet but are not part of the Web is testing exactly this: those services show that the Web is only one of several services running on the Internet. The wrong options usually claim the two are identical, or reverse them (calling the Web the infrastructure). Both are false.

Where the Web came from

The Internet grew out of ARPANET, a research network from 1969; TCP/IP became its standard in 1983. The Web is younger. In 1989–91 Tim Berners-Lee, working at the CERN physics laboratory, invented three things together: HTML (the language for writing pages), HTTP (the protocol for fetching them) and the URL (the address scheme for naming them), plus the first browser and the first web server. The W3C (World Wide Web Consortium) was founded in 1994 to write the open standards that all browsers follow. HTML5 became a W3C Recommendation in 2014, and today HTML is maintained as a continuously updated living standard by the WHATWG, with the W3C endorsing it and publishing the accessibility guidelines (WCAG) you will meet in Unit 2.

1.3 Who asks and who answers: browsers, servers and HTTP

Everything on the Web is a conversation between two programs. The web browser (Chrome, Edge, Firefox, Safari) is the application that requests and displays web pages for a user. The web server is a program running on a computer somewhere else that stores the pages, runs logic and responds to requests. In this arrangement the browser is called the client, because it asks, and the other side is the server, because it serves. Chapter 2 walks through this exchange step by step; here you only need the vocabulary.

The language the two programs speak is HTTP, the HyperText Transfer Protocol. HTTP is not cabling and not a programming language: it is the set of rules for how a request is worded and how a response is worded, so that any browser can talk to any server. HTTPS is HTTP with one addition: the data is encrypted using TLS while it travels, so nobody on the road between you and the server can read or alter it. That is why login pages, banking and this university portal all use https://.

One consequence of this design surprises beginners. What the server sends back is not a picture of the finished page and not a compiled program. It is a block of text: HTML, plus CSS and JavaScript files, which the browser interprets and draws. Everything you see on screen is the browser's interpretation of text it received. And because that text has been sent to the user's machine, nothing sent to the browser is secret: anyone can press Ctrl+U (View Source) or open DevTools and read every line, including your HTML comments and your JavaScript. Anything that must stay private (passwords, answer keys, database credentials) has to stay on the server.

1.4 Naming things: the URL

To ask for a page the browser needs its address. That address is a URL, Uniform Resource Locator. A URL tells the browser how to fetch something (the protocol), which computer to ask (the domain) and what to ask for (the path), optionally with extra parameters (the query string). 1.5 Three languages, three jobs: HTML, CSS and JavaScript

A web page is built from three front-end languages, and each has one job. Keeping those jobs separate is called separation of concerns, and it is the single most important habit this course will try to give you.

HTML (HyperText Markup Language) is the language that gives structure and meaning to content. It says this is a heading, this is a paragraph, this is a link to that page, this is a table of marks. It does not say how anything should look. CSS (Cascading Style Sheets) supplies the presentation: colours, fonts, spacing and the arrangement of boxes on the screen. JavaScript supplies behaviour: what happens when a button is clicked, checking a form before it is sent, fetching new data without reloading the page.

Notice what HTML is not. It is not a programming language: it has no variables, loops or decisions. It is a markup language, a way of annotating text so that a browser knows what each piece of content represents. The word HyperText refers to text with links in it, which is what made the Web different from every document system before it.

Wrong on purpose. "HTML supplies presentation, CSS supplies structure" is backwards; so is "all three are written inside the head element". If a question asks which arrangement correctly separates concerns, the answer is always: HTML for structure, CSS for presentation, JavaScript for behaviour.

Your first look at HTML

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Web Lab</title>
  </head>
  <body>
    <article>
      <h1>Web Lab</h1>
      <p>Build. Test. Learn.</p>
    </article>
  </body>
</html>

Press Run. The browser reads the text from the outside in: the document type, then the <html> root, then a <head> of information about the page and a <body> of visible content. Inside the body an article holds a heading and a paragraph. Nothing here says "make the heading large and bold"; the browser applies a plain default look, and CSS (Unit 3) would change it. Chapters 3 and 4 explain every line.

1.6 Who decides the rules? Standards bodies

Chrome, Firefox, Safari and Edge are made by different companies, yet the same HTML works in all of them. That is only possible because the languages are open standards, written down publicly so every browser maker can implement the same thing.

  • W3C, the World Wide Web Consortium, founded by Tim Berners-Lee in 1994, publishes open web standards: CSS, SVG, the accessibility guidelines (WCAG) and, historically, HTML itself. When an exam asks which organisation publishes open web standards such as HTML and the accessibility guidelines, the answer is the W3C, not IEEE, ISRO or NASSCOM.
  • WHATWG maintains the HTML living standard that browsers actually implement today, in cooperation with the W3C.
  • IETF writes the Internet protocols underneath, including HTTP and TLS.
  • ECMA standardises JavaScript (formally called ECMAScript).

The practical result for you is a reference you can trust: MDN Web Docs documents every element and attribute exactly as the standards define them, and the W3C validator checks your page against them.

1.7 Putting it together: what happens when you click

You now have every word needed to narrate a page load. Say it without using the phrase "it just loads":

  1. You type a URL or click a link. The browser (the client) builds an HTTP request for that address.
  2. The request travels across the Internet to the server named in the URL.
  3. The server processes it: it finds the file, or runs code and looks things up in a database.
  4. The server sends back an HTTP response containing text, usually HTML (or JSON for data).
  5. The browser renders that text into the page you see, fetching any CSS, images and scripts it mentions along the way.

Common misunderstandings

✗ "The Internet and the Web are the same thing."
They are not. The Internet is the network; the Web is one service on it, delivered by HTTP and made of HTML pages.
✓ "The Web runs on top of the Internet, like email does."
Correct, and it explains why you can use the Internet (email, games, WhatsApp) without using the Web.
✗ "HTML is a programming language."
It has no logic, loops or variables.
✓ "HTML is a markup language that gives structure and meaning to content."
Programming on the front end is JavaScript's job.
✗ "The server sends a picture of the page."
It sends text.
✓ "The server sends HTML text; the browser interprets it and draws the page."
Which is also why nothing sent to a browser can be kept secret.

Exam-style checks

Answer each one before opening it. They are written the way CA2 questions are: four options, exactly one correct.

Which statement correctly distinguishes the Internet from the World Wide Web?L2
  • A. The Internet is the underlying network infrastructure; the Web is one service that runs on it
  • B. The Web is the network infrastructure; the Internet is one service that runs on it
  • C. They are two names for the same system
  • D. The Internet uses only HTTP, while the Web uses only TCP/IP

Answer: A. The Internet is the infrastructure (devices, routers, TCP/IP); the Web is one service on top of it, using HTTP and HTML. B reverses the roles, C denies the difference, and D swaps the protocols.

Email, online games and video streaming run over the Internet but are not part of the Web. What does this show?L2
  • A. The Web is only one of several services running on the Internet
  • B. The Internet and the Web are identical
  • C. Those services use HTML internally
  • D. The Web is the infrastructure on which the Internet runs

Answer: A. These services use their own protocols (SMTP, game protocols, streaming protocols), not HTTP, and are not web pages; they prove the Web is just one service among many.

The Internet is best described as:L2
  • A. A single very large computer
  • B. A network of networks connecting devices worldwide
  • C. A website that stores all web pages
  • D. A search feature built into browsers

Answer: B. No single computer or website is the Internet; it is the interconnection of many networks.

A WhatsApp message, a web page, a hyperlink and a website's HTML: which of these is NOT part of the World Wide Web?L2

Answer: the WhatsApp message. WhatsApp uses the Internet with its own protocol; it is not made of pages and links delivered by HTTP. The other three are the very definition of the Web.

Which software application requests and displays web pages for a user?L1
  • A. A web browser
  • B. A web server
  • C. A compiler
  • D. A network router

Answer: A. The browser is the client: it requests pages and renders them. The server stores and serves; a router only forwards packets; a compiler has nothing to do with it.

What does a web server send back to your browser?L2
  • A. A picture of the finished page
  • B. A block of text the browser interprets
  • C. A compiled program
  • D. A database file

Answer: B. The response is text (HTML, CSS, JavaScript). The browser interprets it and draws the page. This is also why anything sent to a browser can be read by the user with View Source.

What does HTTP stand for, and what is it?L1

Answer: HyperText Transfer Protocol: the protocol (set of rules) used to exchange web requests and responses between browser and server. It is not cabling, not a database query language and not a markup language.

HTTPS differs from plain HTTP because it adds:L2
  • A. Encryption of the transferred data using TLS
  • B. Faster compression of HTML files
  • C. Automatic mobile layout adjustment
  • D. Support for server-side scripting

Answer: A. The S is for Secure: TLS encrypts the data in transit so it cannot be read or altered on the way.

What does the abbreviation URL stand for?L1
  • A. Universal Reference Link
  • B. Uniform Resource Locator
  • C. Unified Retrieval Language
  • D. User Request Line

Answer: B. A Uniform Resource Locator is the address of a resource: protocol, domain, path and optional query string.

Which language is used to give structure and meaning to content on the web?L1
  • A. HTML
  • B. CSS
  • C. SQL
  • D. JSON

Answer: A. HTML marks up what each piece of content is. CSS is presentation, SQL queries databases, JSON is a data format.

Which arrangement correctly separates concerns in a web page?L2
  • A. All three are written inside the head element
  • B. HTML supplies presentation, CSS supplies structure, JavaScript supplies content
  • C. HTML supplies structure, CSS supplies presentation, JavaScript supplies behaviour
  • D. CSS supplies structure while HTML supplies behaviour

Answer: C. Structure, presentation, behaviour: HTML, CSS, JavaScript, in that order.

Which three languages make up the front end of a page?L1

Answer: HTML, CSS and JavaScript. PHP, SQL, Java and Python are server-side or unrelated to the browser.

Anything you send to a browser can be read by the user. What does this mean for security?L2

Answer: nothing sent to the browser is secret. View Source and DevTools expose HTML comments, CSS and JavaScript alike. Secrets must stay on the server.

Which organisation publishes open web standards such as HTML and the accessibility guidelines?L1
  • A. W3C
  • B. IEEE
  • C. ISRO
  • D. NASSCOM

Answer: A. The World Wide Web Consortium. IEEE is an engineering body, ISRO is India's space agency and NASSCOM is an industry association.

A user clicks a link and the page appears. Which sequence of events is correct?L2
  • A. Click, request, server processes, response, render
  • B. Request, click, response, render
  • C. Click, response, request, render
  • D. Server processes, click, request, render

Answer: A. Nothing can be processed before it is requested, and nothing can be requested before the user acts.

Quick revision

Key takeaways

  1. The Internet is a network of networks: infrastructure plus the TCP/IP protocols.
  2. The World Wide Web is one service on the Internet: HTML pages joined by links, delivered by HTTP. Email, games, streaming and WhatsApp use the Internet but are not the Web.
  3. The browser is the client (it requests and displays); the server stores data, runs logic and responds. The response is text, which the browser interprets, and nothing sent to a browser is secret.
  4. HTTP = HyperText Transfer Protocol; HTTPS adds TLS encryption. URL = Uniform Resource Locator.
  5. HTML is structure, CSS is presentation, JavaScript is behaviour. HTML is a markup language, not a programming language.
  6. The W3C publishes the open standards (with WHATWG maintaining the HTML living standard); MDN documents them.
