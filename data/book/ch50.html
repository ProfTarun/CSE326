Arrays and Array Operations

A class has sixty students, a cart holds many items, a timetable has eight periods a day. Giving each one its own variable would be hopeless. An array keeps the whole list under one name, in order, with every value numbered from 0. This chapter shows you how to build one, read it, change it, search it, cut it, sort it and walk through it — and the one surprise that catches every beginner: copying an array's name does not copy the array.

About 32 minutes · Course outcome CO4

Before you start — one-line reminders

  • A variable is a named box for a value; const means the name can never be pointed at a different value (Chapter 42).
  • Every value has a type; arrays belong to the object type, so typeof calls them "object" (Chapter 43).
  • A string's characters are counted from 0, the last one is at length - 1 or at(-1), and split cuts text into a list (Chapter 45).
  • A function runs when you call it with (), and an arrow function such as (m) => m > 90 is a short way to write one (Chapter 48).

By the end of this chapter you can

  • Create an array, read or change any element by its index, and get the last element in two ways.
  • Add and remove elements at either end with push, pop, unshift and shift, and say what each one returns.
  • Search an array with indexOf, includes and find.
  • Choose correctly between slice and splice, and predict the result of each.
  • Combine, convert and reorder arrays with concat, spread, join, split, Array.from, reverse and sort, including sorting numbers properly.
  • Walk through an array of values or of student records with for and for...of, and unpack one with destructuring.
  • Explain why two names can share one array, make a real copy, and say which methods change the original.

50.1 One name, many values

Suppose you want to keep the marks of four students. With what you know so far, you would write four variables:

const marks1 = 85;
const marks2 = 72;
const marks3 = 92;
const marks4 = 64;

That works for four. It does not work for sixty, and it fails completely when you cannot know in advance how many values there will be: how many items will a customer put in a cart? You also cannot ask for the total without naming every variable by hand. What you want is one name for the whole list:

const marks = [85, 72, 92, 64];

That is an array. Your slides define it in two lines: an array is an ordered list of values, and its values are accessed by index, starting from 0. You write one with square brackets and commas between the values. Each value in the list is called an element.

const fruits = ["apple", "banana", "orange", "grape"];   // four strings
const empty = [];                                        // no elements yet
const mixed = [1, "banana", true, null];                 // any types, mixed
const grid = [[1, 2], [3, 4]];                           // an array of arrays

An array can be empty, which is how you start a list you will fill later. Its elements can be of any type, even mixed, though in practice one array usually holds one kind of thing. An element can even be another array, which is how a table of rows is stored. Writing the values straight into square brackets is called an array literal, and it is how almost every array is made. (Old code sometimes writes new Array(...). Avoid it: new Array(3) makes three empty slots, not an array holding the number 3.)

Picture this. A goods train is standing at Jalandhar Cantt, its wagons coupled in a fixed order. Imagine the yard staff number each wagon by how many wagons stand in front of it: the first has none in front, so it is wagon 0; the next is wagon 1. Adding or removing a wagon at the back is one quick coupling. Doing it at the front means every wagon's number shifts by one. Cutting into the middle means uncoupling, inserting and recoupling, and every wagon behind the cut gets a new number. An array behaves exactly like that train, and most of this chapter is about those three kinds of change.

50.2 Positions: index and length

Every element has a position number called its index. You read an element by writing the array's name with the index in square brackets. The first element is at index 0, exactly as with the characters of a string in Chapter 45. The easy way to remember it: the index is how many elements come before this one. Nothing comes before the first, so its index is 0.

const fruits = ["apple", "banana", "orange", "grape"];
console.log(fruits[0]);   // apple
console.log(fruits[2]);   // orange

Those lines are from your slides. Every array also has a length that says how many elements it holds. Because counting starts at 0, the last index is always one less than the length: four fruits have indexes 0, 1, 2 and 3. That gives the standard way to read the last element. Modern JavaScript adds a shorter one, at(), which also accepts negative numbers that count back from the end:

console.log(fruits.length);                // 4
console.log(fruits[fruits.length - 1]);    // grape   - the last element
console.log(fruits.at(-1));                // grape   - the last, the modern way
console.log(fruits.at(-2));                // orange  - second from the end
console.log(fruits[4]);                    // undefined - there is no index 4
console.log(fruits[-1]);                   // undefined - [ ] never counts backwards

Reading an index that does not exist is not an error. JavaScript simply gives you undefined, the "nothing is here" value from Chapter 43. That is kind, but it means a wrong index fails silently, so whenever an array hands you undefined, check your index first.

Changing an element

To change an element, assign to its index, exactly as you assign to a variable:

fruits[1] = "mango";
console.log(fruits);    // ['apple', 'mango', 'orange', 'grape']

When you log a whole array, this book's Console shows it in square brackets with each string in single quotes, as above. Chrome's DevTools shows the same thing with the length in front: (4) ['apple', 'mango', 'orange', 'grape'].

Do not write past the end. In a four-element array, fruits[10] = "kiwi" does not fail. It puts "kiwi" at index 10, makes the length 11, and leaves indexes 4 to 9 as empty holes that read as undefined. To add an element, use push from the next section.

An array is a numbered list. The numbers start at 0, so the last one is length - 1. Put a number in square brackets to read that element or to replace it. A number with no element behind it gives undefined.

Quick check: for const days = ["Mon", "Tue", "Wed"]; what are days.length, days[2] and days[3]?

3, "Wed" and undefined. Three elements have indexes 0, 1 and 2, so index 2 is the last one and index 3 is past the end.

50.3 Adding and removing at the ends

Most lists grow and shrink at their ends: a new student joins the back of the queue, the person at the front is served. Arrays have four methods for exactly this, and each one changes the array it is called on.

MethodWhat it doesWhat it returns
push(x)Adds x to the endThe new length
pop()Removes the last elementThe element it removed
unshift(x)Adds x to the startThe new length
shift()Removes the first elementThe element it removed

A way to keep them apart: the two short words, push and pop, work at the end; the two longer words, unshift and shift, work at the start. Working at the start is also the slower pair on a very long array, for the train reason: every other element has to be renumbered.

The return values are the part people forget and exams ask about. push and unshift hand back a number, the new length, not the array. pop and shift hand back the element they removed, so you can use it: serve the person you just took from the front of the queue. On an empty array there is nothing to remove, and both give undefined. push and unshift can take several values at once.

A classic slip. list = list.push("kiwi"); does not give you a longer list. It replaces your array with the number that push returned, its new length. Call push on its own line and keep using the same array. (With const list, the push still happens first, and then the assignment throws a TypeError.)
Quick check: what does [10, 20].push(30) return, and what does [10, 20].pop() return?

push returns 3, the new length. pop returns 20, the element it removed from the end.

50.4 Finding a value

Three methods answer three different questions about what is in an array:

MethodQuestion it answersReturns
indexOf(x)Where is x?The index of the first match, or −1 if there is none
includes(x)Is x there at all?true or false
find(test)Which is the first element that passes this test?That element, or undefined

Why −1 for "not found" and not 0? Because 0 is a real index, the first one; −1 can never be an index. So the correct check is list.indexOf(x) === -1. Never write if (list.indexOf(x)): it is false when x is first (0 is falsy, Chapter 46) and true when x is missing (−1 is truthy), exactly backwards. When you only need yes or no, includes says it more clearly. lastIndexOf(x) searches from the end instead. All of them compare the way === does, so "Meera" and "meera" are different, and so are 5 and "5". (One small exception: includes(NaN) finds a NaN, while indexOf(NaN) always gives −1.)

find works differently. Instead of a value, you give it a small function: a test. find runs the test on each element in turn, from index 0, and returns the first element for which the test gives true. A function handed to another function in this way is called a callback; Chapters 53 and 54 are all about them. For now, read marks.find((m) => m > 90) as "find the first mark m for which m > 90 is true".

50.5 slice and splice

These two names differ by one letter, and their behaviour differs completely. They are the most confused pair in this chapter and a favourite exam question.

  • slice(start, end) copies the elements from start up to, but not including, end into a new array. The original is untouched. Negative numbers count from the end, as with at(). Leave out end to copy to the end; slice() with nothing copies the whole array.
  • splice(start, deleteCount, item1, item2, ...) goes into the original array at start, removes deleteCount elements, and puts any items you list in their place. It returns an array of the removed elements (empty if it removed none) and changes the original.

The two extra calls show that splice is really three tools in one: a deleteCount of 0 with items inserts; a count with no items removes; a count with items replaces.

slice is a photocopy of part of the list: you get a new list and the original stays as it was. splice is surgery on the list itself: it cuts elements out, can stitch new ones in, and hands you what it cut out.

Exam tip. The second number means different things. In slice(1, 3) it is an end position, and it is not included, so you get indexes 1 and 2. In splice(1, 3) it is a count, so three elements go: indexes 1, 2 and 3.
Quick check: const nums = [1, 2, 3, 4, 5]; What does nums.slice(1, 3) return? If you then run nums.splice(1, 3), what does it return, and what is left in nums?

slice(1, 3) returns [2, 3] and leaves nums alone. splice(1, 3) removes three elements starting at index 1, so it returns [2, 3, 4] and nums becomes [1, 5].

50.6 Combining, joining and converting

None of the tools in this section changes the arrays you give it. Each one builds something new.

  • concat joins arrays end to end into a new array: fruits.concat(moreFruits), as in your slides.
  • Spread does the same job with three dots: [...fruits, ...moreFruits]. Spread syntax unpacks an array's elements into the new square brackets, and you can mix in extra values anywhere: [...fruits, "kiwi"]. Written alone, [...fruits] is a copy of the whole array.
  • join(separator) glues the elements into one string, with the separator between them. With no separator you get commas.
  • split(separator) goes the other way, from a string to an array; Chapter 45 showed it.
  • Array.from(thing) makes a real array out of anything list-like: a string becomes its characters, and in Chapter 56 the list of page elements returned by querySelectorAll becomes a proper array. Given an object such as { length: 5 } and a function, it makes 5 places and fills each one by calling the function with that place's index i.
const fruits = ["apple", "pear", "melon", "grape"];
const moreFruits = ["grapefruit", "pineapple"];

fruits.concat(moreFruits);     // ['apple', 'pear', 'melon', 'grape', 'grapefruit', 'pineapple']
[...fruits, ...moreFruits];    // the same new array, written with spread
fruits.join(", ");             // "apple, pear, melon, grape"
fruits.join();                 // "apple,pear,melon,grape"
"29/10/2026".split("/");       // ['29', '10', '2026']
Array.from("LPU");             // ['L', 'P', 'U']
Array.from({ length: 5 }, (v, i) => i + 1);   // [1, 2, 3, 4, 5] (v is unused here)

Two or more arraysOne arraya.concat(b) or [...a, ...b]

50.7 Putting in order: reverse and sort

reverse() turns the array back to front. sort() puts it in order. Unlike the tools in section 50.6, both change the original array, and both return that same array.

sort() has one famous trap. With no instructions, it turns every element into a string and compares the strings character by character, the way a dictionary orders words. For words that is fine. For numbers it is wrong:

const marks = [10, 9, 100, 25, 1];
marks.sort();
console.log(marks);    // [1, 10, 100, 25, 9]   - dictionary order!

As text, "100" comes before "25" because its first character, 1, comes before 2, just as a dictionary puts "ant" before "bee" however long the words are. To sort numbers you must give sort a compare function:

marks.sort((a, b) => a - b);    // [1, 9, 10, 25, 100]   smallest first
marks.sort((a, b) => b - a);    // [100, 25, 10, 9, 1]   largest first

Here is how it works. While sorting, sort keeps picking two elements, calls them a and b, and asks your function which should come first. If the function returns a negative number, a goes first; if positive, b goes first; if 0, their order is kept. a - b is negative whenever a is smaller, so the smaller one goes first: ascending order. b - a turns that round: descending order.

Left alone, sort uses dictionary order, which is right for words and wrong for numbers. For numbers, always write sort((a, b) => a - b) for smallest first, or sort((a, b) => b - a) for largest first.

Dictionary order has one more surprise: every capital letter comes before every small letter, so ["asha", "Rahul", "meera"].sort() gives ['Rahul', 'asha', 'meera']. Keep names in one consistent case before sorting them.

sort changes the original. If you still need the list in its old order (a register in roll-number order, say), sort a copy: [...marks].sort((a, b) => a - b). Recent browsers also offer toSorted() and toReversed(), which return a sorted or reversed copy and leave the original alone.

50.8 Visiting every element

Very often you want to do something with every element: print each name, add up all the marks. Loops get a full chapter of their own (Chapter 52); here are the two forms you need for arrays. The first is from your slides:

const fruits = ["apple", "banana", "orange", "grape"];

for (let i = 0; i < fruits.length; i++) {
  console.log(fruits[i]);        // apple, banana, orange, grape - one per line
}

Read the first line as: start i at 0; while i is less than the length, run the block; after each run, add 1 to i. So i takes the values 0, 1, 2 and 3, which are exactly the indexes, and the block reads fruits[i] each time. The condition is <, not <=: with <=, i would also reach 4, one step past the end, and print undefined.

When you only need the elements and not their positions, for...of is shorter and cannot go past the end:

for (const fruit of fruits) {
  console.log(fruit);            // apple, banana, orange, grape - one per line
}

Read it as "for each fruit of fruits". Each time round, fruit holds the next element. Use for...of to read every element, and the counting for when you need the index too: to number the lines, or to change fruits[i].

Arrays of objects

Real data is rarely a list of bare names. It is a list of records: each student has a name and marks. Chapter 51 teaches objects properly; for now, an object is a bundle of named values in curly braces, { name: "Asha", marks: 85 }, and you read one value with a dot: student.name. An array of such objects is the commonest shape of data on the web:

const students = [
  { name: "Asha",  marks: 85 },
  { name: "Rahul", marks: 72 }
];
console.log(students[1].name);    // Rahul  - the element at index 1, then its name

A preview: forEach, map and filter

Your slides end with three array methods that take a callback, as find does. They are the subject of Chapter 53; here is just enough to recognise them:

const marks = [85, 92, 34, 76, 28];

marks.forEach((mark) => {               // forEach: do something with each element
  console.log(mark);                     // 85, 92, 34, 76, 28 - one per line
});

const bonusMarks = marks.map((mark) => {   // map: transform each one into a NEW array
  return mark + 5;
});
console.log(bonusMarks);                 // [90, 97, 39, 81, 33]

const numbers = [12, 7, 18, 5, 24, 9, 30, 11];
const evenNumbers = numbers.filter(function (number) {   // filter: keep those that pass
  return number % 2 === 0;
});
console.log("Even Numbers:", evenNumbers);   // Even Numbers: [12, 18, 24, 30]

map and filter build new arrays and leave marks and numbers alone. A fourth, reduce, combines all the elements into one value: marks.reduce((sum, m) => sum + m, 0) gives 315. Chapter 53 traces it step by step.

50.9 Destructuring: unpacking an array

Often you want the first few elements of an array in variables of their own. You could write const first = fruits[0]; and const second = fruits[1];, but destructuring does it in one line. You put square brackets on the left of the =, and each name receives the element at the same position:

const fruits = ["apple", "banana", "orange", "grape"];

const [first, second] = fruits;
console.log(first, second);           // apple banana

const [a, , c] = fruits;              // an empty gap skips an element
console.log(a, c);                    // apple orange

const [head, ...rest] = fruits;       // ...rest collects everything left over
console.log(head, rest);              // apple ['banana', 'orange', 'grape']

const [x, y, z = "none"] = ["red", "green"];   // a default for a missing element
console.log(z);                       // none

Destructuring only reads: the array is unchanged. Note the two jobs of the three dots. On the right of an =, ...fruits is spread: it unpacks. On the left, ...rest is a rest element: it collects the leftovers into a new array, and it must come last. One neat use is swapping two variables without a spare one:

let left = "Asha";
let right = "Rahul";
[left, right] = [right, left];
console.log(left, right);             // Rahul Asha

Objects can be destructured too, by property name instead of position; that is in Chapter 51.

To sort records by marks, the compare function compares their marks: y.marks - x.marks is positive when y has more, so y goes first and the highest mark leads.

50.10 Arrays are shared, not copied

In Chapter 43 you saw that numbers and strings are copied by value: after let a = 5; let b = a; b = 6;, a is still 5. Arrays are objects, and objects behave differently. A variable does not hold the array itself; it holds a reference to where the array lives in memory. So const sameList = original; copies only the reference, and both names now lead to one and the same array. Change it through either name and the other sees the change, because there is only one array.

Four consequences follow, and the example below shows each one:

  • To copy, build a new array: [...original], original.slice() or Array.from(original).
  • === asks "the same array?", not "the same contents?" Two separately made arrays are never ===, even with identical elements: [1, 2] === [1, 2] is false.
  • A function receives the same array, not a copy. If it calls push on its parameter, the caller's array grows. Sometimes that is what you want; when it is not, have the function work on a copy.
  • const locks the name, not the contents. A const array can still be changed with push, splice or arr[0] = .... What const forbids is pointing the name at a different array.

The runnable example uses try { ... } catch (err) { ... }, as Chapter 49 did, to print an error and carry on.

An array variable is a name tag tied to an array, not the array itself. b = a ties a second tag to the same array. To get a second array, build one with [...a]. And const only stops you moving the tag; it never stops you changing what is inside.

Quick check: const a = [1, 2]; const b = a; b.push(3); What is a.length now? What would it be if the second statement had been const b = [...a];?

3: a and b are two names for one array, so the push shows through a. With [...a], b is a separate copy, the push changes only b, and a.length stays 2.

50.11 Common misunderstandings

✗ "The first element is at index 1, and the last is at index length."
Both are one too high: index length is always past the end.
✓ "The first element is at index 0; the last is at length - 1, or at(-1)."
The index counts how many elements come before this one.
✗ "push returns the bigger array."
It returns a number: the new length.
✓ "push and unshift return the new length; pop and shift return the removed element."
All four change the array itself, so you rarely need the array back.
✗ "slice and splice are two spellings of the same thing."
One copies, the other operates on the original.
✓ "slice copies a part and leaves the original alone; splice removes or inserts in the original."
And slice's second number is an end (not included), while splice's is a count.
✗ "sort() sorts numbers from smallest to largest."
It sorts them as text: [10, 9, 1].sort() gives [1, 10, 9].
✓ "For numbers, write sort((a, b) => a - b)."
Or b - a for largest first. Remember that sort changes the original.
✗ "const b = a gives me a copy of the array."
It gives a second name for the same array.
✓ "A copy is a new array: [...a], a.slice() or Array.from(a)."
And === on arrays checks whether they are the same array, not whether they look alike.
✗ "A const array can never change."
Its elements can be pushed, popped, sorted and replaced freely.
✓ "const stops the name being pointed at another array."
marks = [1, 2] on a const marks throws a TypeError; marks.push(3) is fine.

Exam-style checks

Answer each one before opening it. For the "what does this print?" questions, trace the code on paper first, writing down the array after every line.

Which expression is true only when x is an array?L1
  • A. typeof x === "array"
  • B. x.length > 0
  • C. typeof x === "object"
  • D. Array.isArray(x)

Answer: D. typeof never gives "array", so A is never true; it gives "object" for arrays, plain objects and even null, so C is true for far more than arrays. Strings have a length too, so B proves nothing.

What does this print? const c = ["red", "green", "blue"]; console.log(c[c.length - 1], c[3]);L2
  • A. green undefined
  • B. blue undefined
  • C. undefined blue
  • D. An error, because index 3 does not exist

Answer: B. The length is 3, so c[c.length - 1] is c[2], "blue". Index 3 is past the end, and reading a missing index gives undefined rather than an error, which rules out D.

What does this print? const a = [5, 10]; const r = a.push(15); console.log(r);L2
  • A. [5, 10, 15]
  • B. 15
  • C. 3
  • D. undefined

Answer: C. push returns the new length of the array, 3. The array itself is now [5, 10, 15], which is why A is tempting, but that is a, not r.

Which method removes the first element of an array and returns it?L1
  • A. shift()
  • B. pop()
  • C. unshift()
  • D. slice(0, 1)

Answer: A. pop removes the last element, unshift adds at the start, and slice(0, 1) returns a new one-element array without removing anything.

What does ["Asha", "Rahul"].indexOf("Meera") return?L2
  • A. undefined
  • B. false
  • C. 0
  • D. -1

Answer: D. indexOf returns −1 when the value is not there, because −1 can never be a real index. 0 would mean "found at the first position"; false is what includes would give.

What does this print? const n = [10, 20, 30, 40, 50]; const s = n.slice(1, 3); console.log(s, n.length);L3
  • A. [20, 30, 40] 5
  • B. [20, 30] 3
  • C. [20, 30] 5
  • D. [10, 20, 30] 5

Answer: C. slice(1, 3) copies indexes 1 and 2 (the end, 3, is not included) and leaves n with all 5 elements. A includes the end; B wrongly assumes slice removed elements.

Predict the output: const n = [10, 20, 30, 40, 50]; const r = n.splice(1, 2); console.log(r, n);L3

Answer: [20, 30] [10, 40, 50]. In splice the second number is a count: starting at index 1, remove 2 elements. splice returns the removed elements as an array and takes them out of n itself.

What does [10, 9, 100, 1].sort() return?L2
  • A. [1, 9, 10, 100]
  • B. [1, 10, 100, 9]
  • C. [100, 10, 9, 1]
  • D. A TypeError, because sort needs a function

Answer: B. With no compare function, sort compares the elements as strings, in dictionary order: "1", "10", "100", then "9", because the character 1 comes before 9. A is what you get with sort((a, b) => a - b).

Which call sorts the array marks from the highest mark to the lowest?L3
  • A. marks.sort((a, b) => b - a)
  • B. marks.sort((a, b) => a - b)
  • C. marks.sort()
  • D. marks.reverse()

Answer: A. b - a is positive when b is larger, so the larger element goes first. B gives smallest first, C gives dictionary order, and D only flips the current order, which is highest-first only if the array happened to be sorted already.

Which of these leaves the original array unchanged?L2
  • A. reverse()
  • B. slice()
  • C. splice()
  • D. push()

Answer: B. slice returns a new array and never touches the original. reverse, splice and push all change the array they are called on.

What does this print? const a = [1, 2]; const b = a; b.push(3); console.log(a.length, a === b);L3
  • A. 3 true
  • B. 2 false
  • C. 2 true
  • D. TypeError: Assignment to constant variable

Answer: A. const b = a copies the reference, so a and b are one array; the push shows through a, and === confirms they are the same array. There is no TypeError: push changes the contents, and const only forbids re-pointing the name.

Predict the output: const [x, , z, ...rest] = [1, 2, 3, 4, 5]; console.log(x, z, rest);L3

Answer: 1 3 [4, 5]. Destructuring assigns by position: x gets index 0, the empty gap skips index 1, z gets index 2, and ...rest collects everything left into a new array.

Quick revision

Key takeaways

  1. An array is an ordered list of values under one name, written in square brackets. Its elements can be of any type, even other arrays.
  2. Indexes start at 0. The last element is arr[arr.length - 1] or arr.at(-1); a missing index gives undefined. Assign to an index to change an element.
  3. push/pop work at the end, unshift/shift at the start. push and unshift return the new length; pop and shift return the removed element.
  4. indexOf gives a position or −1, includes gives true/false, and find(test) gives the first element that passes, or undefined.
  5. slice(start, end) copies a part (end not included) and leaves the original alone. splice(start, count, ...items) removes and inserts in the original and returns what it removed.
  6. concat and [...a, ...b] combine into a new array; join makes a string; split and Array.from make an array.
  7. reverse and sort change the original. sort uses dictionary order unless you pass a compare function: (a, b) => a - b for numbers, smallest first.
  8. Arrays are shared by reference: b = a is a second name, not a copy; [...a] is a copy; === checks for the same array; const locks the name, not the contents.
