Multimedia Elements: Audio, Video and Iframes

Before HTML5, playing a video meant installing a plug-in. Now the browser plays audio and video natively, and an iframe can drop a map, a YouTube player or another whole page into yours. This chapter covers the audio and video elements and every attribute that controls them, the source and track children that make them robust and accessible, and the iframe with the security attributes you must understand before embedding anything.

About 17 minutes · Course outcome CO1

By the end of this chapter you can

  • Embed audio and video with working controls and multiple formats.
  • Explain controls, autoplay, muted, loop, poster and preload.
  • Add captions with track and fallback text for old browsers.
  • Embed external content with iframe, size it, title it, lazy-load it, and restrict it with sandbox and allow.
  • Explain why an autoplaying video stays silent and why some sites refuse to be framed.

10.1 Native media in HTML5

HTML5 added three things that changed the web: <audio> for sound, <video> for moving pictures, and standard, plug-in-free playback built into every browser. The pattern for both elements is the same: the element itself (which is not void: it always needs a closing tag), one or more <source> children pointing at media files, optional <track> children for captions, and fallback text between the tags for browsers that cannot play the element at all.

10.2 The audio element

<audio controls>
  <source src="https://interactive-examples.mdn.mozilla.net/media/cc0-audio/t-rex-roar.mp3" type="audio/mpeg">
  <source src="lecture.ogg" type="audio/ogg">
  Your browser does not support the audio element.
</audio>

controls is the attribute that matters most: it makes the browser show its native play, pause, seek and volume controls. Without it there is no visible player and no way for the visitor to start playback (unless a script does it). The text between the tags is the fallback: browsers that cannot play <audio> ignore the element and show the text instead. There is no alt attribute on audio or video, no <fallback> element, and a title on <source> does nothing of the kind.

Typical uses: music, narration, podcasts, pronunciation clips. As with images, provide a text alternative (a transcript) for audio that carries information.

10.3 The video element and its attributes

<video controls width="480" poster="https://picsum.photos/id/1015/480/270" preload="metadata">
  <source src="https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4" type="video/mp4">
  <source src="https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.webm" type="video/webm">
  Your browser does not support video. <a href="flower.mp4">Download the file</a> instead.
</video>

Why autoplay is usually silent. Unexpected noise is hostile: imagine opening a page in a library and it starts shouting. Browsers therefore block sound that starts on its own. A <video autoplay> that refuses to start on most mobile browsers is almost always missing muted; the fix is <video autoplay muted>. The poster, the number of sources and the controls attribute have nothing to do with it.

10.4 source and track

Why several source elements?

Browsers do not all support the same video formats. <source> lets you list several files; the browser reads them in order and plays the first format it supports, ignoring the rest. They do not all play at once, they do not increase resolution, and there is no minimum number. MP4 (H.264) plus WebM covers essentially every browser. The type attribute tells the browser the format so it can skip files it cannot play without downloading them.

track: captions and subtitles

<track> attaches timed text to a video: subtitles, captions for deaf and hard-of-hearing users, audio descriptions or chapter markers, stored in a .vtt (WebVTT) file. kind says which (subtitles, captions, descriptions, chapters), srclang the language, label the name shown in the player's menu, and default turns it on initially. It is a void element and goes after the sources. The element that supplies subtitles is <track>: not <caption> (tables), not <source> (media files), not <subtitle> (does not exist).

<video controls width="480">
  <source src="lecture.mp4" type="video/mp4">
  <track src="captions-en.vtt" kind="captions" srclang="en" label="English" default>
  <track src="captions-hi.vtt" kind="captions" srclang="hi" label="Hindi">
</video>

10.5 The iframe: a window into another document

An inline frame, <iframe>, embeds another HTML document inside the current one: a YouTube player, a Google Map of the campus, a payment widget, a PDF viewer, a dashboard. The embedded page is a separate browsing context with its own URL, and it is not part of your document's DOM. src gives its address; width and height give the frame its displayed size on the page.

<iframe
  src="https://www.openstreetmap.org/export/embed.html?bbox=75.690%2C31.245%2C75.715%2C31.265&layer=mapnik&marker=31.2555%2C75.7029"
  width="100%" height="260"
  title="Map of the Lovely Professional University campus"
  loading="lazy">
</iframe>

The attributes that matter

AttributePurpose
srcThe URL of the document to embed
width, heightDisplayed size (there are no rows/cols, size/scale or x/y attributes)
titleAn accessible name for the embedded content. Every iframe should have one: without it a screen reader announces only "frame". It is not a visible heading and it is not required for loading
loading="lazy"Defer loading the frame until it is near the viewport, exactly as for images
allowGrants the embedded content specific capabilities such as fullscreen, camera, microphone, geolocation or autoplay (a Permissions Policy)
sandboxRestricts what the embedded content may do. An empty sandbox applies every restriction: no scripts, no forms, no pop-ups, treated as a foreign origin. Add tokens to re-enable specific things: allow-scripts, allow-forms, allow-popups, allow-same-origin
The sandbox surprise. An embedded widget that stops working the moment you add sandbox has almost certainly lost its scripts: an empty sandbox blocks all JavaScript in the frame until you add allow-scripts. Sandbox does not ignore src, does not remove width and height, and does not force lazy loading.

Using iframes responsibly

Embedding third-party content is a trade. The embedded site may set cookies, track your users and slow the page down, because its scripts run in your visitor's browser. So: embed only from trusted sources, keep the frame responsive (a percentage width or CSS), always give it a title, and use sandbox/allow to grant only what the widget needs. Iframes do not disable the parent's CSS or the back button.

One more thing that is not your bug: many sites refuse to be embedded. If your iframe of a large website stays blank, the remote site sent a header (X-Frame-Options or a Content Security Policy) that forbids framing. That is their choice; nothing in your HTML will override it. Sites that want to be embedded, such as YouTube and map providers, give you a special embed URL (https://www.youtube.com/embed/VIDEO_ID) precisely for this.

10.6 Worked example: a college event page

<h1>Tech Fest 2026</h1>
<h2>Promo video</h2>
<video controls width="420" poster="https://picsum.photos/id/1035/420/236" loop muted>
  <source src="https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4" type="video/mp4">
  Your browser does not support video.
</video>
<h2>Announcement (audio)</h2>
<audio controls preload="none">
  <source src="https://interactive-examples.mdn.mozilla.net/media/cc0-audio/t-rex-roar.mp3" type="audio/mpeg">
  Your browser does not support audio.
</audio>
<h2>Venue</h2>
<iframe src="https://www.openstreetmap.org/export/embed.html?bbox=75.690%2C31.245%2C75.715%2C31.265&layer=mapnik"
  width="420" height="200" title="Map of the venue" loading="lazy"></iframe>

Read the choices: controls on both media elements so visitors can play them; loop muted on the promo so it could autoplay if we wanted; a poster so there is something to see before playback; preload="none" on the audio so it costs nothing until played; a titled, lazy-loaded iframe for the map.

Exam-style checks

Which attribute makes the browser's native playback controls appear on an <audio> or <video> element?L2
  • A. autoplay
  • B. muted
  • C. preload
  • D. controls

Answer: D. Without controls there is no way for the visitor to start playback.

What does controls="false" do on a <video>?L3

Answer: it shows the controls anyway. controls is a boolean attribute; only its presence matters. Remove it to hide the controls.

A <video autoplay> refuses to start on most mobile browsers. What is the most likely reason?L3
  • A. The poster attribute is missing
  • B. Autoplay is blocked unless the video is also muted
  • C. The video has more than one <source>
  • D. The controls attribute was not set

Answer: B. Browsers block sound that starts on its own; add muted.

Which <video> attribute makes playback repeat automatically when it ends?L1
  • A. repeat
  • B. loop
  • C. autoplay
  • D. replay

Answer: B.

In <video controls poster="preview.jpg">, what does the poster attribute do?L3
  • A. Forces the video to start automatically
  • B. Adds subtitle text to the video
  • C. Sets the image shown before playback begins
  • D. Sets the download filename of the video

Answer: C.

Which <video> attribute hints how much of the file the browser should fetch before playback?L2
  • A. preload
  • B. poster
  • C. buffer
  • D. loading

Answer: A. Values: none, metadata, auto.

Why does a <video> element often contain more than one <source>?L3
  • A. So the browser can select the first format it supports
  • B. So all the files play at the same time
  • C. To increase the resolution of the video
  • D. Because <video> requires a minimum of two sources

Answer: A. mp4 plus webm covers essentially every browser.

Which element supplies subtitles or captions for a <video>?L2
  • A. <caption>
  • B. <track>
  • C. <source>
  • D. <subtitle>

Answer: B. <track src="captions.vtt" kind="subtitles" srclang="en" label="English">.

How is a fallback message provided for browsers that cannot play an <audio> element?L3
  • A. Text placed between the opening and closing <audio> tags
  • B. An alt attribute on the <audio> element
  • C. A <fallback> element inside <audio>
  • D. A title attribute on the <source> element

Answer: A. Browsers that ignore the element display its content.

Which element is NOT an empty element: <source>, <video>, <img>, <meta>?L2

Answer: <video>. It always needs a closing tag, even when you use src, because its content is the sources, tracks and fallback text.

Which element embeds another web page inside the current one?L1
  • A. <embed>
  • B. <iframe>
  • C. <object>
  • D. <frame>

Answer: B. An inline frame embeds a whole separate document.

Which attributes give an <iframe> its displayed size on the page?L2
  • A. rows and cols
  • B. size and scale
  • C. width and height
  • D. x and y

Answer: C.

Why should every <iframe> carry a title attribute?L2
  • A. It sets the visible heading displayed above the frame
  • B. It gives screen-reader users an accessible name for the embedded content
  • C. It is required before the frame will load
  • D. It improves the video quality inside the frame

Answer: B. Without it a screen reader announces only "frame".

Which <iframe> attribute grants the embedded content specific capabilities such as fullscreen or camera access?L3
  • A. allow
  • B. sandbox
  • C. permit
  • D. enable

Answer: A. allow grants; sandbox restricts.

An embedded widget stops working after sandbox is added to its <iframe>. What is the most likely cause?L3
  • A. The frame's src attribute is ignored when sandbox is present
  • B. Scripts inside the frame are blocked until allow-scripts is added
  • C. sandbox removes the frame's width and height
  • D. sandbox forces the frame to load lazily

Answer: B. An empty sandbox applies every restriction, including no JavaScript.

Which is a genuine concern when embedding third-party content in an <iframe>?L2
  • A. It prevents the parent page from using CSS
  • B. It may set cookies, track users and slow the page down
  • C. It disables the browser's back button
  • D. It converts the page to plain text

Answer: B.

Your iframe stays blank when embedding a large website. Why?L3

Answer: the remote site forbids being embedded (a framing-refusal header). It is their choice, not a bug in your HTML; use the site's official embed URL if it offers one.

What does loading="lazy" do on an image or iframe?L2

Answer: it delays loading until the element is nearly on screen: a genuine performance win on long pages.

Quick revision

Key takeaways

  1. audio and video are paired elements: sources inside, track for captions, fallback text between the tags. No alt attribute.
  2. controls shows the player (boolean: presence only). autoplay needs muted. loop repeats. poster is the pre-play image. preload = none / metadata / auto.
  3. Several source elements = a fallback chain; the browser plays the first format it supports. mp4 + webm covers everyone.
  4. track src kind srclang label supplies subtitles/captions from a .vtt file.
  5. iframe embeds another document: src, width, height, a title for accessibility, loading="lazy".
  6. sandbox removes capabilities (add allow-scripts, allow-forms to restore); allow grants capabilities (fullscreen, camera). Third-party frames can track and slow; many sites refuse framing.
