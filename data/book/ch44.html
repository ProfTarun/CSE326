Operators and Expressions

A variable holds a value; an operator does something with it. Adding up marks, checking whether a student has passed, joining a first name to a surname, falling back to "Guest" when a box is left empty — each of those is one expression built from operators. This chapter teaches the two dozen or so symbols that do most of the work in JavaScript, and the handful of places where they behave in ways that catch out beginners and professionals alike.

About 30 minutes · Course outcome CO4

Before you start — one-line reminders

  • let makes a variable you can change later; const makes one you cannot reassign (Chapter 42).
  • A variable declared without a value holds undefined (Chapter 42).
  • Every value has a type — number, string, boolean, undefined, null — and typeof names it (Chapter 43).
  • JavaScript sometimes changes a value's type on its own, which is why "5" + 1 gives "51" (Chapter 43).

By the end of this chapter you can

  • Tell an expression from a statement, and point to the operands and operators in any line of code.
  • Predict the result of arithmetic with /, % and **, and with prefix and postfix ++.
  • Say when + adds and when it joins text, and convert typed input before doing maths with it.
  • Update a variable with +=, -=, *=, /= and %=.
  • Compare values with === and !==, and explain the surprises that == causes.
  • Combine conditions with &&, || and !, and choose correctly between || and ?? for a default value.
  • Work out the order of a mixed expression from operator precedence, and add brackets to make it clear.

44.1 Expressions, operands and operators

In school you wrote 5 + 2 = 7 without a second thought. JavaScript borrows the same idea and gives its parts names. The 5 and the 2 are the values being worked on; they are called operands. The + is the action; it is called an operator. Put them together and you have an expression: a piece of code that JavaScript evaluates to produce one value. 5 + 2 is an expression, and its value is 7.

Expressions come in every size. A lone value is the smallest kind: 40 is an expression whose value is 40, and so is "Asha". A variable name on its own is an expression too; its value is whatever is in the box at that moment. Bigger expressions are built out of smaller ones, so price * qty + 40 is the smaller expression price * qty, then an operator, then 40.

A statement is something different. It is a complete instruction — one whole sentence of the program — and it usually ends with a semicolon. let total = price * qty + 40; is a statement: it tells JavaScript to work out the expression on the right and store the answer in a new variable called total. console.log(total);, which you met in Chapter 41, is a statement as well.

An expression is a question with an answer: "what is price times qty plus 40?" The answer is one value. A statement is an order: "make a box called total and put that answer in it." Orders often contain questions; a question never contains an order.

A handy test: if a piece of code could sit inside console.log( ... ) and print a value, it is an expression. console.log(price * qty) works. console.log(let x = 5) is a SyntaxError, because let x = 5 is a statement, not a value.

One, two or three operands

Operators are also sorted by how many operands they need:

KindOperandsExamples
UnaryOne-x, !done, typeof x, count++
BinaryTwo, one on each sidea + b, marks >= 40, x = 5
TernaryThreemarks >= 40 ? "Pass" : "Fail" — the only one

Most operators are symbols, but a few are words, such as typeof. The rest of this chapter takes them family by family: arithmetic, assignment, comparison, logical, and the few that are left. Then it settles the question of which one goes first.

Quick check: in let area = length * width;, what is the expression on the right, and what are its operands?

length * width is the expression — it works out to one value. Its operands are length and width, and * is the operator. The whole line, ending with the semicolon, is a statement.

44.2 Arithmetic operators

These are the calculator keys. Six of them cover all of ordinary arithmetic. The table uses the lecture's example values, x = 5 and y = 2:

OperatorNameExampleResult
+Additionx + y7
-Subtractionx - y3
*Multiplicationx * y10
/Divisionx / y2.5
%Remainder (often called modulus)x % y1
**Exponent (power)x ** y25

Four of them deserve a closer look.

Multiplication is * and division is /, because keyboards have no × or ÷ keys. Writing 5 x 2 is a SyntaxError: JavaScript reads the x as a variable name sitting where an operator should be.

Division keeps the decimal. 5 / 2 is 2.5, not 2. If you have used C or Java you may expect whole-number division to throw the fraction away; JavaScript's ordinary number type holds whole numbers and decimals alike, so nothing is thrown away. When you do want a whole number, Math.floor() rounds down (Chapter 46). Dividing by zero is not an error either: 10 / 0 is Infinity and 0 / 0 is NaN, "Not a Number", which Chapter 46 also explains.

% is the remainder, not a percentage. It divides the left number by the right one and gives back only what is left over. 17 % 5 is 2, because 5 goes into 17 three times (making 15) with 2 left over. 5 % 2 is 1. 10 % 5 is 0, because 5 goes in exactly.

Share 17 laddoos equally among 5 friends. Each friend gets 3, and 2 stay in the box. 17 / 5 answers "how much does each get?" (3.4, if you could cut laddoos). 17 % 5 answers "how many are left in the box?" (2).

The remainder is far more useful than it looks. A number is even exactly when n % 2 is 0, and odd when it is 1. Every third row of a table is a row where row % 3 is 0. And 135 minutes is 2 whole hours with 135 % 60 = 15 minutes over. To find an actual percentage, multiply and divide: 18% of 500 is 500 * 18 / 100, which is 90.

** raises to a power. 2 ** 10 is 1024, and 9 ** 0.5 is 3, the square root. Older code writes Math.pow(2, 10) for the same thing.

<script>

  console.log("Subtraction:", x - y);      // 3

  let left = minutes % 60;                 // 15

  // a real percentage: multiply, then divide by 100
  console.log("18% of 500 is", 500 * 18 / 100);   // 90
</script>
Quick check: what are 20 % 6 and 6 % 20?

20 % 6 is 2: 6 goes into 20 three times (18) with 2 left over. 6 % 20 is 6: 20 does not fit into 6 even once, so the whole 6 is left over.

44.3 Increment and decrement

Adding one to a variable happens so often — counting visitors, moving to the next question, scoring a run — that JavaScript has a two-character shortcut for it. count++ adds 1 to count, and count-- subtracts 1. On a line of their own, with a number in the variable, they do the same job as count = count + 1 and count = count - 1. You will see i++ in nearly every loop in Chapter 52.

let score = 0;
score++;       // 1
score++;       // 2
score--;       // 1

The two plus signs can go after the variable (postfix, a++) or before it (prefix, ++a). On a line of its own there is no difference at all. The difference appears only when the increment is part of a bigger expression, because the expression a++ and the expression ++a hand back different values:

let a = 5;
let b = a++;   // postfix: b gets the OLD value 5, then a becomes 6

let c = 5;
let d = ++c;   // prefix: c becomes 6 first, then d gets the NEW value 6
Starting with x = 5Value the expression givesx afterwards
x++5 (the old value)6
++x6 (the new value)6
x--5 (the old value)4
--x4 (the new value)4

Postfix (x++): use the value, then bump it. Prefix (++x): bump it, then use the value. Either way the variable ends up one bigger; only the value handed to the rest of the line is different.

Two rules follow from what ++ does. It needs a variable to change, so 5++ is a SyntaxError. And it really does change that variable, so using it on a const throws TypeError: Assignment to constant variable. — the same error you met in Chapter 42.

Exam tip. Predict-the-output questions love lines like let x = 3; let y = x++ + ++x;. Work left to right and write down x after every step: x++ gives 3 and makes x 4; then ++x makes x 5 and gives 5; so y is 3 + 5 = 8 and x ends at 5. In your own code, keep ++ on a line of its own and nobody ever has to do this.
<p>The answers are in the Console panel below.</p>
<script>
  let a = 5;
  let b = a++;          // postfix: b gets the OLD value, then a goes up
  console.log("After b = a++ : b is", b, "and a is", a);   // b is 5 and a is 6

  let c = 5;
  let d = ++c;          // prefix: c goes up FIRST, then d gets the new value
  console.log("After d = ++c : d is", d, "and c is", c);   // d is 6 and c is 6

  // on a line of their own, x++ and ++x do the same job
  let visitors = 0;
  visitors++;
  visitors++;
  ++visitors;
  console.log("Visitors today:", visitors);                // 3

  let lives = 3;
  lives--;
  console.log("Lives left:", lives);                       // 2

  // the exam favourite: work it left to right
  let x = 3;
  let y = x++ + ++x;    // 3 + 5
  console.log("y is", y, "and x is", x);                   // y is 8 and x is 5
</script>

44.4 When + joins text instead of adding

The + operator has two jobs. Between two numbers it adds. When either side is a string, it switches jobs and joins the two pieces of text end to end. Joining text like this is called concatenation.

"Asha" + " " + "Verma"   // "Asha Verma"
"Marks: " + 85           // "Marks: 85"   the number 85 becomes the text "85"
"5" + 2                  // "52"
5 + "2"                  // "52"

When one side is a number and the other is a string, JavaScript turns the number into text and joins them. This automatic change of type is called coercion, and Chapter 43 introduced it. It is handy for building messages, and it is behind one of the commonest bugs in beginner code.

Left to right, one pair at a time

A chain of + signs is worked out from the left, one pair at a time, and each pair decides for itself whether to add or to join:

2 + 3 + "5"           // 2 + 3 is 5, then 5 + "5" is "55"
"5" + 2 + 3           // "5" + 2 is "52", then "52" + 3 is "523"
"Total: " + 2 + 3     // "Total: 23"   the classic bug
"Total: " + (2 + 3)   // "Total: 5"    brackets make the sum happen first

Once a string has appeared in the chain, everything to its right is joined, not added. Brackets fix it, because the bracketed part is worked out first, while it is still two numbers.

The other operators only do maths

-, *, /, % and ** have only one job, arithmetic, so when they meet a string they try to turn it into a number first:

"10" - 2      // 8
"10" * "2"    // 20
"6" / "2"     // 3
"abc" - 1     // NaN   "abc" is not a number, so the answer is Not-a-Number
Key idea. + joins as soon as a string is involved. Every other arithmetic operator turns strings into numbers. That one asymmetry explains every result in this section.
Everything a user types is a string. The value of a form field, and whatever prompt() returns when the user presses OK, is text even when it looks like a number (if the user presses Cancel, prompt() gives null instead). So if typed holds "40", then typed + 5 gives "405", not 45. Convert first: Number(typed) + 5 is 45. You will also meet the shorthand +typed (the unary plus), which does the same conversion, but Number() says what it means. Chapter 46 covers Number(), parseInt() and parseFloat() properly.

Joining many pieces with + soon gets messy. Template literals, written with backticks, drop values straight into text: `Total: ${2 + 3}` gives "Total: 5". Chapter 45 teaches them.

<p>The answers are in the Console panel below.</p>
<script>
  console.log("Asha" + " " + "Verma");          // Asha Verma
  console.log("5" + 2, typeof ("5" + 2));       // 52 string
  console.log(5 + 2, typeof (5 + 2));           // 7 number

  // left to right, one pair at a time
  console.log(2 + 3 + "5");                     // 55
  console.log("5" + 2 + 3);                     // 523
  console.log("Total: " + 2 + 3);               // Total: 23  (the classic bug)
  console.log("Total: " + (2 + 3));             // Total: 5   (brackets fix it)

  // - * / only do maths, so they turn strings into numbers
  console.log("10" - 2);                        // 8
  console.log("10" * "2");                      // 20
  console.log("abc" - 1);                       // NaN

  // what a form or prompt() gives you is ALWAYS a string
  let typed = "40";
  console.log("Wrong:", typed + 5);             // Wrong: 405
  console.log("Right:", Number(typed) + 5);     // Right: 45
</script>
Quick check: what do "3" + 4 + 5 and 3 + 4 + "5" give?

"345": the string comes first, so every + after it joins. "75": 3 + 4 is added to make 7 while both are still numbers, and only then is 7 joined to "5".

44.5 Assignment and compound assignment

You have been using one operator since Chapter 42: =, the assignment operator. It does not mean "equals". It means: work out the value on the right, then store it in the variable on the left. Read it right to left, like an arrow pointing into the box.

let marks = 70;
marks = marks + 5;   // right side first: 70 + 5 is 75, THEN store 75 in marks

In maths, marks = marks + 5 would be nonsense, because no number equals itself plus five. In JavaScript it is perfectly ordinary: the right side is worked out completely, using the old value, before anything is stored.

Compound assignment: update in place

"Take the variable, do something to it, store it back" is so common that every arithmetic operator has a combined form. Here is the example from the lecture slides, one step at a time:

let num = 10;
num += 5;    // num = num + 5    num is now 15
num -= 3;    // num = num - 3    num is now 12
num *= 2;    // num = num * 2    num is now 24
num /= 4;    // num = num / 4    num is now 6

+= follows the same rules as +, so on a string it joins. That makes it the natural way to build up a message, or to keep a running total:

let greeting = "Welcome";

Every assignment changes a variable, so all of these need a variable that is allowed to change, such as one declared with let. On a const they throw TypeError: Assignment to constant variable.

One = stores; three === compare. marks = 40 puts 40 into marks. marks === 40 asks whether marks holds 40 and answers true or false. Typing one when you meant the other is the most common bug in decisions (Chapter 47), and JavaScript will not warn you, because both are legal code.

44.6 Comparison operators

A comparison asks a yes-or-no question about two values, and the answer is always a boolean: true or false. The lecture uses a = 10 and b = 5:

Write >= and <= with the equals sign second. => is something else entirely (an arrow function, Chapter 48), and =< is a SyntaxError. Because a comparison produces a value, you can store it: let passed = marks >= 40; puts true or false into passed, ready for an if in Chapter 47.

Strict === against loose ==

JavaScript has two equality operators, and the difference matters. ===, strict equality, is true only when both values have the same type and the same value; it never converts anything. ==, loose equality, first converts the two values to a common type if their types differ, and only then compares. Their opposites are !== (strict not-equal) and != (loose not-equal).

The conversion rules behind == are long and odd, and they produce results like these:

=== asks two honest questions: same type? same value? == quietly changes one side to look like the other before it asks, and its rules for doing that fill pages. Use === and !== every time and you never need to learn those rules.

If you really do need to compare typed text with a number, convert it yourself and then compare strictly: Number(typed) === 40 says exactly what you mean. And to test whether something is NaN, use Number.isNaN(value) (Chapter 46), because value === NaN is always false.

Comparing strings

< and > work on strings too, character by character, like a dictionary: "apple" < "banana" is true because a comes before b. Two surprises follow. Every capital letter counts as coming before every small letter, so "Zebra" < "apple" is true. And digits inside strings are compared as characters, not as numbers, so "10" < "9" is true, because the character 1 comes before the character 9. If one side is a real number, the string is converted and proper maths happens: "10" < 9 is false. The lesson is the same as before: turn typed numbers into real numbers before you compare them.

<script>
  // the slide example
  let a = 10;
  let b = 5;
  console.log("a > b:", a > b);         // true
  console.log("a < b:", a < b);         // false
  console.log("a >= b:", a >= b);       // true
  console.log("a <= b:", a <= b);       // false
  console.log("a === b:", a === b);     // false
  console.log("a !== b:", a !== b);     // true

  // == converts first, === does not
  console.log("5 == '5' gives", 5 == "5");                     // true
  console.log("5 === '5' gives", 5 === "5");                   // false
  console.log("0 == '' gives", 0 == "");                       // true
  console.log("0 == false gives", 0 == false);                 // true
  console.log("null == undefined gives", null == undefined);   // true
  console.log("NaN === NaN gives", NaN === NaN);               // false (!)

  // strings compare character by character, like a dictionary
  console.log("'apple' < 'banana' gives", "apple" < "banana");   // true
  console.log("'10' < '9' gives", "10" < "9");                   // true - compared as text!
  console.log("'10' < 9 gives", "10" < 9);                       // false - one real number
</script>

44.7 Logical operators and short-circuiting

Real decisions rarely rest on a single comparison. You may vote if you are 18 or over and you have a voter ID. The office is shut if it is Saturday or Sunday. The logical operators combine true-or-false values in exactly that way:

OperatorNameGives true when
&&ANDboth sides are true

The lecture's example, with p true and q false:

let p = true;
let q = false;
console.log(p && q);   // false   AND needs both
console.log(p || q);   // true    OR needs only one
console.log(!p);       // false   NOT flips

In real code the operands are usually comparisons:

let canVote   = age >= 18 && hasVoterId;
let isWeekend = day === "Sat" || day === "Sun";
let mustRetake = !passed;
A range needs two comparisons. 18 <= age <= 60 looks right and is true for every age. JavaScript works it left to right: 18 <= age becomes true or false, and then that boolean is compared with 60, which converts true to 1 and false to 0 — both less than 60. Write age >= 18 && age <= 60.

Short-circuit evaluation

JavaScript works through && and || from left to right and stops the moment the answer is certain. If the left side of && is false, the whole thing must be false, so the right side is never even looked at. If the left side of || is true, the whole thing must be true, so again the right side is skipped. This is called short-circuit evaluation.

Picture this. The guard at the hostel gate has a rule: show your ID card AND your gate pass. If you have no ID card, he does not even ask for the pass — the answer is already no. That is &&. The library desk has a different rule: ID card OR fee receipt. Show the ID card and you are waved in without anyone asking for the receipt — the answer is already yes. That is ||. JavaScript is that sensible guard: it stops checking the moment the answer cannot change.

&& and || hand back a value, not just true or false

Here is the part most beginners never learn. && and || do not turn their answer into true or false. They return whichever operand they stopped at, unchanged. With booleans on both sides you cannot tell the difference, but with other values you can:

"Asha" || "Guest"    // "Asha"    left side is truthy, so stop there
"" || "Guest"        // "Guest"   left side is falsy, so take the right side
0 && "anything"      // 0         left side is falsy, so stop there
"yes" && "go"        // "go"      left side is truthy, so take the right side

"Truthy" and "falsy" describe how a value behaves where JavaScript expects true or false. The falsy values are false, 0, the empty string "", null, undefined and NaN. Everything else is truthy, including "0", "false" and a string holding a single space. Chapter 46 gives the complete list, including a few rarer members.

This gives the most common use of || in real code: a default value. let name = typedName || "Guest"; reads as "use what was typed, or Guest if nothing was". If typedName is an empty string, it is falsy, so name becomes "Guest".

<p>The answers are in the Console panel below.</p>
<script>
  // the slide example
  let p = true;
  let q = false;
  console.log("p && q:", p && q);     // false
  console.log("p || q:", p || q);     // true
  console.log("!p:", !p);             // false

  // real conditions
  let age = 19;
  let hasVoterId = true;
  console.log("Can vote:", age >= 18 && hasVoterId);         // true

  let day = "Sun";
  console.log("Weekend:", day === "Sat" || day === "Sun");   // true

  // a range needs two comparisons joined by &&
  let grandpa = 75;
  console.log("Wrong range test:", 18 <= grandpa <= 60);              // true (!)
  console.log("Right range test:", grandpa >= 18 && grandpa <= 60);   // false

  // short-circuit: the right side is skipped when the answer is already known
  false && console.log("You will never see this line");
  true || console.log("Nor this one");
  true && console.log("This one prints, because && had to look");

  // || and && hand back one of the two VALUES
  console.log("Asha" || "Guest");     // Asha
  console.log("" || "Guest");         // Guest
  console.log(0 && "anything");       // 0
</script>

44.8 Nullish coalescing: ?? versus ||

The || default has a flaw. It replaces every falsy value, and some falsy values are real answers. Meera sat the test and scored 0. Watch what happens:

let marks = 0;
let shown = marks || "Not entered";   // "Not entered"   but she scored 0!

The nullish coalescing operator, ??, fixes this. It uses the right side only when the left side is null or undefined — the two values that really mean "nothing here". Together those two are called nullish. A 0, an empty string or false is kept, because each of them is a real value.

let marks = 0;
let shown = marks ?? "Not entered";    // 0   correct

let notYet;                            // undefined: nothing entered
let shown2 = notYet ?? "Not entered";  // "Not entered"
Left valueleft || "default"left ?? "default"
"Asha""Asha""Asha"
0"default"0
"""default"""
false"default"false

null"default""default"

|| means "if this is empty-ish, use the default". ?? means "if this is missing, use the default". A score of 0 is not missing, so it needs ??. A blank name box is as good as missing, so || is fine there.

Choose ?? when 0, an empty string or false can be a genuine value — a mark, a count, a volume level, a "no" from a checkbox. Choose || when any empty value should be replaced, such as a blank name becoming "Guest". One rule of grammar: ?? cannot be mixed directly with && or ||. a || b ?? c is a SyntaxError; add brackets to say which you mean, such as (a || b) ?? c.

<p>The answers are in the Console panel below.</p>
<script>
  let meeraMarks = 0;          // Meera really scored 0
  let rahulMarks;              // nothing entered yet: undefined

  console.log("Meera with ||:", meeraMarks || "Not entered");   // Not entered  (wrong!)
  console.log("Meera with ??:", meeraMarks ?? "Not entered");   // 0            (right)
  console.log("Rahul with ||:", rahulMarks || "Not entered");   // Not entered
  console.log("Rahul with ??:", rahulMarks ?? "Not entered");   // Not entered

  // a blank name SHOULD become "Guest", so || is the right tool here
  let typedName = "";
  console.log("Hello,", typedName || "Guest");     // Hello, Guest
  console.log("Hello,", typedName ?? "Guest");     // Hello,   (the empty string is kept)

  let volume = 0;              // the user switched the sound off on purpose
  console.log("Volume with ||:", volume || 50);    // 50  (the sound comes back on!)
  console.log("Volume with ??:", volume ?? 50);    // 0
</script>
Quick check: what does false ?? true give?

false. ?? replaces only null and undefined, and false is neither, so it is kept. (false || true would give true.)

44.9 Two more: typeof and the ternary operator

typeof

Chapter 43 used typeof to find out a value's type. It is worth seeing again for what it is: an operator, a unary one, spelled as a word. It takes one operand and returns a string naming that operand's type.

typeof 42           // "number"
typeof "42"         // "string"
typeof true         // "boolean"
typeof undefined    // "undefined"
typeof null         // "object"   a famous old mistake, kept so old sites still work (Chapter 43)
typeof typeof 42    // "string"   the answer is always a string

Because it is an operator and not a function, the brackets in typeof(x) are optional; they only group, as brackets always do. They do matter when other operators are nearby, because typeof grabs just the operand right next to it. typeof 5 + 5 is "number5": typeof 5 runs first and gives "number", and then "number" + 5 joins. typeof (5 + 5) is "number".

A practical use is checking a value before doing maths with it: typeof marks === "number" is true only when marks holds a number (careful: NaN also reports "number", a quirk Chapter 46 explains). And unlike almost anything else, typeof does not crash on a name that was never declared anywhere: typeof somethingUnknown is "undefined", where using the name in any other way throws a ReferenceError.

The ternary operator

The only operator with three operands picks one of two values, depending on a condition:

condition ? valueIfTrue : valueIfFalse

let result = marks >= 40 ? "Pass" : "Fail";

Read the ? as "then" and the : as "otherwise": is marks at least 40? then "Pass", otherwise "Fail". Because it is an expression, it produces a value, so you can store it, print it or join it into text. Chapter 47 sets it beside if...else and shows when each one is the better choice.

44.10 Precedence: who goes first

When an expression holds several operators, JavaScript needs a rule for which to do first. You learnt one such rule in school as BODMAS: brackets, then division and multiplication, then addition and subtraction. JavaScript's rule is the same idea stretched to cover every operator, and it is called operator precedence.

2 + 3 * 4       // 14   * outranks +, so 3 * 4 happens first
(2 + 3) * 4     // 20   brackets first

Here is a real bug that precedence causes. Asha scored 80 and 90, so her average should be 85:

let wrong = 80 + 90 / 2;     // 125   only the 90 was halved
let right = (80 + 90) / 2;   // 85

The ranking

You do not need to memorise the full official table, which has around twenty levels. These rows cover everything in this chapter, highest first:

RankOperatorsNotes
1( )Brackets: always first
2x++ x--Postfix increment and decrement
3! typeof -x +x ++x --xUnary operators: they grab the one operand next to them
4**Power. Works right to left
5* / %Same rank: left to right
6+ -Same rank: left to right
7< <= > >=Comparisons
8=== !== == !=Equality
9&&AND before OR
10|| ???? cannot be mixed with || or && without brackets
11? : and = += -= …Ternary and assignment: last of all. Work right to left

When two operators share a rank, associativity decides. Most work left to right: 10 - 4 - 3 is (10 - 4) - 3, which is 3, not 10 - 1 = 9; and 100 / 10 * 2 is 20, not 5. Two rows of the table work right to left. One is **, so 2 ** 3 ** 2 is 2 ** 9, which is 512. The other is the bottom row, the ternary and assignment, so a = b = 0 first stores 0 in b and then stores that same value in a. (That works because an assignment is itself an expression, whose value is the value it just stored.)

A few results the table explains:

  • !marks >= 40 is always false. ! outranks >=, so it turns marks into true or false first, and neither of those is at least 40. Write !(marks >= 40), or more simply marks < 40.
  • a || b && c means a || (b && c), because AND outranks OR.
  • total + bonus ?? 0 adds first. If bonus is undefined, then total + undefined is NaN, and NaN ?? 0 stays NaN, because NaN is not nullish. Write total + (bonus ?? 0).
  • -2 ** 2 is a SyntaxError. JavaScript refuses to guess whether you meant (-2) ** 2, which is 4, or -(2 ** 2), which is -4, and makes you write the brackets.

Remember the shape, not the table: brackets first, then the maths (power, then times and divide, then plus and minus), then comparisons, then AND, then OR, and storing the answer last of all. Whenever you are not sure, add brackets. They cost nothing: brackets that only spell out what JavaScript would do anyway never change the answer, and the next person to read your code will not have to guess.

44.11 Common misunderstandings

✗ "= checks whether two values are equal."
It does not check anything. It stores the right-hand value in the left-hand variable.
✓ "= stores; === compares."
marks = 40 changes marks. marks === 40 asks a question and answers true or false.
✗ "% works out a percentage."
The symbol looks like one, but it means something else.
✓ "% is the remainder after division."
17 % 5 is 2. For 18% of 500, write 500 * 18 / 100.
✗ "== and === do the same job; === is just a stricter style."
They give different answers whenever the types differ.
✓ "== converts types before comparing; === never does."
That is why 0 == "" and 0 == false are true. Use === and !==.
✗ "18 <= age <= 60 checks a range."
It compares true or false with 60, so it is true for every age.
✓ "age >= 18 && age <= 60 checks a range."
Two separate comparisons, joined by AND.
✗ "|| is how you give a default value."
Only when every falsy value should be replaced, and a mark of 0 should not be.
✓ "|| replaces any falsy value; ?? replaces only null and undefined."
Use ?? when 0, "" or false can be a real answer.
✗ "A number typed into a form can be added straight away."
Typed input is always a string, so + joins it.
✓ "Convert typed input first."
"40" + 5 is "405"; Number("40") + 5 is 45.

Exam-style checks

Which operator gives the remainder after division?L1
  • A. /
  • B. %
  • C. **
  • D. //

Answer: B. 17 % 5 is 2. / gives the full quotient (3.4), ** raises to a power, and // is not an operator at all: it starts a comment.

What does console.log("5" + 3); print?L2
  • A. 8
  • B. NaN
  • C. 53
  • D. An error

Answer: C. One side is a string, so + joins: the number 3 becomes "3" and the result is the string "53". 8 would need both sides to be numbers, and there is no error because joining is one of the two legal jobs of +.

What does console.log("10" - 4); print?L2
  • A. 6
  • B. 104
  • C. NaN
  • D. 10-4

Answer: A. - only does arithmetic, so it converts "10" to the number 10 and subtracts. Only + has a joining job; 104 is what "10" + 4 would give.

What does this print? let x = 5; let y = x++; console.log(x, y);L3
  • A. 5 5
  • B. 6 6
  • C. 5 6
  • D. 6 5

Answer: D. Postfix x++ hands the old value, 5, to y, and then increases x to 6. The prefix form let y = ++x; would have printed 6 6.

Which of these comparisons is true?L2
  • A. 5 === "5"
  • B. 0 == ""
  • C. NaN === NaN
  • D. null === undefined

Answer: B. Loose == converts the empty string to 0, so 0 == "" is true — exactly the kind of surprise that makes === the safer choice. A and D are false because the types differ and === never converts; C is false because NaN equals nothing, not even itself.

The lecture code is let num = 10; num += 5; num -= 3; num *= 2; num /= 4;. What is num at the end? Show each step.L3

Answer: 6. 10 + 5 = 15, then 15 − 3 = 12, then 12 × 2 = 24, then 24 ÷ 4 = 6. Each compound operator uses the variable's current value and stores the result back in the same variable.

What does this print? let marks = 0; console.log(marks || "Absent", marks ?? "Absent");L3
  • A. 0 0
  • B. Absent Absent
  • C. Absent 0
  • D. 0 Absent

Answer: C. 0 is falsy, so || moves on to the right side and gives "Absent". ?? replaces only null and undefined; 0 is neither, so it stays 0. That is why ?? is the right default for marks, counts and anything else where 0 is a real value.

What is the value of 2 + 3 * 4 ** 2?L2
  • A. 400
  • B. 196
  • C. 146
  • D. 50

Answer: D. ** first: 4 ** 2 is 16. Then *: 3 * 16 is 48. Then +: 2 + 48 is 50. 400 is what you get by working strictly left to right, which JavaScript does not do when the operators have different ranks.

A student writes let ok = 18 <= age <= 60; to check that age is between 18 and 60. Why is ok true even when age is 75, and what is the fix?L3

Answer: the comparisons run left to right. 18 <= 75 gives true; then true <= 60 converts true to 1, and 1 <= 60 is true. (For an age of 10, false becomes 0, and 0 <= 60 is also true.) So the expression is true for every age. The fix is two comparisons joined by AND: age >= 18 && age <= 60.

What does console.log(typeof 5 + 5); print?L3
  • A. number5
  • B. number
  • C. 10
  • D. NaN

Answer: A. typeof grabs only the operand next to it, so typeof 5 runs first and gives the string "number". Then "number" + 5 joins, giving "number5". To get the type of the sum, write typeof (5 + 5), which is "number".

Which statement about &&, || and ?? is correct?L2
  • A. && always evaluates both of its operands
  • B. && and || always return true or false
  • C. || stops at the first truthy operand and returns that operand
  • D. ?? treats 0 as missing, exactly like ||

Answer: C. That is short-circuit evaluation, and it is why name || "Guest" works as a default. A is wrong: && stops at a falsy left side. B is wrong: they return one of the operands, as "" || "Guest" giving "Guest" shows. D is wrong: ?? keeps 0.

What does console.log(1 + 2 + "3" + 4 + 5); print?L3

Answer: 3345. Left to right: 1 + 2 is 3 (both numbers, so add); 3 + "3" is "33" (a string has appeared, so join); then "33" + 4 is "334" and "334" + 5 is "3345". Once a string has appeared, everything to its right is joined.

Quick revision

Key takeaways

  1. An expression works out to one value; a statement is a complete instruction. Operators act on operands.
  2. + - * / % ** do arithmetic. / keeps the decimal; % is the remainder, not a percentage.
  3. x++ and ++x both add 1. Inside a bigger expression, postfix gives the old value and prefix the new one.
  4. + joins text as soon as a string is involved, working left to right; the other arithmetic operators turn strings into numbers. Typed input is always a string, so use Number() first.
  5. = stores. +=, -=, *=, /=, %= and **= update a variable using its current value.
  6. Comparisons produce true or false. Use === and !==; == converts types first, so 0 == "" is true. NaN equals nothing.
  7. &&, || and ! combine conditions. && and || short-circuit and return an operand. || replaces any falsy value; ?? replaces only null and undefined.
  8. Precedence: brackets, then **, then * / %, then + -, then comparisons, then &&, then || and ??, then the ternary and assignment. When in doubt, add brackets.
