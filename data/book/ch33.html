Pseudo-elements

A pseudo-class styles an element in a state. A pseudo-element styles a part of it — the first letter, the placeholder text, the bullet — or invents a small piece of content that was never in your HTML at all. Two colons instead of one, and one property that everybody forgets.

About 20 minutes · Course outcome CO3 · Builds on Chapter 32

Before you start — one-line reminders

  • A pseudo-class uses one colon and styles a state: a:hover (Chapter 32).
  • position: relative on a parent anchors an absolute child (Chapter 29).
  • Decoration belongs in CSS; meaning belongs in HTML (Chapter 12).

By the end of this chapter you can

  • Say what the two colons mean and how a pseudo-element differs from a pseudo-class.
  • Use ::before and ::after, and never forget content.
  • Add an asterisk, an icon or a decorative quote mark without touching the HTML.
  • Style a drop cap, a placeholder, a list marker and the user's selection.
  • Say what should never go in generated content.

33.1 Two colons: a part, not a state

The syntax is the same shape as a pseudo-class, with two colons:

p::first-line { font-weight: 700; }
/* |  |
   |  the pseudo-element: a PART of the paragraph
   the element                                    */
Pseudo-classPseudo-element
ColonsOne — :hoverTwo — ::before
StylesThe whole element, in a stateA part of it, or invented content
Examples:hover, :focus, :first-child, :checked::before, ::after, ::first-letter, ::placeholder, ::marker, ::selection

One colon = a state (hovered, focused, checked). Two colons = a part (the first letter, the bullet, an added piece). Say it once and you will not mix them up again.

You may still see :before with one colon in older code. It works, because browsers keep supporting the old spelling, but write two.

33.2 ::before and ::after — and the rule everyone forgets

These two create a little box inside the element, before or after its real content. They are the most used pseudo-elements by a distance.

And here is the rule: ::before and ::after do nothing at all unless you give them a content property. Even an empty one, content: "";, is enough. Miss it and there is no error, no warning and no pseudo-element.

/* does nothing at all */
.tag::before { color: red; }

/* works */
.tag::before { content: "New"; color: red; }

/* also works - an empty box you can size and colour */
.tag::before { content: ""; display: inline-block; width: 8px; height: 8px;
               background: #138808; border-radius: 50%; }

What can go in content?

ValueProduces
content: "New";That literal text
content: "";An empty box — for shapes, dots and dividers
content: " \2713";A character by its code — here a tick
content: attr(data-label);The value of that attribute on the element
content: url(icon.svg);An image

A shape with content: ""

An empty content plus a width, a height and a background gives you a drawable box — a dot, a bar, a gradient underline — with no extra HTML.

<style>
  body { font-family: system-ui, sans-serif; }
  h2 { position: relative; display: inline-block; padding-bottom: 10px;
       color: #0B2545; }
  h2::after {
    content: "";                     /* required, even though it is empty */
    position: absolute;
    left: 0; bottom: 0;
    width: 60px; height: 4px;
    background: linear-gradient(to right, #FF9933, #138808);
    border-radius: 2px;
  }
</style>
<h2>Skills</h2>
<p>The short coloured bar under the heading is a pseudo-element.</p>
Two things that catch people out. (1) ::before and ::after are inline boxes by default, so width and height are ignored until you add display: inline-block or position: absolute. (2) They do not work on replaced elements — <img>, <input>, <br> — because those have no inside to put content in. Wrap the image in a <span> and style that instead.

Cascading Style Sheets began as a way to separate a document's appearance from its structure, and this opening letter is styled with a single ::first-letter rule rather than an extra element.

<style>
  body { font-family: system-ui, sans-serif; line-height: 1.7; }

::marker deserves a mention for accessibility. The old way to get custom bullets was list-style: none plus a ::before, which in some screen readers stops the list being announced as a list. ::marker colours the real bullet and keeps the list a list.

33.4 What must never go in generated content

Content created by CSS is, by design, decoration. Different screen readers treat it inconsistently, a user cannot always select or copy it, and it vanishes entirely if the stylesheet fails to load.

  • Fine: a decorative quote mark, an arrow after an external link, a coloured dot, a required asterisk that repeats what required already says.
  • Not fine: a heading, a price, an error message, a button label, or anything a reader would miss if it disappeared.

The test is simple: turn the CSS off. Is anything important gone? If yes, that content belongs in the HTML.

Build it: badges and icons with no extra markup

<style>
  * { box-sizing: border-box; }
  body { font-family: system-ui, sans-serif; background: #F1F5F9; padding: 20px;
         color: #3C4A60; }

  .card {
    position: relative;
    background: #fff; border-radius: 12px; padding: 16px 18px;
    margin-bottom: 14px; box-shadow: 0 2px 8px rgba(16,32,64,.08);
  }
  /* a corner ribbon, entirely from CSS */
  .card.featured::before {
    content: "Featured";
    position: absolute; top: -10px; right: 14px;
    background: #E07B1E; color: #fff;
    padding: 3px 12px; border-radius: 999px;
    font-size: 12px; font-weight: 700;
  }
  /* a tick in front of completed courses */
  .card.done h3::before {
    content: "\2713 ";
    color: #138808;
  }
  /* an arrow after any link that opens elsewhere */
  .card a::after { content: " \2197"; color: #E07B1E; }

  h3 { margin: 0 0 4px; color: #0B2545; font-size: 16px; }
  p  { margin: 0; font-size: 14px; }
</style>

Exam-style checks

How many colons does a pseudo-ELEMENT use?L2
  • A. One
  • B. Two
  • C. Three
  • D. None

Answer: B. ::before and ::after are parts; :hover and :focus are states.

p::before does nothing. What is missing?L3
  • A. A colour
  • B. The content property
  • C. A width
  • D. display:block

Answer: B. ::before and ::after require content, even if it is empty quotes.

Which pseudo-element inserts content before the content of an element?L1

::before — and it sits inside the element, as its first child, so it inherits the element's colour and font.

You want an empty coloured bar under a heading. What does content need to be?L2

content: ""; — empty, but present. Then give the pseudo-element a width, a height and a background, plus display: inline-block or position: absolute so the size is honoured.

Why do width and height often appear to be ignored on a ::before?L3

Because it is an inline box by default, and inline boxes ignore width and height (Chapter 29). Add display: inline-block, display: block, or position it absolutely.

Which pseudo-element styles the grey hint text inside an empty input?L1

::placeholder. Remember it is only a hint — it never replaces a real <label> (Chapter 15).

Which pseudo-element colours the bullet of a list item without removing the list?L2

::marker. The older trick of list-style: none plus ::before can stop some screen readers announcing the list as a list.

Why should an error message never be written in a content property?L3

Because generated content is decoration. Screen readers treat it inconsistently, it cannot always be selected or copied, and it disappears completely if the stylesheet fails to load. Anything a reader would miss belongs in the HTML.

Why does img::after never work?L3

Because <img> is a replaced element — its content comes from a file, so there is no inside for CSS to add anything to. The same is true of <input> and <br>. Wrap the image in a <span> and use span::after.

What does content: attr(data-label); put on the page?L3

The value of that element's data-label attribute. It is how a tooltip or a small caption can reuse text that is already written in the HTML, rather than duplicating it in the CSS.

Quick revision

Key takeaways

  1. Two colons mark a pseudo-element: a part of an element, or content CSS invents. One colon is a state.
  2. ::before and ::after need content, even if it is "". They sit inside the element and are inline by default.
  3. content can hold text, an empty string, a character code, attr() or an image.
  4. ::first-letter, ::first-line, ::placeholder, ::marker, ::selection style real parts of an element.
  5. Generated content is decoration. If turning the CSS off would lose something important, it belongs in the HTML.
