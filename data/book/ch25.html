Units and Measurements

Every size in CSS needs a unit. Write font-size: 20 and nothing happens, because twenty of what? This chapter takes the six units you will actually use, explains what each one is measured against, and gives you a rule for choosing — so that your pages still work when a reader zooms in or opens them on a phone.

About 23 minutes · Course outcome CO3

Before you start — one-line reminders

  • A value is the part after the colon: font-size: 20px; (Chapter 22).
  • The parent is the element your element sits inside (Chapter 3).
  • The viewport is the part of the screen the page is shown in (Chapter 21).

By the end of this chapter you can

  • Say what px, %, em, rem, vw and vh are each measured against.
  • Explain why em can multiply unexpectedly and rem cannot.
  • Say why rem is the accessible choice for font sizes.
  • Convert between rem and pixels in your head.
  • Pick a sensible unit for a font size, a width, a border and a full-screen panel.

25.1 A number needs a unit

CSS has no default unit. width: 300 is ignored; width: 300px works. The only exception is zero, because zero of anything is zero, so margin: 0 is legal and common.

Units split into two families, and the whole chapter follows from the difference:

  • Absolute units are fixed. px is the one that matters. 20px is 20px whatever else happens on the page.
  • Relative units are measured against something else — the parent's size, the root font size, or the window. Change that something and every relative size follows.
Picture this. "Make it 30 centimetres wide" is absolute: the same in every room. "Make it half the width of the table" is relative: put it on a different table and it resizes itself. Relative units are how a page fits a phone and a monitor without you writing it twice.

25.2 px — the pixel

px is an absolute unit used for fixed sizes: widths, heights, padding, margins, borders and font sizes.

.box {
  width: 300px;
  padding: 16px;
  border: 1px solid #ccc;
  font-size: 18px;
}

A CSS pixel is not exactly one dot on your screen — modern phones pack several physical dots into one CSS pixel so text stays sharp — but you can safely think of it as "one small fixed step".

Where px is right: borders (1px, 2px), small shadows, and anything that genuinely must not scale.

Where px causes trouble: font sizes. A reader who has set a larger default text size in their browser — because their eyesight needs it — gets ignored, because you pinned the size. That is an accessibility failure, and it is why the next two units exist.

25.3 % — a share of the parent

A percentage is relative to the size of the parent element. width: 50% means half the width of whatever box this element sits in.

<style>
  .frame { border: 2px dashed #94A3B8; padding: 8px; margin-bottom: 10px; }
  .narrow { width: 260px; }
  .bar { background: #E07B1E; color: #fff; padding: 8px; width: 50%; }
</style>
<div class="frame"><div class="bar">50% of a wide parent</div></div>
<div class="frame narrow"><div class="bar">50% of a 260px parent</div></div>

Same declaration, two different results, because the parents differ. That is exactly what you want for a responsive layout: width: 100% fills whatever space is available, on any screen.

The percentage-height trap. width: 50% nearly always works. height: 50% usually does nothing, because a parent's height is normally decided by its contents, so there is no fixed number to take half of. If you need a tall box, use vh (section 25.6) or min-height.

25.4 em — relative to the current font size

em is measured against the font size of the element itself. If an element's text is 20px, then 1em is 20px, 0.5em is 10px and 2em is 40px, inside that element.

It is at its best for padding and margins that should grow with the text:

.btn {
  font-size: 18px;
  padding: 0.6em 1.2em;   /* about 11px and 22px - and it scales with the text */
}

Make the button's text bigger and the padding grows in proportion, so the button keeps its shape. That is a genuinely useful trick.

The compounding problem

  
Here is where em bites. When you set font-size itself in em, it is measured against the parent's font size — and if that parent also used em, the sizes multiply.

  
<style>
  body { font-size: 16px; }
  .a { font-size: 1.5em; }   /* 16 x 1.5  = 24px */
  .b { font-size: 1.5em; }   /* 24 x 1.5  = 36px  (!) */
  .c { font-size: 1.5em; }   /* 36 x 1.5  = 54px  (!!) */
</style>
<div class="a">First level: 24px
  <div class="b">Second: 36px
    <div class="c">Third: 54px, and nobody asked for that</div>
  </div>
</div>

  
Every level multiplies again. In a real page with cards inside sections inside articles, this is how text ends up mysteriously enormous in one corner. The fix is the next unit.






  
25.5 rem — relative to the root, and the accessible choice

  
rem means root em. It is measured against the font size of the root element, which is <html> — one single number for the whole page. Nesting changes nothing, so nothing compounds.

  
The root font size is 16px by default in every browser. That gives you an easy conversion:

  

    
remPixels (at the default root size)Typical use

    
      
0.875rem14pxSmall print, captions

      
1rem16pxBody text

      
1.25rem20pxA lead paragraph

      
1.5rem24pxA sub-heading

      
2rem32pxA page heading

    
  

  
To convert, divide by 16: 24px ÷ 16 = 1.5rem. To go back, multiply by 16.

  
<style>
  .a, .b, .c { font-size: 1.5rem; }   /* all three are 24px */
</style>
<div class="a">First level: 24px
  <div class="b">Second: still 24px
    <div class="c">Third: still 24px. Predictable.</div>
  </div>
</div>

  
Why rem is the accessible choice

  
This is the part that earns marks. A reader who finds text hard to read can raise the default font size in their browser settings — say from 16px to 20px. That setting changes the root font size.

  
    
    
  • Text sized in rem grows with it. The page respects the reader.
    • 
    
  • Text sized in px does not move at all. The reader's setting is ignored.
    • 
  

  
So the reason to prefer rem over px for font sizes is not that it is shorter, or newer, or faster: it is that rem respects the reader's browser font setting. px is not deprecated and remains correct for borders and hairlines — but not for text.

  

    
em looks at the element it is on, so it multiplies when you nest. rem always looks at one number at the top of the page, so it never surprises you. Use rem for text sizes, and em for padding that should grow with its own text.

  






  
25.6 vw and vh — a share of the window

  
The viewport units are measured against the browser window itself:

  
    
    
  • 1vw is 1% of the viewport's width. So 100vw is the full width, and 50vw is half of it.
    • 
    
  • 1vh is 1% of the viewport's height. 100vh is a panel exactly as tall as the window.
    • 
  

  
<style>
  .hero {
    height: 60vh;                 /* 60% of the window's height */
    background: linear-gradient(135deg, #FF9933, #138808);
    color: #fff;
    display: grid;
    place-items: center;
    font-size: 4vw;               /* grows and shrinks with the window */
    font-weight: 800;
    border-radius: 12px;
  }
</style>
<div class="hero">Resize the preview</div>

  
Run that, then drag the edge of the preview or turn your phone sideways. Both the panel and the text resize, because both are measured against the window. Change 60vh to 100vh and the panel fills the screen exactly — the standard way to build a full-screen hero section.

  
Do not size body text in vw. On a narrow phone font-size: 4vw can fall below 14px and become unreadable, and the reader cannot fix it by zooming. Keep vw for big display headings, and use rem for text people have to read.

Unit or keywordMeansHandy for

frOne share of the leftover space, in Grid onlySplitting a grid into columns (Chapter 31)

      
calc()Arithmetic, and units may be mixedwidth: calc(100% - 40px) — full width minus a fixed gutter

      
clamp()A minimum, an ideal and a maximumfont-size: clamp(1rem, 2.5vw, 2rem) — fluid, but never silly (Chapter 37)

    
  

  
calc() needs spaces around the operator: calc(100% - 40px) works, calc(100%-40px) does not.






  
25.8 Which unit should I use?

  
  
<style>
  html { font-size: 100%; }          /* respect the reader's setting: 16px default */
  body {
    font-family: system-ui, sans-serif;
    font-size: 1rem;                  /* 16px, and it scales if the reader zooms */
    line-height: 1.7;
    color: #3C4A60;
    max-width: 60rem;                 /* never absurdly wide on a big monitor */
    margin: 0 auto;                   /* auto: centre the page */
    padding: 1.5rem;
  }
  h1 { font-size: 2rem; }             /* 32px */
  .card {
    background: #fff;
    border: 1px solid #E3E9F0;        /* px: a hairline must stay 1px */
    border-radius: 0.75rem;
    padding: 1em 1.25em;              /* em: grows with the card's own text */
    margin-bottom: 1rem;
    width: 100%;                      /* % : fill whatever space there is */
  }
</style>
<h1>Asha Kumar</h1>
<div class="card"><b>CSE326</b> — Internet Programming</div>
<div class="card" style="font-size:1.25rem"><b>Bigger card</b> — its padding grew too, because it is in em</div>






  
Exam-style checks

  
Which unit is relative to the ROOT font size?L2

    
  • A. px
  • B. em
  • C. rem
  • D. %

    
Answer: C. rem is predictable because it always looks at one number on <html>; em compounds relative to the parent.

  
Why prefer rem over px for font sizes?L3

    
  • A. It is shorter to type
  • B. It respects the reader's browser font setting
  • C. It renders faster
  • D. px is deprecated

    
Answer: B. That is an accessibility win: px pins the size and ignores the reader's preference. px is not deprecated and is still correct for borders.

  
What does 1vw mean?L2

    
  • A. 1 pixel
  • B. 1% of the viewport width
  • C. 1% of the parent
  • D. 1 character width

    
Answer: B. vh is the same for height, so 100vh is a full-window-height panel.

  
The % unit defines a size relative to what?L1

    
Answer: the size of the parent element. So width: 50% is half the parent's width, and the same declaration gives different pixel results in different containers.

  
At the default root font size, how many pixels is 2rem?L2

    
Answer: 32px, because the default root size is 16px and 1rem = 16px. Divide by 16 to convert pixels to rem, multiply by 16 to go back.

  
A parent is 16px. Inside it, .a { font-size: 1.5em } contains .b { font-size: 1.5em }. How big is the text in .b?L3

    
36px. em is measured against the parent's font size, so the factors multiply: 16 × 1.5 = 24, then 24 × 1.5 = 36. Writing both in rem would have given 24px in both places.

  
Which unit would you choose for a 1-pixel table border?L2

    
px. A hairline should stay crisp and must not grow when the reader enlarges text. Borders and small shadows are exactly what absolute units are for.

  
height: 50% on a div appears to do nothing. Why?L3

    
Because the parent has no definite height — its height is being decided by its own contents, so there is no fixed number to take half of. Use vh, or set a height on the parent, or use min-height.

  
Which declaration makes a section exactly as tall as the browser window?L2

    
height: 100vh; — 100 lots of 1% of the viewport height.

  
What does calc(100% - 40px) compute, and what is the common mistake when writing it?L3

    
It means "the full width of the parent, minus 40 pixels" — and it is one of the few places CSS lets you mix units. The common mistake is leaving out the spaces around the minus sign: calc(100%-40px) is invalid and is ignored.
