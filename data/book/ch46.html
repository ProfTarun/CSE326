Numbers and Boolean Values

Marks, prices, percentages and counts are numbers. Has she passed? Is it in stock? Is he logged in? are yes-or-no answers. Those two kinds of value do most of the quiet work on any web page. This chapter shows how JavaScript keeps them, the few surprises numbers hold (why 0.1 + 0.2 is not quite 0.3), how to turn typed text into a number safely, and the short rule that decides when any value counts as true.

46.1 One number type for everything

Many languages keep whole numbers and decimals in separate types. JavaScript has one, number, for marks, prices, temperatures, head-counts and pi alike. The slide's four examples:

const marks = 25;      // an integer: a whole number
const pi = 3.14;       // a decimal
const loss = -10;      // a negative number
const nothing = 0;     // zero

console.log(typeof marks, typeof pi, typeof loss, typeof nothing);
// number number number number

A whole number is called an integer. To JavaScript, 25 and 25.0 are the very same number (25 === 25.0 is true), so when a division of whole numbers does not come out even, nothing is lost: 7 / 2 is simply 3.5.

Three writing rules. A number has no quotes: "25" is a string (Chapter 45). It has no commas or symbols: 1,000 and ₹500 are not numbers to JavaScript. To make a long number readable you may put underscores between digits, which JavaScript ignores: 1_00_000 is one lakh.

How a number is stored

The slide says ordinary numbers are double-precision floating-point. In plain terms, every number gets the same 64 bits of memory: about 15–17 significant digits plus a note of where the decimal point sits. Because the point can sit anywhere, one format holds 0.000001 and 6,00,00,000 equally well. This is floating-point storage, and it has two consequences:

  • Whole numbers are exact up to Number.MAX_SAFE_INTEGER, 9007199254740991. Past that the digits run out: write 9007199254740993 and JavaScript stores 9007199254740992.
  • Many everyday decimals, such as 0.1, can only be stored very nearly. Section 46.3 shows what that does.

For exact whole numbers beyond the limit there is a second, rarely needed numeric type, BigInt, written with an n on the end: 9007199254740993n is exact, and typeof 10n is "bigint". Its zero, 0n, reappears in section 46.9.

46.2 Two special numbers: Infinity and NaN

Arithmetic on ordinary numbers never stops a JavaScript program with an error. When a calculation has no ordinary answer, you get one of two special values instead, both of type number.

Infinity: too big to hold

Infinity means "larger than any number". You get it by dividing a non-zero number by zero, or by going past the largest number that can be stored (about 1.8 × 10308). -Infinity is its negative twin.

console.log(10 / 0);       // Infinity
console.log(-10 / 0);      // -Infinity
console.log(2 ** 1024);    // Infinity - too big to store

So a divide-by-zero bug crashes nothing; it just shows Infinity% on the page.

NaN: Not a Number

NaN is the answer to a calculation that has no numeric answer at all. It turns up in four common ways:

How it happensExampleResult
A sum with no answer0 / 0, Math.sqrt(-1)NaN
Maths on text that is not a number"abc" * 2NaN
Converting text that is not a numberNumber("Hello")NaN
Maths on a missing valueundefined + 1NaN

Three facts about NaN catch everybody once:

  • NaN is a number. typeof NaN is "number" — the quirk Chapter 44 promised to explain. The name means "a number-shaped answer that is not a real number".
  • NaN spreads. Any arithmetic that touches NaN gives NaN, so one bad value early on spoils the final total.
  • NaN equals nothing, not even itself. NaN === NaN is false, so === cannot detect it; section 46.5 gives the proper test.

Quick check: what do 0 / 0 and 5 / 0 give?

0 / 0 is NaN: there is no sensible answer at all. 5 / 0 is Infinity: the answer grows without limit. Neither one is an error.

46.3 Why 0.1 + 0.2 is not 0.3

Now the most famous surprise in JavaScript. Python, Java and C do exactly the same, because they store decimals the same way:

console.log(0.1 + 0.2);            // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3);    // false

This is not a bug. Computers store numbers in binary, and in binary a fraction must be built out of halves, quarters, eighths, sixteenths and so on. Some fractions are built exactly: 0.5 is one half, 0.75 is a half plus a quarter. One tenth cannot be built exactly from those pieces, however many you use — just as one third cannot be written exactly in decimal, where 0.3333… never ends. So JavaScript stores the nearest value it can, about 0.1000000000000000055. The same happens to 0.2. Add two numbers that are each a hair off and, now and then, the two hairs add up to one you can see.

Picture this. A kitchen drawer holds measuring spoons of 1, ½, ¼, ⅛ and 1/16 teaspoon, and smaller and smaller halves after that — nothing else. The recipe says exactly one tenth of a teaspoon. You can get close: 1/16 + 1/32 + 1/256 + 1/512 comes to 0.0996, and more tiny spoons bring you closer still. But no pile of halves, quarters and eighths ever makes exactly one tenth. A computer's number is that drawer of spoons. It builds every fraction from halves of halves, so a tenth is always very nearly right and never exactly right, while ½ or ¾ comes out perfect.

0.1 is kept as a number a tiny bit different from 0.1, the way 0.333 is a tiny bit different from one third. After a sum the difference occasionally shows in the 17th digit. Whole numbers, and fractions made of halves and quarters such as 0.75, are exact and never show it.

Fixing the display: toFixed

The answer is right for every practical purpose; you only need to show it sensibly. toFixed(digits) rounds to that many decimal places and returns the result as a string:

const sum = 0.1 + 0.2;
console.log(sum.toFixed(2));        // 0.30
console.log((2.456).toFixed(2));    // 2.46   rounded
console.log((5).toFixed(2));        // 5.00   padded with zeros
console.log(Math.PI.toFixed(2));    // 3.14

Put a typed-in number in brackets before the dot: 5.toFixed(2) is a SyntaxError, because JavaScript reads that dot as a decimal point.

toFixed gives you text. So the Chapter 44 trap is back: sum.toFixed(2) + 1 is "0.301". Call toFixed only at the end, to show a value, or turn its text back with Number(). Its rounding is not perfect either: (1.005).toFixed(2) is "1.00", because 1.005 itself is stored as 1.00499999…. That is why payment systems count whole paise, which are exact, and divide by 100 only to display.

Never test decimal arithmetic with ===. Round both sides first, or ask whether the two are close enough: Math.abs(a - b) < 0.000001 (Math.abs, the size without the sign, is in section 46.6).

46.4 From text to number: Number, parseInt and parseFloat

Everything a user types arrives as a string, even when it looks like a number (Chapter 44). Before you do maths with it, you convert it. JavaScript has three tools, and the slide shows all three:

console.log(Number("25"));            // 25
console.log(Number("Hello"));         // NaN
console.log(parseInt("25px", 10));    // 25
console.log(parseFloat("3.14kg"));    // 3.14

They differ in how much of the text each insists on reading. To parse text is to read it piece by piece and work out what it says:

  • Number(text) is strict. The whole text, apart from spaces at either end, must be a number. One stray letter and the answer is NaN.
  • parseInt(text, 10) skips any spaces at the start, reads from the left, digit by digit, and stops at the first character that is not a digit. It returns the whole number it has read so far, so it never returns decimals. If the very first character is not a digit (or a sign), it returns NaN.
  • parseFloat(text) reads from the left in the same way but accepts one decimal point, so it can return decimals.
TextNumber(t)parseInt(t, 10)parseFloat(t)
"42"424242
"42px"NaN4242
"3.75"3.7533.75

Number() says: "the whole thing is a number, or it is NaN." parseInt() and parseFloat() say: "read from the left and keep the number you find before the first thing that does not fit." parseInt keeps only the whole-number part; parseFloat keeps the decimals too.

Which one should you use?

  • A box that should hold just a number (marks, age, quantity): Number(). It refuses junk, so "8O", with a letter O typed for a zero, becomes a catchable NaN instead of being quietly read as 8 by parseInt.
  • A measurement with a unit, such as the CSS value "42.5px": parseFloat(), or parseInt() for the whole part only.

Watch the empty-string row: Number("") is 0, so an empty marks box looks like a mark of zero. Form validation (Chapter 60) checks for empty boxes first.

The 10 in parseInt

The second argument of parseInt is the radix, the counting base the text is written in. Always pass 10. Without it, text that starts with 0x is read as base 16: parseInt("0x1A") is 26, while parseInt("0x1A", 10) is 0. parseFloat has no radix; it reads only ordinary decimal.

Converting values that are not text

Number() converts other types too, and these four results are worth knowing:

CodeResult
Number(true) / Number(false)1 / 0
Number(null)0
Number(undefined)NaN

The unary plus from Chapter 44, +"42", does exactly what Number("42") does. The reverse trip, number to text, is String(n) or a template literal (Chapter 45).

Quick check: what do parseInt("12.9kg", 10) and parseFloat("12.9kg") return?

12 and 12.9. Both read from the left; parseInt stops at the dot, parseFloat reads past it and stops at the k. Number("12.9kg") would be NaN.

46.5 Checking a number: Number.isNaN and Number.isInteger

After a conversion, a careful program checks that it really got a number. Since NaN === NaN is false, the test has to be a function.

Number.isNaN against isNaN

Number.isNaN(value) asks one precise question: is this value the special NaN number? The older global function isNaN(value) first converts the value with Number() and only then asks. That hidden conversion makes it answer a different question — would this become NaN if converted? — and the answers mislead:

console.log(Number.isNaN(NaN));        // true
console.log(Number.isNaN("Hello"));    // false - "Hello" is a string, not NaN
console.log(isNaN("Hello"));           // true  - converted first: Number("Hello") is NaN
console.log(isNaN(""));                // false - converted first: Number("") is 0

The clean habit is to convert on purpose, then check with Number.isNaN:

const marks = Number("8O");            // a letter O, not a zero
console.log(Number.isNaN(marks));      // true - the text was not a number
Exam tip. isNaN converts first; Number.isNaN never converts. So for a string that is not a number, such as "Hello", isNaN says true and Number.isNaN says false. Asked which is the precise test, choose Number.isNaN.

Number.isInteger

Number.isInteger(value) is true only when the value is a number with no fraction part. Like Number.isNaN, it never converts:

console.log(Number.isInteger(5));      // true
console.log(Number.isInteger(5.0));    // true  - 5.0 is the same number as 5
console.log(Number.isInteger(5.5));    // false
console.log(Number.isInteger("5"));    // false - a string, not a number

Use it where only whole numbers make sense: a roll number, a number of tickets, a count of students.

46.6 The Math toolbox

JavaScript has a built-in object called Math, holding ready-made maths functions and constants. You just write Math, a dot and the name: Math.round(4.7), Math.PI. (An object is a bundle of named values; Chapter 51 builds your own.)

Four ways to get a whole number

FunctionRule4.74.2−4.7
Math.round(x)nearest whole number; a .5 goes up54−5
Math.floor(x)always down44−5
Math.ceil(x)always up55−4

"A .5 goes up" means up the number line: Math.round(2.5) is 3, but Math.round(-2.5) is −2. To round to decimal places and keep a number (unlike toFixed), multiply, round and divide: Math.round(3.14159 * 100) / 100 is 3.14.

Random numbers

Math.random() returns a new random decimal on every call, from 0 up to but never including 1: perhaps 0.7391…, then 0.0528…. To turn that into a dice roll, take four steps:

StepCodePossible values
1. A random decimalMath.random()0 to 0.999…
2. Stretch it by 6Math.random() * 60 to 5.999…
3. Chop the decimalsMath.floor(Math.random() * 6)0, 1, 2, 3, 4 or 5
4. Shift up by 1Math.floor(Math.random() * 6) + 11, 2, 3, 4, 5 or 6

The general recipe, for any two limits:

// a random whole number from min to max, both included
Math.floor(Math.random() * (max - min + 1)) + min

max - min + 1 is how many different answers you want. From 10 to 20 there are 11 numbers, not 10; forget the + 1 and 20 can never come up.

Stretch, chop, shift. Multiply the random decimal by how many answers you want, chop off the decimals with Math.floor, then add the smallest answer.

Why not Math.round? Math.round(Math.random() * 6) gives 0 to 6 — seven answers, not six — and 0 and 6 come up only half as often as the rest, because only half a step rounds to each of them. Use Math.floor.
Quick check: what are Math.floor(-2.5) and Math.trunc(-2.5)?

-3 and -2. floor always goes down the number line, and below −2.5 comes −3. trunc just chops off the .5, which moves towards zero.

46.7 Worked example: marks, percentages and prices

The slide names the everyday uses: marks and percentages, prices and discounts, counting. Here is a results page, step by step. Asha's five subject marks, each out of 100, are 78, 85, 92, 66 and 81.

const total = 78 + 85 + 92 + 66 + 81;        // 402
const maximum = 5 * 100;                      // 500
const percentage = total / maximum * 100;     // 80.4
console.log(`${percentage.toFixed(1)}%`);     // 80.4%

A percentage is part divided by whole, times 100; / and * run left to right, so 402 ÷ 500 is 0.804, then times 100 is 80.4. The % inside the backticks is only text, not the remainder operator.

The result is a yes-or-no question, so it is a boolean:

const hasPassed = percentage >= 40;           // true
const distinction = percentage >= 75;         // true
console.log(hasPassed ? "PASS" : "FAIL");     // PASS - the ternary from Chapter 44

Turning 80.4 into a letter grade — O, A+, A, B — needs a ladder of decisions, which is where Chapter 47 begins. Math already helps with how many more marks for a distinction? 75% of 500 is 375; half a mark cannot be scored, and a negative shortfall should show as 0:

const needed = Math.max(0, Math.ceil(maximum * 0.75 - total));   // 0 for Asha

Prices work the same way. A ₹1299 shirt with 15% off: the discount is 1299 * 15 / 100, or 194.85, so you pay 1104.15. Show money with toFixed(2), so that ₹59.5 appears as ₹59.50.

46.8 Boolean values: true and false

A boolean has exactly two possible values, true and false, and is named after George Boole, who worked out the algebra of yes and no. Both are reserved words, written without quotes, and each answers a yes-or-no question. The slide's examples: Is the student eligible? Has the user logged in? Are the marks at least 40? Is the product available?

const isLoggedIn = true;
const isAvailable = false;
console.log(typeof isLoggedIn);    // boolean

Booleans are rarely typed by hand. Mostly they come out of comparisons, which always produce one (Chapter 44). The slide's example:

const marks = 85;
const passingMarks = 40;
console.log(marks >= passingMarks);    // true
console.log(marks < passingMarks);     // false
console.log(marks === 85);             // true

Store such an answer in a variable named like a question — isEligible, hasPassed, canVote — so that the code reads like English: const hasPassed = marks >= passingMarks;. Chapter 47's if (hasPassed) then says exactly what it means.

true is not "true". With quotes it is a four-letter string, so true === "true" is false. Values read from an input box's value or from browser storage (Chapter 64) arrive as the text "true" or "false", and the text "false" does not behave like false (section 46.9). Compare to get a real boolean: const isDark = saved === "true";

46.9 Truthy and falsy: Boolean() and the falsy eight

Booleans are not the only values that can answer a yes-or-no question. Wherever JavaScript expects true or false — in the condition of an if (Chapter 47), and around &&, || and ! (Chapter 44) — it accepts any value and treats it as true or false. Boolean(value) does the same conversion out loud, so you can see the result:

console.log(Boolean(1));         // true
console.log(Boolean("Asha"));    // true
console.log(Boolean(0));         // false
console.log(Boolean(""));        // false

The rule is short. There are exactly eight falsy values. Every other value in JavaScript is truthy.

Falsy valueWhat it is
falseThe boolean itself
0 and -0Zero, and minus zero (from calculations such as Math.round(-0.4); it behaves like 0)
0nThe BigInt zero (section 46.1)
""The empty string
null"Deliberately empty"
undefined"Never given a value"
NaNThe not-a-number result (section 46.2)

The surprises are all on the truthy side: "0" (a string holding the digit zero), " " (one space), "false" (five letters), -1, and an empty list [] or object {} (Chapters 50 and 51). An empty box is still a box: a value not among the eight is truthy, however empty or negative it looks. (Strictly, browsers keep one fossil falsy as well — the obsolete document.all object, so that very old pages still work. You will never need it.)

Memorise the short list, not the long one. False, the three zeros (0, -0, 0n), the empty string, null, undefined and NaN count as no. Everything else counts as yes.

You will also meet !!value, a shortcut for Boolean(value): the first ! converts and flips, the second flips it back. !!"Asha" is true.

You have met this rule already: typedName || "Guest" works because "" is falsy, and a real score of 0 needed ?? because 0 is falsy too (Chapter 44). In Chapter 47, if (typedName) will mean "if something was typed".

Exam tip. Options in quotes are the favourite trap. "0", " " and "false" are non-empty strings, so they are truthy; so are [] and {}. Only "", with nothing at all between the quotes, is falsy.
Quick check: what are Boolean("0") and Boolean(0)?

true and false. "0" is a string with one character in it, so it is not on the falsy list. The number 0 is.

46.10 Common misunderstandings

✗ "0.1 + 0.2 is exactly 0.3."
It is 0.30000000000000004, because 0.1 and 0.2 are stored only very nearly. 0.1 + 0.2 === 0.3 is false.
✓ "Round for display, and compare decimals with a small tolerance."
sum.toFixed(2) shows 0.30; Math.abs(sum - 0.3) < 0.000001 tests closeness.
✗ "toFixed(2) gives me a rounded number."
It gives a string, so (0.3).toFixed(2) + 1 is "0.301".
✓ "toFixed is for showing; Math.round(x * 100) / 100 rounds and keeps a number."
Or wrap it: Number(x.toFixed(2)).
✗ "Number() and parseInt() do the same thing."
Number("42px") is NaN but parseInt("42px", 10) is 42; Number("") is 0 but parseInt("", 10) is NaN; parseInt drops decimals.
✓ "Number needs the whole text; parseInt/parseFloat read a number off the front."
Use Number for input boxes, parseFloat for values with units.
✗ "x === NaN tells me whether x is NaN."
It is always false: NaN equals nothing, not even itself.
✓ "Number.isNaN(x) is the test."
Not the older isNaN(x), which converts first and calls "Hello" NaN.
✗ ""0", "false" and [] are falsy."
A non-empty string and an empty list are both truthy.
✓ "Only eight values are falsy: false, 0, -0, 0n, "", null, undefined, NaN."
Everything else is truthy.

Exam-style checks

Answer each one before opening it. Most are four-option questions with exactly one correct answer; the last two ask you to predict the output.

What does typeof NaN return?L1
  • A. "NaN"
  • B. "number"
  • C. "undefined"
  • D. "object"

Answer: B. NaN is a special value of the number type. A is tempting because of the name, but typeof never returns "NaN".

What does console.log(0.1 + 0.2 === 0.3); print?L2
  • A. true
  • B. 0.3
  • C. false
  • D. A SyntaxError

Answer: C. 0.1 and 0.2 are stored only very nearly, so their sum is 0.30000000000000004, which is not the stored value of 0.3. B is wrong because === always gives a boolean.

What does parseInt("25px", 10) return?L2
  • A. 25
  • B. NaN
  • C. "25"
  • D. 25px

Answer: A. parseInt reads digits from the left, stops at the p and returns the number 25. B is what Number("25px") gives; C is a string, but parseInt always returns a number.

Which call turns the text "42.5px" into the number 42.5?L3
  • A. Number("42.5px")
  • B. parseInt("42.5px", 10)
  • C. Boolean("42.5px")
  • D. parseFloat("42.5px")

Answer: D. parseFloat reads from the left, accepts one decimal point and stops at the p. A gives NaN because the whole text is not a number; B stops at the dot and gives 42; C gives true.

What do isNaN("Hello") and Number.isNaN("Hello") return, in that order?L2
  • A. true, true
  • B. false, false
  • C. false, true
  • D. true, false

Answer: D. isNaN converts first: Number("Hello") is NaN, so it says true. Number.isNaN does not convert, and the string "Hello" is not the value NaN, so it says false.

What does Math.floor(-4.2) return?L3
  • A. -4
  • B. 4
  • C. -5
  • D. -4.2

Answer: C. floor always goes down the number line, and the next whole number below −4.2 is −5. A is what Math.trunc or Math.ceil would give, because they move towards zero here.

Which expression gives a random whole number from 1 to 6, each equally likely?L3
  • A. Math.random() * 6
  • B. Math.floor(Math.random() * 6) + 1
  • C. Math.floor(Math.random() * 6)
  • D. Math.round(Math.random() * 6)

Answer: B. Stretch by 6, chop to 0–5 with floor, shift by 1. A gives decimals; C gives 0 to 5; D gives 0 to 6, with 0 and 6 only half as likely as the rest.

What does this print? const p = (2.456).toFixed(2); console.log(p, typeof p);L2
  • A. 2.46 string
  • B. 2.46 number
  • C. 2.45 string
  • D. 2.5 string

Answer: A. toFixed(2) rounds to two places (2.456 becomes 2.46, not 2.45) and returns the result as a string. B is the commonest wrong belief about toFixed.

What does Boolean("false") return?L2
  • A. false
  • B. "false"
  • C. NaN
  • D. true

Answer: D. "false" is a five-letter string, and only the empty string is falsy. Boolean always returns a real boolean, so B and C are impossible.

Which of these gives the number 0?L3
  • A. parseInt("", 10)
  • B. Number("")
  • C. parseFloat("")
  • D. Number("zero")

Answer: B. Number treats an empty string as 0 — the empty-box trap. parseInt and parseFloat find no digits and return NaN, and D is NaN because "zero" is a word.

Predict the output: console.log(10 / 0, -10 / 0, 0 / 0);L2

Answer: Infinity -Infinity NaN. Dividing a non-zero number by zero gives Infinity with the matching sign; 0 / 0 has no answer at all, so it is NaN. None of them is an error.

Predict the output: const total = 402; const pct = total / 500 * 100; console.log(pct.toFixed(1), pct >= 40, Math.ceil(375 - total));L3

Answer: 80.4 true -27. 402 ÷ 500 × 100 is 80.4, shown as the string "80.4"; 80.4 >= 40 is true; 375 − 402 is −27, already whole, so Math.ceil leaves it alone. That negative shortfall is why section 46.7 wraps it in Math.max(0, ...).

Quick revision

Key takeaways

  1. One number type holds integers and decimals as double-precision floating point, exact for whole numbers up to Number.MAX_SAFE_INTEGER; BigInt (10n) goes beyond.
  2. 10 / 0 is Infinity; 0 / 0 and Number("Hello") are NaN, whose type is "number". NaN spreads through sums and NaN === NaN is false.
  3. Decimals such as 0.1 are stored very nearly, so 0.1 + 0.2 is 0.30000000000000004. toFixed(n) rounds for display and returns a string.
  4. Number() needs the whole text to be a number (and turns "" into 0). parseInt(t, 10) reads a whole number off the front; parseFloat(t) reads a decimal off the front.
  5. Number.isNaN and Number.isInteger never convert; the older isNaN converts first, so isNaN("Hello") is true.
  6. Math.round, floor (down), ceil (up) and trunc (towards zero) make whole numbers. A random whole number from min to max is Math.floor(Math.random() * (max - min + 1)) + min.
  7. Comparisons produce booleans, true or false. Eight values are falsy — false, 0, -0, 0n, "", null, undefined, NaN — and everything else, even "0", "false" and [], is truthy.
