HTML Document Structure

Every valid HTML5 page has the same skeleton: a document type declaration, a root element, a head of information about the page, and a body of visible content. This chapter takes that skeleton apart line by line, shows what belongs in the head and what belongs in the body, and explains the metadata that makes a page render correctly on a phone, in a search result and in a screen reader.

About 19 minutes · Course outcome CO1 · Builds on Chapter 3

By the end of this chapter you can

  • Write the minimal valid HTML5 document from memory and explain every line.
  • Decide whether a given element belongs in <head> or <body>.
  • Explain lang, <meta charset>, the viewport meta tag, <title>, <link> and where to put <script>.
  • Tell <head> from <header> and <title> from <h1>.
  • Describe the document as a tree the browser builds from your markup.

4.1 The skeleton

Here is the smallest complete, valid HTML5 page. Type it until you can write it without looking; every page you ever build starts from it.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Website</title>
</head>
<body>
  <h1>Hello World</h1>
  <p>My first webpage.</p>
</body>
</html>

The correct order of the main structural elements is therefore html, then head, then body, with head and body both directly inside html. Any arrangement that puts head inside body, body before head, or the doctype anywhere but the top is wrong.

4.2 Line by line

<!DOCTYPE html>: the document type declaration

The very first line. It is not an element (no closing tag, not part of the tree); it is a declaration that tells the browser to use HTML5 parsing rules, the modern standards mode. Leave it out and the browser drops into quirks mode, emulating 1990s behaviour with different box sizes and spacing; the page still renders but layout goes subtly wrong. The HTML5 form is short and case-insensitive: <!DOCTYPE html> and <!doctype html> both work. There is no <!DOCTYPE HTML5>, no <html5> and no meta tag for it.

<html lang="en">: the root element

<html> is the root element of every HTML document: the single container that wraps everything else. (The doctype is above it but is not an element, so it is not the root.) Its lang attribute declares the document's language: en for English, hi for Hindi, pa for Punjabi. Screen readers use it to choose the right pronunciation, browsers use it to offer translation and pick hyphenation rules, and search engines use it to serve the page to the right audience. It does not force translation, restrict fonts or limit which characters may be typed; it is a statement of what language the content is written in.

<head>: information about the document

The head is the container for the document's metadata: data about the page rather than the page itself. Nothing inside the head is rendered on the visible canvas. It holds the title, the character encoding, the viewport setting, links to stylesheets and icons, and hints for search engines. If you put an <h1>, a paragraph or an image in the head, you have made a mistake: they are visible content and belong in the body.

<meta charset="UTF-8">: the character encoding

This declares the character encoding of the file, so the browser turns the bytes it received into the right characters. UTF-8 is the universal standard: it covers every language's script, mathematical symbols, the rupee sign and emoji. Without it, accented letters and symbols such as ₹ can render as garbage like â‚¹. Put it first in the head, before the title. It does not set the font, the width, or link anything.

<meta name="viewport" ...>: telling phones the truth

<meta name="viewport" content="width=device-width, initial-scale=1.0"> is the line that makes a page usable on a phone. width=device-width tells the mobile browser to lay the page out at the real screen width; initial-scale=1.0 sets the starting zoom to 100%. Without it, a phone pretends to be a 980-pixel-wide desktop, lays the page out at that width and shrinks it to fit, so the user sees a tiny, unreadable desktop layout and has to pinch-zoom. The viewport tag is mandatory for responsive, mobile-friendly pages (Chapter 21).

<title>: the document title

The title is the text shown on the browser tab, used as the name when the page is bookmarked, and used by search engines as the clickable headline in search results. It is metadata, so it lives in the head and never appears in the page body. Every page needs exactly one, and it should be specific: <title>CSE326 Internet Programming | LPU</title> rather than "Home" or "Page".

title versus h1. <title> is metadata shown in the tab and in search results. <h1> is visible page content, the main heading inside the body. They often say similar things but they are different elements in different places; a page has one of each, and they do not render identically.

<link>: connecting external files

<link rel="stylesheet" href="style.css"> attaches an external CSS stylesheet. rel declares the relationship (this file is a stylesheet) and href gives its path. It is a void element and belongs in the head. The same element with rel="icon" adds the favicon, the small icon beside the title on the tab: <link rel="icon" href="favicon.png">, typically a 32×32 PNG or ICO. Note that <link> is not how you make a hyperlink; that is <a> (Chapter 8).

<meta name="description"> and friends

Other meta tags supply named pieces of information: <meta name="description" content="Learn HTML5 with practical examples."> gives search engines the grey summary shown under the title in results; <meta name="author" content="..."> credits the author. Chapter 11 covers the ones that matter for SEO.

<style> and <script>

<style> holds CSS written directly in the page and belongs in the head. <script> loads or contains JavaScript and can go in either place. The recommended position for most scripts is just before </body>: the browser parses and displays the page content before the script runs, so the user sees the page sooner and the script can find every element because they already exist. (Putting it in the head does not cache it, shrink it or grant special access to the head.)

<body>: everything visible

The body is the container for all visible content: headings, paragraphs, images, tables, forms, audio, video, and the semantic regions of Unit 2. If the user can see it or interact with it, it is in the body.

4.3 Head or body? A decision you will make a thousand times

Belongs in <head>Belongs in <body>
<title>Student Portal</title><h1>Welcome</h1> page heading
<meta charset="UTF-8"><p> paragraph text
<meta name="viewport" ...><img> product photo
<meta name="description" ...><form>, <table>, <video>
<link rel="stylesheet">, <link rel="icon"><header>, <nav>, <main>, <footer>
<style><script> (usually last, before </body>)
head is not header. <head> holds invisible metadata. <header> (Chapter 13) is a visible region inside the body: the page's banner with its logo, title and navigation. They are unrelated elements that happen to share four letters, and confusing them is one of the most frequently examined mistakes in the course.

4.4 The page as a tree

The browser reads the document from the outer structure inward and builds a tree (the DOM) in which every element is a node with a parent and children. Seeing the minimal page as a tree makes the rules obvious: head and body are siblings under html; the title lives under head; the visible content lives under body.

4.5 A complete, well-formed head

Here is the head you should copy into every project. The order matters a little: charset first (so the browser decodes the rest correctly), viewport second, then title, then the rest.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>CSE326 Internet Programming | Student Portal</title>
  <meta name="description" content="Notes, labs and results for CSE326 at LPU.">
  <meta name="author" content="Tarun Jangwal">
  <link rel="icon" href="favicon.png">
  <link rel="stylesheet" href="style.css">
  <style> body { font-family: system-ui, sans-serif; } </style>
</head>
<body>
  <h1>Student Portal</h1>
  <p>Only this body content is visible. The head configured everything else.</p>
  <script> console.log("Runs after the content above has been parsed."); </script>
</body>
</html>

Run it and notice: the title is not on the page, the description is not on the page, and the script did not block the text from appearing. That is the head doing its job invisibly.

Common mistakes

✗ Visible content in the head
<head>
  <h1>Welcome</h1>
</head>
A heading is content. The browser will move it into the body anyway, but the page is invalid.
✓ Metadata in the head, content in the body
<head><title>Welcome</title></head>
<body><h1>Welcome</h1></body>
✗ No doctype, no lang, no charset
<html><body>Hi</body></html>
Renders in quirks mode, has no title, may garble symbols, and tells screen readers nothing about the language.
✓ The complete minimal document
<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8">
<title>T</title></head>
<body>Hi</body></html>
✗ Forgetting the viewport tag
<head>
  <meta charset="UTF-8">
  <title>Menu</title>
</head>
On a phone the page appears as a shrunken desktop layout with unreadable text.
✓ Add it to every page
<meta name="viewport"
  content="width=device-width, initial-scale=1.0">

Exam-style checks

Which declaration tells the browser to use HTML5 parsing rules?L1
  • A. <!DOCTYPE HTML5>
  • B. <meta doctype="html5">
  • C. <html5>
  • D. <!DOCTYPE html>

Answer: D. The HTML5 doctype is simply <!DOCTYPE html>, on line one. The others do not exist.

Which element is the root element of every HTML document?L1
  • A. <body>
  • B. <head>
  • C. <html>
  • D. <!DOCTYPE html>

Answer: C. The doctype is a declaration, not an element; html is the root that contains head and body.

Which of the following belongs inside <head> rather than <body>?L1
  • A. <h1> page heading
  • B. <p> paragraph text
  • C. <meta name="description">
  • D. <img> product photo

Answer: C. Metadata goes in the head; headings, text and images are visible content for the body.

Which of the following would be a mistake to place inside <head>?L1
  • A. <title>Student Portal</title>
  • B. <meta charset="UTF-8">
  • C. <link rel="stylesheet" href="style.css">
  • D. <h1>Welcome</h1>

Answer: D. A heading is visible content and belongs in the body.

Which element is the container for a document's metadata?L1
  • A. <meta>
  • B. <body>
  • C. <header>
  • D. <head>

Answer: D. <meta> is one item of metadata; <head> is the container for all of it. <header> is visible content.

What is the difference between <head> and <header>?L2

Answer: head holds invisible metadata; header is a visible landmark inside the body with the page's banner content. They are not the same and header is not deprecated.

Which element supplies the text shown on the browser tab?L1
  • A. <h1>
  • B. <header>
  • C. <title>
  • D. <caption>

Answer: C. The title also becomes the clickable headline in search results and the bookmark name.

Which statement correctly contrasts <title> with <h1>?L2
  • A. <h1> is metadata; <title> is the visible page content
  • B. <title> is metadata shown in the tab and search results; <h1> is visible page content
  • C. Both render identically inside <body>
  • D. A page may have many <title> elements but only one <h1>

Answer: B. One title in the head, one h1 in the body.

What is the purpose of <meta charset="UTF-8">?L2
  • A. It provides the summary shown in search results
  • B. It sets the page's default font family
  • C. It enables responsive layout on mobile devices
  • D. It declares the character encoding of the document

Answer: D. UTF-8 covers every language and symbol; without the declaration, characters such as the rupee sign can render as junk.

Which meta tag is essential for a mobile-responsive page?L2
  • A. <meta charset="UTF-8">
  • B. <meta name="author" content="...">
  • C. <meta name="description" content="...">
  • D. <meta name="viewport" content="width=device-width, initial-scale=1.0">

Answer: D. The viewport tag makes the mobile browser use the real screen width.

A page has no viewport meta tag. What happens on a mobile browser?L3
  • A. It renders a shrunk-down desktop layout with tiny, unreadable text
  • B. The page refuses to load
  • C. The browser applies a default mobile stylesheet
  • D. All images on the page are hidden

Answer: A. The phone assumes a 980px-wide page and scales it down to fit.

What does <html lang="en"> tell the browser and assistive technology?L2
  • A. The page must be translated into English
  • B. The page may use English fonts only
  • C. The document's language is English
  • D. Only English characters may be typed

Answer: C. It declares the content language so screen readers pronounce it correctly and search engines classify it.

Which element attaches an external CSS stylesheet to a page?L1
  • A. <meta>
  • B. <style>
  • C. <script>
  • D. <link>

Answer: D. <link rel="stylesheet" href="style.css"> in the head. <style> holds CSS written inline in the page, not an external file.

A developer places <script> just before </body> rather than in <head>. What is the main benefit?L3
  • A. The script is automatically cached by the browser
  • B. The script file becomes smaller
  • C. The page content is parsed and displayed before the script runs
  • D. The script gains access to the <head> element

Answer: C. The user sees the content sooner and the script can find every element because they already exist.

What is the correct order of the main structural elements?L1
  • A. html > body > head
  • B. html > head, then html > body
  • C. head > html > body
  • D. body > head > html

Answer: B. head and body are siblings inside html, head first.

Which of these is a valid, complete minimal HTML5 document?L2

Answer: <!DOCTYPE html><html lang="en"><head><meta charset="UTF-8"><title>T</title></head><body>Hi</body></html>. A complete document needs the doctype, html with lang, a head with charset and title, and a body. Versions missing the doctype, the head or the body are incomplete.

Quick revision

Key takeaways

  1. Line one is <!DOCTYPE html>: HTML5 standards mode. Without it: quirks mode.
  2. <html lang="en"> is the root; lang declares the content language for screen readers and search engines.
  3. <head> = invisible metadata: charset, viewport, title, description, link (stylesheet, icon), style. <body> = everything visible.
  4. <meta charset="UTF-8"> prevents garbled characters; the viewport meta tag prevents the shrunken-desktop layout on phones.
  5. <title> is the tab text and search headline; <h1> is the visible main heading. <head> is not <header>.
  6. Scripts go just before </body> so content is parsed and displayed first.
  7. Order: html, then head, then body. The browser turns it all into a tree (the DOM).
