Strings and String Methods

Almost everything a web page says to a person is text: a name, a greeting, a mark, an error message, an address. In JavaScript a piece of text is called a string. This chapter shows you how to write one, join strings together, pick out single letters, and use the ready-made methods that tidy, search, cut and reshape text — the quiet work behind every form you have ever filled in.

About 30 minutes · Course outcome CO4

Before you start — one-line reminders

  • console.log(value) prints a value in the Console, where you can read it (Chapter 41).
  • A variable is a named box for a value: const when it never changes, let when it will (Chapter 42).
  • Text in quotes is a value of type string: typeof "Asha" is "string", and String(7) turns a number into text (Chapter 43).
  • + adds numbers but joins text as soon as one side is a string, so "5" + 1 is "51" (Chapter 44).

  • Build a message with a template literal and ${ } instead of a long chain of +.
  • Read a string's length and any single character, counting from 0 at the front or from −1 at the back.
  • Explain why a string method never changes the original, and store the new string it returns.
  • Tidy, search, cut and reshape text with trim, toUpperCase, includes, indexOf, slice, replaceAll, split, join, padStart, repeat and their relatives.
  • Chain methods to do real jobs: format a name, mask a phone number, count words and make a URL slug.

45.1 Writing a string: quotes and escapes

A string is a piece of text: a row of characters — letters, digits, spaces, punctuation, even emoji — kept in a fixed order. Your name is a string. So is "CSE326". So is the empty string "", which has nothing inside it at all, the way an empty form field has nothing typed in it.

To write a string you put the text between quote marks. JavaScript accepts three kinds:

const a = 'Hello';    // single quotes
const b = "Hello";    // double quotes
const c = `Hello`;    // backticks: the key to the left of 1, above Tab

console.log(a === b);     // true   - exactly the same string
console.log(typeof c);    // string

The quotes are not part of the string. They are the wrapping paper: they tell JavaScript where the text begins and where it ends, and they disappear when the text is printed. console.log("Hello") shows Hello, not "Hello". Single and double quotes are completely equivalent; pick one and stay consistent within a file. This book uses double quotes. Backticks are the odd one out: a string in backticks is called a template literal and has two extra powers, which section 45.2 shows.

Digits in quotes are text too. A phone number such as "9876543210", a PIN code or a roll number is best kept as a string: you will never add two phone numbers together, and a number would quietly drop a leading zero ("0172" as a number is just 172).

When the text contains a quote mark

Trouble starts when the text itself contains a quote. 'It's LPU' ends at the apostrophe: JavaScript sees the string 'It', then a stray s LPU' it cannot understand, and stops with a SyntaxError. The easy fix is to wrap the text in a different kind of quote:

const ok1 = "It's LPU";                     // apostrophe inside double quotes
const ok2 = 'She said "hello"';             // double quotes inside single quotes
const ok3 = `It's "easy" with backticks`;   // both kinds inside backticks

The opening and closing marks must be the same kind. "Hello' is not a string; it is an error.

Escape sequences

When switching quotes is not enough, or you need a character you cannot type into a line of code (such as a line break), use an escape sequence: a backslash \ followed by a character (the ones you need are all a single character after the backslash). The backslash says to JavaScript, "the next character is special: do not treat it the ordinary way."

You writeThe string containsUsed for

The backslash trap. "C:\new\notes" does not contain the word new. \n is a line break, so it prints C:, then ew on the next line, then otes on the line after. Every real backslash must be written twice: "C:\\new\\notes".

A line break made with \n shows in the Console and inside a <pre> element, but in ordinary page text the browser squashes every run of spaces, tabs and line breaks into a single space. Quick check: how can you write the text It's 5 o'clock as a string without any backslash?

Wrap it in double quotes or backticks: "It's 5 o'clock" or `It's 5 o'clock`. Single quotes would end the string at the first apostrophe.

45.2 Joining text: + and template literals

Programs rarely print fixed text. They build messages out of pieces: "Hello, " plus a name plus "!". JavaScript gives you two ways to do it.

Joining with +

You saw in Chapter 44 that + joins strings. Joining strings end to end is called concatenation. Here is the slide example:

const firstName = "Aman";
const lastName = "Kumar";
console.log(firstName + " " + lastName);    // Aman Kumar

Look at the " " in the middle. + glues exactly what you give it and nothing more, so firstName + lastName is AmanKumar. A forgotten space is the most common concatenation bug there is.

You can also grow a message bit by bit with +=, the compound assignment from Chapter 44 (msg += x means msg = msg + x). The variable must be a let, because each step puts a new, longer string into it:

let msg = "Dear " + firstName;
msg += ", your result is ready.";
console.log(msg);                           // Dear Aman, your result is ready.

The danger with + is numbers. JavaScript works left to right, and once the running result is a string, every later + joins instead of adding:

console.log("Total: " + 40 + 50);      // Total: 4050   ("Total: 40", then "50" stuck on)
console.log("Total: " + (40 + 50));    // Total: 90     (brackets add first)
console.log(40 + 50 + " marks");       // 90 marks      (40 + 50 is done before any string appears)

Template literals: text with blanks to fill in

A template literal is a string written in backticks that can contain placeholders. Write ${ }, put an expression inside the braces, and JavaScript works out its value and drops it into the text at that spot. Dropping a value into text like this is called interpolation. The slide example:

const firstName = "Asha";
const course = "JavaScript";
console.log(`Hello, ${firstName}!`);       // Hello, Asha!
console.log(`${course} is fun.`);          // JavaScript is fun.

The braces can hold any expression from Chapter 44, not only a variable name. JavaScript evaluates it first, then turns the answer into text:

const marks = 87;
console.log(`With 5 grace marks: ${marks + 5}`);    // With 5 grace marks: 92
console.log(`Total: ${40 + 50}`);                   // Total: 90 - no number trap

A template literal is a form with blanks. You write the sentence once, put ${ } wherever a blank goes, and JavaScript fills each blank with the current value. No plus signs, no forgotten spaces, no numbers glued together by accident.

The second power: a template literal can span several lines. The line breaks you type become part of the string, so you do not need \n:

const card = `Name:   Asha
Course: CSE326
Marks:  92`;
console.log(card);          // prints three lines, exactly as typed

Exactly as typed means exactly: if you indent the second and third lines to make your code look neat, those spaces become part of the string too.

Only backticks fill blanks. 'Hello, ${firstName}!' in single or double quotes is printed literally, dollar sign, braces and all: Hello, ${firstName}!. If ${ } shows up on your screen, check the quote marks.
JobWith +With a template literal

Which should you use? A template literal for anything with more than one piece; + is fine for joining two strings. Both give an ordinary string in the end: typeof says "string" either way. (There is also a concat() method, "Aman".concat(" ", "Kumar"), but almost nobody uses it.)

45.3 Length and characters: counting from zero

A string is a row of characters in a fixed order, and every character has a position number called its index. Here is the rule that trips up every beginner: the first character is at index 0, not 1. The slide example:

const language = "JavaScript";
console.log(language.length);       // 10
console.log(language[0]);           // J
console.log(language.charAt(4));    // S

length is a property: a fact the string carries with it, read with a dot and no brackets. It counts every character, including spaces and punctuation, so "Hi there!".length is 9. Square brackets language[0] and the method charAt(0) both read the character at a given index.

Because counting starts at 0, the last character of a 10-character string is at index 9. The last index is always length - 1, which gives the classic way to read the last character:

console.log(language[language.length - 1]);    // t

Read an index as "how many characters come before this one". Nothing comes before the first letter, so its index is 0. Nine letters come before the t in JavaScript, so its index is 9. A 10-letter word therefore has indexes 0 to 9, and index 10 does not exist.

Modern JavaScript has a neater way to read from the end: at(). For 0 and positive numbers it works like square brackets, but it also accepts negative numbers, which count backwards from the end: at(-1) is the last character, at(-2) the one before it.

You writeFor "JavaScript"Position that does not exist
language[4]"S"undefined — and language[-1] is undefined too: brackets never count from the end
language.charAt(4)"S""" (an empty string)
language.at(4), language.at(-1)"S", "t"undefined

One honest footnote: length counts the units JavaScript stores, not always the letters you see. For English text they are the same. An emoji such as 😀 is stored as two units, so "😀".length is 2, and words in Indian scripts often have more units than visible letters, because vowel signs are stored separately.

Quick check: in "Rahul", what is the index of the last letter, and what does "Rahul".at(-1) give?

Index 4: the length is 5 and the last index is always length − 1. "Rahul".at(-1) gives "l", the last character.

45.4 Strings never change: methods hand back new ones

A method is an action a value knows how to perform. You call it with a dot, its name and round brackets: word.toUpperCase(). Some methods need extra information inside the brackets — "Hello".indexOf("l") has to be told which character to look for. A value handed to a method like this is called an argument. The brackets are compulsory even when there is no argument: they are what makes the method run.

Here is the slide's tour of five methods. Run it, then look hard at the line that prints text again.

<p>Press Run and read the Console below.</p>
<script>
  const text = "  JavaScript Fundamentals  ";

  // the [ ] around each result only make the spaces visible
  console.log(`[${text.toUpperCase()}]`);
  console.log(`[${text.toLowerCase()}]`);
  console.log(`[${text.trim()}]`);
  console.log(text.includes("Script"));
  console.log("Hello".indexOf("l"));

  // after all that, text is exactly what it was
  console.log(`text is still [${text}]`);

  // square brackets cannot change a character either
  const word = "LPU";
  word[0] = "X";
  console.log(word);

  // to keep a result, store it
  const tidy = text.trim();
  console.log("Stored:", tidy);
</script>

The output is [ JAVASCRIPT FUNDAMENTALS ], [ javascript fundamentals ], [JavaScript Fundamentals], true, 2, then text is still [ JavaScript Fundamentals ], LPU and Stored: JavaScript Fundamentals.

Now the most important fact in this chapter. Strings are immutable: once a string exists, nothing can change a single character inside it. Every method that seems to change a string — toUpperCase, trim, replace, slice, all of them — actually builds a brand-new string and returns it. The original is left exactly as it was.

So a method call sitting alone on its own line does nothing useful:

const name = "asha";
name.toUpperCase();               // makes "ASHA" ... and throws it away
console.log(name);                // asha

const upper = name.toUpperCase(); // catch the new string
console.log(upper);               // ASHA

If you want the same variable to hold the new version, it must be a let, and you put the new string into it:

let city = "  delhi ";
city = city.trim();               // the box now holds a different string
console.log(city);                // delhi

That line does not change the string " delhi "; it replaces what is in the box (Chapter 42). With const city the same line fails with TypeError: Assignment to constant variable. (Chrome's wording; other browsers phrase it differently).

Picture this. The photocopy shop outside the LPU gate. You hand over your notes and ask for "the same, but in capitals", or "only page 4", or "with every Rahul changed to Meera". The shopkeeper never writes on your notes. He makes a fresh copy with the change and hands it back, and your original goes back into your bag untouched. If you walk off without collecting the copy, the work is simply lost. String methods are that shopkeeper: they always hand you a new copy, and catching it is your job.

A string method never edits; it copies with a change. Catch the copy in a variable, or it is gone. Square brackets cannot edit either: word[0] = "X" is quietly ignored in an ordinary script, and in strict mode (which JavaScript modules use) it stops with a TypeError.

Quick check: after let city = "delhi"; city.toUpperCase(); what is in city?

Still "delhi". The capitals were made and thrown away. To keep them, write city = city.toUpperCase(); — allowed because city is a let.

45.5 Tidying: capital letters and stray spaces

People type carelessly. They leave Caps Lock on, they paste text with a space at either end, they write Asha@LPU.in one day and asha@lpu.in the next. Before your program compares or stores text, it should tidy it.

Changing case

toUpperCase() returns a copy with every letter in capitals; toLowerCase() returns one with every letter small. Digits, spaces and punctuation are left alone: "Room 34-B".toLowerCase() is "room 34-b".

The main reason to change case is comparing. === compares strings character by character, and a capital letter is a different character from a small one, so "LPU" === "lpu" is false. To compare what someone typed with what you expect, lower-case it first:

const typed = "ASHA@lpu.in";
console.log(typed === "asha@lpu.in");                  // false
console.log(typed.toLowerCase() === "asha@lpu.in");    // true

Removing stray spaces

Spaces, tabs and line breaks are together called whitespace: characters you cannot see but that are really there. trim() removes whitespace from both ends of a string; trimStart() only from the front; trimEnd() only from the back. None of them ever touches the spaces between words.

const raw = "   Asha Kumar   ";
console.log(`[${raw.trim()}]`);         // [Asha Kumar]
console.log(`[${raw.trimStart()}]`);    // [Asha Kumar   ]
console.log(`[${raw.trimEnd()}]`);      // [   Asha Kumar]
console.log(raw.length, raw.trim().length);   // 16 10

Why it matters: a student registers as "asha " with a stray space from a copy-paste, later logs in as "asha", and the site insists the account does not exist. The two strings differ by one invisible character.

Key idea. Tidy first, then check. Almost every piece of text a user types should go through trim() — and, for emails and usernames, toLowerCase() — before your program compares it, searches it or saves it.

45.6 Searching inside a string

Three methods answer a yes-or-no question, so they return true or false (the booleans of Chapter 43):

MethodAsksExample → result
includes(x)Is x anywhere inside?"JavaScript".includes("Script") → true
startsWith(x)Does it begin with x?"JavaScript".startsWith("Java") → true
endsWith(x)Does it finish with x?"notes.pdf".endsWith(".pdf") → true
 
const file = "report-final.pdf";
console.log(file.includes("final"));      // true
console.log(file.startsWith("report"));   // true
console.log(file.endsWith(".pdf"));       // true
console.log(file.endsWith(".PDF"));       // false - case matters

Every search is case-sensitive. "JavaScript".includes("script") is false, because the string has a capital S. When case should not matter, lower-case first: text.toLowerCase().includes("script").

Where is it? indexOf and lastIndexOf

The other two search methods answer where. indexOf(x) returns the index at which x first appears; lastIndexOf(x) returns where it last appears. When x is not there at all, both return -1 — a number that can never be a real position, which makes it a safe way to say "not found".

console.log("Hello".indexOf("l"));            // 2   (from the slides)
console.log("Hello".lastIndexOf("l"));        // 3
console.log("Hello".indexOf("z"));            // -1  not found
console.log("Hello".indexOf("H"));            // 0   found, at the very start
console.log("Asha Kumar".indexOf("Kumar"));   // 5   where the match begins
Exam tip. includes, startsWith and endsWith return true/false; indexOf and lastIndexOf return a number. And -1 means not found, while 0 means found at the front — do not mix them up.

Searching for a kind of text rather than exact text — "any digit", "ten digits in a row", "something that looks like an email" — needs regular expressions, which have a chapter of their own (Chapter 61).

45.7 Cutting out a piece: slice and substring

slice(start, end) returns a copy of part of a string: the characters from index start up to, but not including, index end. Leave out end and it goes to the end of the string.

const language = "JavaScript";
console.log(language.slice(0, 4));     // Java
console.log(language.slice(4, 10));    // Script
console.log(language.slice(4));        // Script - no end means "to the end"

Picture a knife and number the gaps between letters, starting with gap 0 before the first letter. slice(4, 10) cuts at gap 4 and at gap 10 and keeps what is between. That is why the end number is "not included", and why the number of characters you get is simply end − start.

Negative numbers count from the end

Just as with at(), a negative number in slice counts from the end of the string. slice(-4) means "the last four characters" — very handy:

const phone = "9876543210";
console.log(phone.slice(-4));            // 3210
console.log(language.slice(-6, -3));     // Scr        (gaps 4 to 7)
console.log(language.slice(0, -1));      // JavaScrip  (everything but the last)

substring: the older cousin

substring(start, end) does the same job as slice for ordinary positive numbers. It differs in two ways: negative numbers are treated as 0, and if start is bigger than end it quietly swaps them.

Call on "JavaScript"slice givessubstring gives

Quick check: what does "JavaScript".slice(0, 4) return?

"Java" — the characters at indexes 0, 1, 2 and 3. Index 4 (the S) is the fence and is not included; 4 − 0 = 4 characters.

Now search and cut together. Find the @ in an email address with indexOf, then slice on either side of it:

<script>

45.8 Reshaping: replace, split, join, pad and repeat

replace and replaceAll

replace(old, new) returns a copy in which the first match of old is swapped for new. Only the first. To swap every match, use replaceAll:

const s = "I like Java. Java is fun.";
console.log(s.replace("Java", "JavaScript"));      // I like JavaScript. Java is fun.
console.log(s.replaceAll("Java", "JavaScript"));   // I like JavaScript. JavaScript is fun.
console.log(s);                                    // I like Java. Java is fun.  (unchanged)

Both are case-sensitive, and both leave s alone. Replacing with an empty string deletes: "98-765-43210".replaceAll("-", "") gives "9876543210". In older code you will see replace(/Java/g, "JavaScript") doing the job of replaceAll; the /Java/g part is a regular expression (Chapter 61).

split: one string into a list of pieces

split(separator) cuts a string at every separator and returns the pieces as an array — an ordered list in square brackets. Arrays get a chapter of their own (Chapter 50); for now you need three facts: the Console shows one as ['29', '10', '2026'], .length says how many pieces there are, and parts[0] is the first piece, counted from 0 just like characters.

const date = "29/10/2026";
const parts = date.split("/");
console.log(parts);              // ['29', '10', '2026']
console.log(parts.length);       // 3
console.log(parts[2]);           // 2026
console.log("Asha".split(""));   // ['A', 's', 'h', 'a']   - "" splits into characters

The separator itself disappears: the pieces of "29/10/2026" contain no slashes.

join: a list back into one string

join(separator) is the reverse, and it belongs to the array, not the string. It glues the pieces into one string with the separator between them:

console.log(parts.join("-"));           // 29-10-2026
console.log(["CSE", "326"].join(""));   // CSE326
console.log(parts.join());              // 29,10,2026   - no separator means commas

A split followed by a join swaps one separator for another: date.split("/").join("-") and date.replaceAll("/", "-") both give "29-10-2026".

padStart, padEnd and repeat

padStart(targetLength, padText) adds padText to the front until the string is targetLength characters long; padEnd adds it to the back. The first number is the length you want to end up with, not how many characters to add. Leave out the second argument and it pads with spaces.

console.log("7".padStart(3, "0"));            // 007
console.log("42".padStart(3, "0"));           // 042
console.log("123".padStart(3, "0"));          // 123   - already 3 long, nothing added
console.log(String(9).padStart(2, "0") + ":05");   // 09:05
console.log("Asha".padEnd(8, ".") + "92");    // Asha....92

padStart is a string method, so a number must become a string first: String(7).padStart(3, "0"). Writing (7).padStart(3, "0") fails, because numbers do not have this method.

repeat(n) returns the string written n times in a row; repeat(0) gives the empty string.

console.log("-".repeat(20));              // --------------------
console.log("ha".repeat(3));              // hahaha
console.log("★".repeat(4) + "☆");          // ★★★★☆

  console.log(date.replaceAll("/", "-"));

  const roll = 7;
  console.log("LPU" + String(roll).padStart(4, "0"));

  // padEnd + padStart line the marks up in neat columns
  const line = "=".repeat(16);
  const report =
    line + "\n" +
    "Asha".padEnd(12, ".") + "92".padStart(4) + "\n" +
    "Rahul".padEnd(12, ".") + "78".padStart(4) + "\n" +
    "Meera".padEnd(12, ".") + "100".padStart(4) + "\n" +
    line + "\n" +
    "Rating: " + "★".repeat(4) + "☆";
  console.log(report);
  document.getElementById("out").textContent = report;
</script>

Every row of the report is exactly 16 characters wide — 12 for the padded name, 4 for the padded mark — so the marks line up on the right, both on the page and in the Console. Change "Rahul" to "Ravi" and the dots grow to keep the column straight.

45.9 Chaining methods: four everyday jobs

Because a string method returns a string, you can call another method straight on the result, then another on that. Calling methods one after another like this is called chaining, and it reads left to right like the steps of a recipe:

const tag = "  web dev  ".trim().toUpperCase().replace(" ", "_");
console.log(tag);     // WEB_DEV
StepValue after the step
start" web dev "
.trim()"web dev"
.toUpperCase()"WEB DEV"
.replace(" ", "_")"WEB_DEV"

A long chain is easier to read with one call per line. JavaScript does not mind the line breaks, because the dot at the start of each line shows the chain continues:

const slug = title
  .trim()
  .toLowerCase()
  .replaceAll(" ", "-");

A chain of string methods continues only while each step returns a string. includes, startsWith and indexOf return a boolean or a number, so they end a chain: "Asha".includes("sh").toUpperCase() fails with a TypeError, because true has no toUpperCase method. split returns an array, which has methods of its own — that is why split(...).join(...) works.

Here are four small jobs that real websites do every day, each one a short chain.

Job 1: format a name typed carelessly

Someone types " aSHA kUMAR ". Tidy it, lower-case it, split it into the two words, and give each word a capital first letter: the first character upper-cased, joined to the rest of the word.

const parts = "  aSHA kUMAR ".trim().toLowerCase().split(" ");  // ['asha', 'kumar']
const first = parts[0][0].toUpperCase() + parts[0].slice(1);     // "A" + "sha"
const last = parts[1][0].toUpperCase() + parts[1].slice(1);      // "K" + "umar"
console.log(`${first} ${last}`);                                 // Asha Kumar

parts[0][0] reads the first piece, then the first character of that piece. The two nearly identical lines are a sign that a function would help; Chapter 48 shows how, and Chapter 53 handles names with any number of words.

Job 2: mask a phone number

Show only the last four digits, as banks and delivery apps do. Two ways, same answer:

const phone = "9876543210";
console.log(phone.slice(-4).padStart(phone.length, "*"));     // ******3210
console.log("*".repeat(phone.length - 4) + phone.slice(-4));  // ******3210

Job 3: count the words in a sentence

Trim the ends, split at each space, and count the pieces:

const sentence = "  Web pages are made of text  ";
console.log(sentence.trim().split(" ").length);    // 6
Where this breaks. Two spaces between words make an empty piece. Split Web, two spaces, pages at every single space and you get ['Web', '', 'pages']: the empty string between the two spaces counts as a third word. This is also why the trim() matters — a space at either end would add an empty piece too. Splitting on "one or more spaces" needs a regular expression, split(/\s+/), from Chapter 61.

Job 4: make a URL slug

A slug is the readable part of a web address made from a title, like lpu.in/blog/strings-and-string-methods-in-js. A web address cannot hold a plain space (the browser would turn it into an ugly %20), and small letters avoid confusion, so:

const title = "  Strings & String Methods in JS  ";
const slug = title.trim().toLowerCase()
  .replaceAll(" & ", " and ")
  .replaceAll(" ", "-");
console.log(slug);      // strings-and-string-methods-in-js

45.10 Common misunderstandings

✗ "name.toUpperCase() turns name into capitals."
Strings are immutable. The method builds a new string and, if nothing catches it, the new string is lost.
✓ "const upper = name.toUpperCase();"
Store the returned string — or, with a let, put it back: name = name.toUpperCase();.
✗ "The first character is at position 1."
That is how people count, not how JavaScript does. "Asha"[1] is "s".
✓ "The first character is at index 0; the last is at length - 1."
Or use at(-1) for the last one.
✗ "replace() changes every match."
It changes only the first: "banana".replace("a", "o") is "bonana".
✓ "replaceAll() changes every match."
"banana".replaceAll("a", "o") is "bonono".
✗ "slice(2, 5) gives the characters at 2, 3, 4 and 5."
The end index is a fence and is never included.
✓ "slice(2, 5) gives indexes 2, 3 and 4 — 5 − 2 = 3 characters."
"JavaScript".slice(2, 5) is "vaS".
✗ "word.length() gives the length."
It stops with TypeError: word.length is not a function.
✓ "length is a property: word.length, no brackets."
Methods have brackets (trim()); properties do not.
✗ "'Hello, ${name}' fills in the name."
In single or double quotes, ${name} is printed as it stands.
✓ "Only backticks fill blanks: `Hello, ${name}`."
If you see ${ on the screen, check the quote marks.

Exam-style checks

Answer each one before opening it. Most are four-option questions with exactly one correct answer; the last few ask you to predict the output.

Which of these is NOT a valid string in JavaScript?L1
  • A. 'Hello'
  • B. "Hello"
  • C. `Hello`
  • D. "Hello'

Answer: D. The opening and closing quote marks must be the same kind. Single quotes, double quotes and backticks are all valid on their own; mixing them on one string is a SyntaxError.

What does this print? const firstName = "Asha"; console.log('Hi, ${firstName}!');L2
  • A. Hi, ${firstName}!
  • B. Hi, Asha!
  • C. Hi, firstName!
  • D. A SyntaxError

Answer: A. ${ } is filled in only inside backticks. In single quotes it is ordinary text, so it is printed exactly as written. B is what the backtick version would print.

What is the value of "JavaScript".length?L1
  • A. 9
  • B. 11
  • C. 10
  • D. undefined

Answer: C. Ten characters. The tempting 9 is the index of the last character, because indexes start at 0: last index = length − 1.

What does this print? const s = "Hello"; s.toUpperCase(); console.log(s);L2
  • A. HELLO
  • B. Hello
  • C. hello
  • D. undefined

Answer: B. Strings are immutable. toUpperCase() returned a new string "HELLO", but nothing stored it, and s was never changed.

What does "Hello".indexOf("l") return?L2
  • A. 1
  • B. 3
  • C. -1
  • D. 2

Answer: D. H is 0, e is 1, the first l is 2. indexOf reports the first match; 3 is what lastIndexOf("l") would give, and −1 would mean not found.

What does "banana".replace("a", "o") return?L2
  • A. "bonono"
  • B. "banano"
  • C. "bonana"
  • D. "banana"

Answer: C. replace swaps only the first match. A is what replaceAll gives; D would be the original, which is indeed unchanged — but the question asks what the method returns.

What does "JavaScript".slice(-6) return?L3
  • A. "Script"
  • B. "JavaSc"
  • C. "tpircS"
  • D. "Scrip"

Answer: A. A negative start counts from the end: −6 means 10 − 6 = index 4, and with no end it runs to the end of the string. B is slice(0, 6); slice never reverses anything.

Which of these methods returns a number rather than true or false?L2
  • A. includes()
  • B. indexOf()
  • C. endsWith()
  • D. startsWith()

Answer: B. indexOf returns the position of the first match, or −1 when there is none. The other three answer a yes-or-no question with a boolean.

What does "red,green,blue".split(",") return?L2
  • A. The string "red green blue"
  • B. The number 3
  • C. An array of three strings: ['red', 'green', 'blue']
  • D. An array holding one string: ['red,green,blue']

Answer: C. split cuts at every comma and returns the pieces as an array; the commas themselves disappear. Its .length would be 3, but split itself returns the array. D is what split gives when the separator is not found.

What does this print? const word = "LPU"; word[0] = "X"; console.log(word);L3
  • A. LPU
  • B. XPU
  • C. X
  • D. A TypeError, in every kind of script

Answer: A. A string's characters cannot be changed, so the assignment is quietly ignored in an ordinary script. (In strict mode, which modules use, it would stop with a TypeError instead — but it never produces XPU.)

Predict both lines: console.log("Total: " + 40 + 50); console.log(`Total: ${40 + 50}`);L3

Answer: Total: 4050, then Total: 90. In the first line JavaScript works left to right: "Total: " + 40 is the string "Total: 40", and adding 50 to a string joins it. In the template literal, 40 + 50 is worked out first as a number sum, then dropped into the text.

Predict the output: const phone = "9876543210"; console.log(phone.slice(-4).padStart(phone.length, "*"));L3

Answer: ******3210. slice(-4) gives the last four characters, "3210". padStart(10, "*") then adds stars to the front until the string is 10 long: six stars. The first argument of padStart is the target length, not the number of stars.

Quick revision

Key takeaways

  1. A string is text in quotes: '...', "..." or `...`. The quotes are not part of the text. Use the other kind of quote, or a backslash escape (\' \" \\ \n \t), when the text needs them.
  2. A template literal (backticks) fills ${ } with any expression and can span lines. With +, once a string appears everything after it joins: "Total: " + 40 + 50 is "Total: 4050".
  3. Characters are numbered from 0. length (a property, no brackets) counts them; the last is at length - 1 or at(-1).
  4. Strings are immutable. Every method returns a new string; store it or lose it.
  5. Tidy before you compare: trim() for stray spaces, toLowerCase() because === and every search are case-sensitive.
  6. includes, startsWith, endsWith return true/false; indexOf and lastIndexOf return a position, or −1 for not found.
  7. slice(start, end) leaves out the end index and accepts negatives. replace changes the first match, replaceAll every one. split makes an array; join makes a string. padStart/padEnd pad to a target length; repeat(n) repeats.
  8. Chain methods left to right while each step still returns a string.
