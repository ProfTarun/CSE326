SEO Fundamentals

A page nobody can find might as well not exist. Search engine optimisation (SEO) is the craft of making a page easy for search engines to discover, understand and rank, and almost all of it is simply good HTML. This chapter explains how search engines work, which parts of your markup they read, the two small files that guide crawlers, and the tricks that no longer work (and now hurt).

About 15 minutes · Course outcome CO1

By the end of this chapter you can

  • Describe the crawl, index, rank pipeline.
  • Write a title, meta description, heading structure, alt text, link text and URL that help a page rank.
  • Explain robots.txt, sitemap.xml and <meta name="robots">.
  • Say why meta keywords, keyword stuffing and hidden text do not work.
  • List the performance and mobile factors that affect ranking.

11.1 How a search engine works

Google, Bing and the others run the same three-stage pipeline.

  1. Crawl. A program (a crawler or bot) starts from pages it already knows and follows every link it finds, fetching the pages. If nothing links to your page and it is not in a sitemap, it may never be found.
  2. Index. The engine reads each page's HTML to work out what it is about. It cannot see your page the way you do; it reads the title, the headings, the text, the alt text of images, the link text pointing in and out, and the semantic structure. This is why SEO and good HTML are nearly the same thing.
  3. Rank. When someone searches, the engine orders the matching pages by relevance and quality: how well the content answers the query, how trustworthy the site is (measured largely by who links to it), how fast the page loads and how well it works on a phone.
SEO is communication, not tricks. Search engines want the same thing users want: a page that clearly says what it is about and delivers it. Every legitimate technique below makes the page clearer to humans as well as machines. Every discredited trick tries to fool the machine at the human's expense, and engines now punish exactly that.

11.2 The on-page signals in your HTML

A unique, descriptive <title>
The title becomes the clickable headline in search results and the tab text. Make it specific to the page: <title>HTML5 Tutorial for CSE326 Students | LPU</title>, not "Home" or "Page". Every page on the site should have a different title.
A meta description
<meta name="description" content="Learn HTML5 with practical coding examples."> supplies the summary text shown under the title in search results. It does not directly raise ranking, but a good one wins the click. It is never shown in the tab or as a heading.
A logical heading hierarchy
Crawlers read h1 to h6 as the page's outline: main subject, chapters, topics. Exactly one h1 stating the page's topic, then h2 sections and h3 sub-topics (Chapter 6). Repeated or stuffed headings do not help.
Semantic elements
<header>, <nav>, <main>, <article> and friends tell the engine which part of the page is the content and which is navigation or boilerplate. A page built only from divs gives it no such map (Chapter 13).
Descriptive alt text
Engines cannot see images. alt="LPU University Campus Aerial View" lets Google Image search index the photo and tells the engine what the page shows (Chapter 8).
Meaningful link text
The words inside <a> describe the destination to the engine as well as to screen readers. "View our pricing plans" tells it what the linked page is about; "click here" tells it nothing.
Descriptive URLs
A URL such as /courses/web-development signals the page's topic to both users and search engines; /page?id=257 signals nothing. A good URL does not guarantee a first-page ranking, does not speed up loading and does not replace the description; it is one more clear signal.
Real, useful content
Above everything else: text that genuinely answers what people search for. No markup rescues a page with nothing to say.
<head>
  <title>Campus Placement Drive 2026 | School of Computing, LPU</title>
  <meta name="description" content="Dates, eligible programmes and registration steps for the 2026 placement drive at the School of Computing and AI.">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
</head>
<body>
  <main>
    <h1>Campus Placement Drive 2026</h1>
    <img src="drive.jpg" alt="Students at the 2025 placement drive registration desk">
    <h2>Who can register</h2> ...
    <p>See the <a href="/placements/companies-2026">list of participating companies</a>.</p>
  </main>
</body>

11.3 Guiding the crawler: robots.txt, sitemap.xml and meta robots

robots.txt
A plain text file at the site root (https://example.com/robots.txt) that asks crawlers which paths to skip: Disallow: /drafts/. Two things to understand: it is a request, not security: well-behaved crawlers obey it, malicious ones ignore it; and it is publicly readable, so listing your admin page in it advertises the path to anyone looking for interesting places. It is a file, not an HTML tag or attribute.
sitemap.xml
An XML file that lists a website's important pages (and when they changed) so search engines can discover and index them even if the internal linking is poor. Submit it through the engine's webmaster tools. It is not index.html (a page) and not manifest.json (an app description).
<meta name="robots">
A per-page instruction in the head. <meta name="robots" content="noindex"> asks search engines not to include the page in their index (for a thank-you page, a search-results page, a duplicate). nofollow asks them not to follow the page's links. There is no name="index" or name="crawl" tag.
# robots.txt at the site root
User-agent: *
Disallow: /drafts/
Sitemap: https://example.com/sitemap.xml

11.4 What no longer works, and now hurts

Discredited trickWhy it fails
<meta name="keywords" content="html, css, best, free, ...">Google has ignored the keywords meta tag since 2009. It has no SEO value today; you should know it exists because it is on the syllabus, but stuffing it changes nothing.
Keyword stuffing and hidden text (repeating "web development" fifty times, white text on a white background)It degrades the reading experience and search engines treat it as manipulation, lowering or removing the page. It does not disable the description, hit a file-size limit or break validation; it simply gets punished.
Repeated headings, many h1s, longer keyword listsStructure that lies about the content is ignored or penalised.
Bought links, link farmsEngines detect unnatural link patterns and discount them.

11.5 Speed and mobile: the technical half

Two ranking factors live outside your text. Loading performance: engines measure how fast the page becomes usable, so compress images, use modern formats, set width and height, lazy-load off-screen images and defer non-critical scripts and styles (Chapters 4, 8 and 12). Adding meta keywords, replacing semantic elements with divs or splitting CSS into many stylesheets does nothing for speed or ranking. Mobile-friendliness: engines index the mobile version of a page first, so the viewport meta tag and a layout that works on a phone (Chapter 21) are ranking factors. HTTPS is a small positive signal too.

A checklist for every page you publish

  • Unique, descriptive <title>
  • <meta name="description"> written for humans
  • Exactly one <h1>; logical h2/h3 outline
  • Semantic landmarks: header, nav, main, footer
  • Descriptive alt on every informative image
  • Link text that names the destination
  • Readable URLs
  • Viewport meta tag; layout works on a phone
  • Compressed images, lazy loading, scripts before </body>, HTTPS
  • robots.txt and sitemap.xml at the root; noindex on pages that should not appear

Notice that the first seven items are the accessibility checklist from Unit 2 as well. Good SEO and good accessibility are largely the same work: descriptive alt text and link text, in particular, improve both at once.

Exam-style checks

Which tag's content becomes the clickable blue headline in search results?L1
  • A. <h1>
  • B. <title>
  • C. <meta name="description">
  • D. <header>

Answer: B. The title is the headline; the description meta tag is the grey summary beneath it.

Where does the meta description typically appear?L1
  • A. As the summary text under the title in search results
  • B. In the browser tab
  • C. As the page's main visible heading
  • D. It is never shown to users

Answer: A.

Does stuffing keywords into <meta name="keywords"> improve Google ranking?L2

Answer: No. Google has ignored the keywords meta tag since 2009. Know that it exists; do not rely on it.

Why is repeating a keyword many times in hidden text harmful to a site?L3
  • A. It disables the page's meta description
  • B. It increases the page's file size beyond the browser limit
  • C. It prevents the page from being validated as HTML5
  • D. It degrades the reading experience and search engines treat it as manipulation

Answer: D.

Which file lists a website's important pages so search engines can discover and index them?L2
  • A. robots.txt
  • B. sitemap.xml
  • C. index.html
  • D. manifest.json

Answer: B. robots.txt asks crawlers what to skip; the sitemap tells them what to visit.

What is robots.txt, and why is listing an admin path in it a bad idea?L2

Answer: a file at the site root asking crawlers which paths to skip. It is a request, not security, and it is publicly readable, so listing an admin path advertises it to anyone looking.

Which meta tag asks search engines not to include the page in their index?L2
  • A. <meta name="robots" content="noindex">
  • B. <meta name="robots" content="nofollow">
  • C. <meta name="index" content="false">
  • D. <meta name="crawl" content="deny">

Answer: A. nofollow only stops link following; C and D do not exist.

What SEO benefit does a descriptive URL such as /courses/web-development provide?L2
  • A. It guarantees a first-page ranking
  • B. It makes the page load measurably faster
  • C. It signals the page's topic to both users and search engines
  • D. It removes the need for a meta description

Answer: C.

Which link text is better for SEO and accessibility: "click here" or "Download the CSE326 syllabus (PDF)"?L2

Answer: the descriptive one. Link text should describe the destination; a screen-reader user listing links otherwise hears "here, here, here", and the engine learns nothing.

Which change is most likely to improve a page's loading performance?L2
  • A. Adding more meta keywords to the head
  • B. Compressing images and deferring non-critical resources
  • C. Replacing semantic elements with <div> elements
  • D. Increasing the number of separate stylesheets

Answer: B.

Which combination of HTML changes best improves a page's search visibility?L3
  • A. Larger fonts and additional decorative images
  • B. More <div> wrappers and inline styles on every element
  • C. A longer meta keywords list and repeated headings
  • D. A unique title, exactly one <h1>, descriptive alt text and meaningful link text

Answer: D. Every item in D is also an accessibility improvement.

Which practice most improves BOTH SEO and accessibility?L2

Answer: descriptive alt text and link text. Good SEO and good accessibility are largely the same work.

Quick revision

Key takeaways

  1. Crawl, index, rank, click. Links get you crawled; clear HTML gets you understood; quality, speed and mobile-friendliness get you ranked; title and description win the click.
  2. title = clickable headline; meta description = grey summary; one h1 and a logical outline; semantic landmarks; alt text; link text that names the destination; readable URLs.
  3. robots.txt (root file, a public request to skip paths); sitemap.xml (list of pages to index); meta robots noindex (keep this page out).
  4. Meta keywords have been ignored by Google since 2009; keyword stuffing and hidden text are treated as manipulation.
  5. Performance (compressed images, lazy loading, deferred scripts) and mobile-friendliness (viewport) are ranking factors. SEO and accessibility overlap almost completely.
