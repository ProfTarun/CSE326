Loops and Iterative Programming

Print the numbers 1 to 1,000. Add up the marks of a class of sixty. Check every product in a shop for the word a customer has typed. Nobody writes those as a thousand lines of code: you write a few lines once and tell the computer to repeat them. That instruction is a loop, and it is the engine behind almost every interactive page you will build in this unit.

Before you start — one-line reminders

  • A condition such as marks >= 40 is either true or false, and if runs its block only when it is true (Chapter 47).
  • i++ adds 1 to i, and total += mark adds mark to total (Chapter 44).
  • An array keeps a list in order; its indexes run from 0 to length - 1, and arr[i] reads one element (Chapter 50).
  • An object holds key: value pairs, and marks[subject] reads a value whose key is in a variable (Chapter 51).

52.1 Why interactive pages need loops

Unit 4 taught you the language; Unit 5 makes pages respond. A static page shows every visitor the same content. An interactive page changes while you watch: the cart badge goes from 4 to 5 when you tap Add to Cart, and the product list shrinks as you type in a search box. HTML gives the page its structure (the skeleton), CSS its appearance (the skin), and JavaScript its behaviour (the muscles and brain). Your slides trace every interaction the same way: the user acts, JavaScript notices, runs some logic, updates the page, and the browser shows the result. The tool that logic uses most is the loop.

A live subtotal adds up every item in the cart; a search box checks every product name; a results page goes through every student's marks. Whenever a job says "every" or "until", it needs repetition.

Your slides call this iterative programming: executing a set of instructions repeatedly until a condition is satisfied or the required number of repetitions is complete. Each single trip through the repeated instructions is one iteration; this book also calls it a round.

Here is the problem loops solve. To print the numbers 1 to 5 with what you know so far, you would write:

console.log(1);
console.log(2);
console.log(3);
console.log(4);
console.log(5);

Five lines for five numbers. A thousand numbers would need a thousand lines. Worse, if a cart holds 3 items today and 30 tomorrow, you cannot know how many lines to write at all. A loop says it once:

for (let i = 1; i <= 5; i++) {
  console.log(i);
}

Change the 5 to 1000 and it prints a thousand numbers with the same three lines. The statements inside the curly braces are the loop's body, and the line above them decides how many times it runs. Your slides list JavaScript's five loops:

LoopPurpose
forRepeats a known number of times
whileRepeats while a condition is true
do...whileRuns the body once, then checks the condition
for...ofVisits each value of an array or string
for...inVisits each key of an object
Picture this. Your mother is making dinner. "Make ten rotis" is a for loop: she knows the number before she starts and keeps count, checking each time whether she has reached ten. "Keep making rotis while there is dough in the bowl" is a while loop: she looks at the bowl before each roti, and if it is empty to begin with she makes none. "Taste the dal; if it needs salt, add a pinch and taste again" is a do...while loop: she always tastes at least once, because the check comes after the action. Three ways of repeating, chosen by what you know before you start.

52.2 The for loop, step by step

Your slides give the shape of a for loop and an example:

for (initialization; condition; update) {
  // code to repeat
}

for (let i = 1; i <= 5; i++) {
  console.log(i);
}

The round brackets hold three parts, separated by two semicolons:

  • Initialization, let i = 1: runs once, before anything else. It creates the counter and gives it a starting value.
  • Condition, i <= 5: checked before every round, including the first. If it is true, the body runs. If it is false, the loop is over and JavaScript carries on with the line after the closing brace.
  • Update, i++: runs after every round, just before the next check. It moves the counter on.

To trace a loop, play computer: write down the counter and the condition at every step.

The body ran five times, but the condition was checked six times; the sixth check stops the loop, with i equal to 6, not 5. Made with let inside the brackets, i belongs to the loop and disappears afterwards (Chapter 49).

A for loop is a counter with three settings: where to start, when to stop, and how to step. JavaScript does the start once, then repeats check, work, step until the check says no.

52.3 while and do...while

A for loop suits a known count. Often you do not know it. A while loop keeps only the condition in its brackets and repeats as long as it is true. Your slides' example:

let count = 1;

while (count <= 5) {
  console.log(count);     // 1 2 3 4 5, one per line
  count++;
}

These are the for loop's three parts in three places: the start before the loop, the condition in the brackets, the update at the end of the body. Like for, it checks before each round, so it can run zero times. Your slides warn: update the variable, or an infinite loop may occur. Without count++, count stays 1 forever (section 52.8).

while shines when the number of rounds is the answer you want. Rahul saves ₹150 a week towards headphones that cost ₹1,000. How many weeks will it take?

let saved = 0;
let weeks = 0;
while (saved < 1000) {
  saved += 150;
  weeks++;
}
console.log(weeks, saved);   // 7 1050

Nobody wrote 7 anywhere: the loop ran until ₹1,050 was no longer below ₹1,000, and the counter recorded how long that took.

do...while: act first, ask afterwards

A do...while loop puts the body first and the condition at the bottom. Your slides' example:

let number = 10;
do {
  console.log(number);
  number++;
} while (number <= 5);

Output: 10. The condition is false from the start, yet 10 is printed, because do...while runs the body first and checks afterwards; the check only decides whether to go round again. Now number is 11, 11 <= 5 is false, and the loop stops after one round. Note the semicolon after while (number <= 5).

Use do...while when one round must happen before the question makes sense: show a menu, then ask whether to show it again. Counting a number's digits is a neat case. Each round counts one digit and drops the last one with Math.floor(num / 10) (Chapter 46). Zero has one digit, and only do...while says so; a while (num > 0) loop would never start and would report 0.

while asks "shall I?" before every round, so it may never start. do...while does the work first and asks "again?" afterwards, so it always runs at least once.

Quick check: after let x = 0; do { x--; } while (x > 0); what is x? What would it be if the loop were while (x > 0) { x--; } instead?

With do...while, x is −1: the body runs once before the check, and -1 > 0 is false, so it stops. With while, the first check 0 > 0 is already false, so the body never runs and x stays 0.

52.4 Walking through arrays and objects

The commonest loop job on a web page is visiting every item in a list. Your slides use for...of:

const subjects = ["HTML", "CSS", "JavaScript"];

for (const subject of subjects) {
  console.log(subject);     // HTML, CSS, JavaScript - one per line
}

Read it as "for each subject of subjects": each round, subject holds the next element. No counter, no condition to get wrong, no way to run past the end. It can be const because every round gets a fresh subject.

for...of works on anything that is iterable: arrays, strings (one character per round) and, later, the lists of page elements you will meet in Chapter 56. A plain object is not iterable; for (const x of marks) on an object stops with TypeError: marks is not iterable.

When you need the position too

Sometimes the position matters: to number the lines, or to change subjects[i]. Then use the counting for loop you met in Chapter 50:

for (let i = 0; i < subjects.length; i++) {
  console.log("Subject", i + 1, "is", subjects[i]);   // Subject 1 is HTML ...
}

It starts at 0, the first index, and stops with < subjects.length, because the last index is length - 1. The i + 1 is only for human readers.

for...in: the keys of an object

An object has keys, not positions. for...in hands you each key in turn, as a string, and brackets read its value, exactly as Chapter 51 showed:

const marks = { html: 82, css: 74, javascript: 90 };

for (const subject in marks) {
  console.log(subject, "->", marks[subject]);   // html -> 82, css -> 74, javascript -> 90
}
Do not use for...in on an array. It runs, which is why it is a trap. It hands over an array's indexes as strings, "0", "1", "2", so arithmetic goes wrong without any error: i + 1 gives "01", because + joins strings (Chapter 44). It also visits any extra property attached to the array. Use for...of for values, or the counting for when you need numbers.

for...of gives you each value of a list. for...in gives you each key in an object. The counting for gives you the position number, for when you need it.

52.5 break and continue

Chapter 47 met these two words; here they do real work. Both usually sit inside an if in the body:

  • continue skips the rest of this round and moves on to the next one. In a for loop the update still runs; in a while loop JavaScript jumps straight back to the condition.
  • break ends the whole loop at once. JavaScript carries on with the line after the loop's closing brace.

Take a class register in which Rahul was absent for the test, so his marks are null. To average the students who were present, continue skips Rahul and carries on. To find the first student who scored below 40, break stops the search the moment one is found. Once you have what you were looking for, every further round is wasted work: in a list of 60,000 students, stopping at position 3 saves 59,997 rounds.

<p>Press <b>Run</b>, then read the Console panel under this preview.</p>
<script>
  const register = [
    { name: "Asha",   marks: 85 },
    { name: "Rahul",  marks: null },     // absent for the test
    { name: "Meera",  marks: 34 },
    { name: "Vikram", marks: 91 },
    { name: "Priya",  marks: 28 }
  ];

  // continue: skip the absent student, carry on with the rest
  let total = 0;
  let present = 0;
  for (const s of register) {
    if (s.marks === null) {
      console.log("skipping", s.name, "(absent)");
      continue;
    }
    total += s.marks;
    present++;
  }
  console.log("Average of", present, "present students:", total / present);

  // break: stop at the FIRST student below 40
  for (const s of register) {
    console.log("checking", s.name);
    // rule out null first: null < 40 would count as true
    if (s.marks !== null && s.marks < 40) {
      console.log("First student who needs help:", s.name);
      break;
    }
  }
  console.log("search finished");
</script>

The first loop prints skipping Rahul (absent) and then Average of 4 present students: 59.5, which is (85 + 34 + 91 + 28) ÷ 4. The second prints checking for Asha, Rahul and Meera, finds Meera's 34, and breaks: Vikram and Priya are never checked, and search finished follows straight away.

break leaves only one loop. When loops are nested (next section), a break in the inner loop ends the inner loop only. The outer loop carries on with its next round.

52.6 Loops inside loops

Your slides end with a task: print the table of 7 with a for loop. A template literal (Chapter 45) builds each line:

for (let i = 1; i <= 10; i++) {
  console.log(`7 x ${i} = ${7 * i}`);    // 7 x 1 = 7 ... 7 x 10 = 70
}

For the tables of 1, 2 and 3, the 7 must change too, so wrap the loop in a second loop that supplies it. A loop inside another loop is called a nested loop:

for (let i = 1; i <= 3; i++) {            // outer loop: which table
  for (let j = 1; j <= 4; j++) {          // inner loop: which multiple
    console.log(`${i} x ${j} = ${i * j}`);
  }
}

The rule that makes nested loops readable: for every single round of the outer loop, the inner loop runs all of its rounds. When i is 1, j goes 1, 2, 3, 4. Only then does i become 2, and j starts again from 1. Three outer rounds times four inner rounds is twelve lines. The inner counter needs its own name, j, because i is still in use by the outer loop.

Pattern printing uses the same idea, with a twist: the inner loop's limit depends on the outer counter. Row 1 gets one star, row 4 gets four:

for (let row = 1; row <= 4; row++) {
  let line = "";
  for (let star = 1; star <= row; star++) {
    line += "*";
  }
  console.log(line);
}
// *
// **
// ***
// ****

line is emptied at the start of every row, filled by the inner loop, and printed once the row is complete.

Think of the outer loop as rows and the inner loop as columns. The inner loop starts again from scratch every time the outer loop moves on, so the total number of inner rounds is outer × inner.

Quick check: an outer loop runs for (let i = 0; i < 4; i++) and the inner loop inside it runs for (let j = 0; j < 5; j++). How many times does the inner body run?

20 times. The outer loop makes 4 rounds, and in each of them the inner loop makes all 5 of its rounds: 4 × 5 = 20.

52.7 Working with marks: totals, averages, highest and counts

Your slides' practical example is the loop you will write most often:

const marks = [78, 85, 92, 67, 88];
let total = 0;

for (const mark of marks) {
  total += mark;
}

console.log("Total:", total);                     // Total: 410
console.log("Average:", total / marks.length);    // Average: 82

total is an accumulator: a variable that collects the answer as the loop goes round. Every accumulator follows the same three steps: set it before the loop, update it inside, use it after. Trace it:

52.8 When loops go wrong: infinite loops and off-by-one

An infinite loop is a loop whose condition never becomes false. These four are the usual culprits. Read them; do not run them:

// 1. the update is missing
let count = 1;
while (count <= 5) {
  console.log(count);          // count is 1 forever
}

// 2. the update goes the wrong way
for (let i = 1; i <= 5; i--) { }     // i: 1, 0, -1, -2 ... always <= 5

// 3. the condition jumps over its target
for (let i = 1; i !== 10; i += 2) { }   // 1, 3, 5, 7, 9, 11 ... never exactly 10

// 4. continue skips the update in a while loop
let n = 0;
while (n < 5) {
  if (n === 2) {
    continue;                  // back to the check with n still 2 - forever
  }
  n++;
}

What happens when one runs? No error message. A page runs its JavaScript one thing at a time, so while the loop spins nothing else can happen: buttons stop responding, the page stops redrawing, and after some seconds the browser offers to stop the page (Chrome calls it Page Unresponsive). Close the tab, fix the code, reload. while (true) and for (;;) loop forever on purpose, and are safe only when a break inside is certain to be reached.

Four habits prevent nearly all infinite loops:

  • Check that the update moves the counter towards the stopping value.
  • Prefer <, <=, > or >= to !==: a counter can jump over one exact value, but not over a whole range.
  • In a while loop, put the update where every path reaches it, before any continue.
  • While testing a doubtful loop, add a safety guard: count the rounds and break after a generous limit.

Off-by-one errors

The other classic bug runs one round too many or one too few, almost always from choosing between < and <=:

  • for (let i = 0; i <= marks.length; i++) on a 3-element array visits indexes 0, 1, 2 and 3. Index 3 does not exist, so the last round silently reads undefined.
  • for (let i = 1; i < 10; i++), meant to print 1 to 10, stops at 9.

The fix: start at 0 and use < length for indexes; start at 1 and use <= n for counting 1 to n. Then check the first and last rounds in your head, because that is where off-by-one errors hide.

  // a loop that would never end, kept safe by a guard
  let n = 1;
  let rounds = 0;
  while (n !== 10) {            // n goes 1, 3, 5, 7, 9, 11 ... it jumps over 10
    n += 2;
    rounds++;
    if (rounds === 100) {
      console.warn("Gave up after 100 rounds: n is", n, "and was never 10");
      break;
    }
  }

  // the fix: a condition that must become false sooner or later
  let k = 1;
  let steps = 0;
  while (k < 10) {
    k += 2;
    steps++;
  }
  console.log("with k < 10 the loop stops after", steps, "rounds, at k =", k);
</script>

The first loop prints four lines, the last being with <=, index 3 -> undefined; the second prints exactly three. The guard prints the warning Gave up after 100 rounds: n is 201 and was never 10 instead of freezing the page. The fixed loop reports 5 rounds, at k = 11: the counter still jumps over 10, but 11 < 10 is false, so the loop stops.

52.9 Common misunderstandings

✗ "A loop checks its condition after running the body."
Only do...while does that.
✓ "for and while check before every round, including the first; do...while checks after."
So for and while can run zero times, and do...while always runs at least once.
✗ "for...in is the loop for arrays."
It hands over the indexes as strings, so i + 1 gives "01".
✓ "for...of for the values of an array; for...in for the keys of an object."
Use the counting for when you need the index as a number.
✗ "break stops all the loops."
In nested loops it ends only the loop it is written in.
✓ "break ends the innermost loop; continue skips to its next round."
The outer loop carries on as normal.
✗ "i <= arr.length visits every element."
It visits one index too many, and the extra round reads undefined.
✓ "Indexes run from 0 to length - 1, so write i < arr.length."
Or use for...of, which cannot run past the end.
✗ "Writing let total = 0; inside the loop is the same as before it."
Inside, it is reset at the start of every round, so the "total" ends as the last mark only.
✓ "An accumulator is set before the loop, updated inside, used after."
The same goes for counts, highest and lowest.

Exam-style checks

Answer each one before opening it. For the code questions, trace the loop on paper first: counter, condition and output for every round.

Which loop always runs its body at least once, even when its condition is false from the start?L1
  • A. for
  • B. while
  • C. do...while
  • D. for...of

Answer: C. do...while runs the body first and checks afterwards. for and while check before the first round, so they can run zero times; so can for...of, on an empty array.

How many times does the body of for (let i = 2; i <= 10; i += 2) { ... } run?L2
  • A. 5
  • B. 4
  • C. 6
  • D. 10

Answer: A. i takes the values 2, 4, 6, 8 and 10; at 12 the check fails. B forgets that 10 itself passes <=; D assumes a step of 1.

What does this print? let n = 10; while (n < 5) { console.log(n); n++; } console.log("done");L2
  • A. 10, then done
  • B. Nothing at all
  • C. 10, 11, 12 … forever
  • D. Only done

Answer: D. while checks first: 10 < 5 is false, so the body never runs, and the line after the loop prints done. A is what a do...while would print.

What does this print? const a = ["x", "y"]; for (const k in a) { console.log(k + 1); }L3
  • A. 1, then 2
  • B. 01, then 11
  • C. x1, then y1
  • D. NaN twice

Answer: B. for...in hands over the array's keys as strings, "0" and "1", and + with a string joins: "0" + 1 is "01". A is what you would get from a numeric counter; C would need for...of.

Predict the output: for (let i = 1; i <= 6; i++) { if (i % 2 === 0) { continue; } console.log(i); }L2

Answer: 1, 3, 5 on three lines. When i is even, continue skips that round's console.log; the update still runs, so the loop moves on to the next number.

What does this print? let count = 0; for (let i = 0; i < 3; i++) { for (let j = 0; j < 4; j++) { count++; } } console.log(count);L3
  • A. 7
  • B. 4
  • C. 12
  • D. 16

Answer: C. For each of the 3 outer rounds, the inner loop makes all 4 of its rounds: 3 × 4 = 12. A adds the rounds instead of multiplying them.

Which of these loops never ends?L3
  • A. for (let i = 0; i < 10; i++)
  • B. for (let i = 10; i > 0; i--)
  • C. for (let i = 0; i < 10; i += 3)
  • D. for (let i = 0; i < 10; i--)

Answer: D. i goes 0, −1, −2 … and stays below 10 forever. C is tempting because i jumps 0, 3, 6, 9, 12 and never equals 10, but the condition is < 10, and 12 < 10 is false, so it stops.

What does this print? const m = [70, 80, 90]; for (let i = 0; i <= m.length; i++) { console.log(m[i]); }L2
  • A. 70, 80, 90, undefined
  • B. 70, 80, 90
  • C. 80, 90, undefined
  • D. 70, 80, 90, then a RangeError

Answer: A. With <=, i also reaches 3, one past the last index, and reading a missing index gives undefined rather than an error. That is the off-by-one bug; < m.length would print B.

A highest-value finder starts with let highest = marks[0];. Why not let highest = 0;?L3

Because 0 might not be in the list. If every value is below 0, such as the temperatures [-5, -12, -3], a highest that starts at 0 is never replaced and the answer is a wrong 0. Starting from the first element guarantees a real element; here it gives −3.

To visit every key of the object { maths: 82, physics: 74 }, which loop do you use?L1
  • A. for...of
  • B. for...in
  • C. do...while
  • D. A counting for up to obj.length

Answer: B. for...in hands over each key of an object. A throws a TypeError, because plain objects are not iterable, and D runs zero times, because a plain object has no length and 0 < undefined is false.

What does this print? const marks = [40, 60, 80]; let total = 0; for (const m of marks) { total += m; } console.log(total / marks.length);L3
  • A. 180
  • B. 3
  • C. NaN
  • D. 60

Answer: D. The loop builds the total 40 + 60 + 80 = 180, and 180 ÷ 3 = 60. A forgets the division; C would happen only if total had no starting value, because undefined + 40 is NaN.

Predict the output, and explain it: for (let i = 1; i <= 3; i++) { for (let j = 1; j <= 3; j++) { if (j === 2) { break; } console.log(i, j); } }L3

Answer: 1 1, 2 1, 3 1 on three lines. In every outer round the inner loop prints j = 1, then reaches j === 2 and breaks. break ends only the inner loop, so the outer loop carries on with the next i.

Quick revision

Key takeaways

  1. A loop repeats its body; each trip is one iteration. Reach for a loop whenever a job says "every" or "until".
  2. for (start; condition; update): the start runs once, the condition is checked before every round, the update runs after every round. If the first check is false, the body runs zero times.
  3. while checks first and suits an unknown number of rounds; do...while acts first and always runs at least once.
  4. for...of gives the values of an array or string; for...in gives the keys of an object, as strings, and is the wrong choice for arrays.
  5. break ends the loop it is in; continue skips to the next round. A nested inner loop runs in full for every outer round, so rounds multiply.
  6. Accumulators are set before the loop, updated inside and used after: total and count start at 0, highest and lowest at the first element.
  7. An infinite loop freezes the page without an error: make the update move towards the stop, and prefer < to !==. Against off-by-one, loop over indexes with i = 0 and i < length.
