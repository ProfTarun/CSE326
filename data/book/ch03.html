HTML5 Fundamentals

HTML has a tiny grammar: tags, elements, attributes, nesting, comments and a handful of special characters. Learn that grammar precisely and every later chapter becomes vocabulary. This chapter also explains what is new in HTML5, why browsers forgive mistakes (and why that is dangerous), and how to check your work with a validator.

By the end of this chapter you can

  • Define markup, tag, element, content and attribute, and tell a tag from an element.
  • List the common void elements and explain why </br> is wrong.
  • State the nesting rule and count the elements in a snippet.

3.1 What HTML is (and is not)

HTML stands for HyperText Markup Language. A markup language is a way of annotating text: you take the words of a page and wrap them in labels that say what each part is: this is a heading, this is a paragraph, this is a link, this is an image. The browser reads those labels and knows how to treat each piece. HyperText means text that contains links to other text, which is the idea the whole Web is built on.

HTML is not a programming language. It has no variables, no loops, no if-statements and no way to compute anything. It describes structure and meaning; computing is JavaScript's job, appearance is CSS's job (Chapter 1). When someone says they "code in HTML" they mean they write markup.

<h1>Welcome to My Website</h1>
<p>Learn HTML step by step.</p>

Run it. The first line is labelled as a top-level heading, so the browser shows it large and bold; the second is labelled as a paragraph, so it gets normal text with space around it. You never said "large" or "bold": you said what it is, and the browser chose a default look.

What HTML5 added

HTML5 (a W3C Recommendation in 2014, now maintained as a living standard) is the version every browser implements. Compared with HTML 4, it brought:

  • a one-line document type, <!DOCTYPE html>, that tells the browser to use HTML5 parsing rules;
  • semantic elements such as <header>, <nav>, <main>, <article>, <section>, <aside> and <footer> (Chapter 13);
  • native audio and video without plug-ins such as Flash (Chapter 10), inline SVG graphics (Chapter 9) and <canvas> for scripted drawing;
  • new input types (email, date, number, range, colour) and built-in form validation (Chapters 17–18);
  • a precise, standard way for browsers to parse HTML, including how to recover from errors, so pages look the same everywhere.

3.2 Tags, elements and content

A tag is a label written between angle brackets: <p>. It has an opening angle bracket, a tag name and a closing angle bracket. An opening tag like <p> says "a paragraph starts here"; a closing tag is the same name with a forward slash, </p>, and says "the paragraph ends here". Everything between them is the content.

The sandwich analogy from the lectures is worth keeping: the two tags are the slices of bread, the content is the filling, and the element is the whole sandwich. So <p> on its own is a tag; <p>Hello World</p> is an element. Examiners test this distinction directly.

Elements are the building blocks of the page. Some hold text (<p>, <h1>), some hold other elements (<section>, <div>, <ul>), and a few hold nothing at all, which brings us to void elements.

3.3 Paired elements and void elements

Most elements are paired (also called container elements): they enclose content between an opening and a closing tag: <p>Hello</p>, <h1>Welcome to CSE326</h1>, <section>...</section>, <div>...</div>, <video>...</video>, <textarea></textarea>.

A few elements cannot have content, so they have no closing tag. These are void elements (also called empty or unpaired elements). They insert a standalone thing into the page:

Void elementWhat it inserts
<br>A line break inside text
<hr>A thematic break, drawn as a horizontal rule
<img>An image, from its src
<input>A form control
<meta>Metadata in the head
<link>A connection to an external file such as a stylesheet
<source>, <track>Media files and captions inside audio/video
<area>, <base>, <col>, <embed>, <wbr>Rarer ones you may meet in the reference

Two consequences follow. First, writing </br> or </img> is invalid: there is nothing to close. Second, because they are unpaired, void elements cannot wrap anything: you cannot put text "inside" a <br>. The memory rule from the lecture is the right one: can it contain content? Yes, paired; no, void. Note that <video>, <audio>, <p>, <span> and <div> are not void; they always need a closing tag.

Self-closing slash. You will see <br /> and <img ... /> in older code and in SVG. In HTML5 the slash on a void element is allowed but does nothing; <br> is the standard form. Inside inline SVG (Chapter 9) the slash is required, because SVG is XML.

3.4 Nesting: elements inside elements

Elements can be placed inside other elements. The outer one is the parent, the inner one is its child, and the whole page becomes a tree. The browser does not treat HTML as a flat list of tags or a long string; it parses it into a nested tree of elements, the Document Object Model (DOM), and everything it draws comes from that tree.

The one rule of nesting: whatever opens last must close first, exactly like brackets in mathematics. A child must be closed before its parent is closed (the lecture calls this FILO: first in, last out).

✗ Overlapping tags
<p><b>text</p></b>
The bold element opened last but the paragraph closes first. The browser has to guess what you meant.
✓ Properly nested
<p><b>text</b></p>
Last opened, first closed. Indent children by two spaces so the structure is visible at a glance.

Some elements refuse certain children, and the browser will silently rearrange your page to obey. A <p> may only contain text and inline elements; if it meets a block element such as <div>, the paragraph is closed automatically before the div, leaving an empty paragraph and stray text. Chapter 5 covers block and inline; for now the lesson is that the browser fixing your HTML is not the same as your HTML being right.

3.5 Attributes: configuring an element

An attribute adds information to an element: a link's destination, an image's file, a class name for styling. Attributes are written inside the opening tag only, as name="value" pairs separated by spaces:

<a href="https://example.com" target="_blank">Visit</a>
   │                          │
   └─ attribute name: value     └─ a second attribute

In <p class="intro">Hello</p> the part class="intro" is an attribute, not a tag, not an element and not a selector. Three rules save you from the commonest bugs:

  • Always quote the value. <div class=my box> breaks at the space: the browser reads class="my" and then a separate, meaningless attribute called box. With quotes, class="my box" is one attribute holding two class names.
  • Lowercase names. HTML is case-insensitive (<P CLASS=Intro> renders), but the HTML5 convention every style guide and this course require is lowercase tag names and attribute names with quoted values: <p class="intro">.
  • Attributes never go on the closing tag. </p class="x"> is meaningless.

Chapter 5 lists the attributes every element accepts and the important element-specific ones.

3.6 Comments

A comment is a note for humans that the browser ignores. It starts with <!-- and ends with -->:

<!-- Student Registration Section -->
<p>This paragraph is shown.</p>
<!-- <p>This one is commented out and not shown.</p> -->

Comments are not rendered on the page but they are visible in View Source, so never put anything private in them. Use them to label sections and to switch a piece of markup off temporarily while debugging. The other comment styles you may know, // note, /* note */ and # note, belong to JavaScript, CSS and Python; in HTML they are just text and will appear on the page.

The half-blank page. If a page renders normally and then goes blank halfway down, the most likely cause is an unclosed comment: a missing --> swallows everything after it. No error is shown; the content simply vanishes.

3.7 Whitespace, and characters you cannot type directly

Whitespace collapses

In ordinary HTML text, any run of spaces, tabs and newlines is collapsed to a single space. Type ten spaces between two words in a paragraph and exactly one appears on screen; press Enter twice in your editor and nothing changes on the page either. This is why you need <br> for a line break and <p> for a new paragraph, and it is why indentation in your source is free: it never affects the output. The one exception is the <pre> element (Chapter 6), which preserves your spaces and line breaks exactly.

Character entities

Some characters have a job in HTML syntax, so typing them literally confuses the parser. To show a less-than sign you cannot write <, because the browser will think a tag is starting. Instead you write a character entity: an ampersand, a name (or a number), and a semicolon.

EntityShowsWhy you need it
&lt;<"less than"; a literal < would start a tag
&gt;>"greater than"; written for symmetry and inside code samples
&amp;&a literal & would start an entity
&quot;"a double quote inside a quoted attribute value
&nbsp;(space)a non-breaking space that is never collapsed and never wrapped
&copy; &reg; &trade;© ® ™symbols not on the keyboard
&#8377;₹a numeric entity: any Unicode character by its code
 
<p>Use the &lt;p&gt; tag for paragraphs. Fees: &#8377;1200 &amp; taxes. &copy; 2026</p>

With <meta charset="UTF-8"> in the head (Chapter 4) you can type © and ₹ directly in your editor and they will display correctly; entities are still needed for <, > and &, because those are syntax.

3.8 Browsers forgive, validators do not

Browsers are deliberately tolerant. A missing closing tag, an unquoted attribute or a misnested element does not produce an error message; the browser applies recovery rules and draws something. That sounds kind but it is a trap: HTML fails silently. The page "looks fine on my laptop" and breaks on someone else's browser, or reads wrongly in a screen reader, and you never saw a warning. Two habits protect you.

First, declare HTML5. Without <!DOCTYPE html> on line one, browsers switch into quirks mode, an emulation of 1990s rendering in which box sizes and spacing follow old, inconsistent rules. The page still renders, but layout bugs appear that are painful to trace. With the doctype, browsers use standards mode, which is what every tutorial and this book assume.

Second, run your page through a validator. The W3C Markup Validator reads your HTML against the standard and lists every unclosed tag, duplicate id, misnesting and missing attribute. It catches exactly the structural errors that cause inconsistent rendering and accessibility failures, the ones the browser hid from you. It does not compress your file, convert it to HTML5 or generate CSS; it reports problems. Do it before every submission.

3.9 Worked example: counting and correcting

How many elements are in <p>Hi <b>there</b></p>? Count opening tags: <p> and <b>. Two elements: a paragraph with a bold element nested inside. The text "Hi" and "there" are content, not elements.

Which of these is written incorrectly? <br>, <hr>, </br>, <img src="a.jpg">. The third: br is void, so a closing tag is invalid.

Spot the mistakes in this fragment and fix them:

✗ Broken
<h1>My Profile<h2>
<img src="me.jpg">
<a>My Portfolio</a>
<p>Welcome to my page
✓ Fixed
<h1>My Profile</h1>
<img src="me.jpg" alt="Photo of me">
<a href="portfolio.html">My Portfolio</a>
<p>Welcome to my page</p>

Four fixes: close the heading with </h1> (not open another heading), add meaningful alt text to the image, give the link an href so it goes somewhere, and close the paragraph. Replacing everything with divs, moving the title into the body or wrapping it all in a table would fix nothing.

Exam-style checks

Which of the following is a void element, written without a closing tag?L1
  • A. <span>
  • B. <p>
  • C. <div>
  • D. <br>

Answer: D. <br> has no content and no closing tag. The others are paired. (The same question with <img> among the options: <img> is the void one.)

Which element is NOT an empty element: <source>, <video>, <img>, <meta>?L2

Answer: <video>. It always needs a closing tag (its content is the <source> elements and fallback text). source, img and meta are void.

Which is written INCORRECTLY: <br>, <hr>, </br>, <img src="a.jpg">?L2

Answer: </br>. Void elements have nothing to close, so a closing tag is invalid.

How many ELEMENTS are in <p>Hi <b>there</b></p>?L2
  • A. One
  • B. Two
  • C. Three
  • D. Four

Answer: B. A paragraph element with a bold element nested inside. Text is content, not an element; tags are not counted separately from their elements.

In <p class="intro">Hello</p>, what is class="intro"?L1
  • A. A tag
  • B. An element
  • C. An attribute
  • D. A selector

Answer: C. Attributes give extra information and always live in the opening tag.

Which nesting is correct?L2
  • A. <p><b>text</p></b>
  • B. <p><b>text</b></p>
  • C. <b><p>text</b></p>
  • D. <p><b>text</b>

Answer: B. Last opened, first closed. D never closes the paragraph.

Why is <div class=my box> a problem?L2
  • A. div cannot have a class
  • B. Unquoted values break at the space, creating two attributes
  • C. class must be lowercase
  • D. It is perfectly valid

Answer: B. The browser reads class="my" and a stray attribute "box". Always quote attribute values.

Which is the recommended practice when writing HTML attribute values?L2
  • A. Separate values with semicolons
  • B. Leave values unquoted to save bytes
  • C. Write every value in uppercase
  • D. Enclose every value in quotation marks

Answer: D. Quoting prevents the split-at-space bug and is required by every style guide.

A student writes <P CLASS=Intro>Text</P>. Which best practices does this violate?L3
  • A. Class names may not contain capital letters in HTML5
  • B. Paragraphs must always carry an id rather than a class
  • C. Tag and attribute names should be lowercase and attribute values should be quoted
  • D. Every <p> must be nested inside a <div>

Answer: C. It renders, but it breaks the lowercase-and-quoted convention. A, B and D are invented rules.

How is a comment written in HTML?L1
  • A. // comment
  • B. <!-- comment -->
  • C. /* comment */
  • D. # comment

Answer: B. The others are JavaScript, CSS and Python comment styles and would appear as text on the page.

A page renders normally then goes blank halfway down. What is the most likely cause?L3
  • A. A missing doctype
  • B. An unclosed comment (missing -->)
  • C. Too much CSS
  • D. A missing charset

Answer: B. Everything after an unclosed comment is swallowed silently.

Which character entity displays a literal less-than sign (<) in page content?L1
  • A. &lt;
  • B. &gt;
  • C. &amp;
  • D. &nbsp;

Answer: A. lt = less than. gt is greater than, amp is the ampersand, nbsp is a non-breaking space.

You type ten spaces between two words in a <p>. How many appear on screen?L2

Answer: one. HTML collapses consecutive whitespace to a single space, unless the text is inside <pre>.

The browser parses an HTML document as:L2
  • A. A flat list of independent tags
  • B. A single continuous string of text
  • C. A nested tree of elements
  • D. A table of rows and columns

Answer: C. Nesting produces parents and children; the result is the DOM tree.

What happens if you omit the doctype?L2
  • A. The page will not load
  • B. The browser uses quirks mode
  • C. Images stop working
  • D. CSS is ignored completely

Answer: B. The page renders under old, inconsistent rules; spacing and box sizes shift.

Why should HTML be run through a validator?L2
  • A. It catches structural errors that cause inconsistent rendering and accessibility failures
  • B. It automatically compresses the file
  • C. It converts the page into HTML5
  • D. It generates the page's CSS

Answer: A. The validator at validator.w3.org reports unclosed tags, duplicate ids and bad nesting: the bugs that fail silently.

Why is HTML failing SILENTLY a problem?L2

Answer: there is no error message, so bugs survive. The page seems fine on one machine and breaks elsewhere. Validation is the only way to see them.

Consider <h1>My Profile<h2> <img src="me.jpg"> <a>My Portfolio</a>. Which set of fixes is correct?L3
  • A. Close <h1> properly, add alt to the image, add href to the anchor
  • B. Replace <h1> with <div>, remove the image and the anchor
  • C. Add a <title> inside <body> and delete the <h2>
  • D. Wrap everything in a <table> and add borders

Answer: A. Three genuine faults, three genuine fixes. The other options destroy content or add unrelated markup.

Quick revision

Key takeaways

  1. HTML is a markup language, not a programming language: it labels what content is.
  2. Tag = one bracketed marker; element = opening tag + content + closing tag. Attributes sit in the opening tag as name="value".
  3. Void elements (br, hr, img, input, meta, link, source, track) have no content and no closing tag; </br> is invalid. video, audio, p, div, span, textarea are paired.
  4. Nesting builds a tree; last opened, first closed. A p auto-closes before a div.
  5. Comments: <!-- ... -->, invisible on the page, visible in the source; an unclosed comment blanks the rest of the page.
  6. Whitespace collapses to one space (except in pre). Use &lt; &gt; &amp; &nbsp; &copy; for special characters.
  7. Lowercase names, quoted values, doctype on line one, and validate at validator.w3.org because HTML fails silently.
