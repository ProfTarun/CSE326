Unit 5 · Chapter 58 · Dynamic Content Generation

Dynamic Content Generation

Open a shopping site and you see fifty product cards; open UMS and you see your timetable, your marks, your attendance. Nobody typed those cards into an HTML file one by one. A program kept the information as data and wrote the page from it. This chapter teaches you to do the same: turn an array into a list, keep the two in step while the user adds, removes, searches and sorts, and never let a stranger's text run as code.

About 34 minutes · Course outcome CO5

Before you start — one-line reminders

  • An array of objects holds records such as { name: "Asha", marks: 91 }, and students[0].name reads one (Chapter 50, Chapter 51).
  • map turns each item into something new, filter keeps the matches, reduce adds them up, sort takes a compare function (Chapter 53).
  • createElement, append, textContent, innerHTML, classList and dataset change the page (Chapter 56).
  • addEventListener runs a function when something happens, and one listener on a parent can handle clicks on all its children (Chapter 57).

By the end of this chapter you can

  • Generate a list or a set of cards from an array of objects.
  • Choose between a template literal with innerHTML and createElement with textContent, and explain why user text must never go into innerHTML.
  • Write a render() function that redraws the page from the data after every add or delete.
  • Connect each button to its item with data-id and one delegated listener.
  • Show an empty state, a count and a summary line worked out from the data.
  • Filter and sort the displayed list from controls, style items from their data, and attach many elements in one step with a DocumentFragment.

58.1 Data in, page out

Look at a results page, a product grid or a timetable and you will see one pattern repeated many times: one row per student, one card per product, one cell per lecture. When the information changes every day, nobody edits the HTML by hand. The information is kept as data, usually an array of objects, and JavaScript writes the HTML from it while the page runs. That is dynamic content generation.

For each item in the array the recipe has three steps:

  1. Make an element: document.createElement("li"). It exists in memory, but not on the page yet.
  2. Fill it: li.textContent = name.
  3. Attach it: list.append(li). Now it is visible.
<style>
  body { font-family: system-ui, sans-serif; padding: 12px; }
</style>
<h3>My courses this semester</h3>
<ul id="courses"></ul>
<p id="count"></p>

<script>
  const courses = ["Internet Programming", "Data Structures",
                   "Engineering Mathematics", "Communication Skills"];
  const list = document.getElementById("courses");

  for (const name of courses) {
    const li = document.createElement("li");   // 1. make an empty <li>
    li.textContent = name;                     // 2. put the words in
    list.append(li);                           // 3. attach it to the page
  }

  document.getElementById("count").textContent = `${courses.length} courses`;
  console.log("Items on the page:", list.children.length);
</script>

Press Run: four list items appear under the heading, the line 4 courses below them, and the Console prints Items on the page: 4. The HTML held only an empty <ul>. Now add a fifth course to the array and run again: five items and 5 courses, and you never touched the HTML.

Keep the information in an array. Let a loop turn each item into an element. The HTML holds only an empty container for the loop to fill.

58.2 Two ways to build an item

The lecture puts the difference in two lines: textContent inserts text without interpreting it as HTML; innerHTML parses the supplied string as HTML. That gives two ways to build a card.

Technique A: write the HTML as a string. A template literal (Chapter 45) is a string in backticks whose ${...} gaps are filled with values. map turns every product into a string of HTML, join("") glues the strings together, and innerHTML receives the result. The browser then parses the string: it reads the tags and builds the elements.

Technique B: build real elements. createElement each part, put the words in with textContent, then append the parts to each other.

<style>
  body { font-family: system-ui, sans-serif; padding: 12px; }
  .grid { display: flex; flex-wrap: wrap; gap: 10px; margin: 4px 0 14px; }
  .card { border: 1px solid #CBD5E1; border-radius: 10px; padding: 10px 14px; min-width: 130px; }
  .card h4 { margin: 0 0 4px; color: #0B2545; }
  .card p { margin: 0; color: #475569; }
</style>
<p><b>A.</b> Template literal + innerHTML</p>
<div class="grid" id="gridA"></div>
<p><b>B.</b> createElement + textContent</p>
<div class="grid" id="gridB"></div>

<script>
  const products = [
    { name: "Lab record", price: 120 },
    { name: "Calculator", price: 950 },
    { name: "Drawing sheets", price: 60 }
  ];

  // A. Turn each product into a string of HTML, join them, hand over once
  const gridA = document.getElementById("gridA");
  gridA.innerHTML = products.map((p) => `
    <div class="card">
      <h4>${p.name}</h4>
      <p>₹${p.price}</p>
    </div>`).join("");

  // B. Build real elements; the words go in as text
  const gridB = document.getElementById("gridB");
  for (const p of products) {
    const card = document.createElement("div");
    card.className = "card";
    const title = document.createElement("h4");
    title.textContent = p.name;
    const price = document.createElement("p");
    price.textContent = `₹${p.price}`;
    card.append(title, price);
    gridB.append(card);
  }

  console.log("A made", gridA.children.length, "cards");
  console.log("B made", gridB.children.length, "cards");
</script>

Both rows show the same three cards, and the Console prints A made 3 cards and B made 3 cards. Look at .join("") at the end of A. map gives back an array of strings, and an array turned into a single string is joined with commas. Leave join("") out and a stray comma appears between every pair of cards.

A. Template literal + innerHTMLB. createElement + textContent
LengthShort; it looks like the HTML it makesLonger: a few lines per element
Text containing < or &Read as HTML: tags become elementsShown exactly as typed
Safe for text a user typed?No (58.3)Yes, by design
Adding a listenerLook the new elements up afterwards, or delegate (58.5)You already hold each element
Right forFixed markup you wrote, filled with numbers your code calculatedAnything from a user, a form, the address bar or a server (Chapter 65)

A string given to innerHTML is quick to write, but it trusts every character in it. Elements filled with textContent take more lines, but they trust nothing. When in doubt, build elements.

Exam tip. Learn the lecture's wording exactly: textContent inserts text without interpreting it as HTML; innerHTML parses the supplied string as HTML. Most questions on this topic are that sentence turned round.
Quick check: you wrote list.innerHTML = names.map((n) => `<li>${n}</li>`); and commas appear between the items. Why?

map returned an array, and putting an array where a string is needed joins it with commas: <li>Asha</li>,<li>Rahul</li>. Each comma becomes text on the page. Add .join("") after the map.

58.3 Never pour user text into innerHTML

Imagine a notes page where students post comments, and the code shows each one with wall.innerHTML = comment. Rahul types <b>Great notes</b> and his comment appears in bold. Harmless, it seems. Then someone posts a comment containing an image tag whose onerror attribute holds JavaScript. innerHTML builds the image, the image fails to load, and the browser runs the code in the attribute — in the browser of every student who opens the page. Text has become a program. This attack is called cross-site scripting (XSS), and other people's text in innerHTML is how it usually gets in.

<style>
  body { font-family: system-ui, sans-serif; padding: 12px; }
  input { font: inherit; width: 100%; max-width: 460px; padding: 6px; box-sizing: border-box; }
  button { font: inherit; margin: 8px 6px 0 0; padding: 6px 10px; border-radius: 6px; }
  .bad { background: #FDE8E8; border: 1px solid #B42318; }
  .good { background: #E7F6EC; border: 1px solid #138808; }
  .wall { border: 1px dashed #94A3B8; border-radius: 8px; padding: 8px 12px; margin-top: 8px; }
  #wallA::before { content: "innerHTML: "; font-weight: 700; color: #B42318; }
  #wallB::before { content: "textContent: "; font-weight: 700; color: #138808; }
</style>
<label for="msg">Your comment on the Unit 5 notes</label>
<input id="msg" type="text">
<br>
<button class="bad" id="unsafe" type="button">Post with innerHTML (unsafe)</button>
<button class="good" id="safe" type="button">Post with textContent (safe)</button>
<div class="wall" id="wallA"></div>
<div class="wall" id="wallB"></div>

<script>
  const box = document.getElementById("msg");
  // What a mischievous visitor might type. Try <b>Asha</b> as well.
  box.value = `Nice notes! <img src="nothing.png" onerror="console.warn('Code typed into the box just ran!')">`;

  document.getElementById("unsafe").addEventListener("click", () => {
    const wall = document.getElementById("wallA");
    wall.innerHTML = box.value;              // the text is PARSED: tags become elements
    console.log("innerHTML: elements created =", wall.children.length);
  });

  document.getElementById("safe").addEventListener("click", () => {
    const wall = document.getElementById("wallB");
    wall.textContent = box.value;            // the text is SHOWN: nothing is built
    console.log("textContent: elements created =", wall.children.length);
  });
</script>

Press the red button. The first wall shows Nice notes! and a broken-image icon, and the Console prints innerHTML: elements created = 1, followed a moment later by the warning Code typed into the box just ran!. Here the code only writes to the Console; an attacker's code could read the page or send it somewhere else. Press the green button: the second wall shows the whole comment as ordinary characters, angle brackets and all, and the Console prints textContent: elements created = 0. Nothing was built, so nothing could run.

Blocking <script> is not enough. A <script> added through innerHTML never runs, so testing with <script>alert(1)</script> proves nothing. Event attributes such as onerror and onmouseover on the elements innerHTML builds do run. Chapter 77 returns to this.

The rule: anything a person typed, or a server sent, goes in with textContent. If you truly must put such text into a template, escape it first, so that its special characters become harmless codes that display as themselves:

// Only when you must use a template: turn the special characters into codes
function escapeHTML(text) {
  return String(text)
    .replaceAll("&", "&amp;")     // first, or the & in &lt; would be replaced again
    .replaceAll("<", "&lt;")
    .replaceAll(">", "&gt;")
    .replaceAll('"', "&quot;")
    .replaceAll("'", "&#39;");
}
wall.innerHTML = `<p class="comment">${escapeHTML(comment)}</p>`;

Escaping is easy to forget on one line out of fifty, which is why building elements with textContent stays the safer habit.

Quick check: a seller types a product name into a form. Which line shows it safely: card.innerHTML = name or card.textContent = name?

card.textContent = name. The name came from a person, so any tags in it must stay letters. With innerHTML a name containing an <img onerror=...> would run code for every shopper.

58.4 One render() function: state to view

Showing a list once is easy. Real pages change: the user adds a dish to an order, removes one, adds two more. You could patch the page each time, adding one row here and deleting that row there, but every patch is a chance for the page and the data to drift apart. The reliable pattern is simpler. Keep the state in one place, change only the state, then call one function, render(), that wipes the old content and redraws all of it from the state. The data becomes the page's source of truth.

Picture this. At a cricket ground the scorer writes every ball in the scorebook. Nobody climbs up and changes the big scoreboard on a whim: after each ball the operator reads the scorebook and puts up the whole picture again — runs, wickets, overs. If the board and the book ever disagree, the book wins. Your array is the scorebook, render() is the operator, and the page is the scoreboard.

You have already met the smallest render(). The interactive counter of Chapter 57 kept one number and wrote it to the page after every click:

let count = 0;                          // the state: one number
function render() {
  countBox.textContent = count;         // state -> view
}
plusBtn.addEventListener("click", () => { count++; render(); });
minusBtn.addEventListener("click", () => { count--; render(); });

A list works the same way, with an array in place of the number. Here is a canteen order you can add to and remove from:

<style>
  body { font-family: system-ui, sans-serif; padding: 12px; }
  select, button { font: inherit; padding: 4px 10px; }
  #order { list-style: none; padding: 0; max-width: 380px; }
  #order li { display: flex; justify-content: space-between; align-items: center;
              padding: 6px 10px; margin-bottom: 6px;
              border: 1px solid #CBD5E1; border-radius: 8px; }
  #order li.empty { color: #64748B; font-style: italic; }
  #summary { font-weight: 700; }
</style>
<h3>Hostel canteen: my order</h3>
<label for="dish">Dish</label>
<select id="dish"></select>
<button id="add" type="button">Add to order</button>
<ul id="order"></ul>
<p id="summary"></p>

<script>
  const menu = { "Masala dosa": 60, "Veg thali": 90, "Cold coffee": 50, "Samosa": 15 };

  // The state: the ONE place the order lives
  let order = [
    { id: 1, dish: "Veg thali", price: 90 },
    { id: 2, dish: "Cold coffee", price: 50 }
  ];
  let nextId = 3;

  const dishSelect = document.getElementById("dish");
  const list = document.getElementById("order");
  const summary = document.getElementById("summary");

  // Even the drop-down is generated from data
  for (const [dish, price] of Object.entries(menu)) {
    const opt = document.createElement("option");
    opt.value = dish;
    opt.textContent = `${dish} (₹${price})`;
    dishSelect.append(opt);
  }

  function render() {
    list.innerHTML = "";                                // 1. wipe the old picture
    if (order.length === 0) {                           // 2. the empty state
      const li = document.createElement("li");
      li.className = "empty";
      li.textContent = "No items yet. Pick a dish and press Add.";
      list.append(li);
    }
    for (const item of order) {                         // 3. one row per item
      const li = document.createElement("li");
      const label = document.createElement("span");
      label.textContent = `${item.dish} - ₹${item.price}`;
      const remove = document.createElement("button");
      remove.type = "button";
      remove.textContent = "Remove";
      remove.dataset.id = item.id;                      // label the button with its item
      li.append(label, remove);
      list.append(li);
    }
    const n = order.length;                             // 4. the summary line
    const total = order.reduce((sum, item) => sum + item.price, 0);
    summary.textContent = n === 0 ? "Nothing ordered yet."
      : `${n} ${n === 1 ? "item" : "items"} · Total ₹${total}`;
    console.log(`render(): ${n} in the order, total ₹${total}`);
  }

  document.getElementById("add").addEventListener("click", () => {
    const dish = dishSelect.value;
    order.push({ id: nextId, dish: dish, price: menu[dish] });   // change the DATA...
    nextId++;
    render();                                                      // ...then redraw
  });

  // One listener for every Remove button, now and in the future
  list.addEventListener("click", (event) => {
    const button = event.target.closest("button[data-id]");
    if (!button) return;                                // not a Remove button
    const id = Number(button.dataset.id);               // "3" becomes 3
    order = order.filter((item) => item.id !== id);     // change the DATA...
    console.log("Removed id", id);
    render();                                           // ...then redraw
  });

  render();
</script>

Trace it. The order starts with a thali and a cold coffee, so the first render() prints render(): 2 in the order, total ₹140. Press Add to order with Masala dosa selected: the handler pushes { id: 3, dish: "Masala dosa", price: 60 } and calls render(), which clears the list and draws three rows: render(): 3 in the order, total ₹200. Press Remove beside the thali: Removed id 1, then render(): 2 in the order, total ₹110. Remove everything and the list shows its empty message. Even the drop-down was generated, from the menu object with Object.entries (Chapter 51).

Never change the page directly. Change the data, then call render(). Because render() always draws the page from the data, the page and the data can never disagree.

58.5 data-id: which button belongs to which item

Every Remove button looks the same, so how does the handler know which dish to remove? Each button carries a label. render() writes remove.dataset.id = item.id, which puts data-id="3" on the button (Chapter 56). Three steps then turn a click into an item:

  1. Find the button. One listener sits on the list, not on the buttons: event delegation (Chapter 57). event.target is the element actually clicked. closest("button[data-id]") walks up from it, starting with the element itself, to the nearest element matching the selector, and gives null if there is none — a click on the empty-state message, for example.
  2. Read the id and convert it. button.dataset.id is always a string: "3", not 3. Number() converts it, so that item.id !== id compares a number with a number.
  3. Change the data. order.filter((item) => item.id !== id) keeps every item except that one. Then render().

Why one listener on the list? render() throws the old buttons away and makes new ones every time. The <ul> itself is never replaced, so a listener on it handles every Remove button that will ever exist. (Adding a listener to each new button inside render() also works; it is just many listeners doing one job.)

Why an id and not the position? You could label the buttons 0, 1, 2 with their index in the array. But positions shift. Delete item 0 and everything moves up one; sort or filter the list and the third row on screen is no longer the third item in the array. An id stays fixed to its item for life. Try it in the canteen: add two Samosas, then remove one. Same name, same price — yet only the row you clicked disappears, because each got its own id from nextId when it was added (3 and 4 on a fresh run).

Quick check: a button has data-id="3". Why is button.dataset.id === 3 false?

Every dataset value is a string, so the left side is "3", and === never treats a string as equal to a number. Convert first: Number(button.dataset.id) === 3 is true.

58.6 Empty states and summary lines

Two small things separate a finished page from a demo.

An empty state. A list that shows nothing looks broken: has it failed, or is it still loading? When the array is empty, say what is true and what to do next: No items yet. Pick a dish and press Add. In render() it is one if: when the array is empty, draw the message instead of rows. A filtered list needs one too: No students match.

A summary line: a count, a total, an average. Work it out inside render() from the same array the rows came from. Do not keep a separate counter that you add to and subtract from: that is a second copy of the truth, and sooner or later one copy is updated and the other is not.

const n = order.length;
const total = order.reduce((sum, item) => sum + item.price, 0);
summary.textContent = n === 0 ? "Nothing ordered yet."
  : `${n} ${n === 1 ? "item" : "items"} · Total ₹${total}`;

The n === 1 ? "item" : "items" part picks the right word, so the page never says 1 items. One more detail: when a summary changes while the user is looking elsewhere, a screen reader is not told. Chapter 59 fixes that with aria-live, which the results board in 58.9 already uses.

58.7 Styling from the data

Changing CSS from JavaScript (the lecture's slide 31) is most useful when the look depends on the data: a failing mark in red, a sold-out item greyed, a bar as long as the marks. Two tools cover it:

// 1. A class switched by a condition: true adds it, false removes it
li.classList.toggle("low", s.marks < 40);

// 2. A number from the data used as a size: 67 marks -> a bar 67% wide
bar.style.width = `${s.marks}%`;

With a second argument, classList.toggle(name, condition) is a switch, not a flip: true adds the class, false removes it. The colours stay in the stylesheet, in a rule such as li.low { color: #B42318; }, which is why a class beats setting colours with style (Chapter 56). Keep element.style for a value that truly comes from the data and differs on every row, such as a width; there is no sensible class called width-67.

58.8 Build once, attach once

Each time your code changes the live page, the browser notes that it must work out again where everything goes — a reflow — and then repaint. Browsers are clever: they usually wait until your code has finished before doing that work, so appending fifty rows one after another costs about one reflow, not fifty. Two habits defeat that cleverness:

  • innerHTML += inside a loop. a += b means a = a + b, so on every pass the browser turns the whole list back into a string, adds one item, throws the old elements away and parses everything again. The fiftieth pass rebuilds fifty items to add one. It also destroys any listeners on the old items and anything typed into inputs inside them.
  • Asking a layout question in the middle, such as an element's height. The browser must reflow there and then to answer, once per pass.

The tidy answer is to build everything off the page and attach it in one step. A DocumentFragment is an invisible holder that is not part of the page. Append rows to it and nothing on screen changes; append the fragment to the list and all its rows move into the list at once, leaving the fragment empty.

// SLOW and UNSAFE: rebuilds the whole list on every pass
for (const s of students) {
  list.innerHTML += `<li>${s.name}</li>`;
}

// FAST and SAFE: build off the page, attach once
const fragment = document.createDocumentFragment();
for (const s of students) {
  const li = document.createElement("li");
  li.textContent = s.name;
  fragment.append(li);          // the page has not changed yet
}
list.append(fragment);          // ONE change to the page; the fragment is now empty

Chapter 74 times the two with 800 items. Notice the fragment version is also the safe one, because each name went in through textContent.

Build all the new elements in a fragment, away from the page, then attach the fragment once. The page changes one time, however many items there are.

Quick check: a fragment holds 8 rows. After list.append(fragment), how many children does the fragment have?

None. Appending a fragment moves its children into the list; it does not copy them. The list gains 8 rows and the fragment is left empty, ready to be thrown away.

58.9 Filtering and sorting with controls

Now put it all together. A results board shows eight students. A search box filters by name as you type, a drop-down sorts, a checkbox shows only marks below 40, and a summary line says how many are shown and their average.

Key idea. Controls change the view, not the data. The students array is never filtered or sorted itself. Each time, render() works out a fresh array to show.
  1. Read the controls. search.value.trim().toLowerCase() removes stray spaces and lower-cases the word, so ASHA finds Asha.
  2. Filter. students.filter(...) returns a new array and leaves students untouched. An empty search matches everyone, because every string includes the empty string.
  3. Sort the new array. sort() reorders the very array it is called on. Here that array is the copy filter made, so students keeps its order. With no copy to hand, make one: [...students].sort(...) (spread, Chapter 50). Numbers sort with (a, b) => b.marks - a.marks (highest first); names with a.name.localeCompare(b.name), which compares text in dictionary order.
  4. Draw the empty state, or every row built into a fragment and attached once.
  5. Summarise from the same array.

  body { font-family: system-ui, sans-serif; padding: 12px; color: #1E293B; }
  .controls { display: flex; flex-wrap: wrap; gap: 10px; align-items: center; margin-bottom: 8px; }
  input, select { font: inherit; padding: 4px 6px; }
  #board { list-style: none; padding: 0; margin: 0; max-width: 460px; }
  #board li { display: grid; grid-template-columns: 70px 1fr 32px; gap: 10px;
              align-items: center; padding: 5px 8px; border-bottom: 1px solid #E2E8F0; }
  .track { background: #E2E8F0; border-radius: 6px; height: 12px; }
  .bar { background: #138808; border-radius: 6px; height: 12px; }
  #board li.low { color: #B42318; font-weight: 700; }
  #board li.low .bar { background: #B42318; }

<div class="controls">
  <label>Search <input id="search" type="search" placeholder="a name"></label>
  <label>Sort
    <select id="sort">
      <option value="high">Marks: high to low</option>
      <option value="low">Marks: low to high</option>
      <option value="name">Name: A to Z</option>
    </select>
  </label>
  <label><input id="below" type="checkbox"> Only below 40</label>
</div>
<ul id="board"></ul>

<script>
  // The data: never filtered or sorted itself
  const students = [
    { id: 1, name: "Asha",   marks: 91 },
    { id: 2, name: "Rahul",  marks: 67 },
    { id: 3, name: "Meera",  marks: 78 },
    { id: 4, name: "Arjun",  marks: 35 },
    { id: 5, name: "Priya",  marks: 88 },
    { id: 6, name: "Karan",  marks: 52 },
    { id: 7, name: "Sneha",  marks: 74 },
    { id: 8, name: "Vikram", marks: 29 }
  ];

  const board = document.getElementById("board");
  const search = document.getElementById("search");
  const sortBy = document.getElementById("sort");
  const below = document.getElementById("below");
  const summary = document.getElementById("summary");

  // One student in, one row out
  function makeRow(s) {
    const li = document.createElement("li");
    li.classList.toggle("low", s.marks < 40);          // the look decided by the data

    const name = document.createElement("span");
    name.textContent = s.name;
    const track = document.createElement("div");
    track.className = "track";
    const bar = document.createElement("div");
    bar.className = "bar";
    bar.style.width = `${s.marks}%`;                   // a size taken from the data
    track.append(bar);
    const score = document.createElement("span");
    score.textContent = s.marks;

    li.append(name, track, score);
    return li;
  }

  function render() {
    // 1. Work out the view: filter() returns a NEW array...
    const word = search.value.trim().toLowerCase();
    let shown = students.filter((s) => s.name.toLowerCase().includes(word));
    if (below.checked) shown = shown.filter((s) => s.marks < 40);

    // 2. ...so sorting it leaves students in its original order
    if (sortBy.value === "high") shown.sort((a, b) => b.marks - a.marks);
    if (sortBy.value === "low")  shown.sort((a, b) => a.marks - b.marks);
    if (sortBy.value === "name") shown.sort((a, b) => a.name.localeCompare(b.name));

    // 3. Draw: the empty state, or every row built off the page and attached once
    board.innerHTML = "";
    if (shown.length === 0) {
      const li = document.createElement("li");
      li.className = "empty";
      li.textContent = "No students match. Change the search or untick the box.";
      board.append(li);
    } else {
      const fragment = document.createDocumentFragment();
      for (const s of shown) fragment.append(makeRow(s));
      board.append(fragment);
    }

    // 4. The summary, from the same array as the rows
    if (shown.length === 0) {
      summary.textContent = `Showing 0 of ${students.length} students`;
    } else {
      const total = shown.reduce((sum, s) => sum + s.marks, 0);
      const average = (total / shown.length).toFixed(1);
      summary.textContent = `Showing ${shown.length} of ${students.length} students · average ${average}`;
    }
    console.log(summary.textContent);
  }

  search.addEventListener("input", render);
  sortBy.addEventListener("change", render);
  below.addEventListener("change", render);
  render();
</script>

At the start the board is sorted high to low: Asha (91) at the top, Vikram (29) at the bottom, Arjun and Vikram in red with short red bars. The Console prints Showing 8 of 8 students · average 64.3. Type ar: the input event fires on each key press, so you get one line for a (every name here contains an a) and then Showing 2 of 8 students · average 43.5, with Karan (52) above Arjun (35). Clear the box and tick Only below 40: Showing 2 of 8 students · average 32.0. Type z: the empty state appears and the Console prints Showing 0 of 8 students. Clear it, untick, choose Name: A to Z, and Arjun comes first. Through all of it, students never changed. Chapter 71 grows this pattern into a full task manager.

58.10 Common misunderstandings

✗ "innerHTML is safe as long as I block <script> tags."
A <script> added by innerHTML never runs anyway. The danger is attributes such as onerror on the elements it builds.
✓ "Text from a person or a server goes in with textContent."
Keep innerHTML for markup you wrote, with only your own values in it.
✗ "To delete an item, remove its <li> from the page."
The row vanishes, but the array still holds the item, so the total still counts it and the next render() brings the row back.
✓ "Remove it from the data, then call render()."
The page is a picture of the data. Change the data and redraw.
✗ "dataset.id gives back the number I stored."
remove.dataset.id = 3 stores the text "3".
✓ "Every data-* value is a string."
Use Number(button.dataset.id) before comparing with ===.
✗ "Sorting for display does not touch my data."
sort() reorders the array it is called on and returns that same array.
✓ "Sort a copy: the array filter() made, or [...arr]."
The original keeps its order for the next render.

Exam-style checks

Answer each one before opening it. Most have four options and exactly one correct answer; three ask you to predict what code prints or to write a line.

Which of these inserts a string as plain text, without interpreting any tags in it?L1
  • A. innerHTML
  • B. outerHTML
  • C. textContent
  • D. insertAdjacentHTML

Answer: C. textContent puts the characters in exactly as given. A, B and D all parse their string as HTML and build elements from any tags in it.

What does this print? const p = document.createElement("p"); p.innerHTML = "<i>Hi</i>"; console.log(p.children.length); p.textContent = "<i>Hi</i>"; console.log(p.children.length);L2

Answer: 1, then 0. innerHTML parsed the tags and built an <i> element, so the paragraph has one element child. textContent then replaced everything with a single piece of text that happens to contain angle brackets, so there are no element children at all.

A comments page shows each comment with wall.innerHTML = comment;. A visitor posts <img src="x" onerror="stealData()">. What happens when other students open the page?L3
  • A. They see the text exactly as it was typed
  • B. The browser builds an image, the image fails to load, and stealData() runs in their browser
  • C. Nothing, because browsers never run code that arrives through innerHTML
  • D. Only the visitor who typed it is affected

Answer: B. This is cross-site scripting. C is the tempting half-truth: a <script> inserted by innerHTML does not run, but event attributes on the elements it builds do. A is what textContent would have done.

The list is an empty <ul>. What does this print? const fruits = ["Apple", "Mango"]; list.innerHTML = fruits.map((f) => `<li>${f}</li>`); console.log(list.textContent);L3
  • A. Apple,Mango
  • B. AppleMango
  • C. [Apple, Mango]
  • D. A TypeError

Answer: A. map returned an array, and an array used as a string is joined with commas: <li>Apple</li>,<li>Mango</li>. The comma becomes text between the items, visible on the page. With .join("") added, B would be printed.

In the state-to-view pattern, what should a Remove button's click handler do?L2
  • A. Call li.remove() and leave the array as it is
  • B. Hide the row with style.display = "none"
  • C. Reload the page
  • D. Remove the item from the data array, then call render()

Answer: D. The data is the source of truth. A is the tempting one: the row disappears, but the item is still in the array, so the next render() brings it back and the total still counts it.

For <button data-id="7">Remove</button>, what does this print? const id = button.dataset.id; console.log(typeof id, id === 7);L3
  • A. number true
  • B. number false
  • C. string false
  • D. string true

Answer: C. Every dataset value is a string, "7", and strict equality never matches a string with a number. Number(id) === 7 would be true.

Why label each Remove button with its item's id rather than its position in the list?L2
  • A. Positions are not allowed in data attributes
  • B. After a delete, a sort or a filter, positions shift, but an id stays with its item
  • C. Ids make the page load faster
  • D. dataset can store only ids

Answer: B. Delete item 0 and every later item moves up one place; sort the list and the third row is no longer the third item. A, C and D are simply false: a data attribute can hold any text.

What is a DocumentFragment used for when generating a list?L2
  • A. Building many elements off the page and attaching them in a single step
  • B. Saving the list in browser storage
  • C. Escaping text before it goes into innerHTML
  • D. Splitting a page into separate files

Answer: A. Rows appended to a fragment are not on the page; appending the fragment moves them all into the page at once and leaves it empty. It does nothing for storage (B) or safety (C) by itself.

What does this print? const marks = [35, 91, 67]; const ranked = marks.sort((a, b) => b - a); console.log(marks);L3
  • A. [35, 91, 67]
  • B. [35, 67, 91]
  • C. undefined
  • D. [91, 67, 35]

Answer: D. sort() reorders the array it is called on and returns that same array, so marks and ranked are one array, highest first. A is what people expect; to keep it, sort a copy: [...marks].sort((a, b) => b - a).

Write one line that gives a row the class low when marks is below 40 and removes the class otherwise.L3

Answer: row.classList.toggle("low", marks < 40); With a second argument, toggle is a switch: true adds the class and false removes it. Without the second argument it would flip the class on and off each time it ran.

render() rebuilds every row each time the data changes. Where is the simplest place for the Remove buttons' click listener?L3
  • A. On document.body, listening for keydown
  • B. On the list element, using event.target.closest("button[data-id]")
  • C. On each button, added once when the page first loads
  • D. In an onclick attribute typed into the HTML file

Answer: B. The list is never replaced, so one delegated listener handles every button, including ones created later. C fails: the first render() after a change throws those buttons away with their listeners, and new buttons have none. D cannot work for buttons that are not in the HTML file at all.

Which job suits a template literal with innerHTML?L2
  • A. Showing a product name a seller typed
  • B. Showing a comment from a student
  • C. Fixed card markup you wrote, filled with prices your code calculated
  • D. Showing a user's name that came from a server

Answer: C. Every character in that string is yours, so nothing unexpected can be parsed. A, B and D all contain text from outside, which belongs in textContent (or must be escaped first).

Quick revision

Key takeaways

  1. Keep repeated content as data, usually an array of objects, and let a loop make one element per item: create, fill, append.
  2. textContent inserts text without interpreting it as HTML; innerHTML parses the string as HTML. A template literal with innerHTML is short; createElement with textContent is safe. Remember .join("") after map.
  3. Never put text from a person or a server into innerHTML: attributes such as onerror run code (XSS). Blocking <script> is no protection.
  4. State to view: change only the data, then call render(), which clears the container and redraws everything from it. The data is the single source of truth.
  5. Label each button with data-id; one delegated listener finds it with event.target.closest(...); convert with Number(); change the data.
  6. Every list needs an empty state, and its count, total or average is worked out in render() from the same array as the rows.
  7. Controls change the view, not the data: filter, then sort the copy. Style with classList.toggle(name, condition), use style only for sizes from the data, build in a DocumentFragment and attach once, and never use innerHTML += in a loop.
