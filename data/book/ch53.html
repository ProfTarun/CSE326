Higher-Order Functions

Add 5 grace marks to every student. Keep only the students who passed. Add up the whole class. In Chapter 52 each of those jobs needed a loop, a counter and an accumulator. JavaScript arrays come with ready-made methods that do the looping for you: you hand them one small function that says what to do with a single element, and they do it for every element. Once you can read map, filter and reduce, most of the code on real websites starts to make sense.

Before you start — one-line reminders

  • A function is a value: multiply is the function itself, multiply(4, 6) runs it and gives its answer (Chapter 48).
  • (a, b) => a + b is an arrow function; if you write braces, you must also write return (Chapter 48).
  • A function returned from inside another function still remembers that function's variables: a closure (Chapter 49).
  • An array of objects such as students[1].name, and an accumulator such as total += mark built up round by round in a loop (Chapter 50, Chapter 52).

53.1 Functions are values

In Chapter 48 you met a surprising fact: a function is a value, just like 24 or "Asha". typeof multiply gives "function", in the same way that typeof 24 gives "number". Programmers say that JavaScript functions are first-class values. Whatever you can do with a number, you can do with a function. Three of those things matter in this chapter:

  1. Store it in a variable. const yell = shout; gives the same function a second name. No brackets, so nothing runs.
  2. Pass it to another function as an argument. processUser("asha", shout) hands the function itself over, and processUser decides when to run it.
  3. Return it from a function. A function can build a new function and hand it back with return, as makeCounter did in Chapter 49.

Your slides define the chapter's main idea in one line. A higher-order function is a function that takes another function as an argument, returns a function, or does both. Nothing about it is special to look at. It is an ordinary function with a parameter that happens to hold a function, which it calls with brackets, or a return that hands a function back.

function processUser(name, format) {   // format will hold a function
  return format(name);                 // brackets: run it now
}

function shout(text) {
  return text.toUpperCase() + "!";
}

console.log(processUser("asha", shout));                   // ASHA!
console.log(processUser("rahul", (t) => "Hello, " + t));   // Hello, rahul

processUser is the higher-order function: it receives a function. shout and the little arrow function are the functions being handed over. A function handed over like this is usually called a callback; Chapter 54 gives callbacks a chapter of their own. Here, notice what the arrangement buys you. processUser does not know or care how the name will be formatted. Change the function you hand over and the same processUser does a different job.

A higher-order function is a function that works with other functions: it takes one in, or gives one back. You hand over a function by writing its name without brackets; the receiver runs it by writing brackets after the parameter.

53.2 Arrow functions: the usual shorthand

The functions you hand to array methods are usually tiny and used once, so they are almost always written as arrow functions, right inside the call. Your slides recap the form. Arrow functions arrived in ES6 (ECMAScript 2015) as a shorter way to write a function expression:

// Traditional function expression
const add = function (a, b) {
  return a + b;
};

// Arrow function: const name = (parameters) => { ... }
const addArrow = (a, b) => {
  return a + b;
};

// One answer only: drop the braces and the word return
const addShort = (a, b) => a + b;

// No parameters: empty brackets (slide 23)
const greet = () => console.log("Good morning, CSE326!");
greet();                                   // Good morning, CSE326!

All three versions of add make the same function. Here is one test, "did this student pass?", in the three styles you will meet in other people's code:

StyleThe test written in that style
Traditional, written in placefunction (s) { return s.marks >= 40; }
Arrow with braces(s) => { return s.marks >= 40; }
Arrow, one answer (the usual choice)(s) => s.marks >= 40  or  s => s.marks >= 40
The brace trap. (m) => { m + 5 } returns undefined. The braces make a block body, and a block body returns only what a return statement hands back. Inside map that one slip turns every mark into undefined. Either drop the braces, (m) => m + 5, or keep them and write return.

One difference from ordinary functions matters later: an arrow function does not get its own this, so do not use one as an object's method (Chapter 51). Everywhere in this chapter, arrows are the natural choice.

Quick check: what does const half = (n) => { n / 2 }; give for half(10)?

undefined. The braces make a block body with no return. Write (n) => n / 2 or (n) => { return n / 2; } to get 5.

53.3 forEach: do something with each element

Every array method in this chapter has the same basic shape: array.method(yourFunction) (reduce also takes a start value, 53.6). The method does the looping: it starts at index 0, goes to the end, and calls your function once for every element. Your function only has to say what happens to one element. You never write i, i < length or i++, so you cannot get them wrong.

Picture this. A teacher sits in the staff room with a pile of answer sheets for the CSE326 test. She can work through the pile in several ways. She can read each sheet's mark aloud to the class: nothing new is made (forEach). She can copy every mark onto a fresh list with 5 grace marks added: a new list, the same length, the sheets untouched (map). She can pull out the sheets with 40 or more into a new pile (filter). She can key every mark into a calculator, keeping one running total, and end with a single number (reduce). Or she can flip through until she finds the first sheet above 90, and stop there (find). Same pile, the same "one sheet at a time" routine; only the instruction for each sheet changes.

forEach is the simplest. It calls your function for each element, and that is all:

const marks = [78, 35, 91, 40, 63];

marks.forEach((m) => {
  console.log("Mark:", m);        // Mark: 78, Mark: 35, ... one line each
});

// the same job as a for...of loop (Chapter 52)
for (const m of marks) {
  console.log("Mark:", m);
}

Your function is given up to three arguments each time: the element, its index and the whole array. Use only the ones you need. (s, i) => console.log(i + 1, s) numbers the lines from 1.

forEach always returns undefined. It is meant for jobs that make something happen outside the function, such as printing a line or writing on the page. A job like that is called a side effect. If you want a new array back, you want map.

One more limit: you cannot stop a forEach early. break is not allowed inside its function, and a return there only ends that one call, so forEach carries on with the next element, much like continue. When you need to stop at the first match, use find or some (53.7), or a plain for...of loop with break.

53.4 map: transform each into a new array

map calls your function on every element, collects what your function returns each time, and hands you those answers as a new array of the same length. The original array is not changed.

const marks = [78, 35, 91, 40, 63];
const withBonus = marks.map((m) => m + 5);

console.log(withBonus);    // [83, 40, 96, 45, 68]
console.log(marks);        // [78, 35, 91, 40, 63]  - untouched

Read marks.map((m) => m + 5) as "make a new list in which each mark m becomes m + 5". Five in, five out, always. map is the tool whenever the question is "turn each X into a Y": each student into a name, each price into a price with GST, each mark into a grade.

const students = [
  { name: "Asha",  marks: 78 },
  { name: "Rahul", marks: 35 }
];
const names = students.map((s) => s.name);                    // ["Asha", "Rahul"]
const grades = students.map((s) => (s.marks >= 40 ? "Pass" : "Fail"));   // ["Pass", "Fail"]

Lab Task 4: bonus marks without changing the original

Your lab sheet asks for a new array in which every student gets 5 bonus marks, with the original left alone. With objects there is a trap. This version looks right:

// WRONG: changes the original students too
const bonus = students.map((s) => {
  s.marks = s.marks + 5;     // s IS the original object, not a copy
  return s;
});

map builds a new array, but the function receives the original objects, and Chapter 51 showed that an object is shared, not copied. Writing s.marks = ... changes the student in the original array. The right way is to return a new object for each student, using the spread copy from Chapter 51:

// RIGHT: a new object for every student
const bonus = students.map((s) => ({ ...s, marks: s.marks + 5 }));

{ ...s, marks: s.marks + 5 } means "copy every property of s, then set marks to the new value". The round brackets around the braces are the Chapter 48 rule for returning an object from a one-answer arrow.

map is a photocopier with a change applied: what comes out is a fresh list of answers, one per element, and the old list stays as it was. Just do not scribble on the originals while copying them. Build a new object; do not change s.

53.5 filter: keep the ones that pass

filter asks your function a yes-or-no question about each element. A function used like this, which answers true or false, is called a predicate. Every element for which it answers true goes into a new array; the rest are left out. The order is kept, and the original is not changed.

// Lab Task 3: students who scored at least 40
const passed = students.filter((s) => s.marks >= 40);
// Asha 78, Meera 91, Kabir 40, Riya 63  - Rahul (35) is left out

Kabir is in: the rule is "at least 40", so 40 passes. The new array can be any length from zero up to the original length. When nothing passes, you get an empty array [], never undefined, so passed.length is always safe to read. (Strictly, the function only has to give a truthy or falsy value, Chapter 46; a clear true/false test is best.)

Like map, filter makes a new array but does not copy the objects inside it. passed[0] is the very same Asha object as students[0].

53.6 reduce: combine everything into one value

map and filter give back arrays. reduce boils a whole array down to one value: a total, an average, a highest mark. It is the Chapter 52 accumulator pattern, packed into one method. Its shape has two parts:

array.reduce((acc, item) => newAcc, startValue)
  • Your function receives the accumulator (the answer so far, often called acc or sum) and the current element. It must return the new answer so far.
  • The start value, the second argument to reduce, is what the accumulator holds before the first element. For a total, that is 0.

reduce calls your function once per element. Whatever your function returns becomes the accumulator for the next call. What the last call returns is the result of reduce. Lab Task 5 needs the class total first:

const total = students.reduce((sum, s) => sum + s.marks, 0);   // 307
const average = total / students.length;                          // 61.4
Callsum coming ins.marksFunction returns sum + s.marks

5 (Riya)24463307 — what reduce gives back

Each row's answer drops into the next row's sum. Compare it with Chapter 52's loop: let total = 0 became the start value, total += mark became the function's return, and the final total is what reduce returns. The average is then 307 / 5 = 61.4.

reduce is a calculator that keeps one running number. You say what it shows at the start (0) and what to do with each new mark (sum + s.marks). After the last mark, the number on the display is your answer.

Always give the start value

The start value looks optional, and JavaScript does let you leave it out. Then reduce uses the first element as the starting accumulator and begins with the second. For a plain list of numbers that happens to work. It fails in two common cases:

  • Objects. students.reduce((sum, s) => sum + s.marks) starts with sum holding the whole Asha object. An object plus a number turns into text, so the result is the nonsense string "[object Object]35914063".
  • An empty array. With no elements and no start value there is nothing to begin with, and reduce throws TypeError: Reduce of empty array with no initial value. With 0 as the start value it simply returns 0.

reduce can keep any single answer, not just a sum. To find the top scorer, the accumulator holds "the best student so far", and each call keeps whichever of the two is better:

const topper = students.reduce((best, s) => (s.marks > best.marks ? s : best), students[0]);
console.log(topper.name); // Meera

53.7 Searching: find, findIndex, some and every

Four more methods take a predicate, and each answers a different question. Chapter 50 introduced find; here is the whole family:

MethodQuestion it answersReturnsIf nothing matches
find(test)Which is the first element that passes?That elementundefined
findIndex(test)Where is the first element that passes?Its index-1
some(test)Does at least one element pass?true or falsefalse
every(test)Do all elements pass?true or falsefalse (but true for an empty array)

Unlike forEach, map and filter, these four stop early. find stops at the first match, because the answer cannot change after that. some stops at the first true, and every at the first false. On a list of 60 students, some((s) => s.marks < 40) may need to look at only two.

Do not mix up find and filter. find gives one element (or undefined); filter gives an array of every match (or []). And when you are looking for an exact value in a plain list, includes from Chapter 50 is simpler than some. Use some when the test needs a rule, such as "marks below 40".

Exam tip. On an empty array, some gives false (nobody passed) and every gives true (nobody failed). That second one surprises people and is a favourite trick question.

53.8 sort with a compare function

sort is a higher-order function too. Chapter 50 showed its famous trap: left alone, it compares elements as text, so [100, 35, 9].sort() gives [100, 35, 9] ("1" comes before "3" and "9"). The fix is a compare function. sort keeps picking two elements, a and b, and calls your function to ask which goes first:

Your function returnssort puts
A negative numbera before b
A positive numberb before a
0Keeps their order

So (a, b) => a - b sorts numbers smallest first, and (a, b) => b - a largest first. With objects, compare the property you care about. A rank list, highest marks first, is (a, b) => b.marks - a.marks. For names, subtraction makes no sense, so strings have a method made for comparing: a.name.localeCompare(b.name) returns a negative number, 0 or a positive number in dictionary order, exactly what sort wants.

How many times sort calls your function, and in which pairs, is up to the browser. Never depend on it; just make sure the answer for any pair is right.

Two sort traps. First, sort changes the original array and returns that same array. To keep the register in roll-number order, sort a copy: [...students].sort(...), or toSorted(...) in recent browsers. Second, the compare function must return a number. (a, b) => a > b returns true or false, which sort treats as 1 or 0 and never as negative, so the result may not be sorted at all.

53.9 Chaining: filter, then map, then reduce

Because filter and map return arrays, you can call another array method straight on their result, with no variable in between. Writing one method call after another like this is called method chaining. Question: what is the total of the marks of the students who passed?

const passedTotal = students
  .filter((s) => s.marks >= 40)        // 4 student objects (Rahul dropped)
  .map((s) => s.marks)                 // [78, 91, 40, 63]
  .reduce((sum, m) => sum + m, 0);     // 272

Read it top to bottom, like a recipe. Each line starts with a dot, so each step works on what the line above gave back. Putting one step per line is a habit worth copying: every step can carry its own comment, and you can read the chain the way it runs.

A chain is a row of small machines. The first machine (filter) throws out what you do not want, the second (map) changes the shape of what is left, and the last (reduce) packs it all into one answer. If you are ever confused, break the chain into separate variables and print each step.

Order matters in a chain. Give the 5 bonus marks before filtering and Rahul's 35 becomes 40, so he passes. Filter first, then add the bonus, and he does not. Neither is "wrong"; they answer different questions, so put the steps in the order the question asks for.

</script>

Then Bonus, then filter: Asha, Rahul, Meera, Kabir, Riya against Filter only: Asha, Meera, Kabir, Riya: one name's difference, from the order of two steps. The page lists 1. Meera (91), 2. Asha (78), 3. Riya (63). Notice the sort in that last chain is safe: it sorts the new array filter made, not students.

When a plain loop is still fine

These methods do not replace the loops of Chapter 52; they are shorthand for the commonest loops. A plain for or for...of loop is still the better tool when:

  • you need to stop part-way on a condition that is not "first match", using break;
  • you are not walking through an array at all, such as counting down from 10 or repeating until the user types "quit";
  • one pass must do several jobs at once (total, highest and count together), where a chain would walk the list three times;
  • a beginner on your team will read the code, and the loop says it more plainly.

Both styles produce the same answers. Choose the one that makes the code easiest to read: a short chain for "keep, change, combine"; a loop when the logic has many branches and early exits.

53.10 A function that returns a function

The second half of the higher-order definition is returning a function. Here is the classic example:

function makeMultiplier(factor) {
  return (n) => n * factor;
}

const double = makeMultiplier(2);
const triple = makeMultiplier(3);
console.log(double(5));    // 10
console.log(triple(5));    // 15

Follow it slowly. makeMultiplier(2) runs, with factor set to 2. It does not multiply anything. It builds the small function (n) => n * factor and returns it, and we store that function in double. Then makeMultiplier has finished, yet double(5) still finds factor and gives 10. This is the closure from Chapter 49: the returned function keeps a live link to the variables of the call that made it. The second call, makeMultiplier(3), has its own factor, so triple remembers 3 and double still remembers 2.

A function whose job is to build and return other functions is often called a function factory. Factories fit array methods perfectly, because they make exactly what map and filter want: a ready-made function. Instead of writing a new test for every cut-off, write one factory:

function scoredAtLeast(cutoff) {
  return (s) => s.marks >= cutoff;    // a test that remembers cutoff
}
students.filter(scoredAtLeast(40));    // the pass list
students.filter(scoredAtLeast(75));    // the distinction list

makeMultiplier(2) is like setting a machine's dial to 2 and handing you the machine. Every time you use the machine, it multiplies by 2, because it remembers where its dial was set. scoredAtLeast(75) hands you a test with its bar fixed at 75.

53.11 Common misunderstandings

✗ "forEach gives back a new array, like map."
It always returns undefined, whatever your function returns.
✓ "forEach is for doing; map is for making."
Use forEach to print or change the page; use map when you want a new array of answers.
✗ "map and filter can never change my original data."
They never change the array, but the function receives the original objects.
✓ "Return a new object; do not edit s."
map((s) => ({ ...s, marks: s.marks + 5 })) leaves every original student as it was.
✗ "filter gives me the student I am looking for."
It gives an array, even when only one student matches.
✓ "find gives one element; filter gives every match."
find returns the first match or undefined; filter returns an array, possibly [].
✗ "The start value of reduce is optional, so I can leave it out."
Without it, an array of objects gives nonsense text and an empty array throws a TypeError.
✓ "Always give reduce a start value."
0 for a total, "" for text, [] for a list, students[0] for a best-so-far.
✗ "return inside forEach stops the loop."
It only ends that one call; forEach carries on with the next element.
✓ "To stop early, use find, some, every, or a for...of loop with break."
✗ "marks.map(addBonus()) passes my function to map."
The brackets run addBonus now and pass its answer, so map complains that it is not a function.
✓ "Hand over the function without brackets: marks.map(addBonus)."
The array method adds the brackets when it calls it.

Exam-style checks

Answer each one before opening it. Most have four options and exactly one correct answer; several ask what the code prints.

A higher-order function is a function that:L1
  • A. Is written with the arrow symbol =>
  • B. Is declared at the top of the program
  • C. Takes a function as an argument, returns a function, or both
  • D. Calls itself

Answer: C. That is the slide's definition. A is tempting because the functions handed to higher-order functions are often arrows, but the arrow style has nothing to do with it. D describes recursion.

What does [1, 2, 3].forEach((n) => n * 2) return?L2
  • A. undefined
  • B. [2, 4, 6]
  • C. [1, 2, 3]
  • D. 12

Answer: A. forEach always returns undefined and ignores what your function returns. B is what map would give.

What does this print? const r = [78, 35, 91].map((m) => m + 5); console.log(r.join(" "));L3

Answer: 83 40 96. map adds 5 to each mark and returns a new array of the same length; join(" ") puts spaces between them. The original array is unchanged.

What is [78, 35, 91, 40].filter((m) => m >= 40).length?L2
  • A. 1
  • B. 2
  • C. 4
  • D. 3

Answer: D. 78, 91 and 40 pass; 35 does not. B is the answer people give when they forget that >= lets exactly 40 through.

What does this print? console.log([10, 20, 30].reduce((acc, n) => acc + n, 5));L3
  • A. 60
  • B. 5
  • C. 65
  • D. 35

Answer: C. The accumulator starts at 5: 5 + 10 = 15, 15 + 20 = 35, 35 + 30 = 65. A is the answer people give when they forget that the start value counts as part of the total.

What does students.findIndex((s) => s.name === "Zoya") give when no student is called Zoya?L1
  • A. undefined
  • B. -1
  • C. null
  • D. 0

Answer: B. findIndex, like indexOf, uses −1 for "not found", because −1 can never be an index. A is what find gives when nothing matches.

Which method answers "is at least one student below 40?" and stops as soon as it finds one?L2
  • A. every
  • B. filter
  • C. some
  • D. map

Answer: C. some returns true at the first match. filter would also tell you, but it checks every element and gives back an array, not a yes/no.

What does const out = [4, 9].map((n) => { n * 10 }); put in out?L2
  • A. [40, 90]
  • B. [undefined, undefined]
  • C. [4, 9]
  • D. A SyntaxError

Answer: B. The braces make a block body without return, so each call returns undefined, and map collects two of them. Drop the braces to get A.

What does this print? const marks = [5, 25, 100]; marks.sort(); console.log(marks.join(",")); How do you sort them as numbers?L3

Answer: 100,25,5. With no compare function, sort compares text, and "1" comes before "2" and "5". Write marks.sort((a, b) => a - b) to get 5,25,100.

What does this print? console.log([3, 8, 12, 5].filter((n) => n > 4).map((n) => n * 10).join(" "));L3

Answer: 80 120 50. filter keeps 8, 12 and 5 (in their original order); map multiplies each by 10.

With function makeMultiplier(f) { return (n) => n * f; }, what is makeMultiplier(4)(5)?L3
  • A. 9
  • B. A function
  • C. 4
  • D. 20

Answer: D. makeMultiplier(4) returns a function that remembers f = 4; the second brackets call it with 5, giving 20. B would be the answer for makeMultiplier(4) alone.

To get the total fees of all students as a single number, the best single method is:L2
  • A. reduce
  • B. map
  • C. forEach
  • D. find

Answer: A. reduce combines an array into one value. map would give an array, and forEach returns undefined, so you would still need your own accumulator.

Quick revision

Key takeaways

  1. Functions are values: you can store them, pass them as arguments and return them. A function that takes or returns a function is higher-order.
  2. Hand a function over by name, without brackets; the receiver calls it. Short functions are usually written as arrows, and braces need return.
  3. forEach does something with each element and returns undefined. map transforms each into a new array of the same length. filter keeps the matches in a new array.
  4. reduce((acc, item) => newAcc, start) combines everything into one value; each return becomes the next accumulator. Always give the start value.
  5. find gives the first match or undefined; findIndex its index or −1; some and every give true/false. These four stop early.
  6. sort needs a compare function that returns a number (a - b, b.marks - a.marks, localeCompare), and it changes the original, so sort a copy.
  7. Chains such as filter → map → reduce read like a recipe; the order of the steps changes the answer.
  8. A function can return a function that remembers its setting (a closure): makeMultiplier(2) gives a doubler. Plain loops are still fine when they are clearer.
