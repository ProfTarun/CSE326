Audio and Video Events

A video player on a website is more than a moving picture. The Play button turns into Pause, the time ticks along, the bar fills up, and a message appears when the lecture ends. All of that is JavaScript talking to the audio or video element. This chapter gives you the commands you can send it, the readings you can take from it and the events it sends back — and then you build a player of your own.

About 30 minutes · Course outcome CO5

Before you start — one-line reminders

  • <audio> and <video> play files without a plug-in; controls shows the browser's own player, and autoplay only works when the media is muted (Chapter 10).
  • addEventListener("click", fn) runs fn every time the event happens (Chapter 57).
  • getElementById finds an element and textContent changes its words (Chapter 56).
  • Math.floor(135 / 60) is 2 and 135 % 60 is 15 (Chapter 44); "5".padStart(2, "0") is "05" (Chapter 45).

By the end of this chapter you can

  • Control an audio or video element from JavaScript with play(), pause() and its properties.
  • Explain why play() returns a Promise, why a browser may refuse it, and handle the refusal.
  • Read duration only once it is known, and turn seconds into a m:ss time display.
  • Say when each main media event fires: loadedmetadata, canplay, play, playing, pause, timeupdate, seeking, seeked, volumechange, ended and error.
  • Build custom controls: a play/pause toggle, mute, volume, speed and a progress bar you can drag to seek.
  • Keep custom controls accessible, and update the screen from events instead of checking on a timer.

63.1 From tags to a remote control

Chapter 10 put media on the page with two tags. These are the lecture slide's examples:

<audio id="audioPlayer" controls>
  <source src="music.mp3" type="audio/mpeg">
  Your browser does not support audio.
</audio>

<video id="videoPlayer" width="480" controls>
  <source src="lesson.mp4" type="video/mp4">
  Your browser does not support video.
</video>

HTML5 plays both directly in the browser, and controls gives each one the browser's own play button, time bar and volume. For many pages that is enough. But notice the id on each element. An id means JavaScript can find it, and once it has the element it can do everything those built-in controls do, and more: start a lecture at the two-minute mark, slow it to 0.75 speed, or show "Lecture finished — take the quiz" the moment it ends.

const audio = document.getElementById("audioPlayer");
const video = document.getElementById("videoPlayer");

Each of these is a media element object. <audio> and <video> are built on the same foundation, called HTMLMediaElement, so everything in this chapter works on both, word for word. Its tools come in three kinds:

  • Commands (methods) — things you tell it to do: play(), pause().
  • Readings and dials (properties) — values you can read, and some you can set: currentTime, duration, volume, paused.
  • Announcements (events) — it tells you when something has happened: play, timeupdate, ended.
Picture this. Cooking dal in a pressure cooker. You give it commands: light the flame, turn it down. You take readings: how high the flame is, how long it has been on. And the cooker makes announcements of its own: it whistles. Nobody stands at the stove counting the minutes and walking back every ten seconds to check. You listen for the whistle and act then. A media element works the same way: methods are the knobs, properties are the readings, events are the whistles.

63.2 Commands: play() and pause()

Two methods do most of the work:

audio.play();    // start, or carry on from where it was paused
audio.pause();   // stop moving, but stay at this position

pause() keeps the position like a bookmark, so the next play() carries on from there. There is no stop() method. To stop and go back to the beginning, pause and then rewind by setting the position to 0 (63.3 explains currentTime):

audio.pause();
audio.currentTime = 0;   // "stop" = pause + rewind

play() answers later, with a Promise

Playback cannot always begin on the spot. The browser may still be loading the file and, more importantly, it may refuse. So play() does not wait. It hands back a Promise, the object you met at the end of Chapter 54 that stands for "the answer, when it comes". You attach what should happen next: .then(...) runs if playback starts, and .catch(...) runs if it is refused, receiving an error object whose name says why.

audio.play()
  .then(() => console.log("Playing"))
  .catch((err) => console.log("Could not play:", err.name));
err.nameWhat it means
NotAllowedErrorThe browser blocked it: sound tried to start before the user had touched the page (the autoplay policy, below)
NotSupportedErrorThere is nothing it can play: the file is missing, or in a format this browser cannot read
AbortErrorInterrupted: pause() was called, or a new file was loaded, before playback had begun

The autoplay policy

Chapter 10 explained why an autoplaying video must be muted: nobody wants a page that suddenly shouts. JavaScript is held to the same rule. Every modern browser has an autoplay policy: media with sound may only start after a user gesture — a click, a tap or a key press on the page. A play() written straight into the script, running as the page loads, is usually refused with NotAllowedError. The same line inside a click listener works, because the click is the user saying "yes, I want this".

// As the page loads: usually REFUSED for media with sound
audio.play().catch((err) => console.log(err.name));   // NotAllowedError

// Inside a click listener: ALLOWED - the click is the user's permission
playBtn.addEventListener("click", () => {
  audio.play().catch((err) => console.log(err.name));
});

// Muted media may start by itself
video.muted = true;
video.play();

play() means "please start". The browser answers a moment later through the promise: yes (.then) or no (.catch). It says no to sound that tries to start before the user has done anything. So call play() from a click handler, and always add a .catch, so that a refusal is handled quietly instead of appearing as a red "Uncaught (in promise)" error.

<p>A 3-second tone with no built-in controls - only these buttons:</p>
<button id="playBtn">Play</button>
<button id="pauseBtn">Pause</button>
<button id="stopBtn">Stop</button>
<p id="state"></p>

<script>
  const tone = document.getElementById("tone");
  const state = document.getElementById("state");

  // Show two readings, on the page and in the Console
  function report(label) {
    const text = `${label}: paused = ${tone.paused}, at ${tone.currentTime.toFixed(1)} s`;
    state.textContent = text;
    console.log(text);
  }

  document.getElementById("playBtn").addEventListener("click", () => {
    tone.play()                              // a request: the answer comes later
      .then(() => report("Playing"))
      .catch((err) => report("Refused - " + err.name));
  });

  document.getElementById("pauseBtn").addEventListener("click", () => {
    tone.pause();                            // stays at this position
    report("Paused");
  });

  document.getElementById("stopBtn").addEventListener("click", () => {
    tone.pause();                            // there is no stop() method,
    tone.currentTime = 0;                    // so pause and rewind to 0
    report("Stopped");
  });

  report("Ready");
</script>

Run it. The Console says Ready: paused = true, at 0.0 s. Press Play: Playing: paused = false, at 0.0 s. Press Pause part-way: the position is kept, perhaps at 1.4 s, and Play carries on from there. Stop pauses and rewinds to 0.0. Now press Play and let the tone finish. The label still says Playing, although the sound has stopped. Nothing told the page. That is the job of events (63.4).

Quick check: a classmate writes video.stop() for a Stop button. What happens, and what should they write?

A TypeError: there is no stop method, so video.stop is undefined and calling it fails. Write video.pause(); video.currentTime = 0; — pause, then rewind.

63.3 Readings and dials: the properties

A media element carries a set of properties. Some are readings you can only look at; the others are dials you turn by assigning a new value.

PropertyWhat it holdsRead or set?
currentTimeThe playback position in seconds (1.5 = one and a half seconds in). Setting it jumps there — a seekBoth
durationThe total length in seconds. NaN until the browser has read the file's metadata; Infinity for a live streamRead only
pausedtrue before the first play, after pause(), and after the end; false from the moment play() is called (even while it waits for data)Read only
endedtrue once playback has reached the endRead only
volumeLoudness from 0 (silent) to 1 (full, the default). Anything outside that range throws an errorBoth
mutedtrue silences it without changing volumeBoth
playbackRateSpeed: 1 normal, 0.5 half speed, 2 double. Modern browsers keep voices at their normal pitchBoth
looptrue starts again from 0 at the end — the same switch as the loop attributeBoth

The attributes from Chapter 10 work the same way as properties: video.loop = true, video.muted = true and video.controls = false do from JavaScript what the attributes do in HTML. Three details catch beginners.

Time is a plain number of seconds. A position of one minute fifteen seconds is 75, not "1:15". Turning it into 1:15 for the screen is your job, and 63.6 shows how.

The length is not known at first. The length of a recording is stored inside the file, usually near the start, in its metadata. The browser can only read it after it has fetched those bytes, and your script usually runs before then, so duration is NaN. When the metadata arrives, the element fires the loadedmetadata event, and from then on duration is a real number. The safe pattern checks first, then waits if it has to:

if (audio.readyState >= 1) {
  showLength();                                         // already known
} else {
  audio.addEventListener("loadedmetadata", showLength); // wait for it
}

readyState is a number from 0 to 4 saying how much the element has loaded: 0 means nothing yet; 1 or more means the metadata is in. The if covers a file that arrived very fast, before your listener was added; the else covers the usual case.

The browser does not know how long a song is until it has read the first part of the file. Ask too early and duration says NaN, "not a number". Wait for the loadedmetadata event, then ask.

volume and muted are two separate dials. Set volume to 0.5, then muted to true: it goes silent, but volume still says 0.5. Un-mute and the old loudness comes back. That is exactly how a mute button should behave.

<style> body { font-family: system-ui, sans-serif; padding: 14px; } </style>
<audio id="tone" src="media/tone.wav" preload="auto" controls></audio>
<p id="info">Waiting for the file...</p>

<script>
  const tone = document.getElementById("tone");
  const info = document.getElementById("info");

  console.log("At once - duration:", tone.duration, "| paused:", tone.paused);

  function showFacts() {
    console.log("Metadata - duration:", tone.duration, "seconds");
    console.log("volume:", tone.volume, "| muted:", tone.muted,
                "| rate:", tone.playbackRate, "| loop:", tone.loop);

    tone.volume = 0.5;          // half loudness
    tone.playbackRate = 1.5;    // one and a half times as fast
    tone.loop = true;           // the same as writing the loop attribute
    console.log("Changed - volume:", tone.volume, "| rate:", tone.playbackRate,
                "| loop:", tone.loop);

    try {
      tone.volume = 1.5;        // more than 1 is not allowed
    } catch (err) {
      console.log("volume = 1.5 refused:", err.name);
    }
    info.textContent = `Length: ${tone.duration} s. Press play on the bar - fast, quiet, and on repeat.`;
  }

  if (tone.readyState >= 1) {
    showFacts();                                   // metadata already here
  } else {
    tone.addEventListener("loadedmetadata", showFacts);
  }
</script>

The first Console line runs at once: At once - duration: NaN | paused: true. A moment later the metadata arrives and showFacts runs: duration: 3 seconds; the defaults volume: 1 | muted: false | rate: 1 | loop: false; the new values volume: 0.5 | rate: 1.5 | loop: true; and finally volume = 1.5 refused: IndexSizeError, the error a browser throws for a volume outside 0 to 1. Press play on the bar: three assignments changed what the built-in player does.

Quick check: the very first line of a script logs video.duration and gets NaN. Why, and what should the script do instead?

The browser has not read the file's metadata yet, so it does not know the length. Read duration inside a loadedmetadata listener (or first check readyState >= 1).

63.4 Events: the player tells you what happened

Commands and properties let you ask. Events let the element tell. A media element fires events as things happen to it, and you listen with the same addEventListener you used for clicks in Chapter 57:

video.addEventListener("ended", () => {
  message.textContent = "Lecture finished - take the quiz!";
});

These are the events from the lecture slide, plus the four a custom player needs most (canplay, playing, seeking, seeked):

EventFires whenTypical use
loadedmetadataThe metadata has been read: duration (and a video's size) is knownShow the length; set the progress bar's maximum
canplayEnough has loaded to start playingHide "Loading…", enable the Play button
playPlayback has been asked to start: paused has just become falseMake the toggle button say "Pause"
playingPlayback has really begun, or carried on after waiting for dataHide a buffering spinner
pausePlayback has been paused — including at the end, just before endedMake the toggle button say "Play"
timeupdateThe position has changed: several times a second while playing (about four in Chrome), and after every seekMove the progress bar; update 0:42 / 3:15
seeking / seekedA jump to a new currentTime has begun / finishedShow "Loading…" during a long jump
volumechangevolume or muted has changedUpdate the mute button and the volume slider
endedPlayback has reached the end. Never fires when loop is onShow "Finished"; start the next track
errorThe file could not be loaded or playedShow a friendly message

play is the request; playing is the reality. On a fast connection they arrive together. On a slow one, play fires the instant you press the button, and playing only when the picture actually moves.

Four more facts that exams like:

  • At the natural end, pause fires first and then ended; afterwards both paused and ended are true.
  • With loop on, the element jumps back to 0 and keeps going, so ended never fires.
  • Unlike click, media events do not bubble up to parent elements. Add the listener to the audio or video element itself.
  • When an element's src fails, error fires on the element and element.error.code says why: 1 aborted, 2 network failure, 3 could not decode, 4 file missing or format not supported. (With several <source> children, a failing file fires error on that <source> instead.)

The best way to learn the order is to watch it. This logger listens for every event in the table and writes each one to the Console with the position at that moment. timeupdate is only counted on the page, because it would flood the Console.

<style>
  body { font-family: system-ui, sans-serif; padding: 14px; }
  button { padding: 6px 12px; margin-top: 8px; cursor: pointer; }
</style>
<audio id="player" controls preload="auto"></audio>
<p>timeupdate has fired <b id="ticks">0</b> times.</p>
<button id="breakBtn">Load a missing file</button>

<script>
  const player = document.getElementById("player");
  const ticks = document.getElementById("ticks");
  let count = 0;

  const names = ["loadedmetadata", "canplay", "play", "playing", "pause",
                 "seeking", "seeked", "volumechange", "ended"];

  // one listener per event name (forEach from Chapter 53)
  names.forEach((name) => {
    player.addEventListener(name, () => {
      console.log(`${name} (at ${player.currentTime.toFixed(2)} s)`);
    });
  });

  // timeupdate fires several times a second: count it, do not log it
  player.addEventListener("timeupdate", () => {
    count++;
    ticks.textContent = count;
  });

  player.addEventListener("error", () => {
    console.log("error - code", player.error.code);
  });

  document.getElementById("breakBtn").addEventListener("click", () => {
    player.src = "no-such-file.mp3";
  });

  // listeners first, THEN hand over the file, so no event can be missed
  player.src = "media/tone.wav";
</script>

Before you touch anything, the Console shows loadedmetadata (at 0.00 s) and canplay (at 0.00 s): the file has loaded. Press play on the bar: play, then playing, and the counter on the page climbs by about four a second. Drag the bar: seeking, then seeked (often followed by canplay and playing again, as it gets going from the new spot). Change the volume or mute: volumechange. Let it run out: pause (at 3.00 s) and then ended (at 3.00 s) — pause really does come first. Finally press Load a missing file: error - code 4, the code for "this file cannot be used".

Notice the last line of the script. The file is given to the player after the listeners are attached, so even the earliest event cannot slip past unheard.

Quick check: a music page sets audio.loop = true and shows "Song over" in an ended listener. When does the message appear?

Never. With loop on, the element jumps back to the start and keeps playing, so ended does not fire. To react to each repeat, listen for something else — for example seeked, which fires as it jumps back to the start.

63.5 Listen, don't keep checking

Suppose you want a time display that stays up to date. A tempting first idea is a timer from Chapter 54 that checks ten times a second:

// Polling: asking again and again - works, but wasteful
setInterval(() => {
  time.textContent = formatTime(video.currentTime);
  if (video.ended) message.textContent = "Finished";
}, 100);

This is called polling. It works, but it keeps asking for ever: while the video is paused, while the tab is hidden, long after the video has ended. It also reacts late, up to a tenth of a second behind, and a quick pause and resume between two checks is never seen at all. The event version asks nothing. The browser calls your function when — and only when — something has changed:

// Events: the browser calls you when something changes
video.addEventListener("timeupdate", () => {
  time.textContent = formatTime(video.currentTime);
});
video.addEventListener("ended", () => {
  message.textContent = "Finished";
});

Polling is walking back to the cooker every ten seconds to see if it is done. Events are waiting for the whistle. For media, use events. Keep setInterval for jobs that really are about clock time, such as the live clock in Chapter 62.

The same thinking settles a second question: where should the Play button's label change? Not in its own click handler. Playback can start or stop without your button ever being pressed: the native controls, a keyboard's media keys, the end of the file, another script, or a play() that the browser refused. So the click handler only sends the command, and the play and pause listeners change the screen, because they report what really happened.

63.6 Seconds to minutes: a time display

Players show time as 1:15, not 75.4. The conversion is the minutes-and-seconds sum from Chapter 44, plus the zero padding from Chapter 45:

function formatTime(seconds) {
  if (!Number.isFinite(seconds)) return "0:00";   // NaN or Infinity: nothing to show
  const m = Math.floor(seconds / 60);             // whole minutes
  const s = Math.floor(seconds % 60);             // seconds left over
  return `${m}:${String(s).padStart(2, "0")}`;    // 5 becomes "05"
}

Trace formatTime(75.4). 75.4 / 60 is 1.256…, rounded down to 1 minute. 75.4 % 60 is 15.4, rounded down to 15 seconds. String(15).padStart(2, "0") is "15", so the result is "1:15". For 125 seconds the leftover is 5, which padding turns into "05": "2:05", not the odd-looking "2:5".

The first line guards against the two values that are not ordinary numbers. Number.isFinite(x) is true only for a normal number, and false for NaN (a duration that is not known yet) and Infinity (a live stream). Without it, the display would read NaN:NaN for a moment on every page load.

Quick check: what does formatTime(61.9) return?

"1:01". Math.floor(61.9 / 60) is 1; 61.9 % 60 is 1.9, rounded down to 1, padded to "01".

63.7 Build it: a custom player anyone can use

First, a fair question: do you need custom controls at all? The native controls come with keyboard support, screen-reader labels, a captions menu and full screen, all tested by the browser makers. Keep them unless you need a look or a feature they lack. If you do build your own, they must be at least as usable as the ones you replaced:

  • Use real controls: <button>, <input type="range"> and <select>. Tab, Enter, Space and the arrow keys then work for free (Chapter 15). A <div> with a click listener works for nobody without a mouse.
  • Give every control an accessible name: visible text such as "Play", a <label>, or aria-label when nothing visible names it (the seek bar here; an icon-only ▶ button needs aria-label="Play").
  • Keep the name true. The toggle must say "Pause" while playing. Change it in the play and pause listeners, as 63.5 explained.
  • Keep the safety net. Write controls in the HTML and remove it from JavaScript with video.controls = false. If the script fails to load, the native controls are still there. Keep a visible focus outline, and keep your <track> captions.

This is the whole chapter in one player. The clip is a short, silent video, so the volume and mute show their effect in the Console and on the buttons rather than in your ears.

<style>

<script>
  const video   = document.getElementById("video");
  const seek    = document.getElementById("seek");
  const playBtn = document.getElementById("playBtn");
  const time    = document.getElementById("time");
  const muteBtn = document.getElementById("muteBtn");
  const vol     = document.getElementById("vol");
  const speed   = document.getElementById("speed");
  const msg     = document.getElementById("msg");

  video.controls = false;   // our controls take over; without JS the native ones stay

  function formatTime(seconds) {
    if (!Number.isFinite(seconds)) return "0:00";
    const m = Math.floor(seconds / 60);
    const s = Math.floor(seconds % 60);
    return `${m}:${String(s).padStart(2, "0")}`;
  }

  // ---- 1. The user acts: each control only sends a COMMAND ----
  playBtn.addEventListener("click", () => {
    if (video.paused) {
      video.play().catch((err) => { msg.textContent = "Could not play: " + err.name; });
    } else {
      video.pause();
    }
  });
  muteBtn.addEventListener("click", () => { video.muted = !video.muted; });
  vol.addEventListener("input", () => { video.volume = Number(vol.value); });
  speed.addEventListener("change", () => { video.playbackRate = Number(speed.value); });
  seek.addEventListener("input", () => { video.currentTime = Number(seek.value); });

  // ---- 2. The video reports: EVENTS update the screen ----
  function showTime() {
    time.textContent = `${formatTime(video.currentTime)} / ${formatTime(video.duration)}`;
    seek.value = video.currentTime;
  }
  function setUp() {
    seek.max = video.duration;          // the bar now spans the whole clip
    showTime();
    console.log("Ready - length", formatTime(video.duration));
  }
  if (video.readyState >= 1) setUp();
  else video.addEventListener("loadedmetadata", setUp);

  video.addEventListener("timeupdate", showTime);
  video.addEventListener("play", () => {
    playBtn.textContent = "Pause";
    msg.textContent = "";
    console.log("play");
  });
  video.addEventListener("pause", () => {
    playBtn.textContent = "Play";
    console.log("pause");
  });
  video.addEventListener("ended", () => {
    msg.textContent = "Finished - press Play to watch again.";
    console.log("ended");
  });
  video.addEventListener("volumechange", () => {
    muteBtn.textContent = video.muted ? "Unmute" : "Mute";
    vol.value = video.volume;
    console.log("volume", video.volume, "| muted", video.muted);
  });
  video.addEventListener("error", () => {
    msg.textContent = "Sorry, the video could not be loaded.";
  });
</script>

Every control works from the keyboard, and a screen reader would announce "Seek, slider", "Play, button", "Volume, slider", because each has a name. You wrote no extra code for any of that — it came from choosing real controls.

63.8 Common misunderstandings

✗ "There is a stop() method."
Calling it throws a TypeError.
✓ "Stop = pause() + currentTime = 0."
pause() alone keeps the position, like a bookmark.
✗ "I can read duration as soon as the page loads."
The script usually runs before the file's metadata has arrived, and gets NaN.
✓ "duration is ready after loadedmetadata."
Listen for it, or check readyState >= 1 first. Guard the display with Number.isFinite.
✗ "play() always starts the sound straight away."
It is a request, and the browser may refuse it.
✓ "play() returns a Promise: .then if it starts, .catch if it is refused."
Sound needs a user gesture first (NotAllowedError otherwise); muted media may start by itself.
✗ "muted = true is the same as volume = 0."
They are two dials; muting does not touch volume.
✓ "Muting remembers the volume, so un-muting restores it."
And volume must stay between 0 and 1, or the browser throws an error.
✗ "ended fires whenever the video stops."
A pause fires pause, not ended.
✓ "ended fires only at the real end, right after pause — and never when loop is on."
✗ "A setInterval that checks currentTime keeps the display up to date."
It works, but it runs for ever and still reacts late.
✓ "Update the screen from events: timeupdate, play, pause, volumechange, ended."
The browser calls you exactly when something changes.

Exam-style checks

Answer each one before opening it. Most have four options and exactly one correct answer; three ask you to predict or explain.

The page has const v = document.getElementById("videoPlayer");. Which line starts playback?L1
  • A. v.start();
  • B. v.run();
  • C. v.play();
  • D. v.begin();

Answer: C. play() is the media element's method for starting; its partner is pause(). The other names do not exist, so calling them throws a TypeError.

What does audio.play() give back?L2
  • A. A Promise that settles when playback starts or is refused
  • B. true if playback started, false if not
  • C. undefined, like pause()
  • D. The duration in seconds

Answer: A. Playback may need loading time and may be blocked, so the answer comes later: .then runs if it starts, .catch if it is refused. C is true of pause(), which is why it tempts.

Before reading a correct duration, which event must have fired?L2
  • A. ended
  • B. timeupdate
  • C. volumechange
  • D. loadedmetadata

Answer: D. The length is part of the file's metadata. Before loadedmetadata, duration is NaN.

What does this print? const a = document.createElement("audio"); console.log(a.duration, a.paused, a.volume, a.muted);L3

Answer: NaN true 1 false. There is no file, so the length is unknown (NaN); a new element is not playing (paused is true); the default volume is full (1); and it is not muted.

A Stop button must halt the video and return it to the beginning. Which code does that?L3
  • A. video.stop();
  • B. video.pause(); video.currentTime = 0;
  • C. video.currentTime = video.duration;
  • D. video.ended = true;

Answer: B. There is no stop() (A throws a TypeError). C jumps to the end instead of the start, and D does nothing useful because ended is read only.

Which event fires again and again during playback, and is the one to use for moving a progress bar?L2
  • A. timeupdate
  • B. play
  • C. playing
  • D. seeked

Answer: A. timeupdate fires about four times a second while playing, and after every seek. play and playing fire once when playback begins; seeked only after a jump.

What happens when audio.volume = 1.5; runs?L3
  • A. It plays at 150% loudness
  • B. The volume is quietly set to 1
  • C. The audio is muted
  • D. An error (IndexSizeError) is thrown and the volume is unchanged

Answer: D. volume only accepts 0 to 1. B is what many people expect, but browsers throw instead of correcting the value; a slider with min="0" max="1" keeps you safe.

A video has loop switched on. What happens when it reaches the end?L3
  • A. ended fires, then it starts again
  • B. It jumps back to the start and plays on; ended does not fire
  • C. It pauses and waits for the user
  • D. It throws an error

Answer: B. With loop on, the element never reaches the "ended" state, so ended never fires and paused stays false.

A script calls audio.play() as the page loads, for a file with sound, and the .catch logs NotAllowedError. What is the most likely reason?L2
  • A. The file is missing
  • B. play() must be called twice
  • C. The browser's autoplay policy: sound may only start after a user gesture
  • D. The element has no controls attribute

Answer: C. Move the call into a click listener, or mute the media. A missing file gives NotSupportedError or an error event instead; controls has nothing to do with it.

How is muted = true different from volume = 0?L2

Answer: they are separate properties. Muting silences the media but leaves volume as it was, so un-muting brings the same loudness back; setting volume to 0 throws the old value away. Both changes fire volumechange.

Using the chapter's formatTime, what does this print? console.log(formatTime(125), formatTime(59.99));L3

Answer: 2:05 0:59. 125 is 2 minutes with 5 left over, padded to "05". 59.99 is 0 minutes and 59.99 seconds, which Math.floor rounds down to 59.

In a custom player, why should the Play/Pause button's label be changed in the play and pause listeners rather than in the button's click handler?L3
  • A. A click handler is not allowed to change text
  • B. Events run faster than clicks
  • C. The play event fires before the click
  • D. Playback can start or stop without that button — native controls, media keys, the end of the file, a refused play() — and the events report what really happened

Answer: D. The click only sends a request, which might be refused; the events describe the real state. A, B and C are simply false.

Quick revision

Key takeaways

  1. <audio> and <video> share one JavaScript toolkit (HTMLMediaElement): commands (methods), readings and dials (properties) and announcements (events).
  2. play() returns a Promise; sound may only start after a user gesture, or when muted. Always add .catch. pause() keeps the position; to stop, pause and set currentTime = 0.
  3. currentTime is in seconds and setting it seeks; duration is NaN until loadedmetadata; paused and ended are read only; volume runs from 0 to 1; muted, playbackRate and loop are dials.
  4. The events: loadedmetadata, canplay, play, playing, pause, timeupdate (about four a second), seeking/seeked, volumechange, ended (after pause; never with loop) and error. They do not bubble.
  5. Update the screen from events, not from a polling timer and not from your own click handlers.
  6. m:ss = Math.floor(s / 60), then Math.floor(s % 60) padded with padStart(2, "0"); guard NaN with Number.isFinite.
  7. Accessible custom controls: real buttons, ranges and selects; a name for each (text, label or aria-label); labels that stay true; a visible focus outline; captions kept; controls in HTML, removed by JavaScript.
