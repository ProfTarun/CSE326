Conditional Statements

Until now every line of your programs has run, top to bottom, every time. Real programs choose: pass or fail, let in or turn away, the weekday timetable or the weekend one. This chapter teaches the statements that let JavaScript choose — if, else, else if, switch and the ternary operator — how to pick the right one for a job, and the handful of small slips that make a decision go quietly wrong.

Before you start — one-line reminders

  • A comparison such as marks >= 40 or day === "Sun" works out to true or false (Chapter 44).
  • && is true only when both sides are true, || when at least one is, and ! flips a value (Chapter 44).
  • One = stores a value; three, ===, compare without converting types (Chapter 44).
  • The falsy values are false, 0, -0, 0n, "", null, undefined and NaN; every other value is truthy (Chapter 46).

  • Choose sensibly between an if ladder, a switch and the ternary operator.
  • Predict what a non-boolean value such as "", 0 or "0" does as a condition.
  • Say what break and continue do inside a loop.

47.1 The if statement: run this only when…

Every program you have written so far is a straight road. JavaScript starts at the first line, runs it, moves to the next, and carries on until the last. The order in which lines actually run is called the control flow, and so far it has never changed.

Real programs need forks in the road. Show the certificate only if the student passed. Let a user in only if the password matches. Charge delivery only if the order is under ₹500. A conditional statement runs some code only when a condition is true. The simplest one is if. Here is the example from your lecture slides:

let age = 20;

if (age >= 18) {
  console.log("You are eligible to vote.");
}

It has three parts, and you will write them thousands of times:

  • The keyword if.
  • A condition inside round brackets: (age >= 18). The brackets are compulsory.
  • A block inside curly braces: the statements to run when the condition is true.

When JavaScript reaches the if, it works out the condition. age >= 18 is 20 >= 18, which is true, so the block runs and the message is printed. If age were 15, the condition would be false, the whole block would be skipped, and JavaScript would carry on with whatever comes after the closing brace. Either way the program does not stop. An if decides only whether its own block runs.

An if is a question followed by a job. Is age at least 18? If yes, print the message. If the answer is no, the job is skipped and the program simply moves on to the next line after the closing brace.

Always write the braces. The indenting inside a block is for human eyes; JavaScript ignores it, and only the braces decide which lines belong to the if. You may leave them out for a single statement, as in if (age >= 18) console.log("Adult");, but then only that one statement belongs to the if, and a second indented line added later runs every time. Braces cost two characters and make the boundary impossible to miss.

47.2 if...else: one of two roads

An if on its own either does something or does nothing. Often you want a choice between two jobs: print "Pass" or print "Fail". Add the keyword else and a second block, as slide 43 does:

let marks = 35;

if (marks >= 40) {
  console.log("Pass");
} else {
  console.log("Fail");
}

35 >= 40 is false, so the first block is skipped and the else block runs: the output is Fail. The else has no condition of its own. It means "in every other case", and it must follow the if's block directly: no other statement may sit between that closing brace and the word else.

The property that matters: exactly one of the two blocks runs. Never both, never neither. Each possible road through a decision is called a branch.

Picture this. At a railway junction the pointsman sets the points before the train arrives. The train then goes down the left track or the right track — never both, and never neither — and a little further on the two tracks join again and the journey continues. An if...else is a set of points. The condition sets them, the program goes down exactly one branch, and after the closing brace both branches rejoin the main line. The else if ladder, coming next, is a row of junctions: the train takes the first turning set for it.
<p>Press Run, then read the Console panel below.</p>
<script>
  // slide 42: an if on its own
  let age = 20;
  if (age >= 18) {
    console.log("You are eligible to vote.");
  }
  console.log("Age check finished.");      // runs either way

  // slide 43: if...else - exactly one of the two blocks runs
  let marks = 35;
  if (marks >= 40) {
    console.log("Pass");
  } else {
    console.log("Fail");
  }
  console.log("Result check finished.");   // runs either way
</script>

Change age to 15 and the first message disappears, while Age check finished. still prints: it sits outside the braces.

Quick check: with let marks = 40;, does the slide's code print Pass or Fail?

Pass. 40 >= 40 is true, because >= means "greater than or equal to". Had the rule been written marks > 40, a mark of exactly 40 would fail. The boundary value is where decisions most often go wrong, so always test it.

47.3 else if: choosing from many

Grades need more than two roads. An else if ladder checks one condition after another. This is slide 44:

let marks = 85;

if (marks >= 90) {
  console.log("Grade A+");
} else if (marks >= 75) {
  console.log("Grade A");
} else if (marks >= 60) {
  console.log("Grade B");
} else {
  console.log("Needs Improvement");
}

One rule explains every ladder: JavaScript checks the conditions from the top, runs the block of the first one that is true, and skips everything else. Trace it with 85:

  1. 85 >= 90? False. Move down to the next rung.
  2. 85 >= 75? True. Print Grade A.
  3. Stop. The marks >= 60 check is never even made, although 85 is also at least 60, and the else is skipped.

The final else catches whatever fell past every check: here, any mark below 60. It is optional. Without it, a mark below 60 would simply print nothing.

Key idea. Each rung already knows the answers above it. When JavaScript asks marks >= 75, the mark must be below 90, or the first rung would have caught it. So this rung means "75 to 89" without anyone writing marks < 90.

The order of the rungs is part of the logic

Because the first true condition wins, the order you write the rungs in changes the answer. Put the widest condition first and it swallows everything:

let marks = 95;

if (marks >= 60) {             // 95 >= 60 is true, so this wins...
  console.log("Grade B");
} else if (marks >= 75) {      // ...and these can never be reached
  console.log("Grade A");
} else if (marks >= 90) {
  console.log("Grade A+");
}

A topper with 95 is told "Grade B". Worse, no mark can ever reach the Grade A or Grade A+ branches, because every mark of 75 or more is also 60 or more and the first rung takes it. Branches like these are unreachable. JavaScript gives no warning; the program just hands out wrong grades.

In a ladder, the first "yes" wins and the later questions are never asked. So ask the hardest question to pass first: 90 or more? Then 75 or more? Then 60 or more? Ask "60 or more?" first and nearly everyone says yes, and the questions after it are wasted.

The rule: check the narrowest condition first and the widest last. With >= that means the highest threshold at the top; with < it would mean the lowest. Then test the edges, not just one comfortable middle value: try 90 and 89, 75 and 74, 60 and 59.

<p>Press Run, then read the Console panel below.</p>
<script>
  let marks = 95;

  // slide 44: highest threshold first - correct
  if (marks >= 90) {
    console.log("Right order: Grade A+");
  } else if (marks >= 75) {
    console.log("Right order: Grade A");
  } else if (marks >= 60) {
    console.log("Right order: Grade B");
  } else {
    console.log("Right order: Needs Improvement");
  }

  // the same rungs, widest first - wrong
  if (marks >= 60) {
    console.log("Wrong order: Grade B");
  } else if (marks >= 75) {
    console.log("Wrong order: Grade A");      // unreachable
  } else if (marks >= 90) {
    console.log("Wrong order: Grade A+");     // unreachable
  } else {
    console.log("Wrong order: Needs Improvement");
  }
</script>

With 95 it prints Right order: Grade A+ and Wrong order: Grade B. Try 59 too: below 60 both ladders agree, which is how a bug like this survives a quick test.

47.4 Combining conditions and nesting decisions

Often one comparison is not enough. A student may sit the end-term exam only if attendance is at least 75% and the fees are paid. Join the two comparisons with && and put the whole thing inside the brackets:

let attendance = 82;
let feesPaid = true;

if (attendance >= 75 && feesPaid) {
  console.log("Hall ticket issued");
} else {
  console.log("Not eligible");
}

feesPaid already holds true or false, so it needs no === true. Use || when any one condition is enough, as in if (day === "Sat" || day === "Sun"), and ! to turn one round: if (!feesPaid). A range still needs two comparisons: if (marks >= 0 && marks <= 100).

A decision inside a decision

The else above says "Not eligible" but not why. To give a different message for each reason, put one decision inside a block of another. That is a nested if:

if (feesPaid) {
  if (attendance >= 75) {
    console.log("Hall ticket issued");
  } else {
    console.log("Attendance below 75%");
  }
} else {
  console.log("Please pay your fees first");
}

The inner if is reached only when the outer condition is true. Read nested code from the outside in, and use the braces to see which else belongs to which if: each else comes straight after the closing brace of its own if block.

Key idea. if (a) { if (b) { ... } }, with no else anywhere, does exactly the same as if (a && b) { ... }. Prefer the flat && version. Nest only when the levels need their own else messages, as the hall-ticket check does. Two levels are fine; at three or four, readers lose track, and Section 47.8 shows a cleaner shape.
<style>
  body { font-family: system-ui, sans-serif; padding: 14px; }
  #ticket { padding: 10px 14px; border-radius: 10px; background: #F1F5F9; font-weight: 700; }
</style>

<script>
  const student = "Rahul";
  let attendance = 68;
  let feesPaid = true;

  // flat: one combined condition, one yes-or-no answer
  if (attendance >= 75 && feesPaid) {
    console.log("Combined check: eligible");
  } else {
    console.log("Combined check: not eligible");
  }

  // nested: a different message for each reason
  let message;              // declared BEFORE the decision, so it outlives the blocks
  if (feesPaid) {
    if (attendance >= 75) {
      message = `${student}: hall ticket issued`;
    } else {
      message = `${student}: attendance ${attendance}% is below 75%`;
    }
  } else {
    message = `${student}: please pay your fees first`;
  }
  console.log("Nested check:", message);

  // write it onto the page too (changing the page is taught in Chapter 56)
  document.getElementById("ticket").textContent = message;
</script>

It prints Combined check: not eligible and Nested check: Rahul: attendance 68% is below 75%. message is declared before the decision and only assigned inside it, because a let created inside a block disappears at that block's closing brace (Chapter 49).

47.5 switch: one value, many exact matches

Some decisions compare one value against a list of fixed possibilities. Turning a day number into a day name is the classic case: 0 is Sunday, 1 is Monday, and so on up to 6 for Saturday (JavaScript's own dates number the days this way, as Chapter 62 shows). An else if ladder could do it with seven dayNumber === ... checks, but switch says it more directly:

let dayNumber = 3;
let dayName;

switch (dayNumber) {
  case 0:
    dayName = "Sunday";
    break;
  case 1:
    dayName = "Monday";
    break;
  case 2:
    dayName = "Tuesday";
    break;
  case 3:
    dayName = "Wednesday";
    break;
  // ... cases 4, 5 and 6 in the same way ...
  default:
    dayName = "Not a day number";
}

console.log(dayName);   // Wednesday

How it runs, step by step:

  1. The expression in the brackets, dayNumber, is worked out once. It is 3.
  2. That value is compared with each case value in turn, using strict equality, ===. 3 === 0? No. 3 === 1? No. 3 === 2? No. 3 === 3? Yes.
  3. JavaScript jumps in at the matching case and runs its statements: dayName = "Wednesday".
  4. break jumps out of the whole switch, to the first line after its closing brace.
  5. If no case matches, the default part runs instead. Like a final else, default is optional. It is usually written last, where it needs no break.

Notice the punctuation: each case value is followed by a colon, and the statements under a case need no braces of their own.

switch never converts types. Because it compares with ===, the string "3" does not match case 3:. Everything typed into a form box or a prompt() is a string (Chapter 44), so switch (typed) with number cases quietly falls to default every time. Convert first: switch (Number(typed)).

Fall-through: what break is really for

Step 4 hides the most famous trap in switch. A case does not stop by itself when the next case label arrives; only break stops it. Leave the break out and JavaScript keeps going into the next case's statements, without checking that case's value at all, and carries on until it meets a break or the end of the switch. This is called fall-through.

let dayNumber = 1;

switch (dayNumber) {
  case 1:
    console.log("Monday");
  case 2:
    console.log("Tuesday");
  case 3:
    console.log("Wednesday");
    break;
  case 4:
    console.log("Thursday");
}
// prints Monday, Tuesday, Wednesday - and then the break stops it

A switch finds the first case whose value matches exactly and starts running there. It then keeps running, straight down the page, until it reaches a break. The case labels below the match are not checked again; they are just signposts it walks past.

Fall-through is not always a bug. When several values should share one job, stack their cases with nothing between them, and every stacked case falls into the shared statements:

switch (dayNumber) {
  case 0:
  case 6:
    console.log("Weekend: no classes");
    break;
  case 1:
  case 2:
  case 3:
  case 4:
  case 5:
    console.log("Weekday: check your timetable");
    break;
  default:
    console.log("Not a day number");
}

If you ever let a case that has statements fall into the next one on purpose, add a comment such as // falls through, so nobody "fixes" it later with a break.

Exam tip. For a predict-the-output question on switch, find the first case that matches with === (or default, if none does), then read straight down from there, printing everything you pass, until the first break or the closing brace.
<p>Press Run, then read the Console panel below.</p>
<script>
  let dayNumber = 3;

  // 1. one case per value, each ending with break (short cases fit on one line)
  let dayName;
  switch (dayNumber) {
    case 0: dayName = "Sunday"; break;
    case 1: dayName = "Monday"; break;
    case 2: dayName = "Tuesday"; break;
    case 3: dayName = "Wednesday"; break;
    case 4: dayName = "Thursday"; break;
    case 5: dayName = "Friday"; break;
    case 6: dayName = "Saturday"; break;
    default: dayName = "Not a day number";
  }
  console.log("Day name:", dayName);

  // 2. deliberate fall-through: stacked cases share one job
  switch (dayNumber) {
    case 0:
    case 6:
      console.log("Weekend: no classes");
      break;
    case 1:
    case 2:
    case 3:
    case 4:
    case 5:
      console.log("Weekday: check your timetable");
      break;
    default:
      console.log("Cannot tell");
  }

  // 3. the bug: no break anywhere, so everything below the match runs
  switch (dayNumber) {
    case 3:
      console.log("Forgot break - case 3");
    case 4:
      console.log("Forgot break - case 4");
    default:
      console.log("Forgot break - default");
  }
</script>

With 3 it prints Day name: Wednesday, the weekday line and all three Forgot break lines. Now try "3", with the quotes: all three switches fall to default, because a string never matches a number case.

Quick check: in the third switch above, what is printed when dayNumber is 4?

Two lines: Forgot break - case 4 and then Forgot break - default. The switch jumps in at case 4 and, with no break, falls through into default. Case 3's line is above the match, so it never runs.

47.6 The ternary operator, and choosing the right tool

Chapter 44 introduced the only operator with three operands:

condition ? valueIfTrue : valueIfFalse

Here is a job done first with if...else, which needs a variable and two assignments:

let result;
if (marks >= 40) {
  result = "Pass";
} else {
  result = "Fail";
}

and here is the same job with the ternary, in one line:

const result = marks >= 40 ? "Pass" : "Fail";

Read ? as "then" and : as "otherwise". An if is a statement: it does things. The ternary is an expression (Chapter 44): it produces a value, so it can sit anywhere a value can, even inside a template literal, and the variable can be a const.

const count = 1;
console.log(`You have ${count} new ${count === 1 ? "message" : "messages"}`);
// You have 1 new message
Use it to choose a value, not to do a job. marks >= 40 ? console.log("Pass") : console.log("Fail"); works, but it is an if...else in disguise; write the if. Avoid nesting ternaries too: m >= 90 ? "A+" : m >= 75 ? "A" : "B" is legal, yet an else if ladder says the same thing in a way nobody misreads.

Which one should I use?

SituationBest toolExample
Do something, or nothingifShow a warning when attendance is below 75%
Choose between two jobsif...elsePrint a pass notice or a fail notice
Ranges, or conditions on different variableselse if ladderGrades from marks; eligibility from fees and attendance
One value against many fixed valuesswitchDay name from a number; a menu choice 1 to 4
Pick one of two values inside an expressionternary ? :"message" or "messages"

The deciding question for switch is: is every check "is this one value exactly equal to that"? If yes, a switch reads well. If any check is a range, uses &&, or looks at a second variable, use if. Each case asks only "exactly equal?", so a switch on marks has no way to say "75 or more".

47.7 Truthy and falsy conditions

The condition of an if does not have to be a comparison. It can be any expression, and JavaScript turns its value into true or false by exactly the rules of Boolean() from Chapter 46. The values that count as false are called falsy, and the list is short enough to learn by heart:

false    0    -0    0n    ""    null    undefined    NaN

Every other value is truthy. That makes some conditions very short. Here if (typedName) reads "if a name was typed":

let typedName = "";

if (typedName) {
  console.log(`Welcome, ${typedName}`);
} else {
  console.log("Please enter your name");   // this runs: "" is falsy
}

Two surprises live on the truthy side. The strings "0" and "false" are truthy, because they are not empty: only the empty string is falsy. And a string holding just a space, " ", is truthy too, so trim typed text first (Chapter 45) if a box full of spaces should count as empty.

0 is falsy, even when 0 is a real answer. if (marks) looks like "if marks were entered", but a student who scored 0 fails that test and is treated as if nothing was entered at all. When 0, "" or false can be a genuine value, say exactly what you mean: if (marks !== undefined), or if (typeof marks === "number").

Putting a value straight into an if asks "is there something here?" Eight values answer no: false, the zeros, the empty string, null, undefined and NaN. Everything else answers yes. That is handy for names and dangerous for numbers, because a real mark of 0 also answers no.

  body { font-family: system-ui, sans-serif; padding: 14px; }

</style>

<script>
  // Boolean() applies exactly the test that an if uses
  console.log('Boolean(""):', Boolean(""));        // false
  console.log('Boolean(" "):', Boolean(" "));      // true  - a space is something
  console.log('Boolean("0"):', Boolean("0"));      // true  - a non-empty string
  console.log("Boolean(0):", Boolean(0));          // false

Set typedName to " " and the banner asks you to log in: trim() leaves an empty string, which is falsy. The last two lines show the 0 trap and its cure.

Quick check: does if ("false") { console.log("yes"); } print yes?

Yes. "false" is a five-letter, non-empty string, so it is truthy. Only the boolean value false, written without quotes, is falsy.

47.8 Guard clauses: deal with the odd cases first

Nesting grows quickly. Check that marks are a number, then that they lie between 0 and 100, then grade them, and the code drifts further right with every check:

if (typeof marks === "number") {
  if (marks >= 0 && marks <= 100) {
    if (marks >= 90) {
      grade = "A+";
    } else if (marks >= 75) {
      grade = "A";
    } else {
      grade = "B or below";
    }
  } else {
    grade = "Out of range";
  }
} else {
  grade = "Invalid marks";
}

The message for the very first check ends up at the very bottom, far from the check that caused it. Experienced programmers turn the shape inside out with guard clauses: handle each bad case first and leave at once, so the main work needs no nesting at all.

Leaving early needs a function, which Chapter 48 teaches properly. Two facts are enough for now. A function is a named block of code that runs when you call its name with brackets, such as gradeFor(85); the value in the brackets arrives inside it as marks. And return hands a value back to whoever called the function and leaves the function on the spot: no later line of it runs.

function gradeFor(marks) {
  if (typeof marks !== "number" || Number.isNaN(marks)) {
    return "Invalid marks";      // guard 1: not a usable number
  }
  if (marks < 0 || marks > 100) {
    return "Out of range";       // guard 2: impossible marks
  }
  if (marks >= 90) {
    return "A+";
  }
  if (marks >= 75) {
    return "A";
  }
  if (marks >= 60) {
    return "B";
  }
  return "Needs Improvement";
}

Every check now sits next to its own answer, and there is no else anywhere. None is needed: once a return has run, the function has already left, so each later if is reached only by marks that every earlier check let through. The first guard needs Number.isNaN because typeof NaN is "number" (Chapter 46).

47.9 break and continue: a first look inside loops

Your slides finish this topic with two statements that belong mostly to loops. A loop repeats a block; Chapter 52 teaches loops in full, and here you only need to read one line. for (let i = 1; i <= 5; i++) { ... } means: start i at 1; while i is at most 5, run the block; after each run, add 1 to i. So the block runs five times, with i equal to 1, 2, 3, 4 and 5 in turn.

Inside a loop, an if can change that plan:

  • break ends the whole loop at once. It is the same word that leaves a switch.
  • continue skips only the rest of the current round, and goes straight on to the next round.
<p>Press Run, then read the Console panel below.</p>
<script>
  // slide 45: break ends the whole loop
  for (let i = 1; i <= 5; i++) {
    if (i === 3) {
      break;
    }
    console.log("break loop:", i);
  }
  console.log("break loop finished");

  // slide 46: continue skips just one round
  for (let i = 1; i <= 5; i++) {
    if (i === 3) {
      continue;
    }
    console.log("continue loop:", i);
  }
  console.log("continue loop finished");
</script>

Trace the first loop. At 1 and 2 the condition is false and the number is printed. At 3, break runs before the console.log line, and the loop is over: rounds 4 and 5 never happen. In the second loop, continue skips only round 3's console.log, so it prints 1, 2, 4 and 5, exactly as slide 46 says.

Slide 47 sums up the whole topic:

StatementPurpose
ifRuns code when a condition is true
if...elseChooses between two alternatives
else ifChecks several conditions in order; the first true one wins
switchMatches one value against fixed cases
breakEnds a loop, or leaves a switch, immediately
continueSkips the rest of the current loop round

In short, conditional statements make the decisions, while break and continue steer a loop that is already running.

Quick check: in the break loop, change i === 3 to i === 1. What is printed?

Only break loop finished. In the very first round i === 1 is true, so break ends the loop before any number is printed. The line after the loop still runs.

47.10 Common misunderstandings

✗ "if (marks = 100) checks whether marks is 100."
One = stores 100 in marks. The assignment's value is 100, which is truthy, so the block always runs — and the real mark is lost.
✓ "if (marks === 100) compares."
Three equals signs ask a question; one sets a value. JavaScript will not warn you, because both are legal.
✗ "A semicolon after the brackets is harmless."
In if (age >= 18); the semicolon is an empty statement, and it becomes the entire body of the if. The braces after it are just a block that runs every time.
✓ "No semicolon between ) and {."
A semicolon goes after a complete statement, never between an if's condition and its block.
✗ "Indenting a line puts it inside the if."
JavaScript ignores indentation. Without braces, only the first statement belongs to the if: 
if (age >= 18)
  console.log("Adult");
  console.log("You may vote");  // runs for every age
✓ "The braces decide what is inside."
Write { } on every if, else and else if, even for one line.
✗ "The conditions of an else if ladder can go in any order."
The first true condition wins. Put the widest one first and the branches below it become unreachable.
✓ "Narrowest first."
With >=, the highest threshold goes at the top. Then test the boundary values.
✗ "Each case stops by itself when the next case begins."
Without break, execution falls through into the next case's statements, without checking its value.
✓ "End every case with break"
— unless it is an empty case stacked on purpose so that several values share one job.
✗ "case 3: also matches the typed text "3"."
switch compares with ===, so a string never matches a number.
✓ "Convert typed input first."
switch (Number(typed)) turns "3" into 3 before the matching starts.

Exam-style checks

Answer each one before opening it. Most are four-option questions with exactly one correct answer; the others ask you to predict the output and explain it.

Which statement runs one block when its condition is true and a different block when it is false?L1
  • A. if on its own
  • B. continue
  • C. if...else
  • D. break

Answer: C. if...else chooses between two alternatives, and exactly one of its blocks runs. A plain if either runs its one block or does nothing; break and continue steer loops.

What does this print? let marks = 85; if (marks >= 90) { console.log("A+"); } else if (marks >= 75) { console.log("A"); } else if (marks >= 60) { console.log("B"); } else { console.log("C"); }L2
  • A. A
  • B. A+
  • C. A, then B
  • D. C

Answer: A. 85 fails the first check and passes the second, so A is printed and the ladder ends. C is tempting because 85 is also at least 60, but only the first true branch runs.

What does this print, and why can "Distinction" never be printed? let marks = 92; if (marks >= 40) { console.log("Pass"); } else if (marks >= 90) { console.log("Distinction"); }L3

Answer: it prints Pass. Every mark of 90 or more is also 40 or more, so the first rung catches it and the second branch is unreachable for every possible mark. The fix is to put the narrower check first: test marks >= 90, then else if (marks >= 40).

What does this print? let d = 2; switch (d) { case 1: console.log("One"); case 2: console.log("Two"); case 3: console.log("Three"); break; default: console.log("Other"); }L3
  • A. Two
  • B. One, Two, Three
  • C. Two, Three, Other
  • D. Two, Three

Answer: D. The switch jumps in at case 2, falls through into case 3 because there is no break, and case 3's break leaves before default. case 1 is above the match, so it never runs.

How does a switch compare its value with each case?L2
  • A. With loose equality, ==, converting types first
  • B. With strict equality, ===, so "3" does not match case 3
  • C. By turning both values into strings
  • D. With >=, so a case can be a range

Answer: B. Matching is strict and never converts types. That is why typed input, which is always a string, must be converted with Number() before it is switched on number cases.

What does this print, and what is the bug? let marks = 35; if (marks = 100) { console.log("Full marks!"); } console.log(marks);L3

Answer: Full marks!, then 100. The single = stores 100 in marks, and the assignment's value, 100, is truthy, so the block runs and the real 35 is lost. With if (marks === 100) it would print only 35.

Which value makes if (value) { ... } run its block?L2
  • A. 0
  • B. ""
  • C. NaN
  • D. "0"

Answer: D. "0" is a non-empty string, so it is truthy. The number 0, the empty string and NaN are all on the falsy list.

What does this print? const age = 16; const msg = age >= 18 ? "Adult" : "Minor"; console.log(msg);L2
  • A. Adult
  • B. Minor
  • C. false
  • D. undefined

Answer: B. 16 >= 18 is false, so the ternary produces the value after the colon. It returns one of the two values, not the true or false of the condition, which rules out C.

In a switch, when do the statements under default run?L1
  • A. When no case matches, or when a matching case above it falls through into it
  • B. Always, after the matching case has finished
  • C. Only when the value being switched on is 0
  • D. Never, unless it is the first label in the switch

Answer: A. default is the "no match" branch, like a final else, though fall-through can also carry execution into it (the third switch in Section 47.5).

What does this print? for (let i = 1; i <= 5; i++) { if (i === 4) { break; } console.log(i); }L3
  • A. 1 2 3 4
  • B. 4 5
  • C. 1 2 3
  • D. 1 2 3 5

Answer: C. At i === 4, break runs before the console.log and ends the whole loop, so neither 4 nor 5 is printed. D is what continue in place of break would print.

Predict the output: let age = 12; if (age >= 18); { console.log("Adult"); }L3

Answer: Adult. The semicolon after the condition is an empty statement, and it is the whole body of the if. The braces that follow are an ordinary block that runs for every age. Delete the semicolon.

Which task is the poorest fit for a switch statement?L2
  • A. Turning a day number 0–6 into a day name
  • B. Acting on a menu choice of 1, 2, 3 or 4
  • C. Choosing a message for the traffic-light colours "red", "amber" and "green"
  • D. Giving a grade from marks: 90 or more is A+, 75 or more is A

Answer: D. Grades depend on ranges (>=), and a case can only ask "exactly equal?", so grades need an else if ladder. The other three compare one value with a few fixed values, which is what switch is for.

Quick revision

Key takeaways

  1. if (condition) { ... } runs the block only when the condition is true; either way the program carries on after the closing brace. Always write the braces.
  2. if...else runs exactly one of two blocks. An else if ladder checks from the top and runs only the first true branch; the final else catches the rest.
  3. In a ladder the order is part of the logic: narrowest condition first (with >=, the highest threshold first), or later branches become unreachable. Test the boundary values.
  4. Combine conditions with &&, || and !. Nest only when each level needs its own else; if (a) { if (b) { ... } } with no else is just if (a && b).
  5. switch matches one value against fixed cases using ===. break leaves the switch; without it, execution falls through into the next case. default runs when nothing matches.
  6. The ternary condition ? a : b chooses a value inside an expression. Use if for actions, and switch only for exact matches.
  7. Any value can be a condition. false, 0, -0, 0n, "", null, undefined and NaN are falsy; "0", "false" and " " are truthy. Beware if (marks) when 0 is a real mark.
  8. Guard clauses handle bad cases first and return early. In loops, break ends the loop and continue skips to the next round.
