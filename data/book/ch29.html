Positioning Techniques

So far every box has gone exactly where the browser put it. This chapter is about taking control: nudging an element, pinning a badge to the corner of a card, keeping a header visible while the page scrolls, and deciding what sits on top when two things overlap.

About 24 minutes · Course outcome CO3

Before you start — one-line reminders

  • Every element is a box with content, padding, border and margin (Chapter 28).
  • Block elements take a whole line; inline elements sit inside a line of text (Chapter 5).
  • The parent is the element yours sits inside; an ancestor is any element further out (Chapter 3).

By the end of this chapter you can

  • Describe normal flow, and change it with display.
  • Use all five values of position and say what each one is measured against.
  • Explain why an absolutely positioned box sometimes flies to the wrong corner.
  • Make a sticky header, and know the one declaration people forget.
  • Control what overlaps what with z-index.

29.1 Normal flow: what happens when you do nothing

With no positioning at all, the browser lays out a page in normal flow, which is a very simple rule:

  • Block elements stack downwards, each on its own line, each as wide as its parent allows.
  • Inline elements sit side by side within a line, wrapping to the next line when they run out of room, exactly like words in a sentence.

Normal flow is not a limitation to escape from. It is what makes a page reflow sensibly on a phone. Most good layouts stay in normal flow and use Flexbox or Grid (Chapters 30 and 31); positioning is for the few things that genuinely need to sit somewhere specific.

display: changing what kind of box an element is

ValueEffectUse for
blockOwn line, full width, accepts width and heightMaking a link fill a menu row
inlineSits in the line; ignores width and heightWords inside a sentence
inline-blockSits in the line and accepts width, height and vertical paddingButtons, tags, nav items
noneRemoved completely — no box, no spaceHiding a mobile menu
flex, gridTurns the element into a layout containerChapters 30 and 31
 
<style>
  span { background: #FFF1E0; border: 2px solid #E07B1E; padding: 10px;
         width: 180px; }
  .b  { display: block; }
  .ib { display: inline-block; }
</style>
<p>inline: <span>width is ignored</span> and padding overlaps the lines.</p>
<p>inline-block: <span class="ib">width works</span> and it still sits in the line.</p>
<p>block: <span class="b">own line, width works</span></p>
display: none versus visibility: hidden. display: none removes the element entirely: no box, no space, and screen readers do not announce it. visibility: hidden makes it invisible but keeps its space, leaving a hole. For hiding a menu use display: none; for hiding something whose space must be reserved use visibility.

29.2 position: the five values

position decides how an element is placed in the document. It works together with the four offset properties — top, right, bottom, left — which say how far to move it, and from which edge.

The one thing to hold on to: each value measures its offsets against something different. That is the whole chapter.

static — the default

Every element starts as position: static: it sits in normal flow, and top, left, right and bottom are ignored completely. If you set an offset and nothing moves, this is almost always why.

relative — nudge it, but keep its seat

position: relative moves the element from where it would have been. Crucially, its original space is preserved: the gap it left behind stays empty and nothing else moves up.

<style>
  div { background: #E3E9F0; padding: 10px; margin-bottom: 8px; }
  .moved { position: relative; top: 14px; left: 34px;
           background: #FFF1E0; border: 2px solid #E07B1E; }
</style>
<div>First box</div>
<div class="moved">I moved 14px down and 34px right</div>
<div>Third box — notice I did NOT move up into the gap</div>

relative has a second, quieter job that matters more than the nudging: it turns an element into an anchor for absolutely positioned children. That is the next section.

absolute — take it out of the flow

position: absolute lifts the element out of normal flow altogether. Its old space closes up as if it had never existed, and it is then placed using its offsets — measured from the nearest ancestor that is itself positioned.

"Positioned" means having a position of anything other than static. If no ancestor qualifies, the browser falls back to the page itself, and your element flies off to the corner of the document.

<style>
  .card {
    position: relative;               /* THE important line: make an anchor */
    background: #fff; border: 1px solid #E3E9F0; border-radius: 12px;
    padding: 18px; margin-top: 14px;
  }
  .badge {
    position: absolute;
    top: -10px; right: -8px;          /* measured from the card's corner */
    background: #C42B2B; color: #fff;
    padding: 3px 12px; border-radius: 999px;
    font-size: 12px; font-weight: 700;
  }
</style>
<div class="card">
  <span class="badge">New</span>
  <b>CSE326 Internet Programming</b>
  <p style="margin:6px 0 0">Delete the position: relative line and watch the badge run away.</p>
</div>

The pattern is always the same two lines: position: relative on the parent, position: absolute on the child. Remember it as a pair and corner badges, tooltips and overlays all become easy.

fixed — pinned to the window

position: fixed measures against the viewport — the visible window — so the element stays put while the page scrolls. Use it for a back-to-top button, a cookie bar, or a chat bubble in the corner.

<style>
  .up {
    position: fixed; bottom: 16px; right: 16px;
    background: #0B2545; color: #fff; padding: 10px 16px;
    border-radius: 999px; font-weight: 700;
  }
  p { margin: 0 0 20px; }
</style>
<p>Scroll this preview down.</p>
<p>Keep scrolling.</p><p>More text.</p><p>And more.</p>
<p>And more again.</p><p>Nearly there.</p><p>The end.</p>
<div class="up">Back to top</div>

sticky — relative, then fixed

position: sticky behaves like relative while the element is in view, and switches to behaving like fixed the moment you scroll past the offset you gave it. It is how a table heading or a section title stays visible.

Sticky needs an offset. Without a top, bottom, left or right value there is nothing to stick to, and the element silently behaves as if it were static. That is the single most common "sticky is not working" cause. (The second most common is a parent with overflow: hidden.)

<style>
  h3 {
    position: sticky;
    top: 0;                        /* WITHOUT this line, nothing sticks */
    background: #FF9933; color: #fff;
    margin: 0; padding: 10px 14px;
  }
  p { margin: 0 0 18px; padding: 0 14px; }
</style>
<h3>Courses</h3>
<p>Scroll the preview: this heading stays at the top.</p>
<p>More content.</p><p>More content.</p><p>More content.</p>
<p>More content.</p><p>More content.</p><p>The end.</p>

29.3 z-index: who is on top

  
When two elements overlap, the one written later in the HTML is painted on top. z-index overrides that: a higher number sits above a lower one.

  
<style>
  .stack { position: relative; height: 130px; }
  .c { position: absolute; width: 130px; height: 84px; border-radius: 10px;
       padding: 10px; color: #fff; font-weight: 700; }
  .c1 { background: #C42B2B; left: 0;   top: 0;  z-index: 1; }
  .c2 { background: #E07B1E; left: 44px; top: 18px; z-index: 3; }
  .c3 { background: #138808; left: 88px; top: 36px; z-index: 2; }
</style>
<div class="stack">
  <div class="c c1">z-index 1</div>
  <div class="c c2">z-index 3</div>
  <div class="c c3">z-index 2</div>
</div>

  
Two rules save a lot of frustration:

  
    
    
  • z-index only works on positioned elements. On a static element it does nothing at all.
    • 
    
  • Keep the numbers small and meaningful. 1, 10, 100 is plenty. Writing z-index: 99999 is a sign that something else is wrong, and it starts the same arms race as !important.
    •

Exam-style checks

  
What is the default position value?L1

    
  • A. relative
  • B. static
  • C. absolute
  • D. normal

    
Answer: B. With static, the offsets top, right, bottom and left do nothing at all.

  
An absolutely positioned box flies to the page corner instead of its parent's. Why?L3

    
  • A. absolute always uses the page
  • B. No ancestor has a position other than static
  • C. It needs z-index
  • D. The parent needs display:block

    
Answer: B. absolute measures from the nearest positioned ancestor. Add position: relative to the parent.

  
Which position keeps the element's original space in the flow?L2

    
  • A. absolute
  • B. relative
  • C. fixed
  • D. none of them

    
Answer: B. relative shifts the element visually but its space is preserved, so nothing else moves. absolute and fixed are taken out of the flow and their space closes up.

  
Which position is measured against the VIEWPORT?L2

    
  • A. relative
  • B. absolute
  • C. fixed
  • D. static

    
Answer: C. fixed stays put while the page scrolls, which is why it suits back-to-top buttons and cookie bars.

  
position: sticky silently does nothing. What is missing?L3

    
  • A. A z-index
  • B. A top/bottom/left/right offset
  • C. A width
  • D. display:block

    
Answer: B. Without an offset such as top: 0 it behaves like static. The other frequent cause is an ancestor with overflow: hidden.

  
Which two declarations pin a badge to the corner of a card?L3

    
position: relative on the card and position: absolute on the badge, plus offsets such as top and right on the badge. Remember them as a pair.

  
Which display value lets an element sit in a line of text AND accept a width?L2

    
  • A. block
  • B. inline
  • C. inline-block
  • D. none

    
Answer: C. inline ignores width and height; block takes a whole line; inline-block gives you both behaviours, which is why buttons and tags use it.

  
What is the difference between display: none and visibility: hidden?L3

    
display: none removes the element completely — no box, no space, not announced by screen readers. visibility: hidden hides it but keeps its space, leaving a gap where it was.

  
z-index: 5 has no effect on an element. What is the likeliest reason?L3

    
The element is still position: static. z-index only applies to positioned elements (relative, absolute, fixed or sticky), or to flex and grid items.

  
Which technique would you use to lay out three cards in a row?L2

    
Flexbox or Grid (Chapters 30 and 31), not positioning. Absolute positioning takes elements out of the flow, so the container collapses and nothing reflows on a phone. Positioning is for badges, overlays and sticky bars.
