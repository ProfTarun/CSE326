Introduction to CSS

A page written with HTML alone works perfectly, and looks like a photocopy from 1994. This chapter is where that changes. You will learn what a style is, the exact shape of a CSS rule down to the last bracket, the three places CSS can live, and how the browser puts your page and your styles together.

About 32 minutes · Course outcome CO3 · The first chapter of Unit 3

Before you start — one-line reminders

  • HTML is the language that says what each piece of content is: a heading, a paragraph, an image (Chapter 3).
  • An element is an opening tag, some content and a closing tag, like <p>Hello</p> (Chapter 3).
  • An attribute is extra information inside the opening tag, like class="card" (Chapter 5).
  • The head holds information about the page and is never drawn on screen (Chapter 4).

If any of those felt unfamiliar, open that chapter for five minutes first. Nothing here needs more than that.

By the end of this chapter you can

  • Say what CSS is and why a plain HTML page looks plain.
  • Write a CSS rule and name every part of it: selector, braces, property, value, declaration.
  • Add CSS to a page in all three ways, and say which one a real project uses.
  • Explain what the word cascading is doing in the name.
  • Write a comment, and find the missing semicolon when a rule stops working.

22.1 Why a plain page looks plain

Open any HTML file you have written so far and look at it honestly. Black text. A serif font you did not choose. Headings in a few sizes. Blue underlined links. Everything stacked down the left edge.

Nothing is broken. That look is the browser's default style: the appearance a browser falls back on when you have not said what you want. Every browser ships with a small built-in stylesheet so that a bare page is at least readable.

HTML's job is to say what each piece of content is. It has no opinion about colour, size or position. Something else has to supply that, and that something is CSS.

CSS stands for Cascading Style Sheets. It is the language you use to describe how HTML elements should be displayed. Take the name apart:

  • Style — colour, size, spacing, position. The look.
  • Sheet — the rules live together in a sheet, normally one file, which many pages can share.
  • Cascading — when several rules want to style the same thing, a fixed order of priority decides the winner. Section 22.6 introduces it and Chapter 23 finishes the job.
Picture this. Writing HTML is like typing the words of a wedding invitation: the names, the date, the address. Every fact is there and anyone can read it. CSS is choosing the card, the gold border, the size of the couple's names and how far the date sits below them. Same words, completely different card.

22.2 Your very first style

Here is the smallest possible before-and-after. Press Run, look at the result, then read the two lines.

<p>I am a normal paragraph.</p>

<p style="color: green; font-size: 24px;">I have been styled.</p>

The second paragraph carries a style attribute holding two instructions:

  • color: green — paint the text green.
  • font-size: 24px — make the letters 24 pixels tall.

That is CSS. Two facts to take from it. First, styling is always written as a name, a colon, and a value. Second, the browser applies it immediately — there is nothing to install, compile or switch on.

22.3 The shape of a CSS rule

  
Inline styles like the one above are fine for a first look, but real CSS is written as rules, away from the HTML. A rule has two halves: who to style, and what to do to them.

  
  

    
Selector — p

    
Points at the elements you want to style. Here it means "every paragraph on the page". Chapter 23 is entirely about selectors.

    
Braces — { }

    
Also called curly brackets. Everything between them applies to whatever the selector picked. Every opening brace needs a closing one.

    
Property — color

    
The name of the thing you are changing. There are a few hundred; you will meet about forty in this unit. Property names are fixed words — you cannot invent colour or textsize.

    
Value — navy

    
What you are setting the property to. Which values are allowed depends on the property: color takes a colour, font-size takes a size.

    
Declaration — color: navy;

    
Property + colon + value. One complete instruction, ended by a semicolon. A rule can hold as many declarations as you like.

  

  

    
A rule reads out loud as a sentence: "For every paragraph, set the colour to navy." Selector first, then the list of changes.

  

  
<style>
  p {
    color: navy;
    font-size: 18px;
    line-height: 1.7;
  }
</style>

<p>Both of these paragraphs are navy, 18 pixels and comfortably spaced.</p>
<p>I did not have to style them one at a time.</p>

  
Look at what you just got for free. One rule styled every paragraph on the page, and it would style two hundred of them just as easily. That is the saving CSS is really about.

  
Quick check: in h1 { text-align: center; }, which part is the property and which is the value?

    
text-align is the property, center is the value, h1 is the selector, and text-align: center; altogether is one declaration.






  
22.4 The three places CSS can live

  
CSS has to reach the page somehow. There are exactly three ways, and you will be asked to name them.

  
  
1. Inline CSS

  
Written in the style attribute of a single element. It applies a unique style to that one element and nothing else.

  
<h1 style="color: teal; text-align: center;">Welcome</h1>

  
Notice there is no selector and no braces — the element it belongs to is obvious, because the style is written inside it. You only write the declarations.

  
It is genuinely useful for a two-second experiment. It is a poor way to build anything, because the look is now tangled into the content, you must repeat it on every element, and it beats almost every other rule so nothing can override it politely.

  
2. Internal CSS

  
Written once inside a <style> element in the <head> of the page. It defines the style for that single HTML page.

  
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Internal CSS</title>
  <style>
    body { font-family: system-ui, sans-serif; background: #FFFDF7; }
    h1   { color: #B45309; }
    p    { color: #3C4A60; line-height: 1.7; }
  </style>
</head>
<body>
  <h1>Internal styles</h1>
  <p>Everything on this page follows the rules written in the head.</p>
  <p>Adding a third paragraph costs nothing.</p>
</body>
</html>

  
This is what you will use in class exercises and in most of this book's examples, because one file shows the whole story.

  
3. External CSS

  
The rules go into their own file, by convention named something like style.css, which contains only CSS — no HTML tags at all, not even <style>. Each page that wants those rules joins itself to the file with a <link> element in its head.

  
<!-- index.html -->
<head>
  <link rel="stylesheet" href="style.css">
</head>

/* style.css - a separate file, no HTML inside it */
body { font-family: system-ui, sans-serif; }
h1   { color: #B45309; }

  
Two attributes do the work: rel="stylesheet" says what the linked file is, and href="style.css" says where to find it. Both are needed.

  
Why external wins. A site with forty pages and one stylesheet needs one edit to change every heading on the site. The browser also caches the file after the first page, so the other thirty-nine load faster. This is the standard answer to "which is the best way to include CSS in a real project?"

Quick check: your teacher says "put your CSS in an external stylesheet". What two things must you create?

    
(1) A file such as style.css containing only CSS rules, and (2) a <link rel="stylesheet" href="style.css"> inside the <head> of each HTML page. Miss the link and the page looks unstyled — the single most common "my CSS is not working" cause.






  
22.5 What the browser actually does

  
It helps to know the order of events, because most styling bugs are really ordering bugs.

  
  
Two consequences worth remembering now:

  
    
    
  • If a selector matches nothing, the rule sits there doing nothing and no error is shown. CSS, like HTML, fails silently.
    • 
    
  • If two rules set the same property on the same element, one of them has to win. That contest has rules, and it is the subject of the next chapter.
    • 
  






  
22.6 The "cascading" in Cascading Style Sheets

  
Styles can arrive from more than one place: the browser's defaults, your stylesheet, and sometimes the reader's own settings. On top of that, your own stylesheet may contain several rules aimed at the same element. The cascade is the fixed procedure the browser follows to pick one value.

  
For now, two of its three ideas are enough:

  
    
    
  1. Later beats earlier, when everything else is equal. If you write p { color: red; } and then p { color: blue; }, paragraphs are blue. The second rule was read last, so it overwrites.
    2. 
    
  2. More specific beats less specific. A rule aimed at one particular element beats a rule aimed at all of them, no matter which came first. That is why an inline style is so hard to override.
    3. 
  

  
<style>
  p { color: red; }
  p { color: blue; }   /* written later, so this one wins */
</style>
<p>Which colour am I?</p>

  
The third idea is inheritance: some properties pass down from a parent element to the elements inside it. Set color on body and every paragraph inside receives it, without being named. That is why sensible stylesheets set fonts and colours once, high up, instead of on every element.

  
<style>
  body { font-family: Georgia, serif; color: #6D28D9; }
</style>
<h2>Nobody styled this heading directly</h2>
<p>Or this paragraph. Both inherited the font and the colour from <b>body</b>.</p>

  
Exam tip. "Cascading" is not decoration in the name. It refers to this ordered decision procedure: origin, then specificity, then source order, with inheritance filling in anything nobody set. Chapter 23 scores specificity properly.






  
22.7 Comments, spacing, and the missing semicolon

  
A comment in CSS starts with /* and ends with */. The browser ignores everything between. Use comments to label the sections of your stylesheet.

  
/* ---- page layout ---- */
body { margin: 0; }

/* p { color: red; }   switched off while I test something */

  
Note that HTML's <!-- ... --> does not work inside CSS, and CSS's /* ... */ does not work inside HTML. Each language has its own.

  
Spacing and line breaks are free. These two rules are identical to the browser:

  
h1 { color: navy; font-size: 32px; }

h1 {
  color: navy;
  font-size: 32px;
}

  
Write the second form. One declaration per line is much easier to read and to fix.

  
The four mistakes that break beginners' CSS

  

    
✗ Missing semicolon
p {
  color: navy
  font-size: 18px;
}
Both declarations are lost, not just one. The browser reads navy font-size: 18px as one broken value and throws the whole thing away.

    
✓ End every declaration
p {
  color: navy;
  font-size: 18px;
}
Keep the semicolon on the last line too. Then adding a line later cannot break it.

  

  

    
✗ Missing closing brace
h1 { color: navy;
p  { color: grey; }
Everything after the unclosed rule is swallowed. A whole stylesheet can appear to stop working halfway down.

    
✓ Braces in pairs
h1 { color: navy; }
p  { color: grey; }
Indent your declarations so an unclosed brace is visible at a glance.

  

  

    
✗ Colon and semicolon swapped
p { color; navy: }
Nothing happens, and no error appears.

    
✓ Colon inside, semicolon at the end
p { color: navy; }
Name, colon, value, semicolon. Say it while you type it.

  

  

    
✗ Inventing a property or a value
p { text-colour: navy; }
p { color: navyblue; }
Both are ignored silently. British spelling is not accepted: it is always color.

    
✓ Use the real names
p { color: navy; }
If a line does nothing, the first suspect is a typo in the property name.

  

  
When CSS "does not work". Check in this order: (1) is the stylesheet actually linked, with the right file name and the right capital letters? (2) is there a missing semicolon or brace above the rule that fails? (3) is the property name spelled exactly right? (4) is another rule winning — the subject of the next chapter? Press F12, click the element, and the browser lists every rule that applied to it, with the losing ones crossed out.






  
22.8 Build it: start the student profile card

  
Through Unit 3 you will build one page piece by piece: a student profile card with courses, skills and a contact form. Each chapter adds the part it has just taught. Here is the beginning — plain HTML, one internal stylesheet, nothing you have not met.

  
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Asha Kumar | Student Profile</title>
  <style>
    /* ---- the whole page ---- */
    body {
      font-family: system-ui, sans-serif;
      color: #3C4A60;
      background: #FBFCFE;
      line-height: 1.7;
      padding: 24px;
    }
    /* ---- headings ---- */
    h1 {
      color: #0B2545;
      font-size: 30px;
    }
    h2 {
      color: #B45309;
      font-size: 20px;
    }
  </style>
</head>
<body>
  <h1>Asha Kumar</h1>
  <p>B.Tech Computer Science, first year. Learning to build for the web.</p>

  <h2>Courses</h2>
  <p>CSE326 Internet Programming — in progress.</p>

  <h2>Contact</h2>
  <p>asha@example.edu</p>
</body>
</html>

  
Press Run, then Open in Playground and change three things: the two colours, the font-size of h1, and the background of body. Nothing you do there can break anything. Keep the file — Chapter 23 continues from it.






  
Exam-style checks

  
Answer before you open each one. Four options, exactly one right, same as CA2.

  
What does CSS stand for?L1

    
  • A. Creative Style System
  • B. Cascading Style Sheets
  • C. Computer Styled Sections
  • D. Coded Style Syntax

    
Answer: B. Cascading Style Sheets: style for the look, sheet because the rules live together in a file, cascading for the ordered way conflicts are settled.

  
In the rule p { color: navy; }, what is color: navy?L2

    
  • A. A selector
  • B. A declaration
  • C. An attribute
  • D. A property only

    
Answer: B. Property plus colon plus value is a declaration. color alone is the property, navy alone is the value, and p is the selector.

  
Which is the best way to include CSS in a real project?L2

    
  • A. style attributes on each element
  • B. A <style> block in every page
  • C. One external .css file linked with <link>
  • D. JavaScript

    
Answer: C. Reusable across every page and cached by the browser, so one edit restyles the whole site.

  
Which element attaches an external stylesheet, and where does it go?L1

    
Answer: <link rel="stylesheet" href="style.css">, inside the <head>. <style> holds CSS written in the page itself; <script> is for JavaScript; <meta> is metadata.

  
Where is an internal stylesheet written?L1

    
  • A. In a separate .css file
  • B. In a <style> element inside <head>
  • C. In the style attribute of each element
  • D. At the end of <body>

    
Answer: B. It styles that one page.

  
Which of these is an inline style?L1

    
  • A. <p style="color:red">Hi</p>
  • B. <style>p { color: red; }</style>
  • C. <link href="a.css">
  • D. p { color: red; } in style.css

    
Answer: A. Inline means written in the element's own style attribute, and it styles only that element. Note there are no braces and no selector in an inline style.

  
How do you write a comment in CSS?L1

    
  • A. <!-- comment -->
  • B. // comment
  • C. /* comment */
  • D. # comment

    
Answer: C. <!-- --> is the HTML comment and does nothing inside CSS.

  
A stylesheet works down to a certain rule and then everything below it is ignored. What is the most likely cause?L3

    
Answer: a missing closing brace (or a missing semicolon) in the last rule that worked. The browser keeps reading the following text as part of the broken rule and discards it. No error message is shown; DevTools usually reveals it.

  
Two rules, equally specific: p { color: red; } then later p { color: blue; }. What colour are paragraphs?L2

    
Answer: blue. When specificity ties, the rule written later wins. That is the cascade in action.

  
You set color on body and never mention paragraphs. What colour is a paragraph?L2

    
Answer: the same colour. color is an inherited property, so elements inside body receive it unless something else sets it. Box properties such as border and padding are not inherited.






  
Quick revision

  
Key takeaways
    
    
  1. HTML says what content is; CSS says how it looks. Without CSS you get the browser's default style.
    2. 
    
  2. CSS = Cascading Style Sheets. A rule is selector { property: value; }. Property + colon + value = a declaration, ended with a semicolon; declarations live between braces.
    3. 
    
  3. Three ways to add it: inline (style attribute, one element), internal (<style> in the head, one page), external (a .css file joined with <link rel="stylesheet" href="...">, every page). Real projects use external.
    4. 
    
  4. The cascade settles conflicts: more specific wins, and when specificity ties the later rule wins. Inheritance passes properties such as color and font-family down to children.
    5. 
    
  5. Comments are /* ... */. A missing semicolon or brace silently kills more than the line it is on.
    6.
