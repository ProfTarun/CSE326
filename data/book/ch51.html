Objects and Object Manipulation

A student is not one value. Asha has a name, a registration number, marks in several subjects and a home city, and all of them belong together. An object keeps related facts together under labels you choose, so your program can say student.city instead of remembering which variable held what. Nearly all real data in JavaScript arrives as objects: a class list, a product in a cart, the reply from a server.

About 35 minutes · Course outcome CO4

Before you start — one-line reminders

  • Every value has a type that typeof reports, and arrays and functions both count as objects (Chapter 43).
  • a ?? b gives b only when a is null or undefined (Chapter 44).
  • A function is a reusable block you call with (); an arrow function such as (x) => x * 2 is a shorter way to write one (Chapter 48).
  • An array is an ordered list read by position, arr[0], and for...of visits each item in turn (Chapter 50).

By the end of this chapter you can

  • Write an object literal and read its properties with dot and bracket notation, knowing when brackets are required.
  • Add, change and delete properties, and test whether one exists with in, hasOwnProperty and ?..
  • Build and read nested objects and arrays of objects, such as a class list of student records.
  • Write methods that use this, and explain why an arrow function makes a poor method.
  • Loop over an object with for...in, Object.keys, Object.values and Object.entries.
  • Predict whether two variables share one object or hold separate copies, and copy or unpack objects with spread and destructuring.
  • Make many objects of the same shape with a constructor function and new, and recognise the class version.

51.1 One thing, many facts

Suppose a program has to remember one student. With what you know so far, you might write four variables:

const studentName = "Asha Verma";
const studentRegNo = 12215478;
const studentCity = "Phagwara";
const studentMarks = 82;

Nothing in the language ties these four together; only their names hint that they describe one person. A second student needs four more variables. An array from Chapter 50 does keep them together, ["Asha Verma", 12215478, "Phagwara", 82], but then each fact has only a number. Is the city at position 2 or position 3? You have to remember.

An object solves both problems. It is a single value that holds several named facts about one thing:

const student = {
  name: "Asha Verma",
  regNo: 12215478,
  city: "Phagwara",
  marks: 82
};

Each line inside the curly braces is one property. A property has two halves joined by a colon: the key (also called the property name) on the left and the value on the right. Writing an object out like this, braces and all, is called an object literal, and it is by far the most common way to make one. Your lecture slides sum it up: objects are collections of key–value pairs; the keys are strings (or symbols, a rare special type you will not need yet), and the values can be of any type, including arrays, functions and other objects.

Picture this. The college office keeps a steel cabinet for every student. Each drawer has a label on the front: name, reg no, city, marks. To find Asha's city, nobody counts drawers; they read the labels and open the one marked city. A clerk can fit a new drawer, change what is inside one, or pull one out, and the labels keep everything findable. An array is different: a row of numbered pigeonholes, perfect when order matters, awkward when you must remember that pigeonhole 2 meant "city". An object is the cabinet: labels, not positions.

The rules for writing an object literal are few, and JavaScript is strict about them:

  • Curly braces make the object. {} on its own is a valid, empty object.
  • A colon joins each key to its value. An equals sign there is a SyntaxError.
  • A comma separates properties. A comma after the last one is allowed and harmless.
  • A key needs no quotes if it follows the naming rules of Chapter 42. A key with a space or a hyphen must be quoted: "full name": "Asha Verma".
  • Keys are always stored as strings, even if you type a number: in { 1: "first" } the key is the string "1".

As Chapter 43 showed, typeof student is "object". An array is an object too, one whose keys happen to be 0, 1, 2 and so on, which is why both are read with square brackets.

Quick check: what is wrong with const s = { name = "Asha", marks = 82 };?

Inside an object literal a key is joined to its value with a colon, not an equals sign, so this line is a SyntaxError. The correct version is { name: "Asha", marks: 82 }.

51.2 Reading a property: the dot or the brackets

There are two ways to read a property. Dot notation is the object, a dot, then the key: car.make. Bracket notation puts the key, as a string, inside square brackets: car["make"]. Both read the same property. Here is the car from your slides. Its start property holds a function, and car.start() runs it.

<script>

  const car = {
    make: "Toyota",
    model: "Camry",
    year: 2022,
    isElectric: false,
    start: function () {
      console.log("Engine started!");
    }

  // dot notation
  console.log("Make:", car.make);              // Toyota
  console.log("Year:", car.year);              // 2022

  console.log("Model:", car["model"]);         // Camry

  // brackets with a variable: the variable's VALUE is used as the key
  const field = "isElectric";
  console.log("car[field]:", car[field]);      // false
  console.log("car.field:", car.field);        // undefined - there is no key called "field"

  // a key with a space must be quoted, and read with brackets
  const specs = { "fuel type": "Petrol", seats: 5 };
  console.log("Fuel:", specs["fuel type"]);    // Petrol

  // a property that does not exist is simply undefined
  console.log("Colour:", car.colour);          // undefined

  // calling a method: the property that holds a function, plus ()
  car.start();                                 // Engine started!
  console.log("The whole object:", car);

The dot is shorter and easier to read, so use it whenever you can. Brackets are needed in exactly two situations:

  1. The key is not a valid name. specs.fuel type cannot even be read by JavaScript, because the space ends the name. Write specs["fuel type"].
  2. The key is stored in a variable, or worked out while the program runs. With const field = "isElectric";, car[field] first looks inside field, finds the text "isElectric", and reads that property. car.field looks inside nothing: it asks for a property literally called field, and the car has none.

The dot means "the property with exactly this name". Brackets mean "work the name out first, from whatever is between the brackets". That is why a variable only works inside brackets.

Look at the Colour line. Reading a property that does not exist is not an error; you simply get undefined. Section 51.4 shows when that quiet undefined turns into a loud error. The last line shows how the Console panel prints a whole object: strings in quotes, and the method as ƒ start(), meaning "a function called start".

Quick check: with const key = "city"; and const p = { city: "Jalandhar", key: "K23" };, what are p.key and p[key]?

p.key is "K23": the dot asks for the property literally named key. p[key] is "Jalandhar": the brackets use the variable's value, "city", as the key.

51.3 Adding, changing, deleting and checking

An object is not fixed once it is made. One kind of line both adds and updates: an assignment to a property. If the key already exists, its value is replaced; if it does not, a new property is created. The delete operator removes a property completely, key and value together: delete student.regNo;.

JavaScript will not catch your typing mistakes. student.makrs = 90; does not fail. It quietly adds a brand-new property called makrs, and student.marks is unchanged. If a value refuses to update, check the spelling of the key first.

The example below declares student with const and then changes it freely. That is allowed. const locks the variable: the name student must keep pointing at this same object, so student = { } is a TypeError. It does not lock the object's contents. (If you ever need an object that cannot change, Object.freeze(student) makes it read-only.)

Is it there?

Before using a property you sometimes need to know whether it exists. Two tools answer with true or false:

  • "city" in student: the key as a string, the word in, then the object.
  • student.hasOwnProperty("city"): a method every object has. Newer code writes Object.hasOwn(student, "city"), which means the same.

They differ in one way. Every object quietly inherits a few built-in properties from JavaScript itself, such as toString (section 51.9 shows where they come from). in counts inherited properties; hasOwnProperty counts only the object's own.

Why not simply write if (student.backlogs)? Because if tests whether a value is truthy (Chapter 47), not whether it exists. A student with backlogs: 0 has the property, but 0 is falsy, so the test says "no". When the question is "is it there?", use in.

<script>
  const student = { name: "Rahul Sharma", marks: 71 };
  console.log("1. Start:", student);

  student.marks = 78;            // marks exists: UPDATE
  student.city = "Ludhiana";     // city is new: ADD
  student.regNo = 12216032;      // regNo is new: ADD
  console.log("2. After changes:", student);

  delete student.regNo;          // REMOVE the whole property
  console.log("3. After delete:", student);

  // is it there?
  console.log("4. city in student:", "city" in student);
  console.log("5. regNo in student:", "regNo" in student);
  console.log("6. own marks?", student.hasOwnProperty("marks"));
  console.log("7. toString in student:", "toString" in student);
  console.log("8. own toString?", student.hasOwnProperty("toString"));

  // the trap: a property can exist and still be falsy
  student.backlogs = 0;
  if (student.backlogs) {
    console.log("9. has backlogs");
  } else {
    console.log("9. if (student.backlogs) chose else, but the property exists:", "backlogs" in student);
  }

  // const locks the variable, not the object
  try {
    student = { name: "Someone else" };
  } catch (err) {
    console.log("10. Reassigning threw", err.name + ": " + err.message);
  }
</script>

51.4 Objects inside objects, and lists of objects

A property's value can be anything, including another object or an array. That lets one object describe something in layers:

const student = {
  name: "Asha Verma",
  marks: { maths: 82, physics: 74 },
  address: { city: "Phagwara", pin: "144411" },
  subjects: ["CSE326", "CSE310"]
};

console.log(student.marks.physics);    // 74
console.log(student.address.city);     // Phagwara
console.log(student.subjects[0]);      // CSE326

Read a chain of dots from left to right, one step at a time. student.address.city means: take student, get its address (an object), then get that object's city. Dots and brackets mix freely, as in student.subjects[0].

The other direction is just as common: an array of objects. A class list is an array, and each student in it is an object. You will meet this shape constantly, because data fetched from a server usually arrives exactly like this (Chapter 65). classList[1].name reads as: the array, position 1, that object's name. To visit every student, a for...of loop (Chapter 50) hands you one whole object per turn.

Key idea. Use an array for a list of similar things in order; use an object for different facts about one thing. A class list is both at once: an array of objects.

When a layer is missing: optional chaining

Layers bring one new danger. Reading a missing property gives undefined, as you saw. But reading a property of undefined is an error, because undefined has no properties at all. If Meera's record has no address yet, then meera.address is undefined, and meera.address.city stops the program with TypeError: Cannot read properties of undefined (reading 'city').

The optional chaining operator ?. exists for exactly this. meera.address?.city means: if meera.address is null or undefined, stop here and give undefined; otherwise carry on and read city. Pair it with ?? from Chapter 44 to supply a fallback: meera.address?.city ?? "city not given".

51.5 Methods and this

When a property's value is a function, the property is called a method. The car's start was one. Modern code usually writes methods with a shorter syntax that works the same way in everyday use:

start: function () { console.log("Engine started!"); }   // the slides' way
start() { console.log("Engine started!"); }              // method shorthand: the same

Most methods need the object's own data. Inside a method, the keyword this means the object the method was called on: the object written before the dot. When you call meera.describe(), this inside describe is meera, so this.name is Meera's name.

Why not just write meera.name inside the method? Because this lets one function serve many objects. In the example below a single function, report, is stored in two objects. Called as asha.report() it describes Asha; called as rahul.report() it describes Rahul. Section 51.9 relies on exactly this to give thousands of objects one shared method.

<p>The answers are in the Console panel below.</p>
<script>
  const meera = {
    name: "Meera",
    marks: 88,
    describe() {                             // short for describe: function () { ... }
      return this.name + " has " + this.marks + " marks";
    },
    addBonus(points) {
      this.marks = this.marks + points;      // a method can change its own object
    },
    describeArrow: () => {
      return "Arrow sees marks: " + this.marks;
    }
  };

  console.log("1.", meera.describe());       // Meera has 88 marks
  meera.addBonus(3);
  console.log("2.", meera.describe());       // Meera has 91 marks
  console.log("3.", meera.describeArrow());  // Arrow sees marks: undefined

  // one function, two objects: this is whichever object is before the dot
  function report() {
    return this.name + " (" + this.marks + ")";
  }
  const asha  = { name: "Asha",  marks: 82, report: report };
  const rahul = { name: "Rahul", marks: 67, report: report };
  console.log("4.", asha.report());          // Asha (82)
  console.log("5.", rahul.report());         // Rahul (67)
</script>
1. Meera has 88 marks
2. Meera has 91 marks
3. Arrow sees marks: undefined
4. Asha (82)
5. Rahul (67)

Line 3 is the trap. An arrow function (Chapter 48) does not get a this of its own. It borrows the this of the code surrounding the place where it was written, and an object's curly braces do not count as such a place. At the top level of a script, that outer this is the browser window, which has no marks; hence undefined.

In a normal method, this means "me": whichever object is before the dot when the method is called. An arrow function has no "me" of its own, so it is the wrong tool for a method. Use arrows for small helper functions, and the shorthand name() { } for methods.

51.6 Looping over an object

Objects have no length and no positions, so the counting loop of Chapter 50 does not fit. JavaScript gives you two other ways in.

for...in runs its block once for each property, handing you the key, as a string, each time: for (const subject in marks) { ... }. To get the value, use brackets, marks[subject], because the key is in a variable (section 51.2). Loops in general are the subject of Chapter 52; for...in is meant for objects, so for arrays keep using for...of.

The three Object helpers each turn an object into an array, which you can then loop over with for...of or measure with .length:

Object.values(obj)the values[82, 74]
Object.entries(obj)[key, value] pairs[["maths", 82], ["physics", 74]]

So Object.keys(obj).length counts the properties. In the example, for (const [subject, score] of Object.entries(marks)) uses the array destructuring of Chapter 50 to unpack each pair into two variables at once.

Quick check: why does for (const k in marks) { console.log(marks.k); } print undefined four times?

Because marks.k asks for a property literally named k, which does not exist. The variable k holds each key in turn, so it must go in brackets: marks[k].

51.7 Copy, or the same object?

This section explains most of the "but I never changed that!" bugs in JavaScript. Start with numbers, which behave as you would expect:

let a = 82;
let b = a;        // b gets its own copy of 82
b = 90;
console.log(a);   // 82 - a is untouched

Objects behave differently. A variable does not hold an object itself; it holds a reference to it: directions to where the object is kept in memory. The = sign copies those directions, not the object:

const asha = { name: "Asha", marks: 82 };
const same = asha;        // a second name for the SAME object
same.marks = 90;
console.log(asha.marks);  // 90 - asha changed too

Return to the cabinets of section 51.1. The variable asha is not the cabinet; it is a slip of paper saying where the cabinet stands. const same = asha; photocopies the slip. Two slips, one cabinet: whoever opens a drawer through either slip changes what both will find. The same happens when you pass an object to a function: the parameter receives a copy of the slip, so the function can change the caller's object.

Comparison works on slips too. === asks "do these lead to the same object?", not "do these look alike?". So same === asha is true, while { x: 1 } === { x: 1 } is false: two separate objects that merely look the same.

Making a real copy

To get a second, independent object, use the spread syntax: three dots inside a new pair of braces, const copy = { ...asha };. It builds a brand-new object and copies each property of asha into it. Change copy.name and asha.name stays as it was. Spread can also copy and change in one step: { ...asha, marks: 95 } copies everything and then sets marks, because when a key appears twice, the later one wins.

There is one catch, and examiners love it. Spread copies only one level. If a property holds another object, such as address, the copy receives a copy of the reference, so both objects share one address object. This is called a shallow copy. In cabinet terms, a drawer never holds another cabinet, only a slip saying where it stands, and spread photocopies that slip. For a deep copy, where every level is duplicated, modern browsers provide structuredClone(asha). It works on plain data and refuses objects that contain functions.

Exam tip. For any copying question, draw it. Each variable gets an arrow. b = a draws a second arrow to the same object. { ...a } draws a new object, but its inner arrows still point at the old inner objects. Then follow the arrows to read off the answer.

51.8 Destructuring: unpacking properties

Code often begins by pulling a few properties out into variables of their own. Destructuring does it in one line, with the braces on the left of the =:

const student = { name: "Rahul", marks: 67, city: "Ludhiana" };

const { name, marks } = student;       // name is "Rahul", marks is 67
const { city: hometown } = student;    // a variable called hometown: "Ludhiana"
const { section = "K23" } = student;   // no section property, so the default "K23" is used

function card({ name, marks }) {       // destructuring right in the parameter
  return name + " scored " + marks;
}
console.log(card(student));            // Rahul scored 67

// the reverse: property shorthand
const course = "CSE326";
const credits = 4;
const subject = { course, credits };   // same as { course: course, credits: credits }
console.log(subject);                  // {course: 'CSE326', credits: 4}

The variable names must match the keys; their order does not matter. A colon renames: city: hometown reads "take city, call it hometown". An = gives a default, used only when the property is missing (or holds undefined). Destructuring a parameter is very common in real code, because the function then states exactly which properties it needs.

The reverse trick is property shorthand. When a variable already has the name you want as a key, { course, credits } is short for { course: course, credits: credits }.

Quick check: after const { marks: m } = { marks: 50 }; which variable exists, and what does it hold?

Only m, holding 50. The colon renames: take the property marks and store it in a variable called m. No variable called marks is created.

51.9 Many objects, one shape: constructors and new

A college has thousands of students and a library has thousands of books, all with the same properties. Writing thousands of object literals by hand would be slow and error-prone. A constructor function is a template: write the shape once, then stamp out as many objects as you need with new. This is the Book example from your slides:

function Book(title, author, year) {
  this.title = title;
  this.author = author;
  this.year = year;
}

let book1 = new Book("The Catcher in the Rye", "J.D. Salinger", 1951);
let book2 = new Book("To Kill a Mockingbird", "Harper Lee", 1960);

The function has no return and no object literal, yet book1 ends up as a complete book. The keyword new does four things for you:

  1. it creates a new, empty object;
  2. it runs Book with this pointing at that new object;
  3. the lines this.title = title; and so on fill the object in from the arguments;
  4. it hands back the finished object automatically.

Each object made this way is an instance of Book, and book1 instanceof Book is true. The capital B is a convention, and a useful one: it tells every reader "call this with new". Your slides call this idea the object constructor; JavaScript even has a built-in one, new Object(), which is simply a long way of writing {}.

Forget new and nothing warns you. const b = Book("Gitanjali", "Tagore", 1910); runs Book as an ordinary function. It returns nothing, so b is undefined. And this is not a new book: in a normal script it is the browser window, so title, author and year leak out as global variables.

One method, shared by every book

Your slides add that constructors create instances with shared properties and methods. If the constructor did this.describe = function () { ... }, every book would get its own copy of the same function, a real waste with thousands of books. Instead, put the method on the constructor's prototype:

Book.prototype.describe = function () {
  return this.title + " by " + this.author + " (" + this.year + ")";
};

Every object made with new Book is linked to Book.prototype. When you call book1.describe(), JavaScript does not find describe on book1 itself, so it looks in the prototype, finds it there, and runs it with this set to book1. That is also where the inherited toString of section 51.3 comes from: plain objects are linked to Object.prototype.

The class version

Newer code writes the same template with the class keyword. It is a tidier way to write a constructor and its shared methods, not a different idea: the constructor runs when you call new, and methods written inside the class body go on the prototype automatically. A class also refuses to run without new, which removes the trap above.

class Book {
  constructor(title, author, year) {   // runs when you write new Book(...)
    this.title = title;
    this.author = author;
    this.year = year;
  }
  describe() {                          // goes on Book.prototype: shared
    return this.title + " by " + this.author + " (" + this.year + ")";
  }
}

const book3 = new Book("Train to Pakistan", "Khushwant Singh", 1956);
console.log(book3.describe());          // Train to Pakistan by Khushwant Singh (1956)
Book("Godan", "Premchand", 1936);       // TypeError: Class constructor Book cannot be invoked without 'new'

A constructor is a stamp. new presses it: a fresh object, this pointing at it, the properties filled in, and the object handed back. Put methods on the prototype (or inside a class) so that every object shares one copy.

51.10 A preview: objects as text (JSON)

An object lives in your program's memory. To send it to a server or save it in the browser, it must first become text. The format used everywhere for this is JSON, JavaScript Object Notation, which looks almost exactly like an object literal with every key and every string in double quotes:

const student = { name: "Asha", marks: 82, passed: true };

const text = JSON.stringify(student);
console.log(text);              // {"name":"Asha","marks":82,"passed":true}
console.log(typeof text);       // string

const back = JSON.parse(text);
console.log(back.marks);        // 82
console.log(back === student);  // false - a brand-new object

JSON.stringify turns an object into JSON text, and JSON.parse builds a brand-new object from that text. Methods are left out, because JSON holds only data. Chapter 64 uses this pair to save objects in the browser, and Chapter 65 uses it to talk to servers and explains the rules of JSON in full.

51.11 Common misunderstandings

✗ "student.key and student[key] do the same thing."
The dot never looks inside a variable; it asks for a property literally named key.
✓ "Brackets work the name out first; the dot uses the name exactly as typed."
Use brackets for keys held in variables and for keys with spaces.
✗ "A const object cannot be changed."
Its properties can be added, changed and deleted freely.
✓ "const locks the variable, not the contents."
Only student = somethingElse is refused. Object.freeze locks the contents.
✗ "const copy = original; makes a copy."
It makes a second name for the same object, so a change through either name shows through both.
✓ "{ ...original } makes a new object."
And === between two separate objects is false, however alike they look.
✗ "Spread copies every level."
Nested objects are still shared between the original and the copy.
✓ "Spread is a shallow copy."
For a deep copy of plain data, use structuredClone(obj).
✗ "An arrow function is just a shorter way to write a method."
It has no this of its own, so this.marks inside it is not the object's marks.
✓ "Methods use the shorthand name() { }; arrows suit small helpers."
In a normal method, this is the object before the dot.
✗ "if (obj.prop) tells me whether the property exists."
A property holding 0, "" or false exists but fails the test.
✓ "'prop' in obj answers 'is it there?'"
Or obj.hasOwnProperty("prop") for the object's own properties only.

Exam-style checks

Answer each one before opening it. For the "what does this print?" questions, trace the code on paper first, drawing arrows for every object.

Which line correctly creates an object with two properties?L1

  • B. const s = { name: "Asha", marks: 82 };
  • C. const s = [ name: "Asha", marks: 82 ];
  • D. const s = { name: "Asha"; marks: 82 };

Answer: B. A colon joins each key to its value and a comma separates the properties. A uses equals signs, C uses the square brackets of an array, which cannot hold key: value pairs, and D uses a semicolon between the properties. All three are SyntaxErrors.

What does this print?

  • D. K23 undefined

Answer: C. s.key asks for the property literally named key, which is "K23". s[key] uses the variable's value, "marks", as the key, giving 82. A is the trap for anyone who thinks the dot reads the variable.

In which situation must you use bracket notation instead of the dot?L2
  • A. When the object was declared with const
  • B. When the property's value is a number
  • C. When the property is a method
  • D. When the key is stored in a variable, such as const field = "city";

Answer: D. Only brackets evaluate what is inside them, so obj[field] reads the property named by the variable. The other case that needs brackets is a key that is not a valid name, such as obj["full name"]. const, number values and methods make no difference.

Answer: {marks: 75}. The first assignment adds marks because the key is new, the second updates it because the key now exists, and delete removes name completely. const does not stop any of this, because the variable s is never reassigned.

Quick revision

Key takeaways

  1. An object groups facts about one thing as key: value properties inside { }. Keys are strings; values can be anything, including arrays, other objects and functions (methods).
  2. Read with the dot (obj.key) when the name is fixed and valid; use brackets for keys in variables or keys with spaces (obj[field], obj["full name"]). A missing property is undefined, not an error.
  3. Assigning adds a new key or updates an existing one; delete removes one. const locks the variable, not the contents. Test existence with "key" in obj or hasOwnProperty, never with if (obj.key).
  4. Read nested chains left to right, student.address.city. ?. stops safely at null or undefined. Arrays of objects are the everyday shape of real data.
  5. In a method, this is the object before the dot. Arrow functions have no this of their own, so do not use them as methods.
  6. for...in gives each key; Object.keys, Object.values and Object.entries give arrays you can loop over or count.
  7. = copies a reference (one object, two names); { ...obj } is a shallow copy; structuredClone is a deep copy; === compares references, not contents.
  8. A constructor function called with new builds objects of one shape; shared methods go on its prototype, and class is the modern syntax for the same idea. JSON.stringify and JSON.parse turn objects into text and back.
