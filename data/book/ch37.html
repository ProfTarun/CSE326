Responsive Web Design

More than half the people who will ever open your page are holding a phone. Responsive design is using HTML and CSS to make one page automatically resize, hide, shrink or enlarge itself so it works on a phone, a tablet and a monitor. Chapter 21 prepared the HTML; this chapter is the CSS half.

About 21 minutes · Course outcome CO3

Before you start — one-line reminders

  • The viewport meta tag makes a phone use its real width (Chapter 21).
  • %, rem, vw and vh are relative units (Chapter 25).
  • max-width lets a box shrink; width does not (Chapter 28).
  • Flexbox wraps with flex-wrap; Grid adapts with auto-fit (Chapters 30 and 31).

By the end of this chapter you can

  • Write the viewport meta tag and say what breaks without it.
  • Write a media query and read min-width and max-width correctly.
  • Explain mobile-first and why it produces simpler CSS.
  • Choose sensible breakpoints, and know when you need none at all.
  • Make images, text and layouts flexible, and test the result.

37.1 The one line without which nothing works

Before any CSS, the HTML must carry this in its <head>:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Mobile browsers were built when every page was a desktop page, so by default they pretend to be about 980 pixels wide, lay your page out at that width and shrink the result to fit the screen. The reader gets a perfect miniature of a desktop site and has to pinch to read anything.

Worse for this chapter: your media queries then measure the wrong width. The browser believes it is 980px wide, so a rule written for screens under 600px never fires. If your media queries are being ignored on a phone, this missing tag is almost certainly why — not a missing reset, not a missing doctype, not a missing display: flex.

37.2 Media queries

A media query wraps a block of CSS in a condition. The rules inside apply only when the condition is true:

@media (min-width: 700px) {
  .layout { display: flex; }
}

Read it literally: "when the viewport is at least 700 pixels wide, make .layout a flex container." Below 700px the rule simply does not exist, so the layout stays stacked.

min- and max- are easy to get backwards. min-width sets a minimum the screen must reach — so it targets big screens. max-width sets a maximum, so it targets small ones. Say "min means from this width up" out loud a few times.

  }

  }
</style>

37.3 Mobile-first

Mobile-first means writing the phone layout as the default CSS — no media query at all — and then adding with min-width queries as the screen gets bigger.

Three reasons it is the standard approach:

  • Simpler CSS. A phone layout is usually one column, which is close to what HTML does anyway. Adding columns for a wide screen is a short rule; undoing a desktop layout for a phone means cancelling several.
  • Phones do the least work. The device with the slowest connection and the smallest battery gets the smallest set of rules.
  • It forces you to prioritise. If it has to fit a 375px screen, you find out quickly what actually matters.

Note what mobile-first is not: it does not mean designing for phones and discarding the desktop, and it is not only about testing on a phone first.

37.4 Breakpoints

A breakpoint is the width at which your layout changes. Common starting values:

BreakpointRoughlyTypical change
(no query)Phones, up to ~600pxOne column, stacked navigation
min-width: 600pxLarge phones, small tabletsTwo columns of cards
min-width: 900pxTablets, small laptopsSidebar appears beside the content
min-width: 1200pxDesktopsWider gutters, a maximum content width

Treat those as a starting point, not a law. The professional habit is to let the content choose the breakpoint: widen the browser slowly and add a query at the width where the design starts to look wrong. Chasing particular device sizes is a losing game — there are hundreds, and new ones every year.

The best breakpoint is often no breakpoint. repeat(auto-fit, minmax(200px, 1fr)) in Grid (Chapter 31) and flex-wrap: wrap with flex: 1 1 200px in Flexbox (Chapter 30) both adapt continuously, at every width, with no query at all. Reach for a media query when something must genuinely change, not merely resize.

37.5 Flexible everything

Images and media

One rule keeps every image inside its box:

img, video, iframe {
  max-width: 100%;
  height: auto;       /* keep the proportions */
}

Without it, a 1200px-wide photo pushes the whole layout sideways on a 375px phone and produces a horizontal scrollbar. Chapter 8's srcset then goes further and downloads a smaller file rather than merely scaling a large one.

Containers

.page {
  max-width: 1100px;   /* never absurdly wide on a big monitor */
  margin: 0 auto;      /* centred                               */
  padding: 0 16px;     /* never touching the screen edge        */
}

Those three lines are a complete, responsive page wrapper. No media query needed.

Fluid type with clamp()

clamp(minimum, ideal, maximum) lets a value scale smoothly but never go silly:

h1 { font-size: clamp(1.75rem, 5vw, 3rem); }

Read it as: "never smaller than 1.75rem, never bigger than 3rem, and in between grow with the window." One line replaces three media queries, and unlike plain vw it cannot become unreadable on a narrow phone (Chapter 25).

Hiding things — carefully

@media (max-width: 599px) {
  .desktop-only { display: none; }
}

Legitimate for a decorative image or a duplicate navigation. Not legitimate for content a phone user needs. "They are on a phone so they will not want the contact details" has never once been true.

37.6 Build it: the responsive profile page

<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>Asha Kumar</title>
<style>
  * { box-sizing: border-box; }
  img { max-width: 100%; height: auto; }

  body { font-family: system-ui, sans-serif; margin: 0; background: #F1F5F9;
         color: #3C4A60; line-height: 1.7; }
  .page { max-width: 1000px; margin: 0 auto; padding: 16px; }

  h1 { font-size: clamp(1.6rem, 5vw, 2.5rem); color: #0B2545; margin: 0 0 4px; }

  /* MOBILE FIRST: everything stacks, no query needed */
  .layout { display: grid; gap: 16px; }
  .panel  { background: #fff; border-radius: 12px; padding: 16px;
            box-shadow: 0 2px 8px rgba(16,32,64,.08); }

  /* the cards adapt with NO media query at all */
  .cards { display: grid; gap: 12px;
           grid-template-columns: repeat(auto-fit, minmax(150px, 1fr)); }
  .cards div { background: #FFF8F0; border: 1px solid #F0C79A;
               border-radius: 8px; padding: 12px; font-size: 14px; }

  /* ADD a sidebar only when there is room for one */
  @media (min-width: 720px) {
    .layout { grid-template-columns: 260px 1fr; align-items: start; }
  }
</style>
</head>
<body>
<div class="page">
  <h1>Asha Kumar</h1>
  <div class="layout">
    <div class="panel">
      <b>About</b>
      <p style="font-size:14px;margin:6px 0 0">B.Tech Computer Science, first year.
      Drag this preview narrow and wide.</p>
    </div>
    <div class="panel">
      <b>Courses</b>
      <div class="cards" style="margin-top:10px">
        <div>CSE326</div><div>CSE305</div><div>CSE201</div><div>MTH101</div>
      </div>
    </div>
  </div>
</div>
</body>
</html>

Count the media queries: one. Everything else adapts by itself, because the units are relative, the images are capped, the grid uses auto-fit and the heading uses clamp().

Testing

  1. Press F12, then Ctrl+Shift+M for the device toolbar, and drag the width slowly. Watch for the moment the design breaks — that is where your next breakpoint goes.
  2. Check for a horizontal scrollbar at 375px. If there is one, something has a fixed width or an image is uncapped.
  3. Open it on a real phone. Emulators do not reproduce touch targets, real keyboards or a slow connection.
  4. Zoom the browser to 200%. Text should reflow, not disappear.

Exam-style checks

Your media queries are ignored on a phone. What is almost certainly missing?L3
  • A. A CSS reset
  • B. The viewport meta tag
  • C. display:flex
  • D. A doctype

Answer: B. Without width=device-width the phone pretends to be a 980px desktop, so the queries measure the wrong width.

What does 'mobile-first' mean in practice?L2
  • A. Design for phones then discard the desktop
  • B. Write the phone layout as the default, then ADD with min-width queries
  • C. Use max-width queries only
  • D. Test on a phone first

Answer: B. It produces simpler CSS, and phones do the least work.

@media (min-width: 700px) applies when the screen is:L2
  • A. Narrower than 700px
  • B. 700px or wider
  • C. Exactly 700px
  • D. Any size

Answer: B. min-width means "from this width upward", so it targets bigger screens.

Write the viewport meta tag from memory.L1

<meta name="viewport" content="width=device-width, initial-scale=1.0"> — in the <head> of every page.

Which rule stops a large image breaking a phone layout?L2

img { max-width: 100%; height: auto; } — the image can never be wider than its container, and keeps its proportions.

Which layout technique adapts to any width with NO media query?L3

grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)), or Flexbox with flex-wrap: wrap and flex: 1 1 200px. Both recalculate continuously as the window changes.

What does font-size: clamp(1.75rem, 5vw, 3rem) do?L3

Never smaller than 1.75rem, never larger than 3rem, and between those it grows with the viewport width. It replaces several media queries and avoids plain vw's habit of becoming unreadable on a narrow screen.

A designer wants the contact details hidden on phones "to save space". What do you say?L3

No. Hiding with display: none is fine for decoration or a duplicated menu, never for content a phone user needs — and contact details are among the things people most often look for on a phone. Make it fit instead.

How do you choose where to put a breakpoint?L3

Let the content decide. Widen the browser slowly and add a query at the width where the design starts to look wrong. Chasing specific device widths fails, because there are hundreds and more arrive every year.

Name three things to check before calling a page responsive.L2

No horizontal scrollbar at 375px; text readable without zooming; every control large enough to tap. Add: it works at 200% zoom, and you tried it on a real phone rather than only an emulator.

Quick revision

Key takeaways

  1. The viewport meta tag is compulsory. Without it a phone pretends to be 980px wide and your media queries measure the wrong width.
  2. @media (min-width: 700px) applies from 700px upwards; max-width applies downwards.
  3. Mobile-first: the phone layout is the default, and min-width queries add to it. Less CSS, less work for phones.
  4. Let the content choose the breakpoints. Often the best number of breakpoints is zero: auto-fit grids and wrapping flex rows adapt on their own.
  5. img { max-width: 100%; height: auto; }, a max-width page wrapper, and clamp() for headings cover most of the rest.
  6. Test by dragging the width, at 375px, at 200% zoom, and on a real phone.
