6. What to do when you are stuck

Freshers usually get stuck in one of four ways. Each one has a different cure, and reaching for the wrong cure is why an hour disappears.

What it feels likeWhat is actually wrongDo this
“My CSS is doing nothing at all.” The browser never received the file, or the selector matches nothing. Open DevTools → Elements, click the element, read the Styles panel. If your rule is not listed, it never matched. Chapter 22, section 6.
“My rule is there but crossed out.” Another rule won the cascade. Specificity. Chapter 23, and the Specificity Calculator above.
“The spacing is wrong and I cannot see why.” Box model, or two margins collapsing into one. Chapter 28. Hover the element in DevTools — the coloured overlay shows you margin, border, padding and content separately.
“It breaks only on my phone.” A fixed pixel width, or a missing viewport meta tag. Chapter 37. Then resize the browser slowly and watch where it snaps.
The five-minute rule. If you have been stuck for five minutes, stop reading your code and open DevTools instead. The browser will tell you what it actually did, which is almost never what you assumed. Guessing for thirty minutes is the single most common way students lose an evening.

How to actually use a reference page

Key takeaways

  1. Read the textbook to learn something the first time. Read a reference to check a detail you have already met.
  2. Reading a reference top to bottom is almost always wasted time. Arrive with a question; leave when you have the answer.
  3. MDN is the truth. W3Schools is the friendliest. web.dev is the most modern. CSS-Tricks has the best diagrams. Use the one that matches your mood, not the first Google result.
  4. The four puzzle games in section 2 will teach you more in one evening than a week of re-reading. Do them.
  5. When a reference and this textbook disagree, the browser decides. Test it.
