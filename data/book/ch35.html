Form Styling

Forms are where your visitor actually does something, and untouched they are the ugliest part of any page: mismatched fonts, boxes of different heights, a submit button that looks like it came from another decade. Four declarations fix most of it. This chapter covers those four, then the states, the controls that resist styling, and the accessibility rules you must not break.

About 22 minutes · Course outcome CO3

Before you start — one-line reminders

  • A <label> is joined to its control by for matching the control's id (Chapter 16).
  • input types: text, email, password, checkbox, radio, submit (Chapter 17).
  • :focus, :checked, :valid and :invalid style form states (Chapter 32).
  • box-sizing: border-box makes width include padding and border (Chapter 28).

35.1 Why forms look wrong to begin with

Form controls are not ordinary elements. The operating system draws them, which is why a dropdown looks different on Windows, on a Mac and on Android. Two consequences follow, and they are the reason your form looks untidy:

  • Controls do not inherit your font. font-family and font-size are inherited properties, but browsers deliberately reset them on form controls. Your beautiful page font stops dead at the edge of every input.
  • Controls have their own default padding and borders, which differ between browsers, so an input and a button of the same nominal size come out different heights.

The four lines that fix almost everything

input, select, textarea, button {
  font: inherit;              /* 1. use the page's font, at the page's size */
  box-sizing: border-box;     /* 2. width means the whole box              */
  padding: 10px 12px;         /* 3. the same breathing room for all        */
  border-radius: 8px;         /* 4. one shape                               */
}

font: inherit is the one that produces the gasp. One declaration and every field, dropdown and button suddenly belongs to your page.

<style>
  body { font-family: Georgia, serif; font-size: 16px; padding: 12px; }
  h3 { font-size: 15px; margin: 14px 0 6px; }

  .fixed input, .fixed select, .fixed button {
    font: inherit;
    box-sizing: border-box;
    padding: 10px 12px;
    border: 2px solid #CBD5E1;
    border-radius: 8px;
  }
  .fixed button { background: #0B2545; color: #fff; border-color: #0B2545; }
</style>
<h3>Untouched</h3>
<div>
  <input placeholder="Your name">
  <select><option>Choose a course</option></select>
  <button>Register</button>
</div>
<h3>With the four lines</h3>
<div class="fixed">
  <input placeholder="Your name">
  <select><option>Choose a course</option></select>
  <button>Register</button>
</div>

Same HTML both times. The second group simply agreed to join the page.

35.2 Laying out the fields

A form reads best as a single column: label above field, generous spacing, full-width inputs. It is easier to scan, and it survives a phone screen without any extra work.

label {
  display: block;            /* put the label on its own line   */
  font-weight: 700;
  margin-bottom: 4px;
}
input, select, textarea {
  width: 100%;               /* fill the column                  */
  margin-bottom: 16px;       /* space before the next field      */
}

width: 100% only behaves if box-sizing: border-box is in force — otherwise the padding is added on top and the field pokes out of its container (Chapter 28). This is the single commonest form-styling bug.

For two fields side by side, use Flexbox (Chapter 30):

.row { display: flex; gap: 14px; }
.row > div { flex: 1; }     /* each half takes an equal share */

And <fieldset> with <legend> (Chapter 16) groups related fields. Its default border is dated; most designers replace it:

fieldset { border: 1px solid #E3E9F0; border-radius: 12px; padding: 16px; }
legend   { font-weight: 800; color: #0B2545; padding: 0 8px; }

35.3 States: focus, hover, validity

A form should answer three questions at a glance: where am I, what can I press, and is what I typed acceptable. Three groups of rules.

Focus — not optional

input:focus, select:focus, textarea:focus {
  outline: 3px solid #FF9933;
  outline-offset: 2px;
  border-color: #E07B1E;
}

As Chapter 32 insisted: you may replace the browser's focus ring, never simply delete it. Because outline takes no space (Chapter 28), a focus ring never nudges your layout.

Hover and press on buttons

button { cursor: pointer; background: #0B2545; color: #fff; border: none; }
button:hover  { background: #1B3A63; }
button:active { transform: translateY(1px); }   /* it presses down */
button:disabled { background: #CBD5E1; cursor: not-allowed; }

cursor: pointer matters more than it looks. Without it a styled <button> does not feel clickable, because the mouse pointer never changes.

Validity feedback

The browser already knows whether a field is acceptable (Chapter 18). You only have to show it:

input:valid   { border-color: #138808; }
input:invalid:not(:placeholder-shown) { border-color: #C42B2B; background: #FDF0F0; }

Remember the :not(:placeholder-shown) guard, or an untouched required field is red before the user has typed anything.

Colour is never enough. A red border alone is invisible to many colour-blind users. Pair it with a message, an icon, or text such as "Enter a valid email address". WCAG requires that information is not conveyed by colour alone (Chapter 20).

35.4 The awkward controls

Checkboxes and radios — the easy way

These two are drawn by the operating system and ignore background and border. For years the only way to recolour them was to hide the real control and build a fake one. Today there is one property:

input[type="checkbox"], input[type="radio"] {
  accent-color: #E07B1E;    /* recolours the tick and the dot */
  width: 18px; height: 18px;
}

accent-color also works on <input type="range"> and <progress>. It keeps every bit of the native behaviour — keyboard support, screen-reader announcements, the lot — which a hand-built fake control usually loses.

If a design truly demands a custom shape, the accepted technique is appearance: none on the input plus a styled ::before. Do it only when you must, and test it with the keyboard afterwards.

select

The closed box is yours to style; the open dropdown list is drawn by the operating system and cannot be styled with CSS. Accept that, and style the box only:

select {
  appearance: none;                    /* remove the OS arrow  */
  background-image: url("data:image/svg+xml,...");  /* draw your own */
  background-repeat: no-repeat;
  background-position: right 12px center;
  padding-right: 36px;                 /* leave room for it     */
}

textarea

Two useful additions: resize: vertical stops users dragging it sideways out of your layout, and min-height gives it a sensible starting size.

textarea { resize: vertical; min-height: 120px; }

File inputs

<input type="file"> is the least styleable control there is. The usual approach is to hide it and style the <label> that points at it, since clicking a label activates its control.

Every control has a real <label> with for/idA placeholder disappears as soon as typing starts (Chapter 15)

A form can be beautiful and accessible at the same time; they are not in tension. Nearly everything in the table is a line or two of CSS, and the one rule that is HTML — use a real label — you already learned in Unit 2.

35.6 Build it: the contact form

This is the contact section of the project, and it is the kind of form a lab task asks for: labelled fields, a textarea, a styled submit button, visible focus, and validity feedback.

<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>Contact</title>
<style>
  * { box-sizing: border-box; }
  body { font-family: system-ui, sans-serif; background: #F1F5F9;
         color: #3C4A60; padding: 20px; }

  form { max-width: 420px; margin: 0 auto; background: #fff;
         padding: 22px; border-radius: 14px;
         box-shadow: 0 2px 10px rgba(16,32,64,.08); }
  h2 { margin: 0 0 4px; color: #0B2545; }
  .hint { margin: 0 0 18px; font-size: 14px; color: #6B7A90; }

  /* the four lines that make controls belong to the page */
  input, select, textarea, button {
    font: inherit;
    padding: 10px 12px;
    border: 2px solid #CBD5E1;
    border-radius: 8px;
    width: 100%;
  }
  label { display: block; font-weight: 700; font-size: 14px;
          margin: 14px 0 4px; color: #0B2545; }
  .req::after { content: " *"; color: #C42B2B; }

  textarea { resize: vertical; min-height: 110px; }

  /* states */
  input:focus, select:focus, textarea:focus, button:focus-visible {
    outline: 3px solid #FF9933; outline-offset: 2px; border-color: #E07B1E;
  }
  input:invalid:not(:placeholder-shown) { border-color: #C42B2B;
                                          background: #FDF0F0; }
  input:valid:not(:placeholder-shown)   { border-color: #138808; }
  input::placeholder, textarea::placeholder { color: #9AA8BC; }

  button {
    margin-top: 18px; cursor: pointer;
    background: #0B2545; color: #fff; border-color: #0B2545;
    font-weight: 700;
  }
  button:hover  { background: #1B3A63; }
  button:active { transform: translateY(1px); }
</style>
</head>
<body>
<form>
  <h2>Contact Asha</h2>
  <p class="hint">Fields marked * are required.</p>

  <label class="req" for="email">Email</label>
  <input id="email" name="email" type="email" required placeholder="you@example.edu">

  <label for="phone">Phone</label>
  <input id="phone" name="phone" type="tel" placeholder="+91 ...">

  <label class="req" for="msg">Message</label>
  <textarea id="msg" name="message" required placeholder="How can I help?"></textarea>

  <button type="submit">Send message</button>
</form>
</body>
</html>

Run it and try three things: click into a field and watch the focus ring; type two letters into the email box and watch the border turn red, then finish the address and watch it turn green; press Tab all the way to the button and confirm you can always see where you are.

Exam-style checks

Why do form controls not use the font you set on body?L3

Because browsers deliberately reset font on form controls so they match the operating system's widgets. The fix is one declaration: input, select, textarea, button { font: inherit; }.

An input with width: 100% sticks out past its container. What is missing?L3

box-sizing: border-box. Without it, width: 100% sizes the content only, and the padding and border are added on top (Chapter 28). It is the most common form-styling bug.

Which property recolours a checkbox or radio button without replacing it?L2

accent-color. It keeps all the native keyboard and screen-reader behaviour, which a hand-built replacement usually loses.

Which part of a <select> cannot be styled with CSS?L3

The open dropdown list of options — that is drawn by the operating system. You can style the closed box, and replace the arrow with appearance: none plus a background image.

Why add cursor: pointer to a styled button?L2

So the mouse pointer changes and the element feels clickable. Without it a styled button reads as ordinary text to a mouse user.

Why should input:invalid usually be written as input:invalid:not(:placeholder-shown)?L3

So an empty required field is not shown as an error before the user has typed anything. An untouched required input is technically invalid from page load.

Is a red border enough to show that a field is wrong?L3

No. Colour must never be the only signal — colour-blind users will not see it. Add a message in words, or an icon, alongside the colour (Chapter 20).

Which declaration stops a textarea being dragged wider than your layout?L2

resize: vertical; — the user can still make it taller, which is genuinely useful, but not wider.

You replaced the browser's focus ring with your own outline. Why does the layout not jump?L2

Because outline is drawn outside the border and takes no space, unlike a border (Chapter 28). That is exactly why browsers chose it for focus.

A designer wants a completely custom checkbox shape. What is the risk?L3

Losing the native behaviour — keyboard operation with Space, the announcement of checked or unchecked state to screen readers, and the label association. Prefer accent-color; if you must build a custom control, test it with the keyboard and a screen reader.

Quick revision

Key takeaways

  1. Form controls ignore your page font by default. font: inherit on input, select, textarea, button is the first fix.
  2. box-sizing: border-box plus width: 100% gives a tidy single-column form; without it fields overflow.
  3. Style the states: :focus (never remove it), :hover and :active on buttons, :valid/:invalid for feedback.
  4. accent-color recolours checkboxes, radios and ranges while keeping native behaviour. A select's open list cannot be styled.
  5. Keep real labels, visible focus, errors in words as well as colour, 4.5:1 contrast and finger-sized targets.
