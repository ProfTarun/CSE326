HTML Elements and Attributes

Elements say what something is; attributes say the details. This chapter catalogues the attributes every element accepts, the ones that belong to particular elements, the special rules for boolean attributes and unique ids, and the block-versus-inline distinction that decides what may be nested inside what.

About 15 minutes · Course outcome CO1 · Builds on Chapter 3

By the end of this chapter you can

  • State the difference between an element and an attribute in one sentence.
  • Use the global attributes id, class, style, title, lang, hidden and data-* correctly.
  • Explain why id must be unique and what breaks when it is not.
  • Recognise boolean attributes and why controls="false" still shows controls.
  • Classify elements as block-level or inline and apply the nesting rules.

5.1 Elements express meaning; attributes configure them

An element tells the browser what a piece of content is: a link, an image, a paragraph. An attribute tells it the specifics: where the link goes, which image file, which language. The summary you should be able to recite: elements express meaning; attributes configure them. They are not interchangeable, and attributes never appear on closing tags.

In <a href="/courses" target="_blank">Web Course</a>, the part target="_blank" is an attribute of the element: not its content (that is "Web Course"), not the closing tag, and not a CSS declaration. Some attributes are required for an element to make sense (href on a link, src and alt on an image); most are optional.

5.2 Global attributes: valid on almost every element

A small set of attributes can be applied to virtually any element. Learn these seven.

id: unique, and dangerous when it is not

The id attribute names one specific element. It is what fragment links point at (<a href="#contact"> jumps to id="contact"), what a <label for="email"> connects to, and what JavaScript uses to find an element. Because all of those look for one element, an id must be unique on the page.

What happens if two elements share id="main"? Nothing visible. The page renders, no error appears. But fragment links and scripts only ever find the first one; the second is silently unreachable. It fails silently, which is far harder to debug than an error, so it is the thing the validator flags first. For a name that should repeat, use class.

class: reusable, and multiple

A class groups elements that share a role or a look. Many elements can carry the same class, and one element can carry several: class="card featured" is two classes. CSS (Unit 3) selects classes with a dot (.card), ids with a hash (#about).

style: inline CSS

style="..." lets you write CSS directly on one element. It works, but it mixes presentation into structure, cannot be reused and overrides your stylesheet, so in real projects you keep CSS in an external file linked from the head (Chapter 12). You will still see inline styles in quick demos, including some in this book.

Notice the pattern that trips up beginners: href is for links, src is for embedded resources. A link points to a place; an image, a video or a script is loaded from a source.

5.4 Boolean attributes: presence is everything

Some attributes are switches rather than settings: required, disabled, checked, selected, readonly, multiple, hidden, autofocus, controls, autoplay, muted, loop, reversed. These are boolean attributes, and the rule is simple but surprising: the browser only checks whether the attribute is present. Its value is ignored.

<input required>           ← required
<input required="required"> ← also required
<input required="false">    ← STILL required: the attribute is present
<input>                    ← not required: the attribute is absent

So <video controls="false"> shows the controls anyway. To switch a boolean attribute off you remove it entirely. This catches people who come from programming languages where false means off.

5.5 Block-level and inline elements

Every element has a default way of flowing on the page. Block-level elements start on a new line and stretch across the full available width, stacking like bricks: <div>, <p>, <h1>–<h6>, <ul>, <ol>, <li>, <section>, <article>, <header>, <footer>, <form>, <table>, <blockquote>, <pre>, <hr>. Inline elements flow within a line of text and take only the width of their content: <span>, <a>, <strong>, <em>, <b>, <i>, <code>, <img>, <abbr>, <label>, <input>, <br>.

The nesting rules that follow

  • Inline elements go inside block elements, not the other way round. <p><span>Hi</span></p> is valid; <span><p>Hi</p></span>, <em><div>Hi</div></em> and <strong><h1>Hi</h1></strong> are not.
  • A <p> may hold only text and inline elements. If the parser meets a block element inside it, such as <div>, the paragraph is closed automatically before the div, leaving an empty p and stray text: a confusing bug to trace.
  • Inline elements ignore width and height. Set width: 200px on a <span> and nothing happens, because an inline box is sized by its content. Make it display: inline-block or display: block in CSS if it needs a width.
<style>
  .b { background: #FFF1E0; }            /* just to make the boxes visible */
  span.wide { width: 200px; background: #E9F7E7; }   /* ignored: inline */
  span.fixed { width: 200px; background: #E9F7E7; display: inline-block; }
</style>
<div class="b">A div takes the whole line.</div>
<p class="b">A paragraph too. But <span class="wide">this span</span> ignores width,
while <span class="fixed">this inline-block span</span> respects it.</p>

5.6 The generic containers: div and span

Two elements carry no meaning at all; they exist purely to group things so that CSS or JavaScript can get hold of them. <div> is the generic block-level container (it takes the full available width). <span> is the generic inline container (it takes only its content's width), used to target a few words inside a line.

<div style="border: 2px solid #E07B1E; padding: 8px;">
  <p>Hello <span style="color: #138808; font-weight: bold;">Students</span>, welcome.</p>
</div>

Use them only when no meaningful element fits. A generic styling wrapper with no independent meaning is exactly what <div> is for. A copyright notice belongs in <footer>, the main menu in <nav>, a blog post in <article>; wrapping those in divs throws away meaning that screen readers and search engines could have used (Chapter 13).

Quick revision

Key takeaways

  1. Elements express meaning; attributes configure them. Attributes are name="value" pairs in the opening tag, always quoted.
  2. Global attributes: id (unique), class (reusable, multiple), style (inline CSS), title (tooltip), lang, hidden, data-*.
  3. Duplicate ids fail silently: fragment links and scripts find only the first.
  4. href is for links; src is for embedded resources; alt describes an image; width/height set displayed size.
  5. Boolean attributes are on when present, whatever their value: controls="false" still shows controls.
  6. Block elements (div, p, h1, section, ul) stack full-width; inline elements (span, a, strong, em, img) flow in the line, ignore width/height, and must sit inside block elements. A p auto-closes before a div.
  7. div and span are meaningless containers: use them only when no semantic element fits.
