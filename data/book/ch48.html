Functions

Every program you have written so far runs from top to bottom once and stops. A function changes that. You write a job once, give it a name, and run it whenever you like, with different values each time. Every real JavaScript program is built out of functions, and from Chapter 53 onwards you will pass them around as easily as numbers.

About 30 minutes · Course outcome CO4

Before you start — one-line reminders

  • const and let create named variables; names use letters, digits, _ and $, written in camelCase (Chapter 42).
  • An expression works out to one value, and + joins text as soon as a string is involved (Chapter 44).
  • Template literals in backticks drop values into text with ${ } (Chapter 45).
  • if and else choose which lines run, and a grade ladder checks the highest band first (Chapter 47).

By the end of this chapter you can

  • Give three reasons to put code in a function.
  • Write a function declaration, call it, and point to its name, parameters, body and return.
  • Tell parameters from arguments, and predict what happens with missing, extra and default arguments.
  • Explain the difference between returning a value and logging it, and say when a call gives undefined.
  • Write the same function as a declaration, a function expression and an arrow function, including implicit return and returning an object.
  • Tell f from f(), and hand a function to another function.

48.1 Why functions?

You have been using functions since Chapter 41. console.log("Hi") is a call to a function. So are Number("40"), Math.round(4.6) and "asha".toUpperCase(). Somebody wrote each of them once, gave it a name, and now millions of programs run it with one short line. In this chapter you learn to write your own.

Start with a problem. A campus shop adds 18% GST to each price. Without functions, the formula is copied for every item:

const bookTotal = 450 + 450 * 18 / 100;     // 531
const lampTotal = 200 + 200 * 18 / 100;     // 236
const bagTotal  = 1200 + 1200 * 18 / 100;   // 1416

It works. But when the rate changes to 12%, there are three lines to edit, and if you miss one, one price is quietly wrong. With a function, the formula is written once:

function withGst(price) {
  return price + price * 18 / 100;
}

const bookTotal = withGst(450);    // 531
const lampTotal = withGst(200);    // 236
const bagTotal  = withGst(1200);   // 1416

That small change shows the three reasons functions exist:

  • Reuse. Write the steps once and run them as often as you like, for three items or three thousand.
  • A name for a task. withGst(450) says what it does. A program made of well-named functions reads almost like sentences.
  • One place to fix. When GST changes, you edit one line inside withGst, and every price that uses it is right at once.
Picture this. The hostel mess keeps a recipe card for chai: for N cups, boil N cups of water with N spoons of tea leaves, then add milk and sugar. Writing the card once is defining a function, and the blank N is its parameter. Each time the cook makes chai, the card is called with a real number — 2 cups at breakfast, 40 for the evening crowd — and that number is the argument. The cups handed over the counter are the return value. Improve the card once (less sugar) and every pot from then on is better. And a cook who only shouts "chai is ready!" without handing you a cup has given you news, not chai. Keep that cook in mind for section 48.4.

48.2 Writing and calling a function

Here is the first example from your lecture slides. It is a function declaration: a statement that creates a function and gives it a name.

function add(a, b) {
  return a + b;
}

// Invocation
const sum = add(5, 3);
console.log("Function Declaration - Sum:", sum);   // Function Declaration - Sum: 8

Read the first three lines piece by piece:

  • function is a keyword. It tells JavaScript that a function definition starts here.
  • add is the function's name. The rules for variable names apply (Chapter 42).
  • (a, b) are the parameters: names for the values the function will be given. The round brackets are compulsory, even when they are empty.
  • The curly braces hold the body, the instructions that run each time the function is used.
  • return a + b; works out a + b and hands the answer back (section 48.4).

Writing the declaration does not run it. It only stores the instructions under the name add, like writing a recipe card and putting it in a drawer. Nothing happens until a line calls the function by writing its name followed by round brackets: add(5, 3). The slides call this the invocation. JavaScript then jumps into the body, runs it from the top with a as 5 and b as 3, and comes back with the answer.

You can call a function as many times as you like, and each call starts the body afresh. Good names begin with a verb, because a function does something: calculateTotal, showMessage, formatName. A function that answers yes or no usually starts with is, has or can, as in isPassed or hasPaid.

Quick check: you wrote a function, pressed Run, and nothing appeared in the Console. What is the most likely reason?

You defined it but never called it. A definition only stores the instructions. Add a call — the name plus round brackets, such as showResult(); — on a line after the definition.

48.3 Parameters and arguments

Two words are used for the values in brackets, and examiners expect you to keep them apart:

  • A parameter is a name written in the definition: a and b in function add(a, b). It is a variable that exists only inside the function, while it runs.
  • An argument is the actual value written in the call: 5 and 3 in add(5, 3).

When the call happens, each argument is copied into the parameter in the same position: the first argument into the first parameter, the second into the second. Names play no part in the matching; only the order does.

A parameter is a blank on a form; an argument is what you write in the blank. The function is written once, with blanks. Every call fills the blanks in again, left to right.

Exam tip. Parameter = Placeholder, in the definition. Argument = Actual value, in the call. In area(4, 3) the arguments are 4 and 3; the parameters are whatever names the definition uses.

Order matters, and the count is not checked

Because matching is by position, swapping two arguments silently gives a wrong answer. With percentage(obtained, total), the call percentage(60, 75) is 80, but percentage(75, 60) is 125. JavaScript also never complains about the number of arguments. Pass too few and the missing parameters hold undefined, so area(12) works out 12 * undefined, which is NaN. Pass too many and the extras are ignored.

Default parameters

You can give a parameter a default value with = in the definition. The default is used when that argument is missing, or is undefined:

function percentage(obtained, total = 100) {
  return obtained * 100 / total;
}
percentage(85);       // 85   total was left out, so it is 100
percentage(60, 75);   // 80   total is 75 this time

A default does not replace other empty-looking values. greet(""), greet(0) and greet(null) each pass a real value, so the default stays unused. This is stricter than ?? from Chapter 44, which also replaces null. Put parameters with defaults last, so the ones that must always be given come first.

Any number of arguments: rest parameters

Math.max(85, 92, 78) accepts as many numbers as you give it. Your own function can do the same with a rest parameter: three dots before the last parameter's name. It gathers all the remaining arguments into one array (Chapter 50), which has a length just as a string does:

function register(course, ...students) {
  return course + " has " + students.length + " students";
}
register("CSE326", "Asha", "Rahul", "Meera");   // "CSE326 has 3 students"

Only the last parameter can be a rest parameter, and there can be only one. Adding up everything it collected needs a loop (Chapter 52) or reduce (Chapter 53).

Quick check: in function area(length, width) { ... } called as area(4, 3), which are the parameters and which are the arguments?

length and width are the parameters, because they are written in the definition. 4 and 3 are the arguments, because they are the values in the call. Inside that call, length is 4 and width is 3.

48.4 return: handing the answer back

return does two jobs at once:

  1. It hands a value back to the place where the function was called. The call add(5, 3) is an expression (Chapter 44), and its value is whatever the function returned: 8. Any type can be returned — a number, a string, a boolean.
  2. It ends the function immediately. Any lines after it, in that run, are skipped.
Key idea. When the function returns, the call is replaced by the returned value. So a call can go anywhere a value can: add(5, 3) * 2 is 16, `Total: ${add(5, 3)}` is "Total: 8", and add(add(1, 2), 3) passes one call's answer into another.

return is not console.log

This is the commonest confusion for beginners, because in the Console both seem to "give the answer". Compare two functions that look almost the same:

function addAndShow(a, b) {
  console.log(a + b);     // shows the answer in the Console
}

function addAndGive(a, b) {
  return a + b;           // hands the answer back to the caller
}

const x = addAndShow(5, 3);   // the Console shows 8, but x is undefined
const y = addAndGive(5, 3);   // the Console shows nothing, and y is 8

console.log writes text into the Console for a person to read. The program itself gets nothing back. So when you need the answer for anything else — storing it, adding to it, comparing it, putting it on the page — the function must return it. In the recipe card picture, console.log is the cook shouting "chai is ready!"; return is the cup put into your hand.

console.log talks to you, the programmer watching the Console. return talks to the rest of the program. A function that calculates something should return it, and let whoever called it decide whether to print it.

No return means undefined

Every call gives back some value. If the body ends without reaching a return, or reaches a bare return; with no value, the call gives undefined. That explains a puzzle you will meet often: console.log(addAndShow(2, 3)) prints two lines, 5 and then undefined. The inner call prints 5 itself and returns nothing; the outer console.log then prints that nothing.

return ends the function

Because return leaves at once, a decision often needs no else (Chapter 47):

function result(marks) {
  if (marks >= 40) {
    return "Pass";
  }
  return "Fail";      // reached only when marks is below 40
}

For 72, the first return runs and the function is over, so the last line is never reached. For 35, the condition is false and JavaScript carries on to return "Fail". Leaving early like this is called an early return, or a guard.

Keep the value on the same line as return. If you press Enter straight after the word return, JavaScript ends the statement at the line break and returns undefined. The value on the next line is never reached, and no error warns you. Write return a + b; on one line, or open a bracket on the return line, return (, when the expression is long.

48.5 Function expressions: a function is a value

The second slide writes a function a different way:

const multiply = function (a, b) {
  return a * b;
};

// Invocation
const product = multiply(4, 6);
console.log("Function Expression - Product:", product);   // Function Expression - Product: 24

This is a function expression. The word function now appears where a value is expected, on the right of =, so it creates a function as a value, and const stores that value in the variable multiply. There is no name after the word function: the function is anonymous, and you reach it through the variable. The semicolon after the closing brace ends the const statement, exactly as in const price = 450;.

You call it the same way, multiply(4, 6), and inside it works exactly like a declaration. The one practical difference: a function declaration can be called even on a line above the one where it is written, while a function expression cannot be used until its line has run and the variable holds the function. Chapter 49 explains why; the word is hoisting. Use const for function expressions, so the name cannot be pointed at something else by accident.

f or f(): referring and calling

The function expression makes one fact plain: a function is a value, just as 24 and "Asha" are. So there are two very different things you can write:

You writeIt meanstypeof gives
multiplyThe function itself: the recipe card, not yet used"function"
multiply(4, 6)Run it now; the value is whatever it returns, 24"number"

Because a function is a value, you can store it in another variable (const times = multiply; gives the same function a second name), and you can hand it to another function as an argument. The function that receives it can call it whenever it wants:

function doTwice(task) {
  task();
  task();
}
function cheer() {
  console.log("Well played!");
}
doTwice(cheer);     // prints "Well played!" twice

doTwice(cheer) hands over the function itself, and doTwice runs it twice. doTwice(cheer()) is a different instruction. The brackets make cheer run right now, once, and what gets handed over is its return value, undefined. When doTwice then tries task(), the result is TypeError: task is not a function. People make exactly this slip with buttons in Chapter 57, and passing functions around is the whole subject of Chapters 53 and 54.

No brackets: you are talking about the function, like holding up the recipe card. Brackets: you are telling it to run now, and what you get is the finished dish.

48.6 Arrow functions

The third slide uses the shortest form of all:

const subtract = (a, b) => a - b;

// Invocation
const difference = subtract(8, 3);
console.log("Arrow Function - Difference:", difference);   // Arrow Function - Difference: 5

An arrow function is a shorter way to write a function expression. The symbol =>, an equals sign and a greater-than sign with no space between them, is read "gives": a and b give a minus b. Figure 48.3 builds it from the function expression in two steps.

Step 2 works only when the whole body is one expression. Then the braces and the word return are left out, and the value of that expression is returned automatically. This is called an implicit return, and a body without braces is a concise body. When a function needs several lines of work, keep the braces — and with braces you must write return yourself, as in any other function.

An arrow function is a function expression with the word function taken out and => added after the brackets. If the whole body is one answer, you may also drop the braces and the word return; JavaScript returns that answer for you.

The bracket rules

SituationWriteNote
Two or more parameters(a, b) => a + bRound brackets required
Exactly one parametern => n * 2Brackets optional; (n) => n * 2 is the same
No parameters() => "Lab day"Empty brackets required
Several lines of work(a, b) => { const t = a + b; return t / 2; }Braces, so return is required
Returning an object() => ({ marks: 90 })Round brackets around the braces
Two traps with braces. First, (a, b) => { a + b } returns undefined: the braces make a block body, and a block body returns only what a return statement hands back. Second, to return an object (Chapter 51) from a concise body, wrap it in round brackets. Without them JavaScript reads the { as the start of a body, not of an object, and you get undefined or a SyntaxError.

<script>
  // the lecture example: an arrow function
  const subtract = (a, b) => a - b;
  const difference = subtract(8, 3);
  console.log("Arrow Function - Difference:", difference);   // Arrow Function - Difference: 5

  // one parameter: brackets optional.  no parameters: empty brackets
  const double = n => n * 2;
  const today = () => "Lab day";
  console.log("double(21):", double(21));   // 42
  console.log("today():", today());         // Lab day

  // braces make a block body, and a block body needs return
  const addRight = (a, b) => { return a + b; };
  const addWrong = (a, b) => { a + b; };
  console.log("With return:", addRight(2, 3));     // 5
  console.log("Forgot return:", addWrong(2, 3));   // undefined

  // several lines of work: braces AND return
  const average = (a, b, c) => {
    const total = a + b + c;
    return total / 3;
  };
  console.log("Average of 80, 64, 51:", average(80, 64, 51));   // 65

  // returning an object: round brackets around the braces
  const makeStudent = (name, marks) => ({ name: name, marks: marks });
  console.log(makeStudent("Meera", 91));    // {name: 'Meera', marks: 91}
</script>

48.7 Writing good functions

A function that works is not automatically a good one. Five habits make functions easy to read, test and reuse:

  1. One job each, and a name that says it. calculateTotal, formatName and isPassed each promise one thing. If the honest name needs the word "and", it is two functions.
  2. Inputs through parameters, answer through return. Do not bake numbers into the body or reach for variables outside it.
  3. Keep it short. If you need to scroll to read a function, it is probably doing several jobs.
  4. Prefer pure functions, explained below.
  5. Copied the same lines twice? Make a function. Programmers call this rule DRY: Don't Repeat Yourself.
// hard to reuse: the numbers are baked in, and it prints instead of returning
function report() {
  console.log("Asha:", 156 * 100 / 200, "%");
}

// easy to reuse: values in, one answer out
function percentage(obtained, total = 100) {
  return obtained * 100 / total;
}

Pure functions and side effects

A pure function has two properties: its answer depends only on its arguments, so the same arguments always give the same answer; and it changes nothing outside itself. add, percentage and withGst are pure. Anything a function changes outside itself — printing to the Console, changing the page, changing an outside variable — is called a side effect.

let total = 0;                   // a variable outside any function

function addToTotal(amount) {    // NOT pure: it changes total, outside itself
  total = total + amount;
}

function addPrices(a, b) {       // pure: same inputs, same answer, nothing else touched
  return a + b;
}

Call addToTotal(50) twice and total is 100: the same call had a different effect the second time. addPrices(40, 25) is 65 today, tomorrow and on every call, which makes it easy to test. Side effects are not wrong — showing results is why programs exist — but keep them in a few clearly named functions and do the calculating in pure ones. The next section is built exactly that way.

Fixing Chapter 45's repeated lines

Chapter 45 capitalised a name with two almost identical lines, one per word, and promised that a function would help. Here it is:

function capitalise(word) {
  return word[0].toUpperCase() + word.slice(1).toLowerCase();
}

const parts = "  aSHA kUMAR ".trim().split(" ");                  // ['aSHA', 'kUMAR']
console.log(`${capitalise(parts[0])} ${capitalise(parts[1])}`);   // Asha Kumar

The rule "capital first letter, small letters after" now lives in one place. Improve it there, and every name in the program benefits.

<script>
  // 1. a greeting with a default parameter
  function greeting(name = "Student") {
    return `Welcome, ${name}!`;
  }

  // 2. a percentage: two values in, one answer out
  function percentage(obtained, total = 100) {
    return obtained * 100 / total;
  }

  // 3. a grade: highest band first, early returns (Chapter 47)
  function gradeFor(percent) {
    if (percent >= 80) {
      return "A";
    }
    if (percent >= 60) {
      return "B";
    }
    if (percent >= 40) {
      return "C";
    }
    return "F";
  }

  // 4. a yes/no question as a one-line arrow function
  const hasPassed = percent => percent >= 40;

  // 5. the only function that touches the page; it uses the four above
  function showCard() {
    const name = document.getElementById("who").value.trim();
    const obtained = Number(document.getElementById("got").value);
    const percent = percentage(obtained, 200);
    const grade = gradeFor(percent);

    // an empty box gives "", a real value, so call greeting() with no argument instead
    const hello = name === "" ? greeting() : greeting(name);

    document.getElementById("hello").textContent = hello;
    document.getElementById("score").textContent = `Score: ${obtained} / 200 = ${percent}%`;
    document.getElementById("grade").textContent =
      `Grade ${grade}, ${hasPassed(percent) ? "passed" : "not passed"}`;
    console.log(hello, percent + "%", "grade", grade);
  }

  console.log(greeting());                    // Welcome, Student!
  console.log(gradeFor(92), gradeFor(35));    // A F
  showCard();                                 // Welcome, Asha! 78% grade B
  document.getElementById("go").addEventListener("click", showCard);   // no brackets!
</script>

Trace the first card. percentage(156, 200) returns 78. gradeFor(78) tests 80 first (false), then 60 (true), and returns "B" without looking further. hasPassed(78) returns true, so the ternary picks "passed". Now clear the name box and press the button: an empty box gives "", which is a real value, so showCard calls greeting() with no argument and the default "Student" appears.

Look at the last line: addEventListener("click", showCard). There are no brackets after showCard, because you are handing the function to the browser to run later, on every click (Chapter 57). With showCard() it would run once, straight away, and hand over undefined. Try typing 250 as well: the card cheerfully reports 125%, because nothing checks the input yet. That is the job of Chapter 60.

48.9 Common misunderstandings

✗ "Writing a function runs it."
A definition only stores the instructions under a name.
✓ "A function runs only when it is called: its name plus round brackets."
add(5, 3) runs it; function add(a, b) { ... } only defines it.
✗ "console.log inside a function gives the answer back."
It shows the answer in the Console; the caller receives undefined.
✓ "return gives the answer back; console.log only shows it."
Calculate and return; let the caller decide whether to print.
✗ "Parameters and arguments are the same thing."
They are two ends of the same handover.
✓ "Parameters are the names in the definition; arguments are the values in the call."
They are matched by position, first to first.
✗ "JavaScript warns me if I pass the wrong number of arguments."
It never does.
✓ "Missing arguments become undefined; extra ones are ignored, silently."
That is why area(12) is NaN and not an error.
✗ "(a, b) => { a + b } returns the sum."
Braces make a block body, which returns undefined unless it has a return.
✓ "Braces need return; without braces the answer is returned automatically."
Write (a, b) => a + b or (a, b) => { return a + b; }.
✗ "addEventListener("click", showCard()) hands over the function."
The brackets run showCard immediately and hand over its result.
✓ "No brackets hands over the function; brackets hand over its result."
Write addEventListener("click", showCard).

Exam-style checks

In function area(length, width) { return length * width; } called as area(4, 3), what are 4 and 3?L1
  • A. Parameters
  • B. Arguments
  • C. Return values
  • D. Keywords

Answer: B. Values written in a call are arguments. The parameters are length and width, the names in the definition. The return value is 12, which the call produces.

What does this print? function show(a, b) { console.log(a + b); } const r = show(2, 3); console.log(r);L2
  • A. 5 and then 5
  • B. 5 only
  • C. 5 and then undefined
  • D. undefined and then 5

Answer: C. show prints 5 itself, but it has no return, so r is undefined, and the second line prints that. A would need return a + b; inside show.

Which line is a correct arrow-function version of function subtract(a, b) { return a - b; }?L2
  • A. const subtract = (a, b) => { a - b };
  • B. const subtract => (a, b) a - b;
  • C. function subtract => (a, b) { return a - b; }
  • D. const subtract = (a, b) => a - b;

Answer: D. Parameters, then =>, then the answer, with an implicit return. A is the tempting one: it runs, but the braces make a block body with no return, so every call gives undefined. B and C are SyntaxErrors.

What does this print? function greet(name = "Guest") { return "Hi " + name; } console.log(greet(), greet(null));L3
  • A. Hi Guest Hi null
  • B. Hi Guest Hi Guest
  • C. Hi undefined Hi null
  • D. TypeError

Answer: A. The first call passes nothing, so name takes the default. The second passes null, which is a real value, so the default is not used and "Hi " + null gives "Hi null". A default replaces only a missing or undefined argument.

With function add(a, b) { return a + b; }, what does console.log(add(5)); print?L2
  • A. 5
  • B. undefined
  • C. An error saying an argument is missing
  • D. NaN

Answer: D. JavaScript does not check the number of arguments. b is undefined, and 5 + undefined is NaN. The function does return something, so it is not B.

The lecture writes const multiply = function (a, b) { return a * b; };. What kind of function is this, and what is multiply(4, 6)?L2

Answer: a function expression, giving 24. An anonymous function is created as a value on the right of = and stored in the constant multiply; calling it with 4 and 6 returns 4 * 6. Unlike a declaration, it cannot be called on a line above this one.

Predict every line this prints. function check(m) { if (m >= 40) { return "Pass"; } console.log("checking..."); return "Fail"; } console.log(check(55)); console.log(check(20));L3

Answer: three lines — Pass, then checking..., then Fail. For 55 the first return ends the function before the console.log inside it, so only "Pass" is printed. For 20 the test is false, so "checking..." is printed inside the function, and then the returned "Fail" is printed by the outer console.log.

Which statement about cheer and cheer() is correct?L2
  • A. Both run the function
  • B. cheer runs the function; cheer() only refers to it
  • C. cheer is the function itself; cheer() runs it and gives back its return value
  • D. They are the same, because brackets are optional

Answer: C. Without brackets you refer to the function as a value, which is what you hand to addEventListener or to another function. With brackets you run it now. B has it exactly backwards.

What is f(3) after const f = x => { x * 10 };?L3
  • A. 30
  • B. undefined
  • C. NaN
  • D. SyntaxError

Answer: B. The braces make a block body, and it has no return, so the call gives undefined. The multiplication happens and is thrown away. x => x * 10 would give 30.

Which arrow function returns the object { marks: 90 }?L3
  • A. () => ({ marks: 90 })
  • B. () => { marks: 90 }
  • C. () => return { marks: 90 }
  • D. () => [marks: 90]

Answer: A. The round brackets tell JavaScript the braces are an object, not a body. In B the braces are read as a body, so it returns undefined. C is a SyntaxError (return needs braces), and D is not valid syntax.

What does this print? function register(course, ...names) { return names.length; } console.log(register("CSE326", "Asha", "Rahul"));L3
  • A. 3
  • B. 2
  • C. 1
  • D. undefined

Answer: B. "CSE326" goes into course; the rest parameter gathers only the remaining arguments, "Asha" and "Rahul", so its length is 2. A counts the course as well.

A student writes the function below and gets undefined. Why, and what is the fix? function total(a, b) { return (Enter) a + b; }L3

Answer: JavaScript ends the statement at the line break straight after return, so the function returns undefined and the line a + b; is never reached. No error is shown. Fix: keep the value on the same line, return a + b;.

Quick revision

Key takeaways

  1. A function packs a job under a name: write it once, call it as often as you like, and fix it in one place.
  2. function name(parameters) { body } defines; name(arguments) calls. Defining does not run anything.
  3. Parameters are names in the definition; arguments are values in the call, matched by position. Missing ones are undefined, extra ones are ignored, = value gives a default, and ...rest gathers the remainder into an array.
  4. return hands a value back and ends the function at once. With no return, a call gives undefined. console.log only shows a value; it gives nothing back.
  5. A function expression stores a function as a value: const f = function (a, b) { ... };. An arrow function is the short form: (a, b) => a - b.
  6. An arrow with no braces returns its one expression; with braces it needs return; to return an object, wrap it in ({ }).
  7. f is the function; f() runs it. Hand over f when another function should run it later.
  8. Good functions do one job, have verb names, take inputs as parameters, return their answer, and are pure where possible.
