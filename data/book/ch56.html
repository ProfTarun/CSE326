DOM Selection and Manipulation

Chapter 55 showed you the tree the browser builds from your HTML. This chapter gives you the two skills that every interactive page is made of: finding the elements you want, and changing them — their words, their attributes, their classes, their styles, and even whether they exist at all. Every later chapter in this unit is these few tools used in new places.

Before you start — one-line reminders

56.1 Five ways to find an element

Before a script can change anything on a page, it has to get hold of the element's object. In Chapter 55 you did that with getElementById. It is fast and exact, but it only works when the element has an id, and most elements do not. Your slides list five finders, all of them methods of document:

MethodFindsGives back
getElementById("title")The element with that id (no #)One element, or null
querySelector(".student")The first element matching a CSS selectorOne element, or null
querySelectorAll(".student")All elements matching a CSS selectorA NodeList (possibly empty)
getElementsByClassName("hostel")All elements with that class (no dot)An HTMLCollection (possibly empty)
getElementsByTagName("li")All elements with that tagAn HTMLCollection (possibly empty)

The two in the middle are the ones you will use most, because they take a CSS selector, the same pointing language you learned for stylesheets in Unit 3. Any selector you could write before a { in CSS works inside the brackets, written as a string (only pseudo-elements such as ::before never match, because they are not elements):

Selector stringMeansTaught in
"p", ".card", "#login"By tag, by class, by idChapter 23
"nav a" / "ul > li"An a anywhere inside a nav / an li directly inside a ulChapter 23

"First" in querySelector means first in document order: the order the elements appear in the HTML, top to bottom. querySelectorAll collects every match in that same order. One rule trips up everyone once: getElementById and getElementsByClassName want a bare name, while the two querySelector methods want a selector. So it is getElementById("title") but querySelector("#title"), and getElementsByClassName("hostel") but querySelectorAll(".hostel").

Searching inside one element

querySelector and querySelectorAll are also methods of every element. Called on an element, they search only below it. On a page with a dozen lists, document.querySelectorAll("li") finds every item on the page, but toppers.querySelectorAll("li") finds only the items inside the toppers list.

Use getElementById when the element has an id. Use querySelector for "the first element that matches this CSS selector" and querySelectorAll for "every element that matches". Ids and classes go in bare to the getElement... methods and with their # or . to the querySelector methods.

Quick check: which finder call is wrong, and what does it give? document.querySelector("toppers")

The selector "toppers" has no #, so it means "an element whose tag is toppers". There is no such tag, so it gives null. Write querySelector("#toppers") or getElementById("toppers").

56.2 Lists of elements: static and live

Three finders return a list. Neither kind of list is a real array, but both behave like one in the ways you need most: they have a length, you read items with [0], [1] and so on, and a for...of loop (Chapter 52) walks through them. They differ in two ways.

1. Static or live. querySelectorAll returns a NodeList that is a static snapshot: it lists what matched at the moment you asked, and it never changes afterwards. getElementsByClassName and getElementsByTagName return an HTMLCollection that is live: it keeps watching the page, so when an element with that class is added or removed, the collection grows or shrinks by itself.

Picture this. Your class teacher keeps the attendance register on her desk. You ask for the list of students and get one of two things. Either she photocopies today's page and hands it to you — that is querySelectorAll. A student who joins tomorrow is in the register but not on your photocopy; to see them you must ask for a fresh copy. Or she lets you read the register itself — that is getElementsByClassName. Whenever you look, it is up to date, because it is the register. Handy, but if you are crossing names out while you read down the page, the lines shift under your finger.

2. Which tools they carry. A NodeList has a forEach method; an HTMLCollection does not, so calling forEach on one stops the script with TypeError: ... forEach is not a function. Neither has map or filter. When you need the array methods of Chapter 53, turn either list into a real array first with Array.from(list) (Chapter 50).

<style>
  body { font-family: system-ui, sans-serif; padding: 10px 16px; color: #3C4A60; }

<ul id="list">
  <li class="item">Asha</li>
  <li class="item">Rahul</li>

Line 2 is the whole story of this section: after Meera joined, the snapshot still says 2 and the live collection says 3. To see Meera through querySelectorAll you have to ask again (line 3). Lines 4 and 5 show the difference in tools: typeof reports a function on the NodeList and undefined on the HTMLCollection. for...of works on both, and Array.from turned the live collection into an ordinary array, so map could run.

The live list that skips items. Suppose you loop over document.getElementsByClassName("new") with an index and remove the class new from each item. Every removal makes the live collection shorter at once, so the next item slides down into the slot you just handled, and your loop jumps over it: only half of the items lose the class. A querySelectorAll snapshot does not shift, so loop over a snapshot whenever the loop changes the page.
Exam tip. One sentence answers most questions here: querySelectorAll returns a static NodeList; getElementsByClassName and getElementsByTagName return a live HTMLCollection. (The childNodes list from Chapter 55 is a NodeList too, but a live one — the "static" belongs to querySelectorAll.)

56.3 When nothing matches

A finder that finds nothing does not stop your script. What it gives depends on its kind:

  • getElementById and querySelector give null, the value that means "nothing here" (Chapter 43).
  • The three list finders give an empty list, with length 0. A forEach or for...of over an empty list simply runs zero times, so there is nothing to guard.

The danger is the next line. Asking null for a property is an error, so document.querySelector("#reslt").textContent = "Saved", with a typing slip in the id, stops the script with TypeError: Cannot set properties of null (setting 'textContent'). Chapter 55 showed the other common cause: the script ran before the element was built. When an element might really be missing — for example, a script shared by several pages, only some of which have a results box — check before you use it:

const box = document.querySelector("#result");
if (box) {                      // null counts as false, an element as true
  box.textContent = "Saved!";
} else {
  console.warn("No #result element on this page");
}

// shorter, when doing nothing is the right answer:
document.querySelector("#result")?.classList.add("done");

The second form uses optional chaining from Chapter 51: if the finder gives null, ?. stops quietly and the line does nothing. It works for reading and for calling a method, but not for assigning: document.querySelector("#result")?.textContent = "Saved!" is a SyntaxError, and the whole script refuses to run. Use the if for assignments.

Do not guard everything. When an element must be on the page, a check only hides your typing slips. Let the TypeError appear: the Console names the line. Guard only elements that may honestly be absent.
Quick check: the page has no element with class tag. What happens on document.querySelectorAll(".tag").forEach((t) => t.remove());?

Nothing, and no error. querySelectorAll gives an empty NodeList, and forEach over an empty list calls the function zero times. Only the single-element finders give null.

Once you hold an element, three properties read and replace what is inside it. Your slides put the key difference in two lines: textContent inserts text without interpreting it as HTML; innerHTML parses the supplied string as HTML. The old fee, 450, sits in a hidden span. textContent (line 1) collects it anyway, and runs the words together where the <br> was, because a br holds no text. innerHTML (line 2) hands back the markup itself. Then the same string goes in twice. In the first box you see the angle brackets as plain characters; in the second, the browser built a real b element, so Asha appears in bold. Line 3 counts the elements that were built: none, and one. Line 4 arrives last, because it waited for the page to be drawn: innerText gives what a reader sees, with no hidden 450 and a \n line break where the screen breaks the line. (On an ordinary page, a script at the end of the body can read innerText straight away; the browser works out the layout on the spot.)

Why innerHTML needs care

innerHTML turns a string into elements, and it does not ask who wrote the string. If the string came from a user — a comment box, a name field — that user can type tags, and a tag can carry an attribute that runs JavaScript, such as onerror on an img. Text has then become a program running in other people's browsers, an attack called XSS. Chapter 58 shows the attack happening and how to build safely. The rule for now is short: user text goes in with textContent; innerHTML only ever receives markup you wrote yourself.

Two smaller facts. list.innerHTML = "" empties an element in one go. And list.innerHTML += "<li>New</li>" does not just add one item: it rebuilds every element inside from a string, throwing the old ones away. Section 56.8 shows the proper way to add.

textContent is the safe, fast default: words in, words out. innerText gives only what is visible. innerHTML reads and writes tags, so give it only HTML you wrote, never text a user typed.

Quick check: a name box holds <i>Rahul</i>. Which line shows the name exactly as typed, angle brackets and all: out.textContent = name or out.innerHTML = name?

out.textContent = name. It puts the characters in as text. innerHTML would build an i element and show Rahul in italics, and with nastier input it could run code.

56.5 Attributes and properties

Every element in your HTML can carry attributes: href on a link, src and alt on an image, type and value on an input. Four methods work on any attribute by its name, exactly as it is written in the HTML:

MethodDoes
el.getAttribute("href")Reads the attribute's text, or null if the element does not have it
el.setAttribute("href", "unit5.html")Adds the attribute, or changes it if it is already there
el.removeAttribute("title")Takes the attribute off the element
el.hasAttribute("title")true or false

The most common attributes also have a ready-made property of the same name on the element object, which is shorter to write: img.src, img.alt, link.href, input.value, box.checked, button.disabled. You met two in Chapter 55: id, and className for the class attribute. Usually the attribute and the property mirror each other: set one and the other changes. Three differences are worth knowing.

  • value. The value attribute of an input is only its starting text. The value property is what is in the box now, after the user has typed. To read what someone typed, always use the property, input.value. Changing the property does not change the attribute. A checkbox's checked works the same way: the attribute is the starting tick, the property is the tick now.
  • Yes/no attributes. checked, disabled and hidden work by being present or absent; their properties are true or false. Write button.disabled = false, not setAttribute("disabled", "false") — the second one adds the attribute, and a button that has disabled at all is disabled, whatever text the attribute holds.
  • href and src. The attribute is the text you wrote, such as notes.html. The property is the full address the browser worked out from it, such as https://site.example/unit5/notes.html.

Your own data: data-* and dataset

Sometimes an element needs to carry a fact that HTML has no attribute for: a student's roll number, a product's price, which question a button belongs to. HTML lets you invent attributes for this, as long as the name starts with data-: data-roll-no="12", data-section="K23". They do nothing on their own, but scripts can read them, and Chapter 57 uses them to tell buttons apart.

JavaScript reads them through one property, dataset, an object holding every data- attribute of the element. Drop the data- from the name and write the rest in camelCase: data-roll-no becomes dataset.rollNo. Two facts follow: the values are always strings, so "12" needs Number() before you do sums with it, and assigning a new key, dataset.status = "present", writes a new data-status attribute onto the element.

56.6 Classes: classList, not className

The most useful change you can make to an element is to switch a class on or off, because a class brings a whole group of CSS rules with it. Chapter 55 showed className, the class attribute as one string. Assigning to it replaces every class the element had: on <div class="card absent">, the line div.className = "topper" leaves just topper, and the card's border and padding disappear with the lost card class.

So for changing classes, use classList. It holds the element's classes as a small list and handles one class at a time, leaving the others alone:

CodeEffectGives back
el.classList.add("topper")Adds the class (no effect if it is already there)nothing
el.classList.remove("absent")Removes the class (no error if it was not there)nothing
el.classList.toggle("topper")Adds it if missing, removes it if presenttrue if the class is now on, false if now off
el.classList.contains("topper")Changes nothing; just askstrue or false
el.classList.replace("old", "new")Swaps one class for anothertrue if old was there

add and remove can take several names at once, el.classList.add("card", "topper"). Like getElementsByClassName, every classList method wants the bare class name: "topper", never ".topper". toggle is the switch you will use most, for anything with an on and an off: a dark theme, an open menu, a selected answer.

56.7 Inline styles with element.style

Your slides' topic "Changing CSS using JavaScript" has a direct route too. Every element has a style property, and each CSS property is a property of it. Set one and the browser writes it into the element's style attribute as an inline style:

box.style.color = "white";
box.style.backgroundColor = "#138808";   // CSS: background-color
box.style.fontSize = "18px";             // CSS: font-size  - a string, with its unit
box.style.display = "none";              // hides the element
box.style.display = "";                  // removes the inline value: back to the stylesheet

Three rules. Names are camelCase: a CSS name with hyphens loses them and capitalises the next letter, because a hyphen in JavaScript is a minus sign — box.style.background-color would mean box.style.background minus color. Values are strings, exactly as you would write them in CSS, units included: "18px", not 18. And reading style sees only inline styles: if the colour came from a stylesheet, box.style.color is an empty string. To ask what the browser is actually using, call getComputedStyle(box).color.

Why a class is usually better

Inline styles work, but they make a mess:

  • The design is split between the stylesheet and your scripts, so nobody can find all of it in one place.
  • Turning it off is clumsy. Five style lines to switch a look on need five more to switch it off. A class needs one toggle.
  • Inline styles beat your stylesheet. An inline style beats every selector in the stylesheet (only an !important rule from Chapter 23 beats it), so it keeps winning even after you add a class that should change it. The example below shows this.

So the habit is: describe each look once, as a class in your CSS, and let JavaScript switch classes. Keep element.style for values that are worked out while the page runs, such as a progress bar whose width is `${percent}%`.

Line 4 is the className trap: Rahul's class is now only topper. He has the green background, but his border and padding vanished with card. Press again: false, and the border goes back to grey. That is the third reason in action: once a script has set an inline style, your classes can no longer change that property.

Write each look once as a CSS class. Switch it with classList.add, remove and toggle, which leave the other classes alone. Assigning to className wipes them all. Use style, with camelCase names and string values, only for a value your code works out.

56.8 Creating, inserting and removing elements

So far every element was already in the HTML. A script can also make new ones. Building an element takes three steps, and the third is the one beginners forget:

  1. Create it: const li = document.createElement("li"); gives a brand-new, empty li element object.
  2. Fill it: li.textContent = "Meera";, plus any classes or attributes it needs.
  3. Insert it: list.append(li); puts it into the tree, and only now does it appear on the page.

Between steps 1 and 3 the element exists only in memory, like a letter written but not posted: no finder can see it and nothing shows on screen. Where it goes is measured from an element already on the page:

MethodPuts the new contentNotes
parent.append(a, b, ...)Inside, at the endTakes several elements or plain strings at once
parent.appendChild(el)Inside, at the endThe older form: exactly one element, and it returns that element
parent.prepend(el)Inside, at the start
el.before(x) / el.after(x)Outside, just above / just belowNew siblings, not children
el.insertAdjacentHTML(position, html)At one of the four positions in Figure 56.3Parses a string of HTML, so the innerHTML safety rule applies
el.remove()—Takes the element, and everything inside it, out of the page

insertAdjacentHTML is the polite cousin of innerHTML +=: it parses your markup and adds the new elements at one position, leaving every existing element untouched. remove() needs no parent: you call it on the element that should go.

Moving and copying

An element can be in only one place in the tree. So when you append or appendChild an element that is already on the page, it is not copied: it is taken out of its old place and put into the new one. That is how you reorder a list. When you really want a second one, copy it with cloneNode(true), where true means "and everything inside it". (With no true you get an empty shell, without its text.) A clone also copies the id, so give the copy a new id or remove it, because ids must stay unique.

<style>
  body { font-family: system-ui, sans-serif; padding: 10px 16px; color: #3C4A60; }
  h3 { margin: 0; color: #0B2545; }
  li.new { color: #138808; }
</style>
<ul id="list">
  <li>Rahul</li>
</ul>
<p id="end">This line will be removed.</p>
<script>
  const list = document.getElementById("list");
  const order = () => Array.from(list.children).map((li) => li.textContent).join(", ");

  const meera = document.createElement("li");       // 1. create
  meera.textContent = "Meera";                       // 2. fill
  meera.classList.add("new");
  console.log("1. Made:", meera, "| on the page?", meera.isConnected);
  list.append(meera);                                // 3. insert
  console.log("2. On the page now?", meera.isConnected);

  const asha = document.createElement("li");
  asha.textContent = "Asha";
  list.prepend(asha);                                // first child

  const heading = document.createElement("h3");
  heading.textContent = "Section K23";
  list.before(heading);                              // sibling above the list

  list.insertAdjacentHTML("beforeend", "<li>Imran <b>(new)</b></li>");
  console.log("3. Order:", order());

  list.appendChild(asha);                            // already on the page: MOVED, not copied
  console.log("4. After appendChild(asha):", order());

  const copy = meera.cloneNode(true);                // a real second Meera
  list.append(copy);
  console.log("5. After the clone:", order());

  document.getElementById("end").remove();
  console.log("6. Items:", list.children.length, "| #end now:", document.getElementById("end"));
</script>
1. Made: <li class="new"> | on the page? false
2. On the page now? true
3. Order: Asha, Rahul, Meera, Imran (new)
4. After appendChild(asha): Rahul, Meera, Imran (new), Asha
5. After the clone: Rahul, Meera, Imran (new), Asha, Meera
6. Items: 5 | #end now: null

Line 1 catches the new element between creating and inserting: it exists, but isConnected, which says whether an element is in the page, is false. One append later it is true and Meera appears in green. Line 3 shows each insertion where Figure 56.3 said: Asha first, then Rahul, Meera, and Imran, built from a string. The heading went above the list, outside it, so it is not among the list's children. Line 4 is the move: appendChild(asha) did not make a second Asha; it carried the one Asha from the top to the bottom. Line 5 shows the copy, a real second Meera. Line 6: the paragraph is gone, so getElementById gives null.

Create with createElement, fill with textContent and classList, then insert with append, prepend, before or after — nothing shows until you insert. Inserting an element that is already on the page moves it; cloneNode(true) copies it; remove() deletes it.

Quick check: a list holds A, B, C. What order does list.append(list.firstElementChild) leave?

B, C, A. The first child, A, is already on the page, so append moves it to the end instead of copying it.

You can practise every tool in this chapter on any website. Open DevTools (F12), choose the Console tab and try document.querySelectorAll("a").length to count the links, or document.querySelector("h1").textContent = "Hello from me". As Chapter 55 showed, a reload builds a fresh tree and undoes it all.

Exam tip. "Why does my new element not appear?" almost always means step 3 is missing: createElement made it but nothing inserted it. And "why did my element disappear from its old place?" means it was moved by append or appendChild, not copied.

56.9 Common misunderstandings

✗ "querySelector gives me every match."
It stops at the first one in document order.
✓ "querySelector gives the first match; querySelectorAll gives them all."
The All in the name is the whole difference.
✗ "getElementsByClassName(".card") finds my cards."
It looks for a class literally called .card, and finds none.
✓ "Bare names for the getElement... methods and classList; selectors, with # and ., for querySelector."
✗ "All element lists are arrays, so forEach and map always work."
An HTMLCollection has no forEach, and neither kind has map.
✓ "They are list-like. Use for...of, or Array.from(list) for the array methods."
A NodeList from querySelectorAll does have forEach.
✗ "innerHTML and textContent are the same, just two names."
One parses tags; the other shows them as characters.
✓ "textContent for text, innerHTML only for markup I wrote."
User text in innerHTML is how XSS gets in (Chapter 58).
✗ "el.style.color tells me the element's colour."
It shows only an inline value, and is often empty.
✓ "getComputedStyle(el).color tells me the colour actually in use."

Exam-style checks

Answer each one before opening it. For the "what does this print?" questions, write down the page's elements first, in document order.

Which method returns all the elements that match a CSS selector?L1
  • A. getElementById()
  • B. querySelector()
  • C. querySelectorAll()
  • D. getElementsByTagName()

Answer: C. querySelector (B) takes a CSS selector too but stops at the first match. getElementsByTagName returns many elements, but by tag name only, not by any selector.

A page has three elements with class item. What does document.querySelector(".item") return?L2
  • A. The first .item in document order
  • B. A NodeList of all three
  • C. The last .item on the page
  • D. null, because more than one element matches

Answer: A. querySelector always returns one element: the first match, reading the HTML from the top. Several matches are not an error (D); to get all three you need querySelectorAll (B).

No element on the page has the class tag. What do document.querySelector(".tag") and document.querySelectorAll(".tag").length give?L2
  • A. undefined and 0
  • B. An error, then 0
  • C. null and null
  • D. null and 0

Answer: D. A single-element finder that finds nothing gives null; a list finder gives an empty list, whose length is 0. Neither call throws: the error only comes if you then ask null for a property.

What happens when this line runs on a page with three .card elements? document.getElementsByClassName("card").forEach((c) => c.remove());L3
  • A. All three cards are removed
  • B. TypeError: ... forEach is not a function
  • C. Only the first card is removed
  • D. Nothing happens and there is no error

Answer: B. getElementsByClassName returns an HTMLCollection, which has no forEach. Use document.querySelectorAll(".card").forEach(...), whose NodeList does have it — and which, being a snapshot, does not shrink while the cards are removed.

What does this print?
<ul id="u"><li class="x">A</li><li class="x">B</li></ul>

Answer: 2 3. s is a static snapshot taken when there were two .x items. l is a live HTMLCollection, so it counts the third item as soon as it is appended.

A script runs out.textContent = "<i>Hi</i>";. What does the page show?L2
  • A. Hi in italics
  • B. Nothing, because the tags are removed
  • C. The characters <i>Hi</i>, tags included
  • D. Hi in plain text, with the tags removed

Answer: C. textContent inserts text without interpreting it as HTML, so the angle brackets appear as characters. A is what innerHTML would show, because it parses the string.

What does this print?
<p id="p" data-roll-no="7">Asha</p>
const p = document.getElementById("p");
console.log(p.dataset.rollNo, typeof p.dataset.rollNo);L3

Answer: 7 string. data-roll-no is read as dataset.rollNo: the data- is dropped and the rest is camelCase. Every dataset value is a string; convert with Number() before doing sums.

An element is <div class="card red">. After div.className = "big"; what is its class attribute?L2
  • A. "card red big"
  • B. "big"
  • C. "big card red"
  • D. "card big"

Answer: B. Assigning to className replaces the whole attribute. To add big and keep the others, which gives A, write div.classList.add("big").

Which line correctly gives an element a yellow background?L1
  • A. el.style.background-color = "yellow";
  • B. el.style = backgroundColor("yellow");
  • C. el.css.backgroundColor = "yellow";
  • D. el.style.backgroundColor = "yellow";

Answer: D. CSS names become camelCase on style. In A the hyphen is read as a minus sign, so the line is a SyntaxError; B and C use things that do not exist.

An input was written as <input id="n" value="Asha">. The user clears it and types Rahul. What do n.value and n.getAttribute("value") give?L2
  • A. "Rahul" and "Asha"
  • B. "Asha" and "Rahul"
  • C. "Rahul" and "Rahul"
  • D. "Asha" and "Asha"

Answer: A. The value property is what is in the box now; the value attribute is only the starting text written in the HTML, and typing does not change it. Read user input with the property.

A list holds A, B and C in that order. What is the order after these lines?

list.prepend(x);
list.appendChild(list.children[1]);L3

Answer: Z, B, C, A. After prepend the order is Z, A, B, C. Then children[1] is A, which is already on the page, so appendChild moves it to the end rather than copying it.

Quick revision

Key takeaways

  1. One element: getElementById("id") or querySelector(selector). All matches: querySelectorAll(selector). Selectors keep their # and .; the getElement... methods take bare names.
  2. querySelectorAll gives a static NodeList with forEach. getElementsByClassName and getElementsByTagName give a live HTMLCollection without it. for...of works on both; Array.from makes a real array.
  3. No match: null from the single finders, an empty list from the list finders. Guard with if (el); ?. cannot assign.
  4. textContent inserts text without interpreting it as HTML; innerHTML parses the string as HTML, so never give it user text. innerText gives only the visible text.
  5. Attributes: getAttribute, setAttribute, removeAttribute, hasAttribute. Properties such as src, href, value and checked are the live values; value holds what the user typed.
  6. data-roll-no="12" is read as el.dataset.rollNo, always a string.
  7. Switch looks with classList.add, remove, toggle and contains; assigning className replaces every class. element.style takes camelCase names and string values, sees inline styles only, and beats the stylesheet.
  8. New elements: createElement, fill, then insert with append, prepend, before or after. Inserting an element already on the page moves it; cloneNode(true) copies; remove() deletes.
