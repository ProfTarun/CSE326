Variables and Constants

A program has to remember things: a student's name, the marks she scored, the runs on the scoreboard so far. It remembers each one by giving it a name, and a value with a name is called a variable. This chapter shows you how to make one, how to change it, how to make one that can never be changed, and how to choose a name that JavaScript accepts and other people can read.

About 30 minutes · Course outcome CO4

Before you start — one-line reminders

  • console.log("Total:", total) prints its values, separated by spaces, in the Console panel under every Run (Chapter 41).
  • A statement is one complete instruction, and this book ends every statement with a semicolon (Chapter 41).
  • JavaScript is case-sensitive: to it, console and Console are two different words (Chapter 41).

By the end of this chapter you can

  • Explain what a variable is, and point to the declaration, the initialisation and the assignment in a piece of code.
  • Create variables with let and const, and say what a variable holds before it is given a value.
  • Compare var, let and const on reassigning, redeclaring, scope and hoisting.
  • Explain why a const object or array can still change inside.
  • Choose the right keyword: const by default, let when the value changes, never var in new code.
  • Write names that follow JavaScript's rules and its camelCase convention, and spot names that break them.
  • Read the messages "Assignment to constant variable", "is not defined" and "has already been declared", and fix the line that caused each one.

42.1 A name for a value

Every app on your phone remembers things: a shopping app your cart, a game your score, the LPU portal your attendance. A program cannot remember a value unless it has somewhere to keep it and a name to find it by. That named value is a variable.

Here is the smallest useful program with a variable in it:

let marks = 85;
console.log(marks);     // 85

Read the first line aloud as "make a variable called marks and put 85 in it". The second line uses the name. JavaScript sees marks, looks up the value that goes with that name, and hands 85 to console.log. From now on you never type 85 again; you type the name.

The usual picture is a box with a label on it. marks is the label, 85 is what is inside, and later you can take 85 out and put a different value in. Your lecture slides use a more exact word: a variable is a named binding used to refer to a value in a JavaScript program. A binding is that link between a name and a value, like a string tied from a luggage tag to a suitcase. The box and the tag are two pictures of one idea; this book mostly uses the box, because it is easier to draw.

A variable is a name you choose for a value, so the program can find that value again. Write the name, and JavaScript uses whatever value goes with it at that moment.

Why not just type the value each time? Three reasons:

  • One place to change. If the pass mark of 40 appears on ten lines and becomes 35, you edit ten lines and miss one. Give it a name, and you edit one line.
  • Values that change while the program runs, such as a score or a total. You cannot type those in advance; only a variable can follow them.
  • Meaning. totalMarks tells a reader what the number is. A bare 85 tells them nothing.

42.2 Declare, initialise, assign

Three words describe everything you do to a variable, and examiners use all three. Here is the slides' example, one step at a time:

let studentName;          // declaration: create the variable
studentName = "Aman";     // initialisation: give it its first value
let marks = 85;           // declaration with initialisation, in one line
  • Declaration creates the variable. The word let tells JavaScript "a new name is coming", and the name follows it. After let studentName; the box exists, but you have not put anything in it.
  • Initialisation gives a variable its first value. On the second line studentName receives "Aman".
  • Usually both happen in one statement. let marks = 85; declares marks and initialises it to 85. This is the form you will write most often.

The third word is assignment, and it is what the = sign does every time it appears: work out the value on the right, then store it in the variable on the left. A variable's first assignment is its initialisation. Every later one throws the old value away and stores the new one, which is called reassigning the variable:

studentName = "Meera";    // assignment: "Aman" is replaced by "Meera"

Notice that = does not mean "equals" here. It is an order: store this. Chapter 44 meets it again among the operators, where the job of comparing two values goes to ===.

One question remains. What is inside the box between declaring and initialising? Not nothing: JavaScript puts in a special value called undefined, which means "no value has been given yet". Chapter 43 tells its full story; for now, learn to recognise it when the Console shows it.

<p>Press Run, then read the Console panel below.</p>
<script>
  let studentName;                                      // 1. declaration
  console.log("After declaring:", studentName);         // After declaring: undefined

  studentName = "Aman";                                 // 2. initialisation
  console.log("After the first value:", studentName);   // After the first value: Aman

  studentName = "Meera";                                // 3. reassignment
  console.log("After assigning again:", studentName);   // After assigning again: Meera

  let marks = 85;                                       // declare and initialise at once
  console.log("marks:", marks);                         // marks: 85
</script>

Four lines appear in the Console, exactly as the comments say. The name studentName never changed; only the value attached to it did.

Declaring makes the box. Initialising puts the first thing in it. Assigning puts something in it, whether for the first time or the fiftieth, and whatever was there before is gone. A box that has been made but not yet filled holds undefined.

Exam tip. Follow the slides: in let x; followed by x = 5;, the first line declares and the second initialises, and let x = 5; does both at once. (Strictly, the language rules say JavaScript initialises x to undefined when let x; runs, which makes x = 5 its first assignment. Both descriptions agree on what happens: undefined first, then 5.)
Quick check: in let total; total = 90; total = 95; which statement declares, which initialises, and what does total hold at the end?

let total; declares it (it holds undefined), total = 90; initialises it, and total = 95; reassigns it. At the end it holds 95; the 90 is gone.

42.3 Three keywords: let, const and var

let is not the only way to declare a variable. JavaScript has three keywords for the job, and the slides introduce all three:

KeywordIn one line (the slides' definitions)Added in
varThe traditional way. Can be reassigned, and can even be declared again.1995
letDeclares a block-scoped variable whose value can be reassigned.2015
constDeclares a block-scoped binding that must be initialised when declared and cannot be reassigned.2015

Why three? The slides give the reason: these keywords help us store data, manage values, and control where variables can be accessed. For twenty years JavaScript had only var, which has some awkward habits (42.5), so in 2015 the language added let and const. Modern code uses those two. You learn var because old code, and old exam questions, still use it.

The "constants" in this chapter's title are simply variables declared with const: names attached to one value for good.

Picture this. The big scoreboard at a cricket ground. Some panels change all match long: Runs, Wickets, Overs. The scorer wipes them and writes new numbers after every ball. Those are let. Other panels are painted before the toss and never change: the name of the ground, the two teams. Those are const. A panel that is up but still blank, such as "Player of the Match" during the first over, is a declared variable holding undefined. And one last detail: the painted panel "Batting: India" will say India all day, but who is batting for India changes with every wicket. A const fixes which thing a name refers to, not what goes on inside that thing (42.6).

42.4 let and const up close

let: a box you can refill

The slides' let example:

let score = 50;
console.log(score);    // 50
score = 75;
console.log(score);    // 75

Same name, two values at two moments. The third line does not make a new variable; there is no let on it. It replaces 50 with 75 in the variable that already exists. Use let for anything that is meant to change while the program runs: a running total, a counter, the current question number, a score.

const: filled once, at once

The slides' definition of const contains two rules.

  1. It must be initialised when declared. const collegeName = "LPU"; is right. const collegeName; on its own is refused with SyntaxError: Missing initializer in const declaration. That makes sense: a const that starts empty could never be filled, because filling it later would be a reassignment.
  2. It cannot be reassigned. The slide's "Try" line:
const age = 20;
age = 21;      // TypeError: Assignment to constant variable.

The first line is fine. The second stops the program with an error, which section 42.9 teaches you to read. Here are the slides' let and const examples together, with labels on the output:

<p>Press Run, then read the Console panel below.</p>
<script>
  // let: the value can be replaced
  let score = 50;
  console.log("score:", score);                 // score: 50
  score = 75;
  console.log("score:", score);                 // score: 75

  // const: given its value once, on the same line
  const collegeName = "LPU";
  const passingMarks = 40;
  console.log("college:", collegeName);         // college: LPU
  console.log("pass mark:", passingMarks);      // pass mark: 40

  // a const can be USED as often as you like; it just cannot be replaced
  const myMarks = 72;
  console.log("above the pass mark by:", myMarks - passingMarks);   // above the pass mark by: 32
</script>

The last line reads two constants and subtracts one from the other. Using a const is always allowed; only storing a new value in it is forbidden.

Quick check: which of these three lines is an error, and why? const pi = 3.14;   const g;   let h;

const g; is the error: a const must be given its value on the same line, so JavaScript reports "Missing initializer in const declaration". let h; is fine; h simply holds undefined until you assign it.

42.5 var: the old keyword

The slides' var example looks exactly like a let one:

var studentName = "Aman";
var marks = 80;
console.log(studentName);    // Aman
console.log(marks);          // 80
marks = 90;
console.log(marks);          // 90

So far there is no difference. The slides add that var allows reassignment and redeclaration within the same scope, and is function-scoped. Those are the three places where it parts company with let.

  1. Redeclaring. With var you may declare the same name again, and nothing complains: the second var marks = 95; simply replaces the value. With let or const, a second declaration of the same name in the same place is refused: SyntaxError: Identifier 'marks' has already been declared. That is not var being kind: in a long file, a second var marks two hundred lines down wipes out the first value without a warning. let catches that mistake for you.
  2. Scope. A variable's scope is the region of the program where its name can be seen. let and const are block-scoped: they exist only inside the nearest pair of curly braces { } around them. var ignores those braces and belongs to the whole function around it (or to the whole script, if it is not inside a function): it is function-scoped. Chapter 49 shows exactly what this means; for now, learn the two phrases.
  3. Using it before its line. Read a var on a line above its declaration and you get undefined instead of an error. Do the same with let or const and you get ReferenceError: Cannot access 'x' before initialization. This behaviour is part of hoisting, and Chapter 49 explains it properly.
<p>Press Run, then read the Console panel below.</p>
<script>
  // the slides' var example
  var studentName = "Aman";
  var marks = 80;
  console.log(studentName);                          // Aman
  console.log(marks);                                // 80
  marks = 90;
  console.log(marks);                                // 90

  // var lets you declare the SAME name again: no error, no warning
  var marks = 95;
  console.log("after a second var marks:", marks);   // after a second var marks: 95

  // var can even be read above its own line: it gives undefined
  console.log("rollNo before its line:", rollNo);    // rollNo before its line: undefined
  var rollNo = "12302457";
  console.log("rollNo after its line:", rollNo);     // rollNo after its line: 12302457
</script>

Six lines, no errors. Change the second var marks to let marks in the Playground and nothing prints at all: the whole script is refused with "Identifier 'marks' has already been declared". Section 42.9 explains why not even the first line runs.

var is the old, forgiving keyword. It lets you declare a name twice, it lets you use a name before its line, and it ignores the braces of a block. Each of those freedoms hides a mistake. let and const are strict about all three, and that strictness is the reason they were added.

42.6 const fixes the name, not the contents

Here is the fact about const that surprises almost everyone. A const cannot be reassigned, but if its value is an object or an array, the inside can still change.

Arrays and objects have chapters of their own (Chapters 50 and 51), so here is just enough to follow along. An object groups several values under one name, inside curly braces: { name: "Asha", marks: 80 }. You reach one value inside it with a dot: student.marks. An array is a list inside square brackets, such as ["Maths", "Physics"], and push adds an item to the end of the list.

<p>Press Run, then read the Console panel below.</p>
<script>
  // a const object: { } groups several values under one name
  const student = { name: "Asha", marks: 80 };
  console.log("Before:", student.marks);     // Before: 80

  student.marks = 95;                        // change INSIDE the object: allowed
  console.log("After:", student.marks);      // After: 95
  console.log(student);                      // {name: 'Asha', marks: 95}

  // a const array: [ ] is a list, and push adds an item at the end
  const subjects = ["Maths", "Physics"];
  subjects.push("Chemistry");                // change INSIDE the array: allowed
  console.log(subjects);                     // ['Maths', 'Physics', 'Chemistry']
</script>

(Inside a whole object or list, the Console shows text in single quotes, as Chrome's own Console does.)

Why is this allowed? Because student.marks = 95 does not give the name student a new value. student still refers to the very same object it did on the first line; you changed something inside that object. What const forbids is pointing the name at a different value:

student = { name: "Rahul", marks: 70 };   // TypeError: Assignment to constant variable.
subjects = ["Biology"];                   // TypeError: Assignment to constant variable.
Key idea. const fixes which value the name leads to, not what is inside it. For a number or a piece of text there is nothing inside to change, so const passingMarks = 40; really is 40 for as long as the program runs. For an object or an array, only the name is fixed. (If you ever need an object whose contents cannot change either, JavaScript offers Object.freeze; the MDN const page in the references shows it.)

const glues a name to one value. If that value is a list or a group of values, you can still add to it and change things in it. What you cannot do is peel the name off and glue it to something else.

Quick check: const marks = [70, 80]; Which of these lines works: marks.push(90); or marks = [70, 80, 90];?

marks.push(90); works: it changes the inside of the same array. marks = [70, 80, 90]; throws TypeError: Assignment to constant variable, because it tries to point the name at a brand-new array.

42.7 Which keyword should I use?

Most professional teams follow one rule, and so does this book:

  1. const by default. Most names in a program never need a new value: the student's name, the pass mark, a button on the page, a result you worked out once.
  2. let when the value must change: a counter, a running total, a score updated ball by ball.
  3. var never in new code. Read it, understand it, but do not write it.

Why const first? Because it helps whoever reads the code, usually you a week later. A const tells you, without reading another line, that the name means the same thing everywhere. If you change it by mistake, JavaScript stops you with an error instead of letting a wrong value spread quietly. And a let signals: watch this one, it changes. So write const first, and if JavaScript complains when you assign to it and the change really is intended, switch that one declaration to let.

42.8 Naming your variables

The name you give a variable is called an identifier. JavaScript checks four rules. Break one of the first three and the script is refused with a SyntaxError before any of it runs.

  1. Only letters, digits, the underscore _ and the dollar sign $. No spaces, no hyphens, no other symbols such as %, @ or .. A hyphen is especially sneaky: fee-paid reads as "fee minus paid".
  2. It must not start with a digit. marks2 is fine; 2marks is not. JavaScript decides from the very first character whether it is reading a number or a name.
  3. It must not be a reserved word. These are words JavaScript keeps for itself: const, var, if, else, for, function, return, class, new, true, false, null and a few dozen more. Treat let as one of them too.
  4. Names are case-sensitive. marks, Marks and MARKS are three different variables. You cannot break this rule, but you can trip over it, and beginners do, daily.

Letters from other scripts are allowed too (let नाम = "Asha"; works), but code is shared with people everywhere, so stick to English letters.

Conventions: what good programmers choose

The rules decide what JavaScript accepts. Conventions decide what other people can read.

  • camelCase. A name cannot contain a space, so several words are glued together: the first word all small, every later word starting with a capital, as in studentName, totalMarks, passingMarks. The capitals stick up like a camel's humps. All the slides' examples follow it.
  • Say what it holds. totalMarks beats t, x1 or data. You type a name once and read it a hundred times.
  • Yes-or-no values usually start with is or has: isPassed, hasPaidFee.
  • Fixed settings known before the program runs are often written in capitals with underscores: const MAX_MARKS = 100;. This is a habit, not a rule; the slides' const passingMarks = 40; is just as correct.

Every beginner meets the same few messages in the first week. They look frightening in red, but each one names the problem precisely. The example below makes three common mistakes on purpose, one per button, so you can see the real messages.

Press Run and the Console shows Ready: passingMarks is 40 and totalMarks is 72. Then press the three buttons in order. In Chrome and Edge the panel shows:

Uncaught TypeError: Assignment to constant variable.  (line 16)
Uncaught ReferenceError: totalMark is not defined  (line 19)
Uncaught ReferenceError: TotalMarks is not defined  (line 22)

Take the first line apart. Every error message has the same four pieces:

  • Uncaught — nothing caught the error, so JavaScript stopped running that piece of code (Chapter 70 shows how to catch errors).
  • TypeError — the kind of error.
  • Assignment to constant variable. — what went wrong, in one phrase.
  • (line 16) — where. Count down the example to line 16 and you land on passingMarks = 35;. Chrome's own DevTools shows the place at the right-hand end, as something like index.html:16.

Notice when each kind appears. A TypeError or ReferenceError happens while the script is running, so every line above the broken one has already run; that is why "Ready" was printed first. A SyntaxError is found while JavaScript reads the whole script, before running any of it. The script is refused as a whole, not even its first line runs, and the Console shows nothing but the error:

console.log("Starting");     // never printed
let score = 50;
let score = 75;              // Uncaught SyntaxError: Identifier 'score' has already been declared

Read a red line from left to right: what kind of mistake, what exactly, and on which line. Then go to that line. If nothing at all was printed, look for a SyntaxError: the script was refused before it started.

A forgotten keyword is not an error. If you leave out let entirely, as in totl = 90; (a typo for total), a normal script does not complain. It quietly creates a brand-new variable called totl, your real total never changes, and nothing tells you why. Always declare with const or let. Putting the line "use strict"; at the very top of a script turns this silent mistake into a proper error: ReferenceError: totl is not defined.

42.10 Build it: a live scoreboard

Time to put the analogy from 42.3 on screen. The batting team, the ground and the target never change during an innings, so they are const. The runs and wickets change after every ball, so they are let. Each button stores a new value in a let and redraws the board.

Two pieces are borrowed from later chapters, and the comments say which. One line needs a word now: in runs = runs + 4; JavaScript works out the right side first, using the old value (0 + 4 is 4), and only then stores the answer back in runs. Chapter 44 shows the shorter runs += 4;.

<style>
  body { font-family: system-ui, sans-serif; padding: 10px 16px; color: #3C4A60; }
  .board { background: #0B2545; color: #fff; border-radius: 12px;
           padding: 12px 18px; max-width: 340px; }
  .board h3 { margin: 0 0 6px; color: #FF9933; font-size: 16px; }
  .board p { margin: 4px 0; font-size: 20px; font-weight: 700; }
  button { font: inherit; padding: 6px 12px; margin: 10px 6px 0 0; }
</style>
<div class="board">
  <h3 id="title"></h3>
  <p id="score"></p>
  <p id="need"></p>
</div>
<button id="one">1 run</button>
<button id="four">Four</button>
<button id="six">Six</button>
<button id="out">Wicket</button>
<script>
  // fixed for the whole innings: const
  const battingTeam = "India";
  const venue = "Mohali";
  const target = 181;

  // these change after every ball: let
  let runs = 0;
  let wickets = 0;

  // redraw the board (a function is a named job you can repeat: Chapter 48)
  function showBoard() {
    document.getElementById("title").textContent = battingTeam + " at " + venue;
    document.getElementById("score").textContent = runs + "/" + wickets;
    document.getElementById("need").textContent = "Need " + (target - runs) + " to win";
    console.log("runs:", runs, "wickets:", wickets);
  }
  showBoard();

  // each button changes a let, then redraws (buttons are Chapter 57)
  document.getElementById("one").addEventListener("click", () => { runs = runs + 1; showBoard(); });
  document.getElementById("four").addEventListener("click", () => { runs = runs + 4; showBoard(); });
  document.getElementById("six").addEventListener("click", () => { runs = runs + 6; showBoard(); });
  document.getElementById("out").addEventListener("click", () => { wickets = wickets + 1; showBoard(); });
</script>

On Run the board reads India at Mohali, 0/0, Need 181 to win, and the Console says runs: 0 wickets: 0. Press Four and then Six: the board shows 10/0 and Need 171 to win. The + between a number and text, as in runs + "/" + wickets, joins them into one piece of text; Chapter 44 explains why.

Two things to try in the Playground. First, change let runs = 0; to const runs = 0;. The board still draws 0/0, but pressing Four gives TypeError: Assignment to constant variable: the whole difference between let and const, in one click. Second, keep pressing Six past the target: the board says "Need" followed by a negative number. Printing "India won" instead needs a decision (Chapter 47).

42.11 Common misunderstandings

✗ "= means equals."
In JavaScript one = is an order, not a statement of fact.
✓ "= means store: work out the right side, put it in the variable on the left."
That is why marks = marks + 5; makes sense. Comparing is the job of === (Chapter 44).
✗ "A const can never change in any way."
A const object or array can be changed inside.
✓ "A const name can never be pointed at a different value."
student.marks = 95; is allowed; student = {}; is a TypeError.
✗ "A variable declared without a value is empty, or 0, or null."
None of those.
✓ "It holds undefined."
let city; console.log(city); prints undefined.
✗ "var and let are two spellings of the same thing."
They differ in three ways.
✓ "var can be declared twice, is function-scoped and can be read above its own line; let refuses all three."
That is exactly why let was added.
✗ "I typed let x = 5; in the DevTools Console and it said undefined, so x is undefined."
The Console was answering a different question.
✓ "The Console shows the value of the statement I typed, and a declaration has no value."
Type x on its own and it answers 5. (Chrome's Console prompt also lets you declare the same let twice, as a convenience while experimenting; a real script never does.)

Exam-style checks

Which keyword declares a variable that must be given its value at once and can never be reassigned?L1
  • A. var
  • B. let
  • C. static
  • D. const

Answer: D. const must be initialised on the same line and cannot be reassigned. let and var can both be reassigned, and static is not a way to declare a variable in JavaScript.

  • B. null
  • C. An empty line
  • D. ReferenceError: city is not defined

Answer: A. city was declared but never given a value, so it holds undefined. D is what you would get if city had never been declared at all.

What happens when this runs? const age = 20; age = 21; console.log(age);L3

  • B. It prints 20
  • C. TypeError: Assignment to constant variable., and nothing is printed

Answer: C. The second statement tries to reassign a const, which throws a TypeError and stops the script, so console.log never runs. It is not a SyntaxError: the code is grammatically correct, and the problem appears only when the assignment runs.

Which of these is a valid variable name?L2
  • A. 2ndYear
  • B. _totalMarks
  • C. first-name
  • D. class

Answer: B. A name may contain letters, digits, _ and $, and may start with _. A starts with a digit, C contains a hyphen (read as minus), and D is a reserved word.

Which statement about var, let and const is correct?L2
  • A. var can be declared twice in the same scope without an error
  • B. let can be declared twice in the same scope without an error
  • C. const can be declared without a value and assigned later
  • D. var is block-scoped

Answer: A. Redeclaring is the slides' first difference for var. B gives "Identifier has already been declared", C gives "Missing initializer in const declaration", and D is backwards: var is function-scoped, while let and const are block-scoped.

What does this print? const marks = [70, 80]; marks.push(90); console.log(marks);L3
  • A. TypeError: Assignment to constant variable.
  • B. [70, 80]
  • C. [70, 80, 90]
  • D. A SyntaxError

Answer: C. push changes the inside of the same array; the name marks is not reassigned, so const has no objection. Option A is the common wrong belief that const freezes the contents.

Say what each line does, and what fee holds at the end: let fee = 1500; fee = 1750; Could the first line use const instead?L2

Answer: the first statement declares fee and initialises it to 1500; the second reassigns it, so fee ends up holding 1750. It could not use const: the second statement would then throw TypeError: Assignment to constant variable. A value that is meant to change needs let.

What does this print? var score = 50; var score = 75; console.log(score); What happens if both vars are changed to let?L3

Answer: it prints 75: var allows a second declaration, which simply replaces the value. With let the script is refused with SyntaxError: Identifier 'score' has already been declared, and because a SyntaxError is found before the script runs, nothing at all is printed.

What does this print? let Marks = 90; console.log(marks);L3
  • A. 90
  • B. undefined
  • C. marks
  • D. ReferenceError: marks is not defined

Answer: D. Names are case-sensitive, so Marks and marks are different names, and no variable called marks was ever declared. B is tempting, but undefined needs a variable that exists without a value.

Following JavaScript's usual naming convention, which is the best name for a student's total marks?L1
  • A. total_marks
  • B. totalMarks
  • C. TotalMarks
  • D. total-marks

Answer: B. camelCase: the first word small, each later word starting with a capital. A is legal but not the JavaScript style, C capitalises the first word as well, and D is not legal at all, because the hyphen is a minus sign.

A variable counts how many students have submitted an assignment; it goes up by one with each submission. Which keyword should declare it?L2
  • A. var, because counters are old-style code
  • B. const, because it is a count
  • C. Any of the three; they behave identically
  • D. let

Answer: D. The value changes with each submission, so it needs reassignment, and in modern code that means let. B throws a TypeError on the first update, A works but brings var's hidden risks, and C is false.

A student writes const total; on one line and plans to write total = 450; later. What happens, and what are the two ways to fix it?L3

Answer: the script is refused with SyntaxError: Missing initializer in const declaration, because a const must receive its value in the declaration itself. Fix 1: write it in one line, const total = 450;. Fix 2: if the value really is assigned later, or will change, declare it with let total;.

Quick revision

Key takeaways

  1. A variable is a name bound to a value. Write the name and JavaScript uses the value it holds at that moment.
  2. Declaration creates the variable, initialisation gives its first value, and assignment (=) stores a value, replacing the old one. A variable declared but not yet assigned holds undefined.
  3. let can be reassigned. const must be initialised on the same line and can never be reassigned. var is the old keyword: it can be redeclared, is function-scoped, and gives undefined when read above its line.
  4. const fixes the name, not the contents: a const object or array can still change inside.
  5. Use const by default, let when the value must change, and never var in new code.
  6. Names use letters, digits, _ and $; they cannot start with a digit or be a reserved word; they are case-sensitive. Write them in camelCase and make them say what they hold.
  7. Read a red line as kind, message and line number. A SyntaxError stops the whole script before it starts; TypeError and ReferenceError stop it at the broken line.
